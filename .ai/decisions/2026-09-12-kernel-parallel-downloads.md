# 内核并行下载与双列卡片

- 日期：2026-09-12
- 状态：confirmed（用户已明确要求实施；验证结果见对应会话记录）
- 来源：用户本轮三个要求；旧项目 `autoflow-desktop/src/renderer/pages/KernelPage.tsx` 的按版本 pending 集合与卡片操作；当前内核组件、worker 和平台 provider。
- 分类：现有内核模块的有界行为调整，沿用 API、独立工作进程、数据库和 SSE，不新增模块或技术栈。

## 行为

1. 不同内核目标可并行下载安装，点击第一个之后其他版本仍可开始下载；同一 edition/version 对应同一安装目录，Stable/Preview 不得同时覆盖该目标。
2. 请求等待、错误和取消状态分别按目标或 operation ID 记录。取消一个任务不改变其他任务的状态；目录刷新或筛选不能隐藏活动任务的取消入口。
3. 正常桌面尺寸显示双列卡片，窄屏退回单列；每张卡片保留版本、通道、安装状态、元数据和自己的操作。内核管理继续只从配置表单进入。
4. 平台由后端识别；前端只显示返回的平台名称。Windows x64、macOS Intel/Apple Silicon 的下载包、可执行路径和进程行为继续集中于适配器。没有 Windows 实机结果时必须注明仅代码/测试矩阵覆盖。

## 并发边界

旧实施计划的“整个应用只允许一个安装 worker”限制标为 **superseded**。任务继续使用各自的 worker、staging、环境变量和进度；按安装目标防重，目录发布/维护保留短临界区。恢复必须识别其他仍活跃的任务，不能把另一 manager 的 staging 当成中断垃圾。多任务退出须并行取消和回收，不能让等待时间按下载数量累加。

HTTP/SSE 契约不变；不迁移数据、不增加队列产品、下载中心或新的浏览器品牌。沿用现有检查工具，不新增依赖。具体实现、测试及尚未验证的平台结果写入 `.ai/sessions/2026-09-12-kernel-parallel-downloads.md`。
