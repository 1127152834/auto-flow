# Studio 改为 WebRPA 源码迁入

> 2026-09-13 当前状态：用户要求先清除现有 Studio，再重新讨论 WebRPA 迁入。旧实现现已退出当前源码，仅保留独立空窗口；本文相关实现状态/迁入步骤留作历史，不在本轮执行。以[清除记录](../../docs/migration/studio-removal.md)为准。

- 日期：2026-09-13；状态：方向 confirmed；具体架构 proposed。
- 来源：用户明确不接受现有自定义 UI 与逐里程碑重新实现，要求照搬 WebRPA UI、前端交互和后端业务逻辑，在其基础上优化后端。
- 新方向优先于历史“AutoFlow 自定义视觉/节点契约/控制图/运行会话”的取舍；不再继续旧 M6。企业管理、Windows 桌面控制、发布版本管理仍排除；工作台核心完整迁入。
- 用户随后明确允许完全重构、弃用此前 Studio 代码。取消旧编辑器/旧执行器兼容约束；只归档旧源码和保全原数据，不建设双引擎或旧格式自动转换层。
- 正文唯一来源：[新设计](../../docs/superpowers/specs/2026-09-13-studio-webrpa-source-migration-design.md)及[实施安排](../../docs/superpowers/plans/2026-09-13-studio-webrpa-source-migration-implementation.md)。

已静态核对原编辑器/Store/CSS、HTTP/Socket.IO、模型、解析器、执行器、browser_engine 和录制器。原执行器会复用手动打开的共享浏览器，不能继续把 M2 每次独立会话作为强制行为。建议共享会话限制在工作区所属 worker；保留 AutoFlow 鉴权、资源锁、持久化、离开保护及进程监管。

不把原项目测试数量或“经过前人测试”当完整可靠性证据。具体例子：原未知执行器返回成功；迁移时应明确失败并补回归。原测试文档说明外部依赖存在 mock/skip，真实动作仍需实测。

按 AGENTS.md“架构级工作必须先完成设计、规格和实施计划，并等待用户确认”，本轮先交付可审查设计，不提前改变正式 Studio 入口和业务执行器。用户本轮已确认迁入方向，不应再次询问是否想要照搬；后续只确认本文具体架构安排。
