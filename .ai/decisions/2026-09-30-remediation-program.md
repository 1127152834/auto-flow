# 整改计划（M0–M6）

日期：2026-09-30；修订：r2。状态：confirmed（整改方向及文档修订）；具体技术条款为 proposed，生产实施尚未开始。来源：用户要求评审 M0–M6 后“帮我修订”；文档基线 d2c89aeb，业务源码基线 ea2cc5b。

正式依据：[总纲](../../docs/superpowers/specs/2026-09-30-remediation-roadmap.md)、[方案](../../docs/superpowers/specs/2026-09-30-autoflow-remediation-proposal.md)、[阶段索引](../plans/2026-09-30-remediation-program.md)。验证方法：对照现有执行、调度、输入选择、数据身份、环境和历史证据链评审；本次只修订文档，不代表实现通过验收。

## 决定

- 保留 M0–M6。M0 固定真实输入、核对唯一行及成功结果；controlled-one-row-batches-v1 与 M2B 的 native-batch-v1 分开比较。
- M1 修复完整调用链：递归/并行错误语义、容量更新顺序、worker 有界诊断及 API 传递；未知执行结果保留门禁。
- M2 分 A 可靠性、B 数据契约、C 触发与网页扩展；A/B 完成可进入 M3，不受 C 阻塞。主处理输入决定处理单位，参考输入不消费；完整记录身份包括 generation、typed key 和来源 namespace。
- 所有领取模式统一阻止未知结果；自动重试检查整个 Task 已发生的副作用，旧配置不静默激活。人工核实保留原未知事实。
- M2B 前置稳定节点输出元数据与后端 previewWrites；M5 先交付数据绑定、试跑和失败处理，视觉完善后置。
- M3 先测量 SQL 下推/事件批量，再决定单写线程、池和 JSONL 等优化；保留持久 ACK、完整性校验与被引用环境代次。perIdentity 随 M4 身份模型交付。
- M4 新种子登记唯一；迁移保留历史重复种子且不合并不同账号身份，公开创建不能走迁移例外。记录实际出口 IP，不能把代理成员固定等同于出口固定。
- M6 包括完整历史产物迁移与剩余执行入口收敛。旧解析器退役以持久数据、冻结内容、升级/导入兼容门禁为依据，不能仅依赖一个版本或七天观察期。

## 随实施生效的替代关系

容量从固定 1/2 改为可配置的执行/存活双名额；人工等待只占存活名额。新工作流用 v2 错误语义，旧工作流保留旧行为。领取增加台账资格；结构只在设计期修改。Profile 种子改为身份引用种子登记。各阶段合并前，现有代码行为仍是当前事实。

## 保留的用户决定与修订边界

历史记录中的用户决定继续保留：QA 截图历史清理、默认保留身份原种子、冻结 Android/iOS 模拟器管理、桌面触发器和 Sheets 双向同步扩展。历史清理改为独立维护，精确资产清单、归档/备份恢复和有效引用检查先行，推送时仍须明确确认；本轮不执行。

superseded：旧版“全部步骤已原型验证，可直接执行”、13 周固定排期、M0 以历史改写为退出条件、M2 全功能一起阻塞 M3、身份种子列直接全局唯一，以及“仅待一个版本即可删除旧格式”的表述。M0/M1 按修订计划逐项验证，M2–M6 在前置接口稳定后细化并审查；不把计划示例当成已运行代码。

## 后续持续实施授权（同日）

用户在文档复审后明确授权直接实施M0–M6及本地提交；M2–M6前置完成后细化步骤并审查，自主继续，不再逐阶段等待批准。该直接授权替代本组文档中旧的“每阶段需确认开工”要求。常规技术选择自行决定；超范围重大产品取舍、无法安全推进的阻塞、不可逆操作才询问。部署发布、破坏性数据删除、Git历史改写推送和外部消息不在授权内。
