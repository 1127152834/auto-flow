- 状态：资源看板视觉方向 **confirmed**（用户选择上一轮第三张图）；本轮二级页面与交互规则 **proposed**，不代表已实现或已授权正式模块开发。

- 生成方式：内置 ImageGen；完整提示词见 [prompts.json](prompts.json)。画面中的设备、应用、步骤和运行状态均为示意数据。

## 页面结构与流转

资源看板保留“实例列表 / 资源看板”切换；两种视图共享筛选与选中项。返回看板恢复筛选、滚动位置。实例详情包含“控制台 / 应用 / 环境配置 / 运行记录”四个页签。

| 入口 | 去向与细节 |
| --- | --- |
| 打开设备 | 进入控制台，默认观察；点击“开始控制”成功取得占用后才启用输入。原型图展示已取得控制权的状态 |
| 预览 | 同一控制台的只读状态，显示具体工作流和当前步骤 |
| 查看运行 | 打开该实例关联的具体运行记录，保留返回实例入口；不能只打开工作流编辑文档 |
| 分配给工作流 | 右侧抽屉：选择工作流、所需环境、实例与结束策略；确认操作命名“分配并运行”，说明会开始执行 |
| 环境配置 | 从看板进入配置列表；创建表单里的“管理配置”在保留表单草稿的弹窗中打开 |
| 复制配置 | 进入预填创建页；名称加可编辑后缀，明确“新实例为空白数据，不复制已安装应用或登录状态” |
| 省略号菜单 | 重命名、复制配置、停止、重启、删除；按设备状态和占用情况启用 |

看板要补充“手动控制中”和“待处理”归类：前者显示操作者，后者承载启动失败、断连、未知占用与清理失败。不能把这些设备继续计入“可分配”。“全部”过滤条件下列计数相加等于设备总数；过滤时明确显示“匹配数 / 总数”。停止态用中性灰，失败态用警示色。

## 手动控制的交互规则

| 操作 | 设计行为 |
| --- | --- |
| 点击 | 在安卓有效画面内点击才发送触控；留白、工具栏和预览缩略图不发送 |
| 滑动 | 鼠标按下拖动再松开；按实际画面尺寸、缩放和旋转换算。越界或取消时结束手势，避免设备一直处于按下状态 |
| 长按 | 按住不移动达到阈值后发送一次长按；不能额外补发一次点击。阈值需实测调校 |
| 键盘 | 只在控制画面聚焦且开启键盘输入时捕获；表单输入不会传给安卓；按 Esc 退出画面键盘捕获，返回安卓使用专用返回按钮 |
| 中文与粘贴 | 优先使用显式“文本发送”；发送到当前安卓输入焦点，显示发送结果，不自动同步宿主剪贴板。发送成功不冒充目标应用已接受全部内容 |
| 滚轮 | 画面聚焦时转换为有界滑动；未聚焦时滚动应用页面。触控板与连续滚动需独立验证 |
| 系统操作 | 返回、主页、最近任务固定可见；音量、旋转等按实际能力启用，未知能力不能假装可用 |
| 截图 | 保存当前帧并显示产物入口；只读会话也可截图，不改变设备控制权 |
| 全屏与缩放 | 全屏仍在 AutoFlow 内；保留退出、控制权和断连提示；缩放只改变显示，不修改安卓分辨率 |
| 结束控制 | 先停止接收新输入、处理在途动作，再释放手动占用；保留持久数据，不等于停止或删除实例 |

同一设备只能有一个写入者：手动会话或者工作流。只读观察可以共存。多窗口同时请求控制时只有一个成功，另一个显示“已由其他窗口控制”。关掉控制台不能无限占用设备；正常离开释放手动会话，异常断线先核实在途动作与占用，再恢复可分配，不能仅凭超时直接抢占。

实时画面是目标体验。视频尚未就绪时，界面必须如实显示“单帧预览 · 最多 1 帧/秒”；连续画面中断应冻结最后一帧、标明过期并禁用输入。恢复连接后先获取新帧并核对控制权，再允许操作；不缓存重放断连期间的点击和文字。触控、文字等失败结果不明时显示“结果待确认”，不自动重复发送。

## 工作流暂停、接管与归还

1. **运行中**：只读画面，显示工作流名、具体运行标识、当前节点；禁用点击、文字、安装、启动应用、停止和删除设备。
2. **请求暂停**：点击“暂停并接管”，保持输入锁定；文案“等待当前步骤结束”。当前动作完成或执行器确认中止后，才能确认已暂停。
3. **接管成功**：暂停记录持久化、在途动作结束、控制权交接完成后，进入“手动控制中 · 工作流已暂停”。工作流对实例的保留关系仍存在，其他任务不能分配。
4. **接管失败或状态未知**：保留只读与原占用，展示原因和“重新核实”；不显示手动控制成功，不暴露“强制接管”捷径。
5. **归还控制**：提供“归还并继续”和“结束运行并保留设备”。继续前展示下一节点、最新截图和“手动操作可能改变页面状态”，显式确认并重新验证必要前置条件；不盲目从原点击位置继续。
6. **离开或断连**：不自动恢复工作流。暂停状态保持可见；确认会话结束后清除手动输入权，实例仍由暂停运行保留，等待继续或结束决策。

临时实例被接管时暂停自动回收。选择“结束运行并保留设备”须把保留结果记录为“待处理”，并持续计入容量；之后由用户转为持久实例或明确删除。普通临时实例在成功、失败、取消后按本次运行策略回收，清理失败也进入“待处理”。

这是后续目标流程。当前工作流 M2 具有启动、停止、运行事件及产物，但没有本设计所需的安全暂停/恢复与安卓控制权交接。未支持时隐藏或禁用“暂停并接管”，提示原因；停止任务会走清理，不能直接用停止接口冒充暂停。

## 创建实例、配置和批量结果

- 创建页用名称前缀 + 数量生成可编辑名称预览；提交前检查重名、架构、可用镜像与本机运行环境。Mac 当前路线采用 ARM64；不默认给 Apple Silicon 创建 x86_64 配置。
- 持久实例保存数据；临时实例根据绑定运行的结束策略回收。手动创建但尚未绑定工作流的临时实例不得无提示消失，显示“未分配”，支持删除或转持久。
- 启动时区分“等待资源 → 创建中 → 启动 Android → 已就绪 / 失败”；容器启动成功不等于 Android 可操作。
- 批量创建后返回看板并打开结果抽屉，每行显示实例、当前阶段、失败原因及重试入口。部分失败只重试失败项；不会重建成功实例。取消停止后续创建，已创建资源逐台展示处理结果。
- 配置列表显示名称、Android 版本、架构、镜像状态和能力摘要。编辑表单区分可复用模板与已有实例的配置快照；保存模板不静默修改运行设备。
- 实例“环境配置”页签展示实际配置、来源模板和能力检查；需要重建的修改明确引导创建新实例；只需重启的修改说明生效方式，占用时禁止修改。
- shell root 与应用级 root 分别显示“可用 / 不可用 / 未验证”和检查来源。代理、定位、厂商信息、设备指纹及摄像头后续按“请求值 / 观测值 / 检查结果”呈现；第一版不展示虚假的已通过状态。

## 其他二级页与弹窗

| 页面或弹窗 | 内容与交互 |
| --- | --- |
| 应用页签 | 搜索应用名/包名，第三方应用优先；行内启动，菜单卸载。上传 APK 弹窗显示上传、安装、完成三个阶段。仅有控制权时允许写操作；兼容性失败显示实际原因，不能把上传完成当安装成功 |
| APK 安装失败 | 保留文件名、目标设备与失败原因；返回应用列表或显式重试。重试只作用于该实例，不广播到其他设备 |
| 运行记录页签 | 当前与历史运行列表，显示状态、占用/释放、截图产物；进入具体运行后按节点查看日志。手动动作摘要与工作流日志分开，不记录输入文本和剪贴板正文 |
| 分配抽屉 | 检查设备空闲、能力、所选工作流与结束策略；提交时再次检查占用。资源不可用时区分“等待指定设备”和“自动选空闲设备”，排队原因明确 |
| 停止 / 重启 | 确认数据保留；手动控制需先结束会话，工作流占用需先处理运行。执行失败保留原因和实际设备状态 |
| 删除实例 | 明示实例名与数据删除范围；占用时阻止。容器与独立数据清理都确认成功后才移出列表；清理失败显示可重试的待处理项 |
| 无设备 | 简短说明和“创建实例”，无空 KPI 看板 |
| 本机环境未就绪 | 页内准备引导、检查结果和重试；不阻塞 AutoFlow 其他模块 |
| 启动超时 / 连接断开 | 实际错误与诊断入口，画面加过期遮罩。不能用最后一张图片冒充仍在线 |

## 实现边界与评审结果

| 能力 | 当前证据 | 本组原型含义 |
| --- | --- | --- |
| Mac redroid、创建/启停、三实例、APK、基础点击滑动和按键 | Demo [Mac 实测](../../MAC_TEST.md)；本轮未重跑 | 可复用基础能力，正式 UI 尚未接入 |
| 截图预览 | `frontend/src/components/ScreenPreview.tsx`，最多每秒一次 | 不能标成连续视频 |
| 文字 | `DevicePanel.tsx` 仅允许最多 200 个可打印 ASCII 字符 | 中文发送、直接键盘与输入法组合事件需实现验证 |
| shell root | Mac 对照记录 | 不证明任意应用能获取 root |
| 工作流真实运行 | `.ai/decisions/2026-09-13-workflows-m2.md` 与 `application/workflows/runs.py` | 浏览器运行基础已存在；安卓、暂停接管和批量调度仍需扩展 |
| 连续画面、长按、旋转、中文、暂停接管 | 尚无本轮实现或实测 | 目标交互，不承诺现有 Demo 已支持 |

人工核对了三张图的视觉一致性、状态与主操作。生成图保留以下细节偏差，后续组件实现以本说明为准：

- 占用页右上角生成了“打开设备”，应改为“查看运行”；本页已在控制台，不能另设绕过占用的操作入口。
- 手动控制图的应用包名是生成示意，并非实际 Notes APK；实现必须读取真实应用标签与包名。
- 创建页系统图片仅作模板示意，不证明默认镜像包含图中的应用或服务；能力摘要必须来自真实兼容检查。
- 基准看板中停止实例仍显示彩色手机画面；实现改为灰色占位或标注“上次画面”，启动中也不能展示假实时桌面。

验证仅覆盖设计内容、原型文件完整性与文档引用，没有运行功能测试或修改业务实现。设计一致性判断置信度高；连续画面、中文输入及接管的实际体验未验证。

建议先实现“资源看板 → 单实例手动控制 → APK 安装/启动”这一完整切片；随后接入工作流只读观察与排他占用；安全暂停/恢复验证通过后再开放接管。
