# Demo HTTP contract

Implementation contract, 2026-09-13. All routes are relative to the same origin. Host must be localhost, 127.0.0.1 or ::1 (optional port). JSON mutations require `Content-Type: application/json`; APK upload uses multipart. Reject cross-origin mutations; non-browser CLI without Origin is supported. Errors: HTTP 400/404/409/413/415/503/504 with `{ "error": { "code": "...", "message": "..." } }`. Never report fake devices on Docker failure.

## Types

`Instance`: `{id, name, image, image_id, docker_status, android_status, android_version, width, height, dpi, cpu, memory_mb, adb_address, busy, error}`. `id` is the unique container name generated by the backend; name is a user-facing label. Android status is `starting|ready|stopped|failed|unknown`; adb_address, android_version and error can be null. android_version is the observed ro.build.version.release after readiness, never inferred from image tag. cpu is a number, other size fields integers. Ports are inspected from Docker, container port always 5555, host binding loopback. UI labels the address as Docker host/localhost. For Mac with a Linux VM this means the VM loopback, not macOS loopback unless separately forwarded; management uses Docker exec on that same Engine.

`Job`: `{id, action, status, total, done, results}`. Status `queued|running|done|failed`. Each result: `{instance_id: string|null, name: string, status: "success"|"error", message: string, data?: object}`. A job is done only if every result succeeds, otherwise failed; partial results remain visible while running. Job memory is bounded and lost on service restart. POST accepted response is HTTP 202 `{job_id}`. `GET /api/jobs/{id}` returns Job. `GET /api/jobs` returns `{jobs: Job[], session_id: string}`; session_id changes per service process.

## Environment

`GET /api/environment` => `{docker_available: boolean, ready: boolean, checks: [{name, status: "pass"|"fail"|"unknown", message}], daemon: object|null, images: [{ref, cached, id: string|null, digests: string[], architecture: string|null, compatible: boolean}], limits: {max_instances: 3, concurrency: 2}}`.

GET remains HTTP 200 with diagnostic failures; normal instance routes return 503 if Docker unavailable. The Docker socket must address a native Linux amd64 or arm64 Engine; image OS and architecture must match that Engine. `x86_64`/`amd64` and `aarch64`/`arm64` aliases are normalized for comparison. Mac Apple Silicon uses a separate arm64 Linux VM with binder configured; this does not make Docker Desktop a supported baseline. Docker Desktop is reported explicitly as unsupported. Host observations come from read-only `/host/proc` and `/host/dev` mounts in Compose; absence means unknown, not proven ready.

`compatible` describes a cached image whose OS is Linux and architecture matches a supported daemon architecture; it does not by itself prove binder or overall host readiness. Missing images return `cached:false`, `architecture:null`, `compatible:false`. `ready` requires every environment check to pass, including at least one cached compatible image. Creation rechecks the selected image and reports `image_missing` or `image_architecture` rather than silently choosing another image. Docker image ID and repository digests are preserved. The UI disables incompatible cached images and initially selects the first cached compatible image.

## Instances and jobs

- `GET /api/instances` => `{instances: Instance[]}`; list only Demo-owned containers.
- `POST /api/instances` body `{name, image?, width?, height?, dpi?, cpu?, memory_mb?, count?}` => job. Defaults: image is the first configured `REDROID_IMAGES` entry, width720 height1280 dpi320 cpu2 memory_mb2048 count1. With no environment override that entry is `redroid/redroid:13.0.0-latest`; configuring an arm64 base first changes the API default accordingly. Count1–3, at most3 Demo instances (running or stopped). Unique ID/volume for each. Dimension128–2160, DPI120–640, CPU0.5–8, memory512–8192; size/dpi/memory/count integers. Image must be one of environment.images; creation only uses cached Linux images matching the actual Engine architecture. Configuration clone counts against capacity.
- `GET /api/instances/{id}` => Instance. Lifecycle/job reads separate Docker-running from Android-ready.
- `POST /api/instances/{id}/actions` body `{action: "start"|"stop"|"restart"|"clone"|"delete"|"open_settings"|"launch"|"root_check", package?: string}` => job. Delete removes only owned instance+owned volume and reports cleanup failures. Clone creates a new empty data volume with same settings. launch validates package then resolves/starts its launcher. open_settings starts system settings. root_check collects `container_exec_uid`, `magisk_version` and `shell_su` separately, each with `argv`, `exit_code`, `stdout` and `stderr`. Magisk and su checks use the explicit `/sbin/magisk -v` and `/sbin/su -c id` through a fixed `/system/bin/sh -c` invocation: missing optional tools return an observed nonzero exit instead of being mistaken for an OCI transport failure. This intentionally avoids the different AOSP `/system/bin/su` command. Result data always labels `host_adb_root` and `app_root` as `unverified`; collecting a check successfully does not mean that permission check passed.
- `POST /api/batches` body `{action: "start"|"stop"|"restart"|"delete"|"install"|"open_settings", instance_ids: string[], apk_id?: string}` => job. 1–3 distinct owned targets, reserve all before accepting; busy =>409 without partially scheduling. Per-instance failures do not stop other targets. No automatic destruction of pre-existing devices.
- `GET /api/instances/{id}/screen` => one PNG, Cache-Control:no-store. Only ready/not-busy devices, finite timeout. Frontend one active image, nonoverlap requests ≤1/sec, pause when hidden. Use PNG actual dimensions/object-fit content rectangle to map input; ignore letterbox. Screenshot is not a video stream.
- `POST /api/instances/{id}/input` body `{action: "tap"|"swipe"|"key"|"text", x?, y?, x1?, y1?, x2?, y2?, code?, text?}` => `{ok:true}`. Coordinates integer and validated against actual screen dimensions. System keys whitelist 3,4,187,66,67,19,20,21,22,62. Text printable ASCII up to200 chars, spaces supported; reject unsupported characters honestly. Per-device mutual exclusion, use argv and verify exit status.
- `GET /api/instances/{id}/packages` => `{packages: string[]}` third-party packages only.

## APK

- `GET /api/apks` => `{apks: [{id, name, size_bytes}]}`.
- `POST /api/apks` multipart `file` =>201 `{id,name,size_bytes}`. Max256MiB. Unique internal file ID, no user-controlled path; basic APK zip/AndroidManifest validation, no custom AXML parser. Single APK only.
- Install via batches above, even for one target. Wait for Android with a finite boot deadline; timeout aborts that target before installation. The normal transport creates a tar archive and uses Docker `put_archive` to `/data/local/tmp/<apk_id>.apk`.
- A narrowly scoped fallback handles Docker API HTTP 500 only when its error includes both `error setting up pivot dir` and `read-only file system`, which can occur after Magisk remounts the rootfs read-only. It streams the APK over Docker exec stdin into the same writable `/data` path, using only a fixed `cat` command and the validated internal APK filename. Other archive errors propagate; ambiguous partial stdin sends are not retried. Transfer has a 120-second deadline and retains the normal mutation stop/quarantine behavior on an uncertain result.
- Both transports run `pm install -r`, require exit code 0 plus a `Success` output line, and remove the temporary APK. Cleanup failure is reported even if installation succeeded. Successful per-target result data is `{id, apk_id, output, transport: "archive"|"exec_stdin"}`; the job UI preserves this data.

## Runtime constants and delivery

Single Python process, Waitress; backend2 worker threads for jobs, bounded pending jobs (10 active), at most50 retained job records. Per-instance busy ownership; release on completion/failure. Container operations/exec have bounded timeouts; report actual errors. Boot deadline180s default (`REDROID_BOOT_TIMEOUT`), Docker request30s, exec15s default/install120s (`REDROID_EXEC_TIMEOUT`). Timeout with still-running exec must not allow conflicting commands; stop owned container or keep it quarantined/busy until operation has ended, report this outcome. No arbitrary shell endpoint.

During startup, only the fixed read-only `getprop sys.boot_completed` probe is retried after early init/exec failures or probe timeouts, until the boot deadline. Each attempt uses the smaller of the configured exec timeout and remaining boot time, then waits up to one second before retrying. A ready device requires exit code 0 and output `1`; boot timeout reports the last probe failure and prevents subsequent operations. A probe failure does not itself stop the booting device.

Read-only list readiness recovery uses the same fixed property probe, at most once per 10 seconds per idle unknown/starting device, with a 3-second deadline. Its timeout reports unknown and does not stop the device. This exception is not available to arbitrary commands; mutating operations keep the stop/quarantine behavior above. Ready state and the observed Android version are cached against container start time. List recovery alone may leave `android_version:null` until a full readiness wait has collected the version.

Paths: backend/app.py exports `create_app()` and CLI `python -m backend.app`; static root env `REDROID_STATIC_DIR` defaults frontend/dist. `REDROID_UPLOAD_DIR` default local `.data/apks`; `REDROID_BIND_HOST` default127.0.0.1 (container0.0.0.0), `PORT` default8080. `REDROID_IMAGES` is a nonempty comma-separated allowlist, defaulting to `redroid/redroid:13.0.0-latest,autoflow/redroid:13-magisk`. The first entry is the API default when `image` is omitted; the UI explicitly submits its selected compatible image. An absent optional Magisk image does not block creation from an available compatible base. Empty configured lists fail service startup. `REDROID_HOST_PROC` / `REDROID_HOST_DEV` default `/host/proc` / `/host/dev`.

## Root build and host-side evidence tools

`scripts/build_root.py --base-image <ref>` (or `REDROID_BASE_IMAGE`) accepts a cached Android 13 base on native Linux amd64/arm64 only, with process host, local Docker Engine and image architecture matching. On Mac it runs inside the Linux VM. It invokes the pinned redroid-script from an isolated temporary copy, sets the native build platform, verifies the generated image and records IDs/digests. Image build success remains `built_not_boot_verified`; it does not certify Android startup or app root.

`scripts/check_root.py` runs on the actual Docker host so its loopback ADB mapping resolves correctly. It records shell UID before/after `adb root`, then calls explicit `adb shell /sbin/magisk -v` and `adb shell /sbin/su -c id`. `transport_ok` describes successful ADB shell access; it is separate from the reported `adb_shell_root` observation and the always-unverified application-root field. The script exits successfully when the evidence transport worked, even if an optional root command was unavailable.

Frontend user operations (including package reads) retry only HTTP 409 with error.code=busy, which means the operation was rejected before execution: 200ms intervals, a 2-second retry window, at most10 retries. Network and other errors are never retried. Screenshot polling has no additional fast retry. Temporarily paused preview retains its last frame with an explicit frozen-state label.

## Mac 原生窗口验证 API（独立 8082 入口）

`scripts/native_monitor.py` 在 Mac 宿主提供下列固定接口，不由 VM 中的 Flask 执行。页面位于 `/native`；只接受本机 Host，POST 必须带同源 Origin 和 JSON，不能提交命令、任意路径或 ADB 地址。

| 方法与路径 | 输入与返回 |
| --- | --- |
| `GET /api/native` | 返回原 Demo 的 `instances` 和本次原生窗口 `session`；session 包含 `phase`、`instance_id`、`message`，出画面后有本机 `serial`，失败时可包含相对日志路径 |
| `POST /api/native/open` | 仅接受 `{"instance_id":"afd-…"}`；202 表示启动任务已接受，不表示 Android 或窗口已就绪；已有窗口/启动任务返回 409；状态通过 GET 查询 |

窗口状态为 idle → starting → connecting → open → closing → closed，任一步失败返回 failed 和具体原因。用户在 Mac 原生窗口关闭按钮结束连接；本入口没有网页 Android 输入、删除或停止设备接口。启动器对已停止实例调用原 Demo 的 start job，并核实逐台结果后才连接 scrcpy。当前一次一个窗口，不提供正式会话排他租约。详见 [NATIVE_MAC_TEST.md](NATIVE_MAC_TEST.md)。
