# Demo HTTP contract

Implementation contract, 2026-09-13. All routes are relative to the same origin. Host must be localhost, 127.0.0.1 or ::1 (optional port). JSON mutations require `Content-Type: application/json`; APK upload uses multipart. Reject cross-origin mutations; non-browser CLI without Origin is supported. Errors: HTTP 400/404/409/413/415/503/504 with `{ "error": { "code": "...", "message": "..." } }`. Never report fake devices on Docker failure.

## Types

`Instance`: `{id, name, image, image_id, docker_status, android_status, android_version, width, height, dpi, cpu, memory_mb, adb_address, busy, error}`. `id` is the unique container name generated by the backend; name is a user-facing label. Android status is `starting|ready|stopped|failed|unknown`; adb_address, android_version and error can be null. android_version is the observed ro.build.version.release after readiness, never inferred from image tag. cpu is a number, other size fields integers. Ports are inspected from Docker, container port always 5555, host binding loopback. UI labels address as WSL host/localhost; management uses Docker exec.

`Job`: `{id, action, status, total, done, results}`. Status `queued|running|done|failed`. Each result: `{instance_id: string|null, name: string, status: "success"|"error", message: string, data?: object}`. A job is done only if every result succeeds, otherwise failed; partial results remain visible while running. Job memory is bounded and lost on service restart. POST accepted response is HTTP 202 `{job_id}`. `GET /api/jobs/{id}` returns Job. `GET /api/jobs` returns `{jobs: Job[], session_id: string}`; session_id changes per service process.

## Environment

`GET /api/environment` => `{docker_available: boolean, ready: boolean, checks: [{name, status: "pass"|"fail"|"unknown", message}], daemon: object|null, images: [{ref, cached, id: string|null}], limits: {max_instances: 3, concurrency: 2}}`.

GET remains HTTP 200 with diagnostic failures; normal instance routes return 503 if Docker unavailable. Defaults: image `redroid/redroid:13.0.0-latest`; optional cached root image `autoflow/redroid:13-magisk`. Docker socket must address Linux amd64 daemon; Docker Desktop is an unsupported baseline, reported explicitly. Host observations from read-only `/host/proc`, `/host/dev` mounts in Compose; absence means unknown, not proven ready. Explicit preflight/create errors for unsupported host. Image metadata and Docker actual image ID/digest are preserved in outputs.

## Instances and jobs

- `GET /api/instances` => `{instances: Instance[]}`; list only Demo-owned containers.
- `POST /api/instances` body `{name, image?, width?, height?, dpi?, cpu?, memory_mb?, count?}` => job. Defaults: image above, width720 height1280 dpi320 cpu2 memory_mb2048 count1. Count1–3, at most3 Demo instances (running or stopped). Unique ID/volume for each. Dimension128–2160, DPI120–640, CPU0.5–8, memory512–8192; size/dpi/memory/count integers. Image must be one of environment.images; creation only uses cached image. Configuration clone counts against capacity.
- `GET /api/instances/{id}` => Instance. Lifecycle/job reads separate Docker-running from Android-ready.
- `POST /api/instances/{id}/actions` body `{action: "start"|"stop"|"restart"|"clone"|"delete"|"open_settings"|"launch"|"root_check", package?: string}` => job. Delete removes only owned instance+owned volume and reports cleanup failures. Clone creates a new empty data volume with same settings. launch validates package then resolves/starts its launcher. open_settings starts system settings. root_check reports container-exec UID, Magisk command/version and shell su output separately; app root and host ADB root remain unverified (not inferred from exec uid).
- `POST /api/batches` body `{action: "start"|"stop"|"restart"|"delete"|"install"|"open_settings", instance_ids: string[], apk_id?: string}` => job. 1–3 distinct owned targets, reserve all before accepting; busy =>409 without partially scheduling. Per-instance failures do not stop other targets. No automatic destruction of pre-existing devices.
- `GET /api/instances/{id}/screen` => one PNG, Cache-Control:no-store. Only ready/not-busy devices, finite timeout. Frontend one active image, nonoverlap requests ≤1/sec, pause when hidden. Use PNG actual dimensions/object-fit content rectangle to map input; ignore letterbox. Screenshot is not a video stream.
- `POST /api/instances/{id}/input` body `{action: "tap"|"swipe"|"key"|"text", x?, y?, x1?, y1?, x2?, y2?, code?, text?}` => `{ok:true}`. Coordinates integer and validated against actual screen dimensions. System keys whitelist 3,4,187,66,67,19,20,21,22,62. Text printable ASCII up to200 chars, spaces supported; reject unsupported characters honestly. Per-device mutual exclusion, use argv and verify exit status.
- `GET /api/instances/{id}/packages` => `{packages: string[]}` third-party packages only.

## APK

- `GET /api/apks` => `{apks: [{id, name, size_bytes}]}`.
- `POST /api/apks` multipart `file` =>201 `{id,name,size_bytes}`. Max256MiB. Unique internal file ID, no user-controlled path; basic APK zip/AndroidManifest validation, no custom AXML parser. Single APK only.
- Install via batches above, even for one target. Put archive into container tmp, `pm install -r`, verify success+exit, remove tmp. Wait for Android with finite boot deadline; timeout aborts target.

## Runtime constants and delivery

Single Python process, Waitress; backend2 worker threads for jobs, bounded pending jobs (10 active), at most50 retained job records. Per-instance busy ownership; release on completion/failure. Container operations/exec have bounded timeouts; report actual errors. Boot deadline180s default (`REDROID_BOOT_TIMEOUT`), Docker request30s, exec15s default/install120s (`REDROID_EXEC_TIMEOUT`). Timeout with still-running exec must not allow conflicting commands; stop owned container or keep it quarantined/busy until operation has ended, report this outcome. No arbitrary shell endpoint.

Read-only list readiness recovery is a separate fixed `getprop sys.boot_completed` probe: at most once per10 seconds per idle unknown/starting device, with a3-second deadline. Its timeout reports unknown and does not stop the device. Mutating operations keep the stop/quarantine behavior above. Ready state is cached against container start time.

Paths: backend/app.py exports `create_app()` and CLI `python -m backend.app`; static root env `REDROID_STATIC_DIR` defaults frontend/dist. `REDROID_UPLOAD_DIR` default local `.data/apks`; `REDROID_BIND_HOST` default127.0.0.1 (container0.0.0.0), `PORT` default8080. `REDROID_IMAGES` optional comma-separated allowlist defaults both images above; absent optional Magisk image is diagnostic info, does not block default base creation. `REDROID_HOST_PROC` / `REDROID_HOST_DEV` default `/host/proc` / `/host/dev`.
