# 设置页原型交互说明

- 日期：2026-09-12
- 状态：confirmed；用户授权自主实施，验证边界见 ../../migration/settings-dashboard-status.md
- 原型：`settings-general.png`、`settings-workspace-flow.png`、`settings-about-diagnostics.png`
- 事实边界：参见 `settings-capability-baseline.md`。本文描述界面状态与反馈，不定义正式 API 契约或实施计划。
- 信息架构：保留“常规 / 工作区 / 关于”三个页签，不增加侧栏，不混入代理、内核、浏览器配置等业务设置。

## 全局交互

- 页签切换保留当前页内状态；正在执行不可中断的突变操作时，允许浏览内容但禁止再次提交冲突操作。
- Modal 入场为 `150ms`、位移 `8px`；系统或本机偏好为“减少动效”时取消移动、缩放和旋转，只保留瞬时透明度变化与明确文字状态。
- Toast 入场 `150ms`。成功 Toast 显示 `2.6s` 后自动消失；错误提示持续显示并可关闭，避免用户来不及读取或复制错误码。
- Modal 打开后焦点进入标题后的首个可操作控件；Tab 焦点限制在 Modal 内；关闭后焦点返回触发按钮。普通预览可用 `Esc` 或点遮罩关闭。
- 正在切换、重启、生成或保存时，Modal 不响应 `Esc`、遮罩和关闭按钮，避免界面掩盖仍在进行的操作。失败或超时后恢复关闭能力，不允许永久卡在加载态。
- 所有“已恢复”“已保存”“已退出”只在对应动作被确认完成后出现。恢复失败必须显示真实结果，不能用成功文案覆盖未知状态。

## 01 `settings-general.png`：常规正常态

### 本地服务状态

- `starting`：显示“本地服务正在启动”和文字进度；重启按钮禁用。
- `ready`：显示“运行正常 / 本地服务已连接”，允许重启；连接详情读取失败不影响服务状态本身。页头和卡片使用同一状态源。
- `failed`：显示“启动失败”、可读错误摘要/错误码和“重试启动”；不得显示“运行正常”。
- `stopped`：显示“本地服务已停止”和“启动服务”。
- 点击重启后按钮变为“正在重启…”，同一操作及工作区切换入口禁用，重复点击不产生第二次提交。
- 任一当前执行器占用进程、浏览器会话、文件或写事务时，禁止重启和切换工作区。控件旁说明占用任务及等待原因；已接入当前内核、代理、浏览器配置占用与 API 写入预检。
- 重启失败时展示恢复原服务的真实结果：恢复成功、恢复失败或状态未知必须区分。不得笼统提示“原服务保持不变”。
- 服务已停止时，由桌面主进程确认旧进程和占用已释放，再允许启动；不能要求一个已停止的服务回答占用查询，造成无法恢复的死循环。状态未知时保留读取状态/恢复入口，不能直接显示可切换。

### 界面偏好

- 界面缩放提供 `90% / 100% / 110% / 125%`。
- 动效提供“跟随系统 / 减少动效 / 完整动效”。
- 两项偏好属于本机应用，不随 Workspace 切换，也不写入 Workspace。
- 选择后立即应用并持久化；持久化失败时回滚到上一个已保存值，显示持续错误提示。界面显示值始终与实际生效值一致。

### 连接详情

- 保留旧版监听范围、API 版本、连接方式等技术信息，收纳到“连接详情”折叠只读区，默认折叠。
- 监听地址从实际主进程状态读取，API 版本来自受支持的契约/构建信息，连接方式按实际启用通道展示。读取失败显示“不可用”，不回退为“运行正常”；未启用 SSE 时不得照抄旧版的 SSE 文案。图中已包含折叠入口。

## 02 `settings-workspace-flow.png`：工作区流程

### 02A 工作区

- 展示当前 Workspace、已知子目录和占用状态；打开目录只能定位应用已知路径。
- 产品中的“工作区”指业务数据根 `data_dir`，与代码中的 `AppPaths.workspace = data_dir/workspace` 子目录不是同一层。图中相对路径遵循当前新仓库：数据库 `data/autoflow.sqlite3`、配置 `workspace/profiles/`、内核 `data/kernels/`、日志 `logs/`。实际完整路径由平台适配器提供，前端不自行拼接。数据库的“打开目录”定位其父目录。
- 存在 previous 时显示“切回上一个”；没有 previous 时隐藏，不展示无效占位按钮。
- “切换工作区”先执行任务占用预检；占用时进入 02E，不打开目录选择器。

### 选择结果

- 用户取消目录选择：原状态不变，不显示成功、失败或“已取消”Toast。
- 选择当前同一路径：按 noop 处理，关闭选择流程，不停止服务、不刷新、不改写设置。
- 选择空目录：02B 明确说明将初始化为新的 AutoFlow Workspace，用户确认后创建新格式 marker。
- 选择非空且缺少新格式 marker 的目录：进入 02F 并拒绝，不在其中自动创建 marker。
- 旧版数据或旧 marker 不兼容：明确提示“此版本不能直接打开旧数据”，不尝试读取、转换、复制或覆盖。
- 切换仅改变后续使用的数据根，不搬迁、合并或删除当前目录内容。

### 02B 选目录后新增确认

- 显示目标路径、目标类型（空目录待初始化 / 已识别的新 Workspace）和“不会搬迁当前数据”。
- 主按钮为“确认切换”，次按钮为“取消”。确认前再次执行占用与目录可写预检，防止选择后的状态变化。
- 默认焦点放在“取消”；Esc 或遮罩等同取消。图中目标示例为已识别的工作区，空目录时补充初始化说明。

### 02C 切换中

- 顺序为停止旧服务、启动目标 Workspace 服务、验证就绪、成功后再保存 current/previous。
- 显示“正在切换…”和“请等待操作完成”；进度线是不确定进度，不推算百分比。禁止关闭 Modal、重复切换、重启服务和退出入口提交；系统退出事件由主进程统一协调收尾，不能仅靠禁用页面按钮。
- 多次切换请求必须串行；界面正常情况下不允许产生第二次提交。

### 02D 失败与回滚

- 新服务启动失败后尝试恢复原服务与原 Workspace。
- 回滚成功：显示“切换失败，已恢复原工作区”，保留目标错误摘要与重试入口。
- 回滚也失败：显示“切换失败，原服务恢复也失败”，状态标为需要处理；提供重试恢复和退出应用，不宣称数据或服务安全。
- 设置只在目标服务验证成功后落盘；失败与回滚过程中不提前把目标写成当前 Workspace。

### 02E 任务占用

- 显示“任务进行中，暂时无法切换”和等待说明；重启与切换均禁用。后端能提供占用类别/阶段时可在说明中补充，不能编造任务名称或进度；图中是未展示具体任务详情的通用提示。
- 持续更新占用状态，任务完成后才恢复操作，不增加单独的“刷新状态”按钮。状态读取失败则保留禁用并显示读取错误及重试。新版已覆盖当前内核与代理任务、配置占用和 API 写入；不声称发现任意外部进程打开的文件。

### 02F 目录不可用

- 不可写、不是目录、非空且无新 marker、路径消失分别显示具体原因。
- 不可写路径提供“重新选择”，不提供忽略后继续。
- 瞬时检查错误提供“重试检查”；重试不会创建 marker 或修改目录。

### 设置恢复与启动阻断

- 主设置损坏但备份可用：恢复备份并保留证据，进入应用后显示可关闭的恢复提示。
- 主设置与备份均不可用，或已保存 Workspace 不可用：启动阶段要求“重新选择 Workspace”或“退出应用”。
- 新选目录仍须遵守空目录初始化和新 marker 校验；取消选择不得越过启动阻断进入主界面。

## 03 `settings-about-diagnostics.png`：关于与诊断

### 03A 关于

- 保留旧版桌面运行时、本地服务和数据存储信息，收纳到“运行环境”折叠只读区，默认折叠；应用版本和当前平台直接可见。图中已包含折叠入口。
- 应用版本来自主进程/构建信息，后端版本和 API 信息来自实际后端；读取失败显示“不可用”，旧静态版本不得伪装成实时值。
- macOS 文案：关闭最后一个窗口后应用继续运行，可重新打开窗口；退出应用时主进程先停止本地服务。
- Windows 文案见 03E：关闭最后一个窗口即开始退出，主进程先停止本地服务。
- 点击退出只表示向主进程提交退出请求；界面显示“正在退出…”并禁止重复提交。只有主进程完成停止流程才算退出，renderer 不显示虚假的“退出成功”。

### 03B 导出预览

- 默认白名单固定包含三项：基础版本与平台信息、本地服务状态、最近错误码。组件版本属于第一项。它们是只读清单，图中使用无方框的 check 标识；唯一可选 checkbox 是“添加最近日志”。
- “包含日志”默认不勾选。默认不上传，诊断包只保存到用户选择的本地路径。
- 勾选日志后必须重新收集并生成完整脱敏预览；预览成功前“保存诊断包”不可用。
- 正式按钮文案为“选择保存位置”。保存的内容必须与已确认预览一致；后台新日志不得在确认后偷偷追加。预览区允许滚动查看完整的单一 JSON 文件，不能只展示四行示例却导出未展示的内容。
- 日志预览或脱敏失败时中止含日志导出，显示错误与“重试生成”；绝不能回退为导出原始日志。

### 03C 导出中

- 区分“生成脱敏预览”和“保存诊断包”两个阶段，显示文字进度；执行中禁止关闭 Modal 或重复提交。
- 用户在系统保存选择器中取消：返回预览，不显示成功提示，也不丢失已生成预览。

### 03D 成功 / 失败

- 保存成功：显示“诊断包已保存”和文件名，成功 Toast `2.6s` 后消失；只有写入完成才能出现成功提示。
- 目标不可写：显示“无法写入所选位置”和“重新选择”，保留预览结果，不自动更换路径。
- 瞬时生成或保存错误：显示错误码、持续错误提示和“重试”；重试只重复失败阶段。
- 实现采用固定白名单 JSON，不读取原始日志；仅导出当前会话生命周期事件，预览与保存一致性、凭据和路径排除已通过测试。

### 03E Windows 退出文案

- 显示“关闭最后一个窗口会退出 AutoFlow；退出前将停止本地服务”。
- macOS 与 Windows 文案按运行平台互斥显示，不让用户手动选择平台行为。

## 相对旧版的有意变化

- 新增选目录后的明确确认，说明初始化、兼容性和“不搬迁数据”。
- 把任务占用保护从内核任务扩展到所有执行器，并同时约束重启与切换。
- 将回滚成功、回滚失败和未知状态分开，取消无法证明的“原状态保持不变”。
- 用受控已知路径替代任意路径打开能力。
- 技术信息折叠且动态读取，失败显示不可用；退出文案遵循实际平台语义。
- 提出界面缩放、减少动效、诊断导出三项新增建议；用户已授权本轮实施，不借设置页引入其他业务配置。

## 静态画板的覆盖边界

01 为常规正常态与保存成功提示；02 覆盖切换确认、进行中、回滚成功、任务占用和路径错误；03 覆盖诊断预览、写入、成功/失败以及平台退出差异。服务启动/停止/失败、下拉菜单展开、连接详情展开、运行环境展开、首次空工作区、回滚失败和启动恢复暂以本文逐态说明为准，未另生成画板。静态图片不代表这些交互已经可运行，也不代表键盘与屏幕阅读器行为已验证。
