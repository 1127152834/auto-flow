# 模型管理重设计简报

- 日期：2026-09-12
- 状态：superseded（2026-09-12 用户最新指令取消原型与整体 UI 重设计，保留现有界面，只微调首页模型数量提示位置）。以下保留为历史研究，不作为实施任务。
- 输入：[现场问题审查](../../migration/model-ui-audit-2026-09-12/README.md)、[产品与组件模式调研](../../references/model-management-redesign-2026-09-12/README.md)、当前模型领域契约。
- 产出：信息架构、关键任务流程、视觉规则及原型范围。本文不是已完成原型或实施计划。

## 设计目标

用户能快速找到已配置模型、理解调用来源、按需补充模型并检查单次调用；维护连接时不必穿过模型表单。模型选择与模型管理的界面复杂度分别适应其任务。

本轮按整个模块重新设计。原有供应商侧栏、三步布局和双栏编辑不再是必须照搬的设计前提；业务能力、凭据保护和数据关系继续保留。暖灰画布、黏土棕强调色、React/shadcn/ui/Tailwind 继续沿用。

## 信息架构建议

模型管理在全局导航下提供两个页面内视图：**已添加模型 / 供应商连接**。默认打开已添加模型，不额外增加永久模块侧栏。

| 场景 | 用户任务 | 建议容器 | 主动作 |
| --- | --- | --- | --- |
| 已添加模型 | 查找、筛选、维护现有模型 | 主内容区表格 | 添加模型 |
| 供应商连接 | 配置与验证访问方式 | 独立视图中的连接列表 | 添加连接 |
| 目录添加 | 从一个连接的目录挑选多个模型 | 宽弹窗、可滚动列表、固定底栏 | 添加所选 N 个模型 |
| 手动添加 | 加入目录未提供的模型 ID | 简短表单 | 添加模型 |
| 模型编辑 | 修改名称、上下文、标签和使用说明 | 中等宽度单栏弹窗 | 保存修改 |
| 模型测试 | 查看一次轻量调用结果 | 清楚标注的测试区域 | 测试模型 |
| 任务中选择 | 从已启用本地模型中选一个 | 可搜索单选弹层 | 点选或 Enter 确认 |

任务内选择器在本轮定义共享视觉与规则，不意味着开始开发自动化页面。

## 已添加模型

- 页面由标题、操作区、筛选区、模型表格组成；连接参数不常驻在目录上方。
- 表格保留名称/ID、供应商连接、上下文、启用状态和操作；用户标签作为名称附近的可选补充信息，避免多数为空的宽列。
- 名称与 ID 相同时只显示一次；不同时名称为主、ID 为辅。长 ID 截断但可查看全文和复制，动作不换行。
- 搜索支持名称、ID、连接名称和用户标签；筛选首先提供连接与启用状态。排序与筛选可以由现有全部数据在客户端派生，暂不增加服务端搜索架构。
- 点击名称进入编辑；行尾保留清楚的测试入口及更多菜单。行点击与复选框含义不得混用。
- 初版不为本地列表添加批量删除、收藏、推荐、最近使用和健康分；没有真实任务及数据时不堆功能。
- 无模型时引导添加；筛选无结果时提供清除筛选；连接停用与模型停用分别解释，已存在条目不静默消失。

## 目录多选添加

1. 先选择已配置连接，来源始终可见。从连接列表进入时预选该连接。
2. 目录搜索始终可见；结果显示名称、ID、可用的上下文及“已添加”标记。已添加模型不重复进入新增选择。
3. 勾选只改变临时选择集，不立即写入。底栏固定显示新增数量和提交按钮。
4. “选择当前 N 项”只作用于当前筛选下可新增的候选。若有分页，要明确当前页与全部筛选结果的范围。初版可使用滚动结果区，避免不必要的分页语义。
5. 修改筛选后保留选择，显示“已选 N 项，其中 M 项不在当前结果中”，提供查看已选和清空选择。
6. 切换连接会改变选择作用域；存在选择时先清楚确认是否清除，不能把上一连接的候选带入另一连接。
7. 目录读取失败保留当前输入和已有数据，错误块内提供重试及手动添加入口。重试完成前不重置整个弹窗。
8. 加载、无匹配、全部已添加、选中、提交、失败与完成均有对应状态。成功后回到列表并清楚显示本次增加数量。

“刷新目录”只重新获取候选，不覆盖本地自定义名称、标签和说明，不自动删除本地模型。

## 单选与编辑

- 单选弹层打开后焦点进入搜索，按连接分组展示本地可选模型；同名模型使用连接名称和 ID 区分。
- 活动项与已选项分别有可见状态；方向键移动活动项，Enter/点击走同一确认逻辑，Escape 取消当前浏览并返回原控件；输入法组词期间 Enter 不误确认。
- 不在单选过程中展开完整连接配置、批量目录或模型编辑表单。无候选时提供明确的“管理模型”入口。
- 当前业务 options 只保证供应商及模型都启用，不能根据历史目录检查失败直接把模型判定为永久不可用。
- 模型编辑采用单栏字段，ID 为只读带稳定复制动作。名称、上下文、用户标签、使用说明保持明确分组。
- 测试区采用紧凑区域，未测试时不为结果预留半个空白弹窗；展开结果后标明“本次测试”、耗时和响应。模型 ID 改变时，旧测试结果不能继续显示为新模型结果。
- 删除/移除使用统一命名，解释只影响本地配置；焦点先放取消，确认后正确返回列表。

## 供应商连接

- 显示连接名称、供应商标记、地址摘要、启用状态、上次检查结果和时间。使用自定义网关的预设仍只是连接模板，不暗示端点一定属于品牌官方。
- 同一品牌可有多个连接，以用户命名的连接区分；不要用一个品牌图标合并不同凭据下的模型。
- 新增可以使用供应商预设选择与连接表单；编辑直接进入连接表单，不显示没有实际步骤的进度条。
- 保存成功后再引导添加模型；连接可保存为零模型。连接验证失败保留表单并显示原因，本轮不新增绕过验证的“未验证凭据草稿”业务状态。
- 测试连接独立可执行。启用、停用与删除的语义不同；移除连接前展示实际受影响模型数量。

## 视觉语言建议

下列数值为 AutoFlow 下一版原型的拟议基准，不是从某个参考产品抄来的测量值。

| 要素 | 拟议规则 |
| --- | --- |
| 画布与表面 | 沿用当前暖灰背景和浅色内容面，减少层层套卡片 |
| 强调色 | 黏土棕集中用于主动作、当前选中和必要焦点；成功只用紧凑状态 |
| 字体层级 | 页面标题约 24 px，区块标题 16 px，表单/表格主体 14 px，辅助说明不低于 12 px |
| 密度 | 两行模型条目约 56 px，常规控件约 36 px；通过信息取舍控制密度，不靠不断缩小文字 |
| 间距 | 以 4/8/12/16/24/32 的节奏分组，字段组间距大于组内间距 |
| 圆角 | 复用当前控件 8 px、主要容器约 12 px，避免所有元素都做大圆角卡片 |
| 图标 | 真实供应商品牌标记统一视觉容器；操作图标使用现有库并配可访问名称 |
| 表格 | 轻量横向分隔、稳定列对齐、清楚 hover/focus；主要属性优先获得宽度 |
| 反馈 | 字段错误就近；目录错误在结果区；操作成功短暂反馈；不常驻大面积绿色横幅 |
| 动效 | 延续现有约 150 ms 淡入与轻微位移；减少动态高度变化，支持减少动态效果设置 |

原型需要同时检查 1440×1024 与较窄桌面窗口；Windows/macOS 字体回退与键盘习惯分别验证。不得以宽屏截图好看代替窄窗口验收。

## 数据与 API 可行性

依据：`apps/backend/src/autoflow/adapters/http/model_schemas.py`、`models.py`、`apps/desktop/src/renderer/domains/models/api.ts`。

| 拟议内容 | 当前支持 | 设计限制或后续工作 |
| --- | --- | --- |
| 跨连接已添加模型列表 | 可由现有供应商及嵌套模型派生 | 首版不要求新搜索接口 |
| 名称、ID、连接、标签、上下文、启用状态 | 有真实字段 | 上下文未知显示未知，不推断能力 |
| 连接的最后检查时间和耗时 | 有持久字段 | 表达上次检查，不称实时在线或推理健康 |
| 模型测试响应与耗时 | 有单次返回 | 不持久，不包装为历史平均速度 |
| 为新连接一次添加多个模型 | connect 已支持 selected_models | 继续检查提交时目录变化 |
| 为已有连接一次添加多个模型 | 目前只有单模型创建接口 | 正式规格需补批量契约及重复、失败、重试语义，不能用连续请求伪装成原子提交 |
| 任务选择器 | options 返回已启用模型和连接标识 | 上下文不在 options 中，原型不依赖其显示或另行修订契约 |
| 价格、余额、视觉/工具能力、平均速度 | 当前缺少可靠字段 | 不出现在首版原型中 |

供应商目录请求成功、模型启用和某次生成成功是三件不同的事。最近一次失败也不能自动推断当前不可用。用户标签不是验证过的能力标记。

## 下一轮高保真原型范围

围绕同一设计语言绘制：已添加模型主页面、供应商连接视图、目录多选弹窗、手动添加、紧凑单选、模型编辑/测试及连接编辑。重点状态包括搜索无结果、已添加禁选、隐藏选择计数、目录失败与恢复、提交反馈和危险确认。

先用同一任务与同一批真实字段比较视觉方案，避免只换配色。原型继续以图像资产呈现，不用 HTML 页面代替；确认后同步正式规格、契约变化和实施计划，再按组件先于页面的顺序实施。
