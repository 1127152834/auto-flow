# PM9 修复实施记录

日期：2026-09-28。状态：in_progress。授权来源：已确认 PM9 R1–R4 规格及本轮连续实施授权。

当前事实：项目 worker 已使用共享 WorkflowRuntime，不能再按历史“仅四节点执行器”结论改造。未完成处是项目数据能力私有通道、End 收尾和持久人工恢复。运行内存表继续只属于 ExecutionContext；项目记录由既有 ProjectDataCapabilityService 写入；Task 输入快照保持领取时事实；Run 事件与代次属于持久核心；环境工作副本、保存账本和人工项仍由 EnvironmentService 管理。

R2 采用一个显式“项目数据”配置入口，操作固定为输入快照、读/查/写/建/删记录、状态及字段命令，复用现有领域 command 校验与 SQL 仓储。它不向 worker 暴露数据库或 HTTP 令牌。宿主从 runId 查 Task/项目与能力绑定，不接受 worker 自报工作区、项目或执行代次；每次请求必须对应已提交且仍活动的 nodeVisit/attempt。写入使用稳定 commandId 对应原有幂等 operation，不因丢响应换键重发；CAS、租约和代次在既有事务内复验。前端配置、运行预检和正式目录一起接入，未装配该能力的入口明确拒绝。

R3 在共享调度器边界持久保存继续执行所需事实，不把已有用于展示的 execution_context_snapshot 当作完整恢复状态。持久化前须明确处理循环、分支、子流程与不可序列化资源；秘密不得明文进入检查点。End 必须在 worker 浏览器关闭确认后复用 end_task；进程或响应不明确时保留核验状态。具体实现与验证继续记录，尚未声明交付。

回归顺序：宿主授权红绿（未提交访问、跨项目、旧代次、重复命令、版本冲突）→真实 SQLite/生产 worker 数据链→浏览器与 End→持久人工/重启→最终同版打包 UI。不得直接改业务行来代替执行结果。此文件是已批准计划的落地细化，不改变数据所有权和业务复用规则。
