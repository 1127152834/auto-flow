# AutoFlow 系统架构审计与真实 QA

- 日期：2026-09-28（Asia/Shanghai）。
- 来源：用户要求审查当前系统的缺陷、漏洞和设计不足，并设计、执行真实场景测试。
- 基线：`33ae3aa49600840b1700c83723408c494dc201a8`，分支 `codex/project-management-pm9`，以审计开始时实际工作树为准；已有未提交资料保留。
- 状态：审计事实 confirmed；整改建议 proposed。未实施业务修复。
- 结论置信度：真实复现及明确源码事实为高；维护成本/规模上限为中；未测试的外部账号、平台和场景为未知。

## 并发变更与取证时间

本轮只提交此审计目录及对应 `.ai/sessions` 记录。测试开始时已有的迁入资料与历史证据保持原状；收尾期间另一任务改动 `.gitignore`、`AGENTS.md`、`docs/PROJECT_STRUCTURE.md`，并新增项目地图和 AOCI 资产，均不属于本轮修改或提交。未观察到同期业务源码变更，因此没有仅为文档变更重跑全部回归。

原生导入导出的源码清单来自**取样时**实际文件；字节数与 SHA-256 证明导出、导入与该样本一致，不能声称与后来修改的 AGENTS/目录文档仍一致。A-06 已反映目录文档入口的并行修正。

新增 AOCI 规范已读取；显式重载交付了当时的 40 条索引，但提交认知确认时工具报告 `cognition_snapshot_unavailable`（正式认知资产在组装期间变化）。本轮停止该认知链，没有重试语义答案或修改并发索引；完整认知验证未完成。本报告依据实际源码与执行证据，不把正在初始化的 AOCI 索引当作完整覆盖证明。未调用增量维护替代另一任务正在进行的索引建立。

## 核心结论

**当前不能视为通过生产验收。** 系统已有实质性的生产执行器、真实浏览器、SQLite 持久化、桌面 UI 和打包运行能力；但本轮真实发现了共享边界与凭据隔离问题，项目数据/环境/人工恢复闭环仍有缺口，默认回归和部分质量门禁也没有全绿。

不能用“测试多数通过”反证这些问题，也不能把 64 个后端失败、54 个前端失败逐条称为产品漏洞。大量失败来自旧版本常量、旧快照或测试夹具；本轮对它们进行了单独复核，保留原始红灯，不通过删除断言或改业务代码制造通过。

本轮已完整执行现有默认回归集，并在隔离环境做了真实场景验收；**没有穷尽所有节点分支、平台、真实账号与硬件，也不声称“所有真实测试均已完成/通过”**。全部未完成项在 [46 项覆盖矩阵](coverage-matrix.md) 和 [217 类型节点台账](nodes/coverage.md) 中明确列出。矩阵的一行可能只完成部分场景，不能由行数推导覆盖率。

## 应先处理的问题

| 优先级 | 问题与影响 | 已有证据与限制 |
|---|---|---|
| P1 | **共享静态 GET 可以跟随符号链接读取共享根目录外的文件** | 自有临时文件 + 真实 HTTP：普通 GET 200、受保护 download 路由 403。需共享开启且目录中存在越界链接；不是无条件远程利用。[SEC-01](security-audit.md#sec-01静态文件回退绕过共享根目录) |
| P1 | **重名上传的最终文件名未再次校验，可能在共享目录外创建文件** | 真实 multipart 上传成功跟随预置悬空链接；未证明覆盖任意已存在文件。[SEC-02](security-audit.md#sec-02重复文件名上传绕过最终路径检查) |
| P1 | **同一 OS 用户的两个工作区，同名 Studio 凭据互相覆盖/删除** | 两个真实 SQLite + 本次唯一新建 Keychain 条目：B 写后 A 读到 B 值，B 删除后 A 失效；测试条目已清理。[SEC-03](security-audit.md#sec-03工作区凭据命名空间串扰) |
| P1 | **项目运行尚缺受限业务数据写回、环境 End 和持久人工检查点的完整桥接** | 静态调用链与真实 worker 表格语义补证。`table_add_row` 只操作运行内存表，这是其职责，不是它写错库；不能代替项目数据库 capability。[A-01](architecture-coverage.md) |
| P1 验收门禁 | **默认 Studio smoke 验收的仍是退役 Mock 阶段** | 根脚本要求真实 workflows 路由不存在/返回 404，与当前实现相反。PM4–PM8 的部分测试替代执行器/外部服务，不能作为完整生产链证明。[A-02/A-03](architecture-coverage.md) |
| P2 | **ORM 与迁移后的数据库约束漂移** | 全新真实 SQLite 的 Alembic check 失败；cursor 唯一键 ORM 为 `(task_id,lease_id)`，迁移为 `(task_id,record_ref)`。有误生成后续迁移风险，未发现当前库损坏。[后端报告](backend-regression.md) |
| P2 | **零记录 CSV 被当成 1 条业务数据** | 真实导出仅表头 CSV，在 hasHeader=true 时返回标题作为记录。[N-01](node-realqa.md) |
| P2 | **Python 文件模式参数拆坏带空格路径** | 真实文件、真实 Python 子进程，`str.split()` 破坏带引号路径并 FileNotFoundError。[N-02](node-realqa.md) |
| P2 | **共享文档预览必然导入缺失模块** | 真实合法 HTTP 预览请求 500；不是对 Office 渲染的猜测。[FUNC-01](security-audit.md) |
| P2 | **Android“环境可用”不能保证启动，错误无法定位** | 两次创建成功、start 失败；实际 VM 缺 docker0。应用诊断未覆盖该依赖，错误丢失具体原因。未把共享 VM 故障本身归因于应用代码。[Android 报告](android/android-realqa.md) |
| P2 | **界面和文档承诺超出能力边界** | Android 页面引导分配工作流但接口明确不可用；通知教程仍教已移除渠道；部分入口文档仍描述 Mock（PROJECT_STRUCTURE 已由并行任务补充 superseded 标记）；新增 3 个代理节点缺必填元数据。[架构](architecture-coverage.md)、[前端](frontend-regression.md)、[后端](backend-regression.md) |
| P2 设计 | **可定位的导入错误在 UI 被压成通用错误** | 原生导入选择错误类型被后端正确拒绝，并给出行/列/字段；界面仅“填写内容有误”。修正类型重试成功。[UI 报告](ui-realqa.md) |
| P2 防御缺口 | **Electron 主窗口导航与 IPC 页面来源校验不完整** | 源码确认，动态利用链未知；不称已复现 token 泄漏或 RCE。[SEC-04](security-audit.md) |
| P2 依赖 | **Monaco 内嵌的旧 DOMPurify 进入实际产物，公开公告命中** | npm 完整扫描872项，2个moderate包级项来自同一依赖链、涉及18条公告；顶层DOMPurify已新，但内嵌副本仍旧。未验证应用中的具体利用条件。[依赖报告](dependency-audit.md) |
| P2 依赖治理 | **后端锁定Paramiko/setuptools命中公开公告** | 已安装与生产闭包各命中2个去重公告；原始重复项不累加。Paramiko为Low、setuptools为Moderate；实际可利用性未验证，setuptools公告针对sdist构建，不能说当前App已泄露文件。[后端依赖](dependency-backend.md) |
| P3 | **未知 SHA 算法静默降级并报成功** | 实际源码文本输入与未知算法，返回 SHA-256；正式下拉限制选项降低手工触发概率。[N-03](node-realqa.md) |

所有行的事实依据、前提、精确源码位置和最小整改建议在分报告中。优先级表达修复顺序，不是 CVSS 评分；不能将“防御缺口”“环境失败”“证据未覆盖”混成同一种漏洞。

## 没有证据支持的结论

本轮没有证明：真实 Google Sheets 双向同步/冲突恢复、付费模型与 AI 生图/视频、供应商代理切换、真实邮箱/Telegram/SSH 写操作、摄像头/麦克风/打印、Windows/macOS Intel 安装升级、发行签名公证、10 万条真实业务数据、长期 soak、多客户端高并发、完整辅助技术无障碍，以及全部节点全部参数分支。

外部服务需要专用测试资源与明确允许的目标/预算；本轮没有收到这些具体条件，因此未擅自使用既有账户或发出消息。Android 条件部分具备，已经实际尝试启动，结果是环境失败，不能改称从未测试或通过。

还纠正了旧资料中的三条不适用评价：当前项目与 Studio 已共用 WorkflowRuntime；全局资源已有静态引用删除守卫；packages/ui 空壳是已批准组织方式，不是要立即搬包的理由。

## 建议的修复与验收顺序

1. 修复共享路径的统一解析/最终安全创建，给 Studio 凭据引入稳定工作区身份，并保留这次真实复现作回归。
2. 按已经批准的 PM9 R2/R3 补齐一条真实纵向业务闭环：领取记录 → 浏览器处理 → 正式项目写回/状态推进 → 环境 End → 人工恢复。沿用共享执行器，不重新造引擎。
3. 对齐 ORM 与迁移；修复 CSV/Python 参数/预览/错误定位；让 Android 诊断能说明故障依赖，并在独立授权的环境修复后重测启动/截图/停止。
4. 评估并处理已命中的依赖公告，核验实际使用路径与升级兼容性；更新过期测试、生成器、根 smoke 和教学文档，保留有意义断言，让 CI 验证当前正式能力；把检查写文件改为临时输出或 --check。
5. 使用明确的外部测试账号/预算和其他平台设备，完成覆盖矩阵剩余项。性能只在真实业务规模超过当前实测边界时扩大，不凭推测换库。

以上为 proposed 的整改次序。本次没有实施架构修改、业务修复、外部发布或共享 VM 修复；后续架构改动应按项目规范先形成规格与实施计划。
