# AutoFlow 架构审计与真实场景测试计划

- 日期：2026-09-28。
- 状态：本轮执行与报告已完成；已执行结果为 confirmed，未覆盖/阻塞项与后续用例为 proposed，详见覆盖矩阵。完成本轮不等于所有真实场景均已完成或通过。
- 来源：用户要求全面检查系统缺陷、漏洞、设计不足，并设计、执行真实场景测试。
- 性质：审计与验证，不进行架构改造或业务修复。保留开始时已有工作区改动。

## 判定规则

1. 真实场景必须经过实际应用服务、实际存储和适用的生产执行器；浏览器场景必须实际启动浏览器。Mock、Fake、stub 单元测试的通过单独计入辅助回归。
2. 使用独立工作区、随机端口与本次创建的项目/文件。业务输入优先来自当前仓库真实文件、Git 元数据、实际生成的审计文件及公开网页，不伪造已有客户/账号数据或供应商成功响应。
3. 每项记录环境、前置条件、动作、预期、实测、证据和限制。失败、未执行、环境阻塞、范围外分开，不能把缺少证据当通过。
4. 不外发邮件/消息、不提交远端管理变更、不消费未经授权的付费凭据、不改变已有用户浏览器/数据库。任何外部写入场景先完成可审查用例，再确认具体目标和授权。
5. 不声称穷尽所有输入、硬件和平台。全量指已发现的现有回归集完整执行，以及明确矩阵中的真实场景逐项交代。

## 并行工作包

| 包 | 输入与检查 | 输出与验证 |
|---|---|---|
| 安全/边界 | Electron IPC、HTTP 身份、路径、凭据、脚本入口、资源归属 | 可复现问题、隔离复现、安全审计报告 |
| 后端回归 | 当前 Python 源码、全部 pytest、ruff、mypy、Alembic | 原始日志、精确计数、失败与跳过原因 |
| 前端工程 | 全部 Vitest、lint、typecheck、build、脚本/结构/OpenAPI 检查 | 原始日志、失败根因、Mock 范围说明 |
| 生产运行链 | 真实 sidecar/SQLite/worker/CloakBrowser、真实仓库文件/网页 | 工作流成功/失败/停止/恢复与持久事实核验 |
| 应用界面 | 独立 Electron 工作区、项目/数据/全局导航/Studio | 实际 UI 创建和读取、重载/重启、截图、布局/可访问性检查 |
| 整体覆盖 | 当前源码与有效决策、浏览器/代理/模型/Android/Sheets/平台 | 功能覆盖矩阵、外部先决条件、设计缺口 |

## 真实场景及预期

- 审计项目：用当前仓库名称、HEAD、文件元数据创建项目与审计数据；经 UI/API 写入后，重新加载和重启仍一致。
- 文件处理：实际读写隔离审计目录内的中文/空格路径文件，验证内容和导出结果；失败不得变成成功。
- 浏览器：由生产执行器打开真实公开页面或实际仓库文档，读取可独立核验内容，保存结果与运行日志。
- 控制流：实际条件/变量/数据流与停止、进程重启，验证最终状态、释放资源及旧执行代次权限。
- 边界：未认证请求、跨工作区/路径访问、坏输入、版本冲突与重复命令，验证拒绝且不产生不应有的写入。
- UI：项目各页、浏览器、代理、模型、Android、设置和 Studio 的空态/失败态/实际信息；检查正常尺寸和 200% 缩放。
- 外部依赖：代理供应商、模型、Google Sheets、Android、SSH/邮件/Telegram 等逐项标注可用资源；不以模拟服务代替实网结果。
