## 3. 逐步用例

结果记入 §5。每项都写：前置资料 / 操作步骤 / 预期业务结果 / 实际结果 / 截图编号 / 对应原型 / 运行版本 / 证据类型。

### M-01 概览事实（对应 `01-overview/001`）

1. 打开 `手测-A` → 概览页签。
2. 读顶部统计条：自动化数、数据表数、今日数据变化（新增/更新）。
3. 读左栏「项目活动」：当前区与最近区分别有内容（若刚创建，最近区至少有你刚才创建记录/表的事实）。
4. 读右栏「需要关注」与「继续工作」。

预期：每个数字都能在数据页/自动化页对上；**没有 120 / 24 / 6 / 3 这类原型演示数字**；空项目时显示 `0` 与「暂无数据」，不出现假数字；「继续工作」条目可点击且**不出现「执行记录尚未接入」占位**。

### M-02 概览分区独立降级

1. 在概览页停住，用脚本注入一次概览读取失败（见 §4 `--inject=overview-read-failure`）。
2. 观察页面。

预期：页面提示「概览刷新失败…以下是上次加载的结果」，**上次数值与标题保留**；不出现新标题配旧数值；其他分区不整体变 0。

### M-03 统计四指标与口径（对应 `04-statistics/001`）

1. 进入统计页签，区间选近 7 天。
2. 逐项核对四个指标（界面文案为准）：**本期已结束任务**（副行「成功 x · 失败 y」）、**任务成功率**、**失败任务**（副行「取消 x · 超时 y · 中断 z」）、**平均任务耗时**。
3. 读底部口径脚注。

预期：成功率 = 成功 /（成功 + 失败）；**分母为 0 时显示「无样本」，不是 0% 也不是 100%**；无有效耗时时显示「无有效样本」；脚注逐字包含「成功率 = 成功 /（成功 + 失败）」「不计运行中与等待人工」「任务数不等于数据新增量」；底部「资源使用 — 尚未采集」固定显示「尚未采集」，不填估算值。

### M-04 统计趋势与失败去向

1. 看左「按日处理量」横向条形图与右「失败任务去向」。
2. 把区间拉到一个只有空白日的范围。

预期：**只返回非空桶**，空桶渲染为「无已结束任务」说明文案而不是假柱子；失败去向按自动化分组并显示计数与最近失败原因摘要。

### M-05 统计下钻与返回恢复

1. 点「本期已结束任务」卡片副行里**带下划线的失败数字**下钻（`失败 3` 里的 `3`；「失败任务」指标卡本身不可点）。
2. 在结果列表中打开一个失败任务详情。
3. 返回。

预期：下钻只显示**该结果集内**的失败任务（携带 `resultSetId` 与 `result`）；返回后统计区间、筛选与滚动位置恢复；结果集过期（TTL 注入，见 §4）时显示「结果已过期，请刷新统计」+ 刷新动作，**不静默换数据**。

### M-06 任务证据：三视图（对应 `03-runs/002`、`003`）

1. 从失败任务进入任务详情，切换三个页签：**「日志」**、**「输入与输出」**、**「异常与证据」**（任务详情只有这三个页签，没有独立的「输出」页签；输出与附件在「输入与输出」内）。
2. 在「输入与输出」页签对照「冻结快照」与「当前值」两组值。
3. 回数据表把该输入记录的一个字段改掉，返回任务详情刷新。

预期：快照值**永不变**；当前值更新并明确标注为当前值；仅变化的字段被标出；把该记录删除后，当前值显示「记录已不存在」，**不伪造空值、不显示可点按钮**。

### M-07 节点访问与重试链

1. 在证据视图展开节点访问。
2. 找一个重试过的节点（隔离执行器会在可控节点重试）。

预期：同一节点多次尝试合并为**一条访问**，尝试次数独立计数（3 次尝试 = 1 条访问 + 计数 3，不是 3 条访问）；每次尝试的起止时间与错误各自可见。

### M-08 日志分页与迟到事件

1. 在日志视图连续翻页。
2. 触发一次迟到事件注入（§4 `--inject=late-event`）。

预期：翻页**不漏不重**；已加载页不错位；迟到事件到达后**任务状态字段不变**；加载或读取失败显示错误/加载态，**不得显示为「已确认空数据」**。

### M-09 失败后续批次（对应 `03-runs/004`）

1. 在失败任务详情点任务头部的**「以此输入重新运行」**（只有终态 `failed` 的任务显示该按钮）。
2. 读二次确认弹窗「从原输入组重新运行？」的文案后点**「确认重新运行」**。

预期：入口**只在源任务终态 `failed` 时可见**（成功/运行中任务不显示）；确认文案含「已经发生的网页动作不会重放」；提交后 202 并跳转到新批次；新批次的 `frozen_request.followUp.sourceTaskId` 指向原任务；新批次只领取**原输入组钉住的候选记录**；原失败任务的状态、`statusRevision`、错误与输出**逐字段不变**。

### M-10 后续批次候选失效与状态不自动改

1. 把原输入组里那条记录删除（或改成不满足当前筛选条件）。
2. 再次发起后续批次。

预期：显示「候选已失效」，可少建或不建任务；**不换行、不凑组**；**不自动修改任何业务状态**（用数据表业务状态列逐行比对前后一致）。

### M-11 修订冲突与响应丢失（§4 注入）

1. 打开「以此输入重新运行」弹窗，但**不提交**。
2. 触发修订冲突注入（§4 `--inject=followup-conflict`）后点「确认重新运行」。

预期：提示任务状态已更新、请刷新重试；**已填写的参数覆盖保留**，表单不被清空。

3. 触发响应丢失注入（§4 `--inject=response-loss`）后提交。

预期：弹窗**保持打开**并显示「结果尚未确认，请按原操作身份核对。」，主按钮变为「**核对原操作**」；脚本按**原 Idempotency-Key** 查询原操作；**不生成新 key、不重复创建批次**；核验后只出现**一次**成功事实。

### M-12 隔离、缩放与键盘

1. 在 `手测-A` 切到 `手测-B`，再切回。
2. 用 Tab / Enter / Escape 走完统计筛选、证据视图与失败后续确认框。
3. 把系统缩放到 200%。
4. 制造长文本：自动化名 36 字符、描述 120 字符、长失败原因。

预期：两个工作区不串数据（数字、任务、状态各自独立）；归档项目统计与概览**只读可查**；焦点在关闭浮层后回到原控件；200% 缩放下只有表格内部可横向滚动，页面不撑宽；长文本截断或换行但**不撑宽应用**。

### M-13 既有能力回归

1. 数据页：记录新增/编辑/删除、字段编辑、业务状态设置与清空、筛选/排序/分页。
2. 数据页：Excel 检查、导入为新表、重新导入、导出并打开新文件核对内容。
3. 运行记录：启动参数批次、普通停止、强制停止、批次与任务详情。
4. 环境、浏览器配置、代理、模型、设置与 Studio 入口仍可打开。

预期：以上全部未退化；来源 Excel 文件哈希不变。

## 4. 异常复现工具（不需要你直接改数据库）

脚本提供一次性故障注入，均为**测试注入**，只作用于本次隔离工作区：

```sh
node scripts/qa-project-management-pm7.mjs --manual --inject=overview-read-failure
node scripts/qa-project-management-pm7.mjs --manual --inject=statistics-ttl     # 统计结果集 TTL 立即过期
node scripts/qa-project-management-pm7.mjs --manual --inject=followup-conflict  # 提交前把源任务 statusRevision 推进
node scripts/qa-project-management-pm7.mjs --manual --inject=response-loss      # 提交成功后丢弃 HTTP 响应
node scripts/qa-project-management-pm7.mjs --manual --inject=late-event         # 终态后投递迟到事件
node scripts/qa-project-management-pm7.mjs --manual --inject=service-restart    # 重启测试服务
```

每次注入都会在 `report.json` 中留下 `injected: true` 与目标对象，便于区分「真实故障」与「测试注入」。**注入明确记录为测试注入，不冒充真实故障。**

服务/应用重启：使用 §1 打印的 `workspace` 路径，配合 `--inject=service-restart`，或重跑脚本并复用同一 `--workspace`。

## 7. 清理方法

脚本只创建带**本次 runId 标记**的目录，并在报告中记录其绝对路径：

1. 关闭应用（`Ctrl+C` 或关窗）。
2. 删除本次隔离工作区：报告 `workspace` 字段指向的目录（路径含 `pm7-<runId>`）。
3. 截图与报告默认**保留**：`docs/project-management/implementation/pm7/qa-runs/<runId>/`。如需删除，确认目录名含本次 runId。
4. 不要删除你的应用数据目录 `~/Library/Application Support/@autoflow/desktop`——那是真实业务数据。
5. 若脚本异常中断，重跑时用 `--cleanup-only --workspace=<报告里的 workspace 路径>` 让它按 runId 标记清理残留（**必须带 `--workspace=`**，否则脚本直接报错）；不要手工 `rm -rf` 未核对的路径。
