## 启动

在实施工作区执行：

```bash
cd /Users/zhangtiancheng/Documents/projects/autoflow-project-management-pm3
npm run build
node scripts/qa-automation-management-pm3.mjs --manual
```

需要现有 npm 依赖、uv 后端环境和本机 Electron。工具先运行真实管理流程，再保持应用打开。每次新建带 `.pm3-management-qa.json` 标记的隔离目录；具体位置在终端输出 `Isolated workspace retained`。主项目和用户业务工作区不作为测试目标。

工作流“资料整理流程”由真实文档服务准备，这是测试资料准备，不是 Studio 用户操作。项目“自动化管理验收”、数据表“内容资料库”、字段“标题”和自动化“资料整理”由界面创建。不存在人为伪造的成功 Run。

终端输入 `s` 回车保存当前截图；输入 `q` 关闭本次测试应用。自动化结果及截图在 `docs/project-management/implementation/pm3/management-runs/run-*/`，每次独立保留。人工结果另记，不改写自动报告。

## 异常复现与证据边界

启动工具会自动执行以下故障场景，无需修改 SQLite：

- **真实竞争编辑**：UI 持有旧修订时，由隔离测试工具通过真实 PUT 提交另一修改；UI 保存返回 409，保留草稿；读取最新后须用户确认才能替换。
- **提交成功后响应丢失**：CDP 只在真实 PUT 返回 200 后丢弃响应，再让首次原操作查询失败；UI 显示结果未确认，点击核对后按原 Idempotency-Key 恢复。报告明确标记测试注入，核对只产生一次修改。
- **完整重启**：关闭测试 Electron 和服务后重新启动。重启后用 GET 核对持久事实；该 GET 不冒充用户打开页面。
- **未应用查询**：UI 创建真实表及字段，输入映射后产生筛选/排序草稿，验证整体保存不会写入旧条件。

本工具不测试 Studio demo，不修改原型，不将工作流结构可运行等同于浏览器资源或许可就绪。双工作区真实切换、所有异常状态截图、Windows、其他架构与打包测试没有实际执行时，在报告中保持“未执行”；组件/HTTP 测试不替代这些结果。
