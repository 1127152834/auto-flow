## 3. 逐步用例

结果记入 §5。每项都写：前置资料 / 操作步骤 / 预期业务结果 / 实际结果 / 截图编号 / 对应原型 / 运行版本 / 证据类型。

### M-01 归档影响预检列出真实阻断（过程阻断不是拒绝）

1. 用 `node scripts/qa-project-management-pm8.mjs --manual --inject=executor-pause` 启动，等自动段落结束、窗口保留后开始。
2. 在 `手测-A` 自动化页启动 1 个批次，确认任务停在运行中（隔离执行器被暂停）。
3. 顶部导航进入项目目录 → `手测-A` 卡片右下角「更多」→「归档项目」。

预期：弹窗标题「归档项目」，正文「归档后项目变为只读，可随时恢复。」；「归档影响」列出真实条目；「过程阻断」列出 `批次尚未结束` / `任务尚未结束`（含真实对象与状态）；**提交按钮仍可用**（过程阻断是提示，不是拒绝）；点「取消」后项目状态与批次状态**逐条不变**。

### M-02 归档命令、进度视图与入口

1. 重新打开「归档项目」弹窗并提交。

预期：弹窗显示「命令已接受，正在处理。」；关闭弹窗（取消 / X）**只表示离开进度视图**，不取消命令；随后项目目录「已归档」筛选下能看到该项目，「活动项目」筛选下看不到；归档事实只有一条（可在操作查询中核对 `kind=archiveProject`）。

### M-03 归档后只读：写入被拒、读取与导出可用

1. 切到「已归档」筛选 → 打开 `手测-A`。
2. 观察项目页头状态条与数据页。

预期：页头显示归档提示条 `项目已归档，仅可查看与导出` 与「已归档」标记；数据页仍能打开 `资料库`、查看记录；新建/编辑/删除/字段/状态等写入口不可用；直接调用写接口返回 `409 LIFECYCLE_CONFLICT`；记录的「更多 → 导出 Excel」仍可用并产出**真实 xlsx**（文件前两字节为 `PK`），导出文件落在你选择的受控目标目录。

### M-04 恢复不改写历史事实

1. 目录 →「已归档」→ `手测-A` 卡片「更多」→「恢复项目」→ 确认。
2. 记录恢复前 `手测-A` 的批次与任务清单（状态、状态修订、时间戳）。

预期：恢复后项目回到「活动项目」；批次/任务的状态、修订与时间戳**逐字不变**（不重跑、不重发）；归档与恢复各只有一条 Operation 事实；已完成的导出**不被重放**。

### M-05 永久删除：确认名、影响过期与残留

1. 目录 → `手测-A`「更多」→「永久删除」。
2. 不输入名称：确认按钮必须禁用。输入错误名称：仍然禁用。
3. 触发影响过期注入（§4 `--inject=expire-lifecycle-impact`，需在启动时带上），提交。

预期：提示「影响范围可能已变化，请重新核对后再确认。」并清空已输入名称；点「重新核对影响」后重新读取影响；直接调用删除接口在同条件下返回 `412`。

4. 输入精确名称 `手测-A` → 点「永久删除」。

预期：项目与本地数据集消失（`projects` / `project_data_tables` 行归零）；`手测-B` 与 `PM8 隔离执行器资源` **完整保留**；外部 Excel 原文件字节不变。

### M-06 自动化删除 / 解绑

1. `手测-A` 自动化目录 → 卡片「更多」→「删除自动化」。
2. 输入自动化名，确认删除。

预期：影响清单区分「将删除」与「保留（解除引用）」；独立工作流文档**只解绑不删除**（工作流列表仍可见）；项目其它对象、批次与任务历史不变；确认名不符时按钮禁用、直连接口 `422`。

### M-07 环境删除影响与阻断

1. 环境页 → 打开一个环境 → 「删除」。

预期：展示影响与阻断清单；关联只解除引用，记录与自动化本身保留；被运行时占用时拒绝并给出阻断对象与状态；不出现「强制删除」。

### M-08 双工作区隔离

1. 设置 → 工作区 → 切换到第二个工作区，在其中创建 `手测-C` 与 1 张表、1 条记录。
2. 切回原工作区，核对 `手测-A` / `手测-B` 与 `手测-C` 的可见性、归档状态、最近访问顺序。
3. 在两个工作区之间重复切换两次。

预期：两个工作区数据互不可见；归档/删除状态不串；最近访问与浏览偏好各自保留；切换过程不出现旧工作区的迟到响应污染当前页面（无凭空出现的卡片或提示）。

### M-09 跨重启核验与残留可见

1. 在有一个运行中批次时，执行 `--inject=service-restart`（§4），或直接重启应用后重新进入同一隔离工作区。

预期：重启后未终态批次按**持久事实**收尾（`succeeded`/`failed`/`stopped`），不重复执行已提交的节点；结果尚不明确时保持「未确认」并**保留占用**，不提前释放；任务详情能看到 `cleanup` 残留摘要；项目目录对被引用/残留的对象给出可点击的处理入口。

### M-10 响应丢失后按原身份找回

1. 用 `--manual --inject=lifecycle-response-loss` 启动。
2. 对 `手测-B` 发起「归档项目」。

预期：提示「上次操作结果尚未确认，请先核对原操作」；按**原 Idempotency-Key** 核验而不是换键重发；项目最终收敛为 `archived`；同项目 `archiveProject` 事实**只有一条**。

### M-11 退出 / 切换工作区阻断

1. 在 `手测-A` 有活动批次/任务时，进入 设置 → 工作区。

预期：显示「任务进行中，暂时无法切换：项目批次正在运行；…」，切换按钮禁用；阻断项是可处理的中文对象名而不是内部英文键（不出现 `project_batches_active` 这类代码）；处理掉阻断后按钮恢复可用。

### M-12 全局资源引用保护

1. 浏览器配置页 → 删除被 `手测-A` 自动化引用的 `PM8 隔离执行器资源`。
2. 再尝试删除一个未被任何项目引用的配置（可临时新建一个）。

预期：被引用的配置删除返回 `409`，提示列出**引用它的项目与自动化名**；不提供「强制删除」；未被引用的配置可以正常删除；失败时**没有**发生部分删除（相关对象仍在）。

### M-13 既有能力回归与交互边界

1. 数据页：记录新增/编辑/删除、字段新增/编辑、业务状态设置与清空、筛选/排序/分页、Excel 检查/导入为新表/重新导入/导出。
2. 运行记录：启动参数批次、普通停止、强制停止、批次与任务详情。
3. 浏览器配置、代理、模型、设置与 Studio 入口仍可打开。
4. 把系统缩放调到 200%，制造长文本（自动化名 36 字符、描述 120 字符），用 Tab / Enter / Escape 走完归档弹窗、删除弹窗与导出弹窗。

预期：以上全部未退化；来源 Excel 文件哈希不变；200% 缩放下只有表格内部可横向滚动，页面不撑宽；焦点在关闭浮层后回到原控件；长文本截断或换行但不撑宽应用。

## 4. 异常复现工具（不需要你直接改数据库）

```sh
node scripts/qa-project-management-pm8.mjs --manual --inject=executor-pause        # 让隔离执行器停在运行中，稳定复现“活动批次阻断”

node scripts/qa-project-management-pm8.mjs --manual --inject=expire-lifecycle-impact  # 让当前删除影响确认立即过期（412 路径）
node scripts/qa-project-management-pm8.mjs --manual --inject=lifecycle-response-loss  # 提交成功后丢弃 HTTP 响应
node scripts/qa-project-management-pm8.mjs --manual --inject=service-restart          # 重启隔离测试服务
```

每次注入都会写进 `report.json` 的 `injected` 字段，并打印「已注入 …（测试注入）」；**注入是测试工具制造的条件，不冒充真实故障**。

服务 / 应用重启：使用 §1 打印的 `workspace`，或重跑脚本并复用同一 `--workspace=<已存在目录>` 保持同一份数据。

## 7. 清理方法

脚本只创建带**本次 runId 标记**的目录（根目录另有 `.pm8-qa.json` 所有权标记），并在报告 `workspace` 字段记录绝对路径：

1. 结束应用：在启动终端按 `Ctrl+C`（手测模式）或等自动段落自行关闭。
2. 删除本次隔离工作区：
   ```sh
   node scripts/qa-project-management-pm8.mjs --cleanup-only --workspace=<report 里的 workspace 路径>
   ```
   脚本会校验 `.pm8-qa.json` 标记（`kind=pm8-project-management-qa`）后才删除；**必须带 `--workspace=`**，否则直接报错。
3. 截图与报告默认**保留**：`docs/project-management/implementation/pm8/qa-runs/<runId>/`。如需删除，先确认目录名含本次 runId。
4. 不要删除你的应用数据目录 `~/Library/Application Support/@autoflow/desktop`——那是真实业务数据。
5. 不要手工 `rm -rf` 未核对的路径；清理失败时用上面的 `--cleanup-only` 重试。
