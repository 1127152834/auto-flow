## 2. 关键画面对照说明

**画面 1（批次详情，vs `03-runs/004`）** —— 面包屑「项目 / 运行记录 / 批次详情」、紧凑项目头、六页签（运行记录高亮）、「返回批次列表」、批次卡（运行中徽标 + 开始/结束/耗时/结束原因）、「本批次 1 个任务 成功 0 失败或异常 0 进行中 1」、任务工具栏（搜索 + 自动化 + 状态 + 时间）与六列表格、分页、底部「本次运行的配置快照」折叠条，与画板逐块对应。
偏离：画板把批次元信息放在标题同一行（6 列一行），实际拆为标题下方一行 4 列；画板的失败汇总警示条只在有失败时出现（本画面无失败，故不显示，PM7 已单独覆盖该状态）。

**画面 3（归档被真实阻断，vs `05-data/015`）** —— 弹窗列出「归档影响」（删除 3 张数据表及其记录、删除 1 个自动化）与「过程阻断」（批次尚未结束、任务尚未结束，各带真实 `state`）。
偏离 D1：画板中被阻断的主操作是**禁用**的；本项目归档的阻断是**过程阻断而非拒绝**（`design/pm8-lifecycle-recovery.md` 第 57 行明确："归档预检出的 blockers 是过程阻断（列出真实对象与处理入口），不是拒绝；删除预检出的 blockers 是拒绝"），所以「归档项目」保持可点、由后端在事务内拒绝并给出 409 `LIFECYCLE_CONFLICT`。这是规格要求的行为差异，不是视觉缺陷。删除路径的禁用语义见画面 8/9。

**画面 4（归档确认，vs `02-automation/004`）** —— 标题 + 说明、影响清单、「过程阻断 / 没有阻断项，将立即归档。」、取消 + 归档项目。
偏离 D2：`02-automation/004` 是**删除**确认画板，含琥珀警示条与「将删除/将保留」分组面板；归档是**可逆**操作，因此实际只保留纯文本说明与影响清单，未套用删除特有的警示与分组。删除路径在画面 8/9 按画板结构实现。
