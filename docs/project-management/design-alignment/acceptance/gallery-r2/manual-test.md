## 启动、资料和清理

在 `/Users/zhangtiancheng/Documents/projects/autoflow-project-management-implementation` 执行：

```bash
npm run build
node scripts/qa-project-alignment-r2.mjs --manual
```

工具打开真实 Electron/FastAPI，创建专用标记 `.r1-qa.json` 的临时父目录及 A/B 工作区，并输出路径。不得传入用户业务目录。终端保留用于下列命令。`shot` 保存当前截图；`quit` 退出并保留测试资料；`clean` 仅在验证本次目录标记后清理该目录，报告截图仍保留。不要求修改数据库。

从顶部“项目”新建“内容采集项目”，描述“收集资料，整理内容，维护项目数据”。进入数据→新建数据表“资料库”，描述“文章与温室管理资料”。在“字段与校验”逐个建立：标题（文本、必填）、文章链接（文本、必填）、发布日期（日期、可选）、摘要（文本、可选）；字段标识依次填 title/url/published/summary。当前连续交付版本已包含R3：每个字段点击“应用到草稿”，全部编辑完成后点击外层“保存字段”→检查影响→“确认保存字段”。R2原阶段业务证据保持历史范围，本段仅更新当前手测准备步骤。

## 异常命令与证据边界

`recordconflict` 是真实隔离 HTTP 竞争写入（E2）；`lost/readerror/readonly` 是明确测试注入（E4），`restore` 清除 fetch 注入。`service/restart/switch` 调用隔离桌面测试桥（E3），不新增生产调试接口。原始 UI 操作记 E1。用户不必调用这些技术接口，按上述终端命令执行即可。

结果记录格式：用例编号、通过/失败/未执行、提交与构建标识、前置资料、实际步骤、期望、实际、截图路径、原图编号。示例：`G-R2-M04 / 失败 / <commit> / 编辑标题后Esc / 应保留草稿 / 实际丢失 / <shot.png> / 006`。

Windows、其他架构、打包版本、用户本人手测均独立记录；未运行时不得写通过。自动CDP视口与原生窗口尺寸分开登记，当前截图只是候选回归基线，未冒称用户已批准。
