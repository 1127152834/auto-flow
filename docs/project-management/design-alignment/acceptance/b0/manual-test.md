## 4. 可见视觉检查

本节只检查静态 PNG 中可以直接看见的布局、层级、文字和状态。诸如点击后查询是否改变、URL 编码、实际提交值、事务原子性、Operation 查询、焦点恢复、键盘可达和文件是否被改写，不能由静态图验证；这些行为只在第 5 节核对文档是否明确，并留到对应 R 阶段真实应用测试。

### B0-M01：共同外壳与可读性

1. 分别打开五个 PNG，并以 100% 查看；必要时放大单个画板。
   - 期望：每个画板都能单独读清标题、标签、按钮和状态文案，不以大量不可读缩略图代替画板。
2. 检查应用级导航和项目内导航。
   - 期望：全局模块导航位于顶部，没有新增左侧全局侧边栏；项目内使用水平页签。字段 Drawer 和详情属性区不被画成第二套导航。
3. 检查共同视觉。
   - 期望：暖灰画布、浅色 surface、黏土棕主强调色与既有控件体系一致；危险、警告、成功除颜色外还有文字或图标；长内容、错误摘要和主操作没有明显重叠或截断。

### B0-M02：最近项目、全部项目与数据目录

1. 打开 `r1-directory-overview.png`，定位“最近项目”。
   - 期望：最近访问项目以卡片呈现，名称、用途、访问事实和更多操作层级清楚；未访问项目不被伪装为最近访问。
2. 定位“全部项目”入口及对应目录画板。
   - 期望：全部项目是明确入口；搜索、排序、分页或目录工具不会挤占项目主信息，未访问项目仍可在全部目录出现。
3. 定位项目内“数据”页的数据目录。
   - 期望：保留顶部全局导航、项目头和水平六页签；数据表采用清楚的卡片层级，展示名称、用途、真实来源状态、记录数或未知状态及异常提示。
4. 检查缺失事实的表达。
   - 期望：未接通来源、未加载数量或未来能力显示“未连接 / 未知 / 暂未开放”等准确状态，不伪造为 `0`，不展示无真实落点的可用按钮。

### B0-M03：R2-A/B/C 记录详情、新增、编辑与返回

1. 打开 `r2-record-pages.png`，依次定位记录列表、独立详情、新增页和编辑页。
   - 期望：详情、新增、编辑是对象二级整页；有紧凑上下文头和明确“返回记录列表”或“返回详情”，不是 Modal 截图。
2. 检查详情信息顺序。
   - 期望：左侧或主区展示业务字段，右侧或后续区展示业务状态、更新时间和可用动作；窄布局可自然转为上下顺序。链接有复制/打开的目标表现，但静态图不声称外链桥已实现。
3. 检查统一虚构数据和身份展示。
   - 期望：详情/编辑围绕 `001 温室管理清单`，新增围绕 `002 灌溉检查记录`；可见字段使用 `record_id/title/url/published_at/summary`，`001` 的前导零没有在画面上丢失。
4. 检查返回和查询草稿的可见提示。
   - 期望：有明确返回目标；筛选浮层区分未应用草稿、取消和应用。是否真实恢复 URL、页码、滚动和触发行留到 R2 验证。

### B0-M04：R2-D 至 R2-I 记录状态

1. 打开 `r2-record-states.png`，定位加载失败或校验失败画板。
   - 期望：加载失败提供重试；校验失败有顶部摘要和字段错误，不表现已提交。实际保留输入和聚焦首错留到 R2 验证。
2. 定位脏表单离开状态。
   - 期望：默认主次关系支持“继续编辑”，并明确放弃修改的后果。各类导航拦截和 URL 一致性留到 R2 验证。
3. 定位 409 冲突状态。
   - 期望：同时显示“我的修改”和“最新事实”摘要，提供继续编辑或采用最新基线；不暗示自动覆盖或自动合并冲突字段。
4. 定位响应未知与恢复状态。
   - 期望：显示“正在核验上次操作”及原操作线索，不出现“再创建一次”或换键重试之类相反文案。真实查询和重发顺序留到 R2 验证。
5. 检查 PM4 占用参考。
   - 期望：若出现占用，只明确标注为“PM4 未来参考/尚未实现”；记录业务状态不随任务成功或失败自动变化。当前记录与任务原始输入分开，不把并发占用解释为永久消费。

### B0-M05：R3-A 至 R3-D 字段整体草稿

1. 打开 `r3-schema-draft.png`，定位字段表和未保存标识。
   - 期望：字段使用表格，不回退成分散卡片；`record_id/title/url/published_at/summary` 可辨，新增 `category`（分类，默认“未分类”）和待保存状态清楚。
2. 定位新增或编辑 Drawer。
   - 期望：Drawer 的主动作明确为“应用到草稿”；画面不把该动作称为“保存完成”。应用后的字段表有待保存变化。
3. 定位整体预检。
   - 期望：统一“保存字段”先预检全部变化，展示修改项、记录影响、来源映射和引用事实；未接通的自动化或来源引用明确显示未接通/未知，不填 `0`。
4. 检查预算与失败语义。
   - 期望：阻断/恢复画板明确写出至多 1000 行、至多 4 MiB 和“整个候选未保存”；不出现分段成功或局部发布文案。真实预算计算与事务留到 R3 验证。
5. 定位确认保存与完成状态。
   - 期望：确认画板把多项变化作为一个候选展示，并以一次“确认保存字段”表达；阻断恢复画板保留草稿及核验入口。真实原子提交、差量 DTO 和候选身份映射留到 R3 验证。

### B0-M06：R3-E 至 R3-J 文件与批状态

1. 打开 `r3-file-and-batch-states.png`，定位 Excel 初次导入。
   - 期望：先选择文件并检查/映射，再出现创建或发布确认；画面区分“关闭进度”与真正取消操作。真实接受状态留到 R3 验证。
2. 定位更换文件或重导入。
   - 期望：新文件先形成候选，确认发布才产生新代次；可见说明明确“新代次业务状态清空”。实际代次隔离留到 R3 验证。
3. 定位导出。
   - 期望：导出画板明确“保存为新文件，来源不变”；取消只针对当前选择视图。实际文件不变性留到 R3 验证。
4. 定位批状态进行中、部分完成和恢复。
   - 期望：批设置、进度核验和部分完成分成 `R3-I/H/J`；部分成功、部分失败显示“部分完成”和分项，失败项可追溯；关闭进度与停止后续处理使用不同文案。冻结 RecordRef 和恢复执行留到 R3 验证。
5. 检查来源事实。
   - 期望：来源文件、工作表、导入时间、记录数和本地副本说明来自已知事实；未接通或未核验时标为未知，不伪造 `0` 或完整成功。

### B0-M07：静态原型与未来实现边界

1. 搜索五图中的“已实现”“已接通”“可点击”等宣称。
   - 期望：不以静态图声称应用能力已实现或图片可点击；未来 PM4 占用、自动化引用、Sheets 等均明确阶段或未接通状态。
2. 对照[原型交互说明](../../prototype-interactions.md)检查可见文案。
   - 期望：图中没有与返回、查询草稿、业务状态、未知先查询、取消视图、导出新文件、重导入新代次和来源未知等规则相反的文字。静态图未展示某条内部规则不直接判失败。

## 6. 反馈格式

每个问题单独记录，使用下列格式；严重性只描述对后续实现基准的影响。

```text
反馈编号：B0-FB-001
结果：失败 | 未执行
严重性：阻断 | 高 | 中 | 低
文件：r2-record-states.png
实际画板号：R2-G
用例/步骤：B0-M04 / 4
区域：响应未知状态的主操作区
实际所见：<只写实际可见事实>
期望：画面显示“正在核验”，不提供换键再写入口；真实查询顺序留待R2
建议：<可选，不能用建议替代期望>
审阅环境：<平台> / <图片查看器> / <缩放> / <实际审阅时间>
```

阻断问题包括：缺图或不可读、出现全局侧边栏、整页记录被画成 Modal、字段保存被文案画成多次独立提交、重导入文案声称沿用旧代次状态、未知响应提供换键再写入口、未来能力被标成已接通。所有失败项修图后应按原用例重审，并关联原反馈编号。
