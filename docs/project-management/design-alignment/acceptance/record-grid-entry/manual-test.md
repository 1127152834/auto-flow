# 行尾连续录入：手动测试

日期：2026-09-14。版本：主项目整合版（包含 `361d4fd` 及已交付 R2/R3），源码目录 `autoflow`。本文件是交给用户执行的用例，用户结果初始均为“未执行”。自动证据另见机器报告，不能互相代替。

## 启动

在终端运行：

```bash
cd /Users/zhangtiancheng/Documents/projects/autoflow
npm run build
node scripts/qa-record-grid-entry.mjs --manual
```

工具创建带 `.grid-qa.json` 标记的两个临时工作区（report.json 的 workspace / secondaryWorkspace），先执行自动流程，然后保持真实 Electron 应用打开。控制台输出 workspace 与 evidence 的绝对路径。它不会连接或修改主项目的业务数据库。按 Ctrl+C 退出测试进程，截图报告保留。

环境依赖：Node/npm、uv、项目依赖与 Electron 已安装。后端由 Electron 自动启动，不手工填写端口或令牌。

自动模式 `node scripts/qa-record-grid-entry.mjs` 会重复创建一套隔离资料，执行完自动关闭。响应丢失、原请求未接受、字段竞争和服务重启由该脚本复现；这些是明确标记的测试注入，没有新增生产调试接口。完整重启后的测试路径恢复使用直接 hash，不能当作 UI 导航验收。

## 资料与操作

工具通过界面创建“行内录入验收 / 资料库”，包含标题（必填）、文章链接、摘要；通过真实导入向导创建“文本身份验收”。文件选择结果在自动流程中注入，文件内容、IPC、HTTP、数据库和导入过程真实执行。

开始手测时点顶部“项目”，打开“行内录入验收”，点“数据”，打开“资料库”。如希望从空白开始，在数据目录点击“新建数据表”，输入“我的录入测试”，在“字段与校验”逐项点击“新增字段”并“应用到草稿”，随后点击“保存字段”→“确认保存字段”，统一创建上述三个字段。所有正常新增操作留在记录表中。
