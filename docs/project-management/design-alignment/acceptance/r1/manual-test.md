# R1 手动测试方案

日期：2026-09-13。阶段：R1 待用户验收。这里的用例均为**交给用户执行**，不以自动脚本通过替代手动通过。自动执行结果及截图见 [验证报告](verification.json)。视觉依据：[R1-A/B/C 图稿](../../prototypes/r1-directory-overview.png)。

## 启动与隔离

版本：分支 `codex/project-management-implementation` 本次 R1 交付提交；在下面目录用 `git log -1 --oneline` 确认提交。不要从主项目目录启动此验收。

```bash
cd /Users/zhangtiancheng/Documents/projects/autoflow-project-management-implementation
npm run build
node scripts/qa-project-alignment-r1.mjs --manual
```

需本机已有 Node/npm、uv 与本分支依赖。工具打开真实 Electron，使用临时 `autoflow-r1-qa-*` 目录中的 `workspace-a`、`workspace-b`；终端打印确切路径。不会加载用户原工作区。应用保持打开，终端可输入下表命令并回车。自动模式是 `node scripts/qa-project-alignment-r1.mjs`，完成后退出。

| 终端命令 | 行为和使用时机 |
| --- | --- |
| `seed` | 当前隔离工作区生成 52 个 `R1分页001`–`052` 项目；001 内生成“分页资料库”、文本字段“标题”及 120 条温室/花园记录。每次会话仅生成一次。用于分页，不代替下述界面创建。 |
| `fixture` | 打开上述分页表；先执行 seed。 |
| `conflict` | 先进入项目概览 → 编辑项目，或具体表 → 设置 → 编辑数据表，弹窗已有草稿时执行。目录的更多编辑不能据 URL 确定对象。通过真实 HTTP 以最新版本修改对象描述；然后在界面保存旧草稿触发真实 409。不要在数据目录的表编辑弹窗使用此命令：先打开具体表 → 设置 → 编辑数据表。 |
| `readfail` | 当前 renderer 下一次 /api/v1/projects 下 GET（含表等资源）失败一次，现有自动重试可能自行恢复；用于观察刷新过程中旧内容保留。 |
| `readerror` | 下一轮读取及两次自动重试均注入失败，刷新后能稳定看到错误与重试入口。 |
| `lost` | 下一次项目成功写入**先由真实服务提交**，再丢弃响应，同时阻断一次原操作查询。随后界面显示核验入口，点击核验查询原幂等身份。禁止另建同名对象来“补救”。 |
| `restore` | 恢复当前 renderer 的原 fetch；已接受操作仍通过原身份核验。上述均是测试注入，不是服务端故障证明。 |
| `service` | 真正重启本次测试服务，等待新的实例恢复；不是刷新网页。若提示任务进行中，等待读取或业务操作结束后再执行，不能绕过工作区保护。 |
| `restart` | 结束本次 Electron 与服务，再使用同一测试 userData 启动，验证持久化。 |
| `switch` | 在工具创建的 A/B 两个工作区之间切换。已有未完成业务操作或脏草稿时，按实际界面先处理，不绕过保护。 |
| `entries` | 自动依次进入浏览器、代理、模型、设置、总览和 Studio 窗口并截图；只验证入口，不替代各模块完整手测。 |
| `shot` | 将当前截图保存在终端打印的本次 `acceptance/r1/runs/run-*` 目录。 |
| `zoom200` / `zoom100` | 设置 200% / 100% 缩放。 |
| `quit` | 退出应用，保留隔离资料与证据。 |
| `clean` | 退出应用，校验本次目录所有权标记后清理该临时根；截图报告保留。 |

工具临时根中附有 `sample.xlsx`（“资料”工作表，标题/链接两列，温室/花园各一行）。Excel 对话框中手动选择此文件，导出选择这个临时根中**尚不存在的新文件名**。导入只生成本地副本，禁止覆盖来源。

## 前置样例（通过界面建立）

1. 顶部“项目” → 新建项目：名称 `手测 A`，描述 `内容采集测试`；创建后进入概览。返回项目目录，再创建 `手测 B`，描述 `跟进测试`。
2. “查看全部项目” → 打开 `手测 A` → 数据 → 新建数据表：名称 `资料库`，描述 `温室资料`；创建后进入记录。
3. 字段页签 → 新建字段：名称 `标题`、字段键 `title`、文本类型、非必填；创建。重复创建 `链接` / `url` / 文本。
4. 状态页签 → 新建状态 `已核对`。新建状态不会自动修改记录。
5. 记录页签 → 新增记录。每个待填字段先将“值状态”选为“填写值”；新增两行：`温室管理清单` / `https://example.com/greenhouse`，`花园记录` / `https://example.com/garden`。新行业务状态应为未设置。

## 逐步用例

### R1-M01 项目往返与菜单

1. 返回项目目录，查看全部项目，先打开 A，再返回并打开 B。
2. 返回目录 → 返回最近。预期 B 在 A 前，从未打开的分页项目不补入最近卡片，最多 6 个。
3. 点击 A 的“更多”图标 → 编辑项目。预期只弹表单，URL 不进入项目；改描述保存后卡片和项目头显示新事实。
4. 再次打开编辑，改描述后取消；未保存确认中选择放弃修改。卡片仍显示第 3 步已保存值；刷新后顺序仍由最近访问决定。

### R1-M02 全部目录恢复

1. 终端 seed。最近视图输入 `R1分页`，预期进入全部目录并在第一页搜索，不只搜最近六张。
2. 排序选择“名称 A–Z”，预期第一页 50 项。滚动到第一页下方，打开项目后返回；搜索、排序、第一页及滚动位置恢复。
3. 点击下一页，预期仅剩 2 项。打开其中一个项目，然后返回项目目录。
4. 预期仍为全部、搜索 `R1分页`、名称排序、第二页。第二页只有两项，不用它验证滚动恢复。返回最近再查看全部，全部条件仍在；最近不受其过滤。
5. 清除搜索，未访问项目仍能在全部找到。同工作区服务重连不重置模式和条件。

### R1-M03 数据目录层级与事实

1. 打开 A → 数据，确认只有一个页面主标题“数据表”，项目名作为紧凑上下文；没有侧栏。
2. 编辑“资料库”描述为 `手测描述更新`，保存。预期对应卡片更新。
3. 来源选择“本地数据”、排序选择“名称升序”，打开表再返回，条件与分页保留。
4. 检查长连续名称/描述不挤出卡片，数量来自真实记录；不出现示例数量。来源“本地表”与“Excel 本地副本”可区分。

### R1-M04 三个查询草稿

1. 记录 → 筛选 → 添加字段条件，选择标题与“包含”，值状态“填写值”，填 `温室`。点击取消，预期两行仍在。
2. 重开筛选，预期没有刚取消的条件。重复编辑，按 Escape 或点页面外部，同样不应用。
3. 编辑筛选后直接点排序，预期只存在排序面板，筛选草稿丢弃。
4. 再按第 1 步添加并应用筛选，预期只显示温室记录且回第一页。
5. 排序增加标题降序，先取消验证无变化，再应用。添加重复排序字段应显示校验错误，面板保留且焦点到错误；修正再应用。
6. 显示列取消“链接”勾选后点取消，列仍在；再次取消勾选并应用，链接列隐藏。列显示不会重置页码。无修改直接应用，不重新发业务请求。

### R1-M05 指定字段搜索与导出一致

1. 清除高级字段条件并应用。搜索字段选“标题”，输入 `温室`。未按 Enter/搜索前，两行仍在；提交后只剩温室。
2. 将温室记录设为“已核对”；高级筛选添加该业务状态并应用，列表同时满足文本和业务状态。
3. 点击“清除文本搜索”。预期高级业务状态条件保留；只解除文本搜索，不清业务状态或其他条件。
4. 再搜索温室 → 导出 Excel → 范围“当前筛选结果”，选所需列，选择新的 `r1-filtered.xlsx`。预期文件中的记录与屏幕最终组合筛选一致。
5. 通过表格软件打开并核对标题、行数及列。没有文本字段的表应禁用快捷搜索并说明原因，高级筛选仍可用。

### R1-M06 异常与恢复

1. 项目目录已有内容时执行 readfail → 刷新；预期旧内容保留，自动重试可恢复。执行 readerror → 刷新；预期错误提示且旧内容仍在，再刷新恢复。
2. 打开 A → 编辑项目，修改描述但先不保存；终端 conflict，然后界面保存。预期冲突、原输入保留，不能显示保存成功。点击“基于最新内容重新编辑”，检查竞争者描述，再写入需要的内容保存。
3. 具体表 → 设置 → 编辑数据表，修改描述后执行 conflict → 保存修改；预期冲突且输入保留。点击“载入最新资料”，出现“替换当前草稿？”；选“继续编辑”验证草稿仍在。再点击载入最新资料 → 重新编辑，确认竞争者描述已加载，然后修改描述 → 保存修改，关闭表单。
4. 返回项目目录，执行 lost，再点击新建项目，名称 `手测响应不明`。预期显示“核对保存结果”、输入冻结。点击核对，成功进入概览。回全部搜索此名称，只有一个项目。不要把重复提交当作恢复。
5. 截图失败态和恢复态。注入为一次性；需要撤销时 restore。

### R1-M07 重连、隔离和重启

1. A 的项目编辑表单输入未保存描述，执行 service。预期同工作区草稿保留、恢复后可以处理；旧实例不能弹误导成功提示。
2. 取消或明确放弃草稿。记录 A 工作区全部目录条件，执行 switch。预期项目活动上下文清空，第二工作区没有 A 的项目。
3. 在第二工作区通过界面创建 `隔离 C`，保存其浏览条件；switch 回原工作区。预期看不到 C，原目录偏好恢复。
4. 执行 restart，重新打开 A。项目、表、最近访问仍在；服务实例已变。sessionStorage 的浏览偏好仅承诺会话内保留，不将应用全退出后的搜索位置当作持久业务数据。

### R1-M08 视觉与键盘

1. 对照 R1-A/B/C，检查顶部全局导航、最近卡片/全部条目、数据卡片、唯一主标题与紧凑工具栏。记录页和字段流程仍沿用 PM2，R2/R3 未交付。
2. Tab 到卡片标题，Enter 打开；更多菜单键盘可进入编辑，Escape 关闭并恢复焦点。
3. 打开筛选，Tab 到字段下拉并展开。一次 Escape 只关下拉，再一次关闭查询浮层。点击浮层外页面空白处丢弃查询草稿，焦点回触发按钮。
4. zoom200；分别打开筛选、排序、显示列。预期面板内部滚动可操作取消/应用，应用宽度不变化。长字段值只在表格区域水平滚动，不让整个窗口横向滚动。
5. 连续保存产生通知，最多 3 条；重复核验原操作不堆叠通知，错误不会被汇总成“操作成功”。通知可手动关闭。
6. shot 保存 100%/200% 对照图，再 zoom100。

### R1-M09 既有能力回归

1. 用前置两行记录完成详情 → 编辑 → 保存，设置/清空单条状态。选两行执行批量状态预检与确认；无选择时批量按钮禁用。
2. 通过数据目录导入 sample.xlsx，选择工作表、完成映射、创建新表。验证编辑本地副本不改变源文件。
3. 重新导入时检查影响确认；导出使用新路径；同一已存在路径应拒绝覆盖。
4. 顶部浏览器配置、代理管理、模型管理、设置分别进入；原按钮、弹窗和下拉仍正常。总览 → 工作流工作台，确认原 Studio 窗口入口可用。
5. 对发生失败或结果不明的批量/文件操作使用既有操作查询恢复，不自动重复执行。
