## 2. 固定外壳、层级与反馈

全局导航固定在顶部，不增加左侧全局侧边栏。项目一级页依次为返回项目目录、项目上下文和概览/自动化/运行记录/统计/数据/环境六个水平页签。数据表内使用记录/字段/状态/来源/设置五个水平页签。字段 Drawer 是临时编辑器，记录详情的属性区是内容，两者都不是导航。

对象二级页使用紧凑页头，显示业务标题和明确返回目标，不重复巨型项目头。记录详情、新增、编辑都是独立页面；表格在自身区域滚动，窄宽度时详情双栏转上下。错误、警告和成功不能只靠颜色区分。加载失败保留页头并提供重试；无数据、无匹配和能力未开放使用不同文案。

通知与页面状态必须归属当前对象和原 operationId。迟到响应不能关闭另一个对象的页面、覆盖新工作区缓存或弹出误导成功。结果未知、冲突、校验失败等需要后续动作的状态保留在所属页面，不能只依赖短暂 Toast。

## 3. 路由、返回与记录身份

沿用 hash 导航，不为原型引入第二套路由系统。既有一级路由为：

```text
#/projects/{projectId}/{tab}
#/projects/{projectId}/data/{tableId}/{tableTab}
```

记录页面目标路由为：

```text
新增  #/projects/{projectId}/data/{tableId}/records/new
详情  #/projects/{projectId}/data/{tableId}/records/{datasetGeneration}/{keyType}/{encodedKey}
编辑  #/projects/{projectId}/data/{tableId}/records/{datasetGeneration}/{keyType}/{encodedKey}/edit
```

`keyType` 只允许 `text`、`integer`、`uuid`，`encodedKey` 使用规范 UTF-8 base64url 无填充编码。记录身份包含工作区、项目、表、datasetGeneration、keyType 和键值；文本 `001`、文本 `1` 与整数 `1` 是三个不同身份，不能因展示或 URL 解析而折叠。数字 `0`、布尔 `false`、空字符串、`null` 与未提供也是不同值；UI和提交 DTO 不能用 truthy 判断吞掉 `0` 或 `false`。

从列表进入详情/编辑时保存返回快照：搜索、已应用筛选、排序、页码、列显示、滚动位置和触发行。返回后恢复该快照并把焦点放回触发行；行已删除则聚焦列表标题并说明变化。外部深链没有快照时返回当前表第一页。返回地址必须由当前工作区和对象归属校验，不能采用任意 return URL。代次或结构改变后移除失效查询字段并提示，绝不把旧 RecordRef 静默改写成新代次。

## 4. 查询草稿与数据草稿

筛选、排序和选列是查询状态，不是业务写操作。筛选 Popover 打开时复制当前已应用查询形成草稿；编辑草稿不请求业务写接口。“应用筛选”提交查询草稿并回第一页；“取消”或关闭恢复已应用查询。清空条件也只改变查询草稿，直到应用才影响列表。

记录新增/编辑和表设置草稿绑定稳定工作区、对象和编辑会话，不绑定短暂服务实例。同一工作区重连保留草稿并刷新远端事实；实际切换工作区完成后才清理对象上下文。后台刷新不得覆盖脏字段。失效代次草稿可以查看、复制，但不能直接提交到新代次。

脏表单离开确认覆盖返回、页签、全局导航、关闭、Escape、遮罩及前进/后退，默认动作是继续编辑。用户取消离开后，URL和页面必须仍指向当前编辑对象。多页签共享同一业务草稿时，在这些页签间切换不触发离开确认。

## 5. 记录查看、编辑、冲突与业务状态

记录详情主区展示业务字段，属性区展示业务状态、更新时间和相关动作。系统身份只读；创建时输入并校验业务键，普通编辑不能改键。链接展示复制与打开入口；真实实现必须使用受控 desktop 外链桥，仅允许 HTTP/HTTPS。B0 图稿只描述入口，不证明桥已实现。

普通编辑只提交相对基线发生变化的字段。未触碰的异常 Excel 原始值可以原样保留，不强迫用户先修整行。需要表达空值、未提供或原始异常时才展开值语义；普通文本、数字和布尔字段直接编辑，并保留 `0`、`false` 等 typed 值。

业务状态由表和工作流规则维护，不随任务成功、失败、完成或页面关闭自动改变。状态变化只能由明确的工作流节点或人工命令提交。记录是否可再次使用取决于当前业务状态和工作流条件；短暂 lease 只防并发写，不能被画成永久消费或“本批用过即排除”。PM4未来占用页面需要分开显示“本次任务原始输入”和“当前记录事实”。

校验失败时保留所有输入，显示顶部摘要和字段错误，并聚焦首个错误；不发送写命令。409冲突显示“我的修改”和“最新事实”摘要，不自动覆盖，也不自动合并冲突字段；用户采用最新基线后重新校验并使用新的命令身份。

所有写操作使用稳定 Operation 幂等身份。超时或断线造成响应未知时，UI先进入“正在核验上次操作”，以原 operationId 查询：

1. 已接受或已完成：展示原操作进度或结果，不再写一次。
2. 明确未接受：才允许以同一 operationId 重发。
3. 仍未知：继续核验并保留草稿，不能换键尝试。

## 6. 取消视图与取消操作

取消表单、关闭 Drawer、关闭进度视图或离开详情，只取消当前视图或未提交草稿。它们不等于取消已经被后端接受的持久操作，也不能删除命令事实。提交请求尚未确认接受时，UI应按响应未知规则核验。

被接受的导入、重导入、导出和批状态操作允许离开进度视图，重新进入后继续按 operationId 查询。若业务提供真正的取消或停止，它必须是独立命令并有清楚命名。批状态的“停止后续处理”只阻止尚未开始的项，不把已经成功的项回滚为未执行。

## 7. 字段整体草稿、预检与保存

字段页显示完整 schema 草稿，每个当前 fieldId 恰好出现一次；缺失、重复或未知 fieldId 都是无效候选，不能把遗漏解释为删除。身份字段和其他受保护属性保持锁定。新增字段先使用候选身份，确认成功后才映射为持久 fieldId。

字段 Drawer 只编辑一个候选项，主动作是“应用到草稿”。该动作不写服务端；应用后回到字段表并标出相对已保存基线的新增或修改。统一“保存字段”只提交实际变化，先对整个候选执行一次预检，再由用户确认一次原子提交。不能在前端循环调用多个单字段 PATCH 来伪装整体保存。

预检绑定完整候选、tableRevision、相关 impactRevision、记录影响、来源映射和已接通引用事实。字段或引用事实变化后，旧预检作废。尚未接通的自动化引用、来源映射或占用事实显示“未接通/未知”，不得显示 `0`。

新增或修改默认值需要回填时，候选必须同时满足：影响记录不超过 1000 行，且写后所有受影响 `values_json` 的 UTF-8 总量不超过 4 MiB。提交在同一个短事务中重新校验版本和两项预算，并原子写入结构与回填：任一超限、版本冲突、约束失败或引用核验失败，整个候选不提交；不分段发布、不换 datasetGeneration、不留下半套结构。结果未知继续以原 operationId 查询。

## 8. Excel 导入、重导入与导出

初次导入先经受控文件选择取得文件令牌，再检查工作表、类型、映射、记录身份和影响。Excel 原子创建不能先建立无来源空壳再补数据。关闭或取消检查视图只丢弃尚未提交的选择；命令已接受后按 operationId 查询。

重导入选择新文件后只形成候选，不能立即替换当前数据。确认发布时创建新的 datasetGeneration。新代次清空每条记录的业务状态，不按相同键复制旧代次状态；旧代次的草稿、RecordRef、批选择和迟到响应不得写入新代次。旧代次事实保留供审计或既有操作查询，具体保留期由实现合同决定。

导出始终写入用户选择的新文件，不修改、覆盖或回写 Excel 来源文件，也不改变来源绑定。导出失败或响应未知不能把来源标成已更新。归档项目虽禁止业务写和重导入，仍允许受控查询并导出到新文件；工作区切换或不可访问时继续执行既有准入保护。

来源页只展示已经取得的事实：文件名、工作表、导入时间、记录数、本地副本或绑定状态。来源未连接、统计未加载、查询失败或外部能力尚未交付时显示未知/未连接/待核验，不假设为 `0`、空数据或成功。

## 9. 批状态与部分完成

批状态提交前冻结明确 RecordRef 列表和 statusRevision，不能在执行中重新运行筛选扩大或替换目标。进度按 operationId 恢复，至少区分等待、处理中、成功、失败、停止和未知。

部分记录成功、部分失败时，整体结果是“部分完成”，并显示基于已知事实的分项计数、失败原因和可追溯记录；未知项单列，不能并入失败或当成 `0`。成功项保持已提交状态，后续重试只针对合同允许的失败或未接受项。任务运行结果不参与自动推导这些业务状态。

## 10. B0 审阅与后续实现关系

B0通过只说明五组图稿成为可审查的视觉与交互基准。静态图可以检查布局、层级、文字、按钮命名和状态表达；它不能验证点击、路由编码、查询请求、`0`/`false` 的实际提交、事务原子性、Operation恢复、焦点/键盘、文件写入或持久化。R1、R2、R3仍需真实组件、API、持久化、错误注入、可访问性和应用截图验收。

手动审阅按 [B0 高保真原型手动审阅](acceptance/b0/manual-test.md) 执行。任何图缺失、实际画板号未核实、中文不可读、出现全局侧边栏、未来能力被画成已接通或关键状态与本文冲突时，B0保持未完成。

## 11. 图稿文案和运行状态补充

R1-A中“查看全部项目”进入全部目录视图；图内上下组合用于审阅两个层次，不要求实际页面把两份目录永久重复展示。最近区排除从未打开的项目，全部目录可包含“尚未打开”。R1-C的三个浮层是独立展开状态，应用只改变查询，取消不改变结果。

R2-F“保留我的输入”保留草稿且不写服务端；“采用最新内容”先允许复制草稿，明确确认替换本地编辑基线，再重新编辑和校验，不直接提交。R2-A“清空状态”是显式命令，即使原状态为空也按既有合同推进状态修订；内容保存不顺带改状态。R2-I多个提示为独立状态样例，归档只读页面不能执行清空。

R3-A仅修改title显示名（标题→资料标题）并新增category；url/published_at/summary为已保存字段。结构保存成功Toast文案“字段已保存”；记录新增/保存分别“记录已创建”“记录已保存”。R3-F“新一批数据”对应新datasetGeneration，最终原子发布前旧数据不变。R3-E是向导步骤汇总示意，实际每步单独校验，不在第1步直接绕过检查提交。

Modal/Drawer使用150ms淡入及不超过8px上移；Toast停留2600ms后150ms退出；进度300ms linear；遵循减少动态效果偏好。危险确认默认焦点取消；最上层Escape先关闭，提交中禁止关闭，已接受长操作允许关闭进度视图。Tab/Shift+Tab、ARIA标签、首错聚焦、缩放和滚动的实际效果在R阶段验收。
