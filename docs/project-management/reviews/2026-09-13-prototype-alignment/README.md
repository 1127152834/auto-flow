## 1. 审查结论

**偏差已经达到页面结构与交互流程层面，不能用一次样式微调解决。** 当前保留了暖灰、黏土棕及统一基础控件，但项目入口、记录查看/编辑、筛选、字段管理没有忠实沿用原型。PM2 的功能测试通过不等于原型对齐通过；此前缺少逐画板的视觉退出条件。

建议保留已验证的数据与恢复底座，对项目领域组件和页面组合进行有依据的重构。不能因为视觉不合格就丢弃幂等、CAS、文件授权、原子发布、批量状态和工作区隔离；也不能因为这些工程能力已经完成，就把现有页面当成最终产品。

**旧项目有实际可复用的管理面代码。** 自动化四页签、字段映射、条件预览、参数配置、运行前资源解析与聚合保存都有源码及测试代码。它们应是后续迁移的起点。旧项目缺真实批次执行等能力，不等于旧管理模块只剩图片。当前工作树中的删除不能代替固定 Git 版本取证。

置信度：已查看画面与已读代码的结论为高；未逐图检查的交互状态、旧测试当前可运行性未知。本轮没有计算整体相似度百分比。

## 5. 推荐的纠偏方案

选择 **保留数据底座、按原型重组项目体验、优先适配旧管理代码**。

| 方案 | 取舍 |
|---|---|
| 推荐：有范围的重构与迁移 | 保留当前事务、恢复、跨工作区能力，重做不符原型的领域组件/页面；旧代码先提取、测试，再适配。既能纠偏，也避免丢失已验证成果。 |
| 只改CSS | 无法补记录详情路由、字段聚合草稿，也无法把查询编辑器变成正确任务路径，不足以解决此次问题。 |
| 整体丢弃或复制旧项目 | 会丢掉新身份/恢复/安全机制，或带入旧数据库和工作流归属。旧大型文件也不符合组件化目标，不采用。 |

### 5.1 原型作为可执行的设计依据

每个正式页面/状态都必须绑定一个原图ID，而不是只写“暖灰、shadcn”。当前阅读集作视觉输入；同日候选及业务冲突单列，不能按文件名猜批准顺序。20张已看图只支持本报告结论；剩余状态图在完整对齐规格冻结前逐张审阅。

原型适配只允许明确列出的差异：顶部全局导航；受控本地表取代旧SQLite入口；新业务状态与环境语义；当前不可用能力的真实状态；缩放/平台适配。演示文字、示例数量、Windows水印不进入产品。

自动化四页签在这份图库中没有完整画板，需以旧实际 `ManagementWorkspace` 及配套设计为补充来源，再输出适配当前外壳的缺页基准。不能让开发者自行发挥，也不需要重新创作已经有图的列表页面。

### 5.2 组件与页面落点

继续使用现有 `shared/components/ui`，不建设第二套基础控件库。以下名称为拟新增或重组的职责，不表示已经实现：

- `domains/projects/components`：项目上下文栏、带图标的项目头、项目页签、项目卡片。
- `domains/project-data/components`：数据表卡片、记录工具栏、筛选Popover、列选择、只读字段值、字段表格、字段Drawer、结构草稿操作栏、状态表格。
- `domains/project-data/pages`：记录详情、记录创建/编辑、表内五页签页面组合；状态和链接动作消费已有API/适配器。
- 继续复用 `use-data-table-editing` 的持久命令恢复与CAS思想，提取适合页面使用的接口，不能把几种全页/弹窗UI继续堆进一个详情文件。
- 自动化：从旧 `ManagementWorkspace` 提取四页签草稿和子组件，保留其交互反例；不要复制2300行组件后改名字。

普通数据浏览不新增模块侧栏。原型详情右侧的状态内容区、字段编辑Drawer是局部功能容器，不是另一套导航。

### 5.3 必须补齐的交互合同

1. 记录详情身份包含项目、表、代次及typed key；旧代次、删除、只读、404/410各有明确落点，不能自动打开新代次同名记录。
2. 详情/编辑的来源位置独立保存，返回恢复筛选、页码、列和滚动；跨项目/工作区、刷新、前进后退不能串上下文。
3. 整页草稿沿用修改字段提交；关闭、导航、重新导入冲突均保护草稿；状态修改与字段内容修订分离。
4. 字段统一草稿/保存交互来自原型和完整设计 `functional-structure.md` DT-05；旧 `write_schema` 可作事务实现参考。本报告提议补聚合结构写入与原子提交，但它是相对已批准PM2逐字段CAS的新契约提案，尚待确认。原图本身不证明事务语义。适配新字段身份/修订后，再接统一保存按钮；不能先发多个PATCH却声称全部一起保存。
5. 当前未找到Renderer可用的通用受控外链API，需要在桌面适配层新增HTTP/HTTPS外链能力与调用窗口校验；不能把现有本地目录openPath当作外链接口。普通文本不靠显示名称猜链接字段。复制操作要有结果反馈。
6. 成功、部分完成、结果待核对显示不同事实；不在正常界面把修订号/代次/Operation当主要内容。

## 7. 验收方式需要改变

- 每个页面绑定referenceId、允许差异、正常/空/错误/加载/冲突/返回状态。截图与功能测试缺一不可；没有截图覆盖的状态写“未验证”。
- 先核对区域、信息层级、主动作和交互载体，再比字体、间距、边框、圆角。顶部导航是显式差异，不因排除侧栏就免除内容区对齐。
- 后续同一比较使用固定内容区宽度、缩放、业务fixture、滚动位置和浮层状态；差异要附解释，不编一个“90%相似”分数。
- 列表返回、详情深链、脏草稿、字段聚合、未知结果、服务重连和工作区隔离继续走真实API。
- 普通字段填写不强迫先理解NULL/undefined；仍测试false、0、空字符串、显式空值和保留异常证据。
- 真实页面检查Tab/Enter/Escape、焦点恢复、浮层滚动、长文本和200%缩放；不以基础控件测试代替集成验收，也不由图片声称符合完整WCAG。
- 旧测试先在固定版本隔离副本中运行，移植相关测试及功能再验证新系统；不重写旧仓的未提交删除。
