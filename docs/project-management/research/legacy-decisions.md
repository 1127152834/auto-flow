## 本方案新提出、需要用户审查的调整

1. **两条建设线**：管理/数据与 Studio 专项对齐契约后并行，按真实运行门槛汇合；不把六个页面作为六个独立系统开发。
2. **创作与运行门槛分开**：允许资源未就绪时编辑流程，阻止真实启动；修订旧“缺资源不能首次进入画布”。
3. **内核从 Profile 获取**：新 AutoFlow Profile 已含内核，不在项目表单里再造一套内核配置或内核管理页。
4. **内部运行证据**：固定实际流程解释内容、参数、输入和资源，不提供恢复编辑/版本列表；补充当前 Studio Run 草案。
5. **失联先失权、核验后再分配**：fencing 不能撤销已发网页动作，未知现场/输入不能立刻交给新任务。
6. **同批默认不重复处理同输入记录**：防止未修改业务状态时循环领取；需要同批反复处理的业务另行明确。
7. **人工现场有容量上限**：释放执行名额不释放浏览器现场；限制存活现场，防止越过并发数持续堆积。
8. **在用记录普通字段编辑与任务写回 CAS**：任务持有完整输入证据，人工新版本不被旧任务覆盖；业务状态/身份/删除/重绑受限。
9. **一个 Sheets 工作表首期只保留一个有效可写绑定**：修订早期跨项目同源各自推送造成最后写入覆盖的风险；不引入分布式共享数据层。
10. **持久环境独占维护，任务使用工作副本**：不允许并发共享可变数据目录；不宣称浏览器登录态跨 Windows/macOS 直接迁移。
11. **统计结果一致性**：只固定时间不足以防迟到记录改变集合，聚合和下钻要带同一个服务端结果版本与失效提示。

这些是总体方案的一部分，不是用户已经逐项同意的结论。下一步以总体设计审查为准。
