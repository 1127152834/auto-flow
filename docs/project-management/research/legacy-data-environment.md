## 2. 数据对象与字段规则

历史 accepted `Workflow-Data-and-Execution-Model.md:62–68`：一个项目可有多张数据表；一份来源的一张工作表对应一个模型，一个模型最多一个当前来源；同物理来源可跨项目引用，但模型、字段和状态独立。字段有稳定 UUID，改名不换身份；字段名是区分大小写的字面键，不解释路径。类型仅字符串、数字、布尔、日期，无对象/数组/嵌套。空模型/空字段可先保存；字段/状态/来源共享模型 revision，归档整体只读。

源码佐证 `models.py:69–117`：字段、状态稳定主键，DataSourceBinding.model_id unique；`models.py:137–155` 状态版本与内容版本分开；`models.py:159–199` 持久业务变化记录包含身份代次、操作、origin、目标版本、目标值与状态闭合集合。

历史目标 `Workflow-Data-and-Execution-Model.md:90–117`：新状态目录为空，无预填默认状态；业务状态由项目维护，任务占用不能变成业务状态；状态 UUID 不随名称变化。独立“设置数据状态”节点成功后立即写状态，后续节点失败不自动回滚；结束节点只管任务/业务结果/环境处置。

新规格数据 UI `docs/superpowers/specs/2026-09-11-project-data-design.md:18–26`：目录具有名称/说明/来源/记录数/活动/健康，搜索、来源/连接筛选、排序和边界状态；单表工作区五页签：数据记录、字段与校验、数据状态、来源设置、数据表设置。业务状态、来源同步状态不能共用一个“状态”。

## 3. 稳定记录身份

来源：`Milestones/Record-Identity-Contract.md:10–20,26–50`；实现 `record_identity.py:11–25`。

- 推荐顺序为精确 `id` → 唯一大小写变体 → 用户选其他业务字段 → 用户显式选系统生成；推荐仍需全表唯一/非空/类型/公式核验。
- 文本编号保留前导零，长编号用文本；不默默转换或截断。
- 身份至少由数据表、绑定代次与记录键组成，UI 编号 R013 不够；业务唯一值同绑定内重现可恢复其既有状态；系统生成的同内容重复行是不同记录，删除再新建生成新身份。
- 重绑/重新导入换代次，历史状态与未完成出站变化不自动迁移。
- Excel 系统身份只在本地，不动原工作簿。Sheets 系统模式需显式确认在末尾建立带归属元数据的隐藏 `_autoflow_id`；先登记目标 UUID/操作归属再发请求，超时核验，避免重复初始化和覆盖未知归属列。
- Sheets 已验证系统列可跨项目复用；项目状态独立；解绑不能删除共享云端列。每次推送重新读取归属、业务列位置、UUID；行号只是当次定位。
- 不应承诺识别所有系统 ID 篡改：同内容记录之间换 ID 可能无可区分证据，旧契约明确承认此限制。
- 新项目范围已收缩后，外部 SQLite 物理身份跨项目排他规则只适用于历史读取/迁移研究，不应为了历史功能重做新来源 UI。

## 4. 来源行为与 Sheets 同步

### Excel

`Workflow-Data-and-Execution-Model.md:72–75`、最新规格 `:11,57`：一次导入为托管本地副本，不回写、不后台监测原文件；重新导入是显式全量替换/新代次；inspect 与 import 之间文件指纹变化则拒绝；完整临时副本核验后才发布，失败仍读原数据。来源已导入不等于持续连接。

### Google Sheets

当前主要历史 accepted 来源：`Milestones/M5.1-Sheets-Local-Write-Contract.md:12–21,42–64`。旧 `M5-Sheets-Sync-Contract.md:3,9–10` 只读单向镜像已被替代，不能回退。

- 一个项目一个 Google 连接，项目中多表共用；项目独立。连接断开保留本地副本/状态/队列，换账号不自动换表。跨平台新项目应使用既有凭据端口，不能把旧 DPAPI 实现作为跨平台架构。
- 本地托管 SQLite 为运行主库。云端新增按周期拉取，已有普通业务值以本地为准；不是通用双向冲突合并。
- 人工写入先本地、立即唤醒推送；工作流写入先本地，首次待推送锚定五分钟截止，后续写不延迟，人工带同记录未发工作流字段优先推送。
- 系统业务状态只本地保存，不上云。业务唯一字段与公式字段不可直接编辑。
- 新增/修改/删除变化持久化，可重启恢复；未发变化合并，已发/未知版本必须先核验；旧应答只确认其实际发出的内容版本。
- 拉取保留本地普通字段、状态、内容版本，刷新远端定位/公式结果/公式错误与来源信息；本地删除标记防止旧云端行复活；云端缺行仅提示，不删本地。
- 同 Spreadsheet 串行定位和写入；跨项目写同云端字段最后成功者生效，各项目本地值仍独立。这有业务风险，推荐新方案在检测同物理来源跨项目写入时明确提示冲突来源，不声称本地总是与云端全量一致。
- 网络/权限失败保留本地值与队列；未知结果与明确失败分开。再次发送之前重新定位并核验；来源/账号/映射/代次变更后不得把旧请求向新来源重放。
- 用户“放弃未推送变化”不是回滚本地业务值，M5.1 `:50` 明确本地继续保留覆盖层，后续云端拉取不悄悄覆盖。

实现佐证：`sheets_records.py:602–615` mutation_key+请求指纹去重；`:669–699` 内容版本冲突、身份和公式保护；`:773–792` 5分钟与人工优先；`sheets_merge.py:92–170` 本地优先、公式例外、missing保护；`sheets_push.py:1–5,141–168,198–215` 持久请求证据与重启核验。旧代码包上限200子请求/1.5 MB（`:20–21`）是实现参数，不必写入产品主方案。

## 10. 对成熟新方案的建议（proposed）

1. 以最新两来源边界为当前方案，不恢复外部 SQLite 新入口；定义“本地数据表”实体，使 Excel 导入和 Sheets 绑定都汇入统一记录 CRUD、业务状态、内容版本，来源适配只处理导入/同步。
2. “本地已保存”和“云端已确认”分开；遵守最新规格的成功后核验，新设计需把验收成本与状态转移补全。将新增拉取、变化推送、结果核验分别呈现。
3. 优先完成稳定身份、统一写入、冲突守卫、删除/字段影响，再接真实数据领取和完整输入快照；不可通过假租约接 UI。
4. 环境先做项目默认资源+引用解析（复用新 AutoFlow 已有 profiles/proxies/kernels），执行切片再交付临时实例/所有权/清理；持久环境和人工接管作为独立切片验收。运行/清理/lease永远三维表达。
5. 保留上述候选规则为推荐设计，尤其占用编辑、资源保存分级、清理重试与统计快照；明确尚待批准/尚未实现，不把静态图和纯规则脚本包装为成熟可运行模块。
6. 统计在真实不可变任务终态和起止时间稳定后建设；没有运行事实时显示未接入，而不是0任务/100%成功。
7. 关键验收应覆盖：重导入隔离旧状态；重启恢复未知写入但不重复外部副作用；快照后编辑不影响当前任务；旧代次不能写回；清理完成不冒充数据占用释放；跨项目同来源不串状态；归档阻断写/同步；读失败、真零、无记录不混用。

8. 主任务补充的新取舍（proposed）：worker失联立即撤销提交权限并提升代次，但待旧浏览器执行已确认停止或被隔离后再把数据发给新任务；外部副作用无法被本地fencing撤销。此取舍明确替代旧执行目标的“立即释放逻辑租约”，应在新方案给出未知结果人工核查入口。
