## 1. 先核实“数据状态”的含义

以下旧文件路径均相对旧仓库。旧状态事实的置信度为**高**，来源与代码一致。

| 核实项 | 旧事实与精确证据 | 本稿处理 |
|---|---|---|
| 单值还是多值 | `autoflow-desktop/backend/src/autoflow/models.py:137–144` 的 `DataRecordState` 主键为代次＋记录键，只有一个可空 `status_id: str \| None`，不是状态集合 | `legacy-confirmed`：每条记录一个业务状态或空值 |
| 状态目录初始值 | `.ai/01-Project-Management/Workflow-Data-and-Execution-Model.md:90–105` 与 `Milestones/M3-SQLite-Contract.md:25`：用户声明目录，初始为空，“未设置”是空值 | `legacy-confirmed`：不预建待处理、成功、失败等目录项 |

| 状态写入与节点结果 | `Workflow-Data-and-Execution-Model.md:108–117`：独立设置状态节点，成功即生效，后续失败不回滚 | `legacy-confirmed`：终结任务不隐式更改记录状态 |

因此推荐沿用**单个可空业务状态**，不新增多选状态、自动状态转换图或隐式初始状态。有两个独立业务维度时，用户可用既有普通字段分别表达；若实际业务需要两套独立状态目录，应作为明确扩展重新审查，不能把“多个流程共享数据”擅自解释成“每个流程偷偷拥有一套当前状态”。

### 1.1 本轮设计选择

| 问题 | 可行选项 | 推荐与取舍（均为 recommended/proposed） |
|---|---|---|
| 多输入使用 | 此前本批去重/消费类型建议已被用户否决 | **user-confirmed**：活动租约防止并发占用；释放后仅按当前状态与筛选重新领取，包括同一批次，不设消费类型 |
| 输入关联 | 只独立领取；受控单条关联；通用 JOIN/任意表达式 | 支持独立领取、固定 RecordRef、按单字段相等或已保存 RecordRef 关联；不做 JOIN 编辑器，也没有默认主表 |
| 同源 Sheets | 一个可写绑定；多项目独立副本；全局共享数据服务 | 保留多绑定与各自本地状态，复用同机 Spreadsheet 串行写入；明确重叠写入影响，不新建全局数据服务 |
| 状态转换 | 结果自动映射；表级状态机；人工/节点显式设置 | **user-confirmed + legacy-confirmed**：节点决定写哪些字段/状态，不把运行结果变成记录状态 |
| 在用普通字段 | 全锁；无条件覆盖；保留输入快照并检查版本 | 允许人工提交新版本，任务仍读原始证据；任务旧版本写入冲突，不自动吸收人工新值 |
| Excel 再导入 | 自动合并；显式全量替换；新增第二份表 | 沿用全量替换新代次，并允许导入到另一张表；不猜匹配、自动覆盖本地修改或迁移状态 |

本文以最新用户确认展开：总规格早期“所有输入同批不复用”已被本次用户决定替代。本稿推荐多绑定以及刷新既有公式结果，明确替代此前“同一工作表只允许一个可写绑定”和“入站仅拉新增”的限制；这些来源机制仍待整体审查。关联、并发与来源细节完整定义，不同时实现互相冲突的旧建议。

## 3. 数据对象、身份与引用

### 3.1 对象和版本

| 对象 | 正向规则 | 失败与竞争规则 | 固定例 / 验收 |
|---|---|---|---|
| DataTable | 属于一个项目；有稳定 tableId、名称、用途、字段目录、状态目录与至多一个当前来源。一个工作表对应一张项目表 | 修改检查项目活动状态与表配置修订；同名处理沿项目既有规则，重命名不迁移数据身份 | FX-01 改名后自动化仍绑定同表；`DATA-OBJ-01` |
| Field | 稳定 fieldId、字面键、显示名称、类型、必填、校验。工作流引用 fieldId，用户通过选择器选择字段 | 键含点号也只是字面键，不形成对象路径；同一表不允许重复字面键；删除/改型前计算来源与自动化影响 | 字段 `account.name` 改名仍为同字段；`DATA-OBJ-02` |
| DatasetGeneration | 某次数据身份空间；Excel 全量导入、真实换源或改身份策略创建新代次 | 旧引用不能按行号、同名或相似内容自动跨代次接续；旧任务证据仍可读 | FX-06 两次导入分别取代次 G1/G2；`DATA-ID-01` |
| RecordRef | 精确组成是 projectId、tableId、datasetGeneration、带类型 recordKey；展示编号不是身份 | 服务端验证全部归属；同键跨表/跨代次/跨项目不互认；任一分量过期返回明确旧来源错误 | 文本 `001`、文本 `1`、整数 `1` 三者不同；`DATA-ID-02` |
| SharedRecordIdentity / leaseKey | Excel 独立导入按本地 RecordRef；Sheets 按 Workspace＋SpreadsheetId＋SheetId＋已验证共享身份命名空间＋规范记录键识别同一物理资料 | 不同本地 RecordRef 可以指同一物理资料并共用活动排他；不能凭同值、行号或项目ID制造/拆分共享身份 | FX-05 P/Q 状态独立但只一个活动任务占用该云端行；`DATA-ID-06` |
| Record | 当前业务字段、业务状态、关联元数据、校验结果、删除标记与来源摘要 | 当前记录与任务输入是不同读取对象，更新当前值不重写历史输入 | FX-04 更新后两种视图值不同且有时间版本；`DATA-VER-01` |
| 内容/状态/关联修订 | contentRevision、statusRevision、linkRevision 分开；表配置使用 tableRevision；每次写只推进实际改变的领域修订 | 清空状态保留新修订；不能用一个全表修订制造无关记录互斥。跨领域一次明确提交可同时检查并推进所需修订 | 两条不同记录并行改状态均成功；`DATA-VER-02` |

业务字段沿用字符串、数值、布尔、日期四类标量，不存对象或数组。空值与空字符串不同；类型转换不靠界面显示猜测。日期保留日期/日期时间的源语义、精度及已知时区，禁止把无时区日期默默按当前电脑时区偏移；界面和 API 使用同一规范化表示。数值展示不能使长编号失真，身份规则比普通数值字段更严格。

### 3.2 稳定身份

`legacy-confirmed` 的依据为旧 `Milestones/Record-Identity-Contract.md:14–20,26–38,46–50`。

1. 优先建议精确 `id`，其次唯一大小写变体；建议仍需全表校验。用户可选择其他可靠业务字段，最后显式选择系统身份；没有任何模式自动授权云端写入。
2. 业务身份只接受非空字符串或整数，拒绝浮点（不区分看起来是否稳定）、布尔、日期、公式、行号。保留文本前导零与类型；超出安全传输/来源整数范围要求改为文本，不截断、舍入或自动转数字。
3. 同一代次同一业务唯一键代表同一记录；外部删除后重新出现仍是原身份。系统模式中重复业务内容是不同记录，重新新增生成新 UUID；重复提交同一次新增则通过操作身份返回同一结果。
4. Excel 系统身份仅存在本地。Sheets 系统身份列必须显式建立并核验归属，可复用已验证系统列，解绑不删除它。列位置和行位置仅用于当次定位。
5. 身份无法确认时保留上次完整本地数据供查看与排障，禁止受影响记录的写入和排他领取；不能用仍有缓存作为身份可靠的证明。

**验收**：`DATA-ID-03` 在 FX-06 排序、插行后状态跟随身份；`DATA-ID-04` 验证空键、重复键、浮点与公式键分别拒绝，失败不发布半张表；`DATA-ID-05` 系统身份初始化响应未知后核验原 UUID，不生成第二批 ID，不覆盖归属不明同名列。

### 3.3 记录间关联与环境引用

`recommended/proposed`：关联保存为**记录元数据**，不改变四类业务标量字段，也不把内部 ID/目录藏进一个可自由编辑的普通字符串字段。记录间关系使用具名槽，每槽有稳定 slotId、名称、目标表、是否必需，每记录每槽一个目标或 null；浏览器环境使用每记录一个 `currentEnvironmentId` 和独立关联版本。关联元数据不向 Excel/Sheets 自动推送。

- 记录槽保存受校验的同项目 RecordRef。它适合“这条待办属于哪个账号”等已知关系；名称更改不影响关系，目标换代次则显式失效，不猜迁移。标量业务键关联也可使用 §5 的精确查找，不要求事先把所有来源数据转成 RecordRef。
- `currentEnvironmentId` 保存同项目稳定 environmentId，不保存环境目录、显示名、Cookie 或模板 ID。一条记录当前只有一个环境，多个表/多行可以关联同一环境；环境内容更新保持 environmentId，下一任务解析实际内容代次，该代次成为任务证据，不回写每条记录关联。
- `bindRecordEnvironment` 是内部**组操作**，检查 projectId、去重后的 targets[] RecordRef、expectedLinkRevisions[]、目标环境归属与各记录有效 lease；人工须无冲突占用。关联与事件同事务全有或全无，不要求工作流用户配置额外 Bind 节点。
- **End 保留环境为用户确认的复合业务动作**：勾选后默认关联本 Task 持有写 lease 的已声明数据输入（别名去重）；高级目标允许显式选择相关输入、本 Task 新建行、或本 Task 写节点返回且仍实际持有 lease 的记录。无数据输入时允许只保存项目环境，纯只读查询结果不能作为写入关联目标。不能在运行后猜哪个字段像账号，也不能要求用户手工补上约定关联。当前关联为空或已是同一环境允许；要替换另一个已有环境时，End 配置明确选择替换，仍检查 linkRevision。
- 环境文件发布与本地关联是两个可观察步骤，但属于同一 End 操作身份。所有仍需更新的相关记录关联在一个本地事务校验并提交；环境保存成功而关联 CAS 失败时，保留已保存环境与修复上下文，End 不显示“保留并关联已完成”；重试同一 End 操作只续做未完成关联，不生成第二环境。若更新的就是已关联环境内容代次，不重复改写记录引用。具体重试、Task 结果与保存状态见执行文档。
- End 尚在收尾时复用其仍有效的 lease；若已经明确失败并形成 Run 终态，之后修复必须重新核对目标与版本、取得新的合法写 lease，并把恢复提交关联到原 End 操作证据。旧 Worker/已撤销 lease 不复活；恢复仅完成保存后的关联，不重跑网页、不把历史失败 Run 改成成功。
- 来源表/记录/环境删除影响包括当前关联和自动化引用；活动任务已固定的输入关联证据不改写。存在引用时先显式解除/改绑，删除不可隐式改成“未设置”；归档不能绕过保护。
- 读取一个关联只获得只读目标快照，**不自动获得写权限或独占权**。初始数据输入在领取时已有 lease；工作流后来查询出的记录若要修改，由显式写节点在提交前取得有效写 lease 并检查版本，规则见 §7.3；若要操作环境，由环境协调获取其独占权。

**验收**：FX-07 保存 E01 新内容代次，A01 仍关联 E01，下一任务取新代次（`DATA-LINK-01`）；跨项目环境 ID 被拒绝且 linkRevision 不变（`DATA-LINK-02`）；并发改绑只有一个提交成功，另一个保留选择草稿（`DATA-LINK-03`）；只读查询不授予租约，写节点另行校验占用，抢不到时不改值（`DATA-LINK-04`）；End 只勾保留并选关联输入，实际保存及关联均完成，无 Bind 节点（`DATA-LINK-05`）；保存后关联失败重试不重复保存环境（`DATA-LINK-06`）。

## 4. 业务状态目录与显式转换

### 4.1 目录、空态和初始化

| 规则 | 正向行为 | 失败/竞争与例子 | 验收 |
|---|---|---|---|
| 单个当前状态 | 每记录 `statusId` 指向本表目录项，或 null；状态名称 trim 后按既有归一规则同表唯一 | 不能提交两个状态 ID 或另一表的同名状态 | `DATA-STATE-01` |
| 空目录 | 新表状态目录为空；记录显示“未设置”，状态目录页提供创建动作 | “未设置”不是目录项，不能删、改名或作为真实 ID；系统不自动加“可用” | `DATA-STATE-02` |
| 初始记录 | Excel 导入、Sheets 新行与本地新增默认 statusId=null | 业务文件 status 列只作为普通字段；若用户要初始化，显式选择记录执行状态操作，或明确配置创建节点的后续状态节点 | `DATA-STATE-03` |
| 重命名 | 修改显示名称，保留 statusId；当前记录、筛选与节点引用仍有效 | 预期目录修订过期保留草稿，不按同名重建状态 | `DATA-STATE-04` |
| 删除目录项 | 无当前/隔离代次记录、自动化或活动运行引用时可删 | 有引用展示真实数量与对象；用户先清空/改设记录和修复引用；历史事件保留当时名称，不跟着删 | `DATA-STATE-05` |
| 清空状态 | 明确设置 null，推进 statusRevision，写事件 | 旧状态请求不能因删除状态行而重新通过 revision=0 | `DATA-STATE-06` |

批量人工设置属于一个明确操作，用户先选择记录范围及目标状态，服务端返回固定 RecordRef 清单与影响数；提交时逐条检查状态版本、身份与占用。**推荐一个提交批块全有或全无**，批量规模分块处理，界面明确已经完成和未执行块，不能把部分成功显示成全部成功；取消仅停止后续块，已提交状态不回滚。不把长表修改放进无限数据库事务。固定三条记录 W01/W02/W03 中 W02 被占用时，包含它的提交块不改任何一条，提示 W02；用户可明确排除后重新提交（`DATA-STATE-07`）。

### 4.2 谁能在何时设置状态

| 发起者/触发 | 允许条件与效果 | 拒绝条件与恢复 | 验收 |
|---|---|---|---|
| 用户在记录页设置/清空 | 项目活动、身份有效、状态属于本表、无活动写占用、statusRevision 匹配；格式不合格的记录仍可标记为用户定义“报废” | 被任务占用或占用未知时阻止提交并显示占用任务；先处理/结束任务，确认释放后重试 | `DATA-STATE-08` |
| 工作流设置状态节点 | 指定初始输入、本任务新建记录或查询结果；后者按 §7.3 显式取得写 lease；目标状态/清空；可选“仅当前状态属于这些值时执行”，显式支持 null | lease/代次或状态版本失效、前置状态不符合、未取得写权、目标状态删除时返回冲突或配置错误；不悄悄换目标 | `DATA-STATE-09` |
| 创建记录后的初始化 | 创建节点默认 null；用户明确连接设置状态节点后再赋值 | 后一节点失败则记录仍保留已创建和 null 的事实，不把创建伪装失败或自动删除 | `DATA-STATE-10` |
| 领取/等待人工/任务成功失败/取消 | 不触发业务状态变化；仅更新各自运行/占用事实 | 不内置“领取=处理中”“成功=完成”“失败=待重试”映射 | `DATA-STATE-11` |
| Sheets 拉取、推送、核验 | 不触发业务状态变化 | 云端已有同名状态字段、同步失败或公式变化均不替换本地 statusId | `DATA-STATE-12` |

状态节点不是一个表级状态机。推荐默认“任意当前业务状态可由显式命令设置”，用户需要条件时在节点选择允许前态或在流程中分支；条件比较基于稳定状态 ID。没有背景任务监听状态变动自动启动另一工作流。要串接注册→资料更新，两个自动化共享同一记录，各自筛选相应业务状态，在新批次领取时检查；自动启动仍属于已有调度/执行专项边界。

状态筛选提供“未设置”“已设置”“等于”“属于集合”等明确操作。集合表示对一个当前状态做成员判断，**不意味着记录有多个状态**；null 不用字符串“未设置”编码。状态名称为“失败”时它仍是用户业务状态，不能被统计页当成执行失败数（`DATA-STATE-13`）。

## 5. 多输入：筛选、关联与重复领取

每个具名输入独立声明：inputId、名称、表/字段契约、必需性、选取方式、条件与稳定排序。**没有消费类型字段或本批已消费集合**。名称可变，引用 inputId 和 fieldId。参数属于批次固定值，不是记录；实例变量和节点输出不自动成为项目数据。没有默认“主数据”，选取依赖的拓扑顺序只是技术求值顺序。

### 5.1 三种选取方式

| 选取方式 | 完整规则 | 失败/竞争 | 固定例 / 验收 |
|---|---|---|---|
| 独立筛选 | 在该表当前有效记录中按本输入条件和稳定排序取一个。多个输入不按表行号拉链，也不把所有组合创建为任务 | 某候选不能组成完整输入组时继续检查其他候选，不能因第一个候选失败就断言表耗尽 | FX-02 各取一人一邮箱；`DATA-IN-01` |
| 指定一条记录 | 通过选择器保存完整 RecordRef，仍按本输入业务条件检查并领取；不因曾使用就跳过 | 目标删除/换代次不按键值猜替代；无记录时按该输入必需性处理，归属错误始终为配置错误 | FX-01 账号 A01；`DATA-IN-02` |
| 按已选输入关联一条记录 | 两种受控方式：使用具名 RecordRef 槽；或 UI 选择“目标字段等于已选输入的某字段”。目标字段、源字段以稳定 ID 记录，严格同类型精确匹配，不解释任意表达式 | 匹配 0 条=本组不匹配；1 条=获得候选；多条=关联含糊，不能取第一条。空源值不与所有目标空值匹配；不隐式做模糊匹配、跨类型转换或多行展开 | W01.account_key=A01，仅选 A01；`DATA-IN-03` |

关联关系必须是无环依赖。含循环时保存草稿允许，但启动报出具体循环输入，不能任选一个当主表。必需输入依赖的祖先属于“本组有效必需输入”；如果界面把祖先标为可选，要同时显示其因下游依赖而有效必需，不在运行时悄悄把缺失替换成空值。仅可选的依赖分支遇到空上游时整条分支为空（`DATA-IN-04`）。

精确关联只有单条结果，不需要通用 JOIN 编辑器。关联键来源可为普通业务字段，字段值变动在下一次任务求值时生效；已经领取的任务保持当时关系。显示编号与环境名称都不能被当成关联键。已经存在非唯一目标值时显示涉及值及记录供修复；其他可组成合法组的记录仍可被处理，结束时单列未匹配/含糊数量而不伪称全部完成（`DATA-IN-05`）。

### 5.2 状态与条件是唯一的重复使用规则

`user-confirmed`：数据输入领取后取得排他 lease，直到本任务权威释放。释放后再次检查**当前业务状态与本输入筛选条件**；仍匹配就能在同批或其他批次再次领取，不检查是否曾创建任务、执行成功或失败。不自动标记“已用”，也不把节点输出当成状态写回。

| 明确场景 | 下一次领取结果 | 验收 |
|---|---|---|
| 账号 A01 的条件为状态“可用”，任务未改该状态 | 释放后 A01 仍可领取；同批最大任务数 3 可连续使用 3 次 | `DATA-IN-06` |
| 待办 W01 条件为“待处理”，流程显式设为“已完成” | 释放后 W01 不再匹配；领取 W02，而不是依靠本批历史跳过 W01 | `DATA-IN-07` |
| 流程筛选最终态“已完成”，执行后保持此状态 | 仍可反复领取；“最终态”是该流程的业务意义，不是系统禁止复用标记 | `DATA-IN-08` |
| Task 失败/取消但节点此前没改状态 | 只要批次仍允许创建且占用已释放，记录仍可再次领取；取消整个批次则不再创建 | `DATA-IN-11` |

只读查询是**节点行为**，不是输入消费类型。`readProjectRecord`/查询节点读取 D01 等资料，固定此次读取的完整快照但不取得任务写 lease；其他任务或用户后来修改当前记录不影响已返回的快照。查询不会成为隐式任务生成来源，也不会自动升级成写权限。需要同时独占参与业务的资料可以声明为具名数据输入；只是查资料则无需人为把它加入全部必要输入。

### 5.3 同表多个输入与别名

1. **独立选取的输入默认要求组内 RecordRef 不同**，避免 sender/receiver 意外取到同一行。用户确实要同一行扮演两个角色时，第二输入显式引用第一输入的 RecordRef；这是关联推荐，不是禁止跨任务重复使用。
2. 显式相同 RecordRef 的多个名字属于同任务别名。占用按解析后的 leaseKey 去重，只取得一份 lease；业务节点通过输入/字段稳定引用选择要修改的目标。Sheets 独立输入的“不同记录”约束也比较共享物理身份，不能通过不同表绑定别名规避；各本地内容/状态版本仍按 RecordRef 检查。
3. 别名共用本任务“最新已确认版本”游标，避免通过两个名字写同一记录时拿各自旧版本制造冲突。原始输入证据各自保留当时映射，不随写入改变。
4. 本批不保存用于排除记录的历史安排集合。同一记录能否后来以相同或另一个角色使用，只由当时状态、条件和活动占用决定。若业务要求用后不再取，流程显式更改状态或条件依赖字段；系统不隐藏补写。

**验收**：FX-03 sender/receiver 独立选取时不同（`DATA-IN-09`）；显式 receiver 引用 sender 时只有一个 lease，一次字段写后另一别名用新游标成功（`DATA-IN-10`）；记录角色互换、或下轮仍用原角色均按状态和条件判断，不被本批使用史过滤（`DATA-IN-12`）。

## 6. 领取、暂占、耗尽与多自动化并发

### 6.1 原子完整输入组

`legacy-confirmed`：旧执行契约 `:154–176` 已要求懒领取、必要输入全有或全无、不创建半任务。以下展开为本地单 sidecar/单数据库的 `recommended/proposed` 契约，与执行文档共用一次协调流程。

1. `prepareInputGroup` 根据批次固定的配置，在一个一致读取视图里求候选输入组、只读值、环境关联目标与预期版本；它只准备候选，不代表已创建 Task、已消费记录或永久占用。
2. 独立筛选与关联同时满足后，解析来源的共享身份，合并重复 leaseKey，检查必要排他输入与资源的可用性。准备过程中有短期暂占时必须带同一个准备操作身份、截止时间和释放路径；不得在等另一个必要输入期间长期扣住已有记录。
3. `commitInputGroup` 在本地短事务重新检查批次允许领取、项目活动、各 RecordRef/内容/状态/关联版本、条件、绑定代次和临时持有权；原子提交所有必要数据 lease、Task、完整输入证据、批次计数与启动操作身份。只记录事实，不新增过滤后续领取的“已消费”标记。
4. 任一必要项失败，全组不创建 Task、不增加上限计数；释放本轮临时数据/环境保留，通知执行协调层回收相应准备资源。数据库事务不包住网络请求、浏览器启动或文件复制。
5. Task 提交后浏览器启动失败属于该 Task 的失败，计入批次上限；其占用权威释放后，如果批次仍允许且条件匹配，该记录可以再次领取。外部启动请求用同一操作身份恢复，不能把一次超时恢复创建为第二 Task；系统性资源故障则按执行契约显示受阻，不能把故障伪装成记录耗尽。

**验收**：FX-02 M01 在准备后被另一任务取得，P01 不被长占、没有半 Task、任务数不增加（`DATA-CLAIM-01`）；同一启动请求超时重试仍只有一 Task/一组有效 lease（`DATA-CLAIM-02`）；Task 提交后启动失败仍占本批一个任务名额，业务状态不改，后续能否再取由条件和资源事实决定（`DATA-CLAIM-03`）。

### 6.2 可选输入和候选失败

| 遇到的事实 | 规定结果 | 验收 |
|---|---|---|
| 可选记录真正没有匹配项 | 该输入为 null；其可选依赖分支也为 null，必要输入有效则正常创建 Task | `DATA-CLAIM-04` |
| 可选输入只有被暂时占用的候选 | 不阻塞必要任务，不抢占；以 null 固定并记录“当前占用，未选取”，不在执行中自动补入 | `DATA-CLAIM-05` |
| 必要输入有匹配但暂时全被占用 | 批次显示等待可用输入，不标耗尽，不扣住其他准备记录；权威释放事件或重新查询后再尝试 | `DATA-CLAIM-06` |
| 关联没有目标或目标不合格 | 当前组合不成立，尝试其他候选；完整扫描后报告无匹配组合及具体原因，不能拿别人的记录填上 | `DATA-CLAIM-07` |
| 关联匹配多条、身份不可靠、字段契约错误 | 相关候选标记不能运行；可继续其他明确合法组，末尾保留未处理原因；不把错误当空记录 | `DATA-CLAIM-08` |
| 来源读取失败但本地已完整、身份可靠 | Sheets 网络推送失败不阻止本地读取/领取；显示来源时间和同步异常。无法确认本地副本/身份有效则阻断该输入 | `DATA-CLAIM-09` |
| 可选表整体不可访问/结构失效 | “可选”只允许缺记录，不允许默默吞掉配置或读取错误；本批受阻并指出输入，用户修复或改配置开新批次 | `DATA-CLAIM-10` |
| 一轮候选扫描到达工作预算但未完成 | 返回“继续查找”，保留扫描进度再调度；不报告 0 或耗尽。候选选择允许换组合，避免贪心首选造成假耗尽 | `DATA-CLAIM-11` |

同表交叉条件固定例：输入 X 可取 R01/R02，输入 Y 只能取 R01，且要求不同记录。系统必须找到 X=R02、Y=R01；不能选择 X=R01 后就宣告 Y 无数据。只需支持已定义的单条精确关联与不同记录约束，不开放用户任意查询脚本。

扫描游标只服务于本轮候选查找；Task 提交后开始下一轮，或相关记录/占用事实变化后重新检查当前条件。不得把跨页“本轮已检查”集合留下来充当跨 Task 的已消费过滤。只有基于当前完整查询确认无合法组，才报告耗尽。

### 6.3 上限、耗尽与共享记录

- 最大任务数是**已提交 Task 总数上限**，与并发数、成功数、节点重试数无关。启动失败/取消占用上限，准备失败不占；节点 retry 保留 Task，不重复登记输入。
- 稳定排序决定每轮先尝试谁；同一排序下最前记录释放后仍匹配，可以再次优先领取。有限 N 次不保证 N 条不同记录。想让处理推进到其他行，流程明确改变使当前行不再匹配的状态/字段，或明确使用相应排序依据，系统不暗加“最近使用后排除”。
- 不限数量要求至少有一个有效必要数据输入；不要求证明工作流一定使它耗尽。零输入或仅可选输入没有必要数据耗尽条件，必须给正的有限上限，建议默认 1。不得重新加入“一次性输入”作为不限数量的门槛。
- 不限数量按真实条件耗尽或用户停止结束。若任务始终不改变使记录匹配的字段/状态，记录就可以一直反复处理；这是用户确认的允许行为，不自动去重、不强行失败、不替用户改状态。运行前摘要明确“若记录持续符合条件，将持续运行至停止”；运行中显示已创建数、重复使用事实与未发生条件变化的连续次数，提供停止，计数仅供解释而不影响领取。
- 必要输入真实耗尽时停止创建，已创建任务继续；不等待未来未知时间的新数据而形成永续监听器。记录正在被活动任务占用或本批任务可能提交影响条件的已知写入时，先据实等待现有占用/任务终结再复查；释放后仍匹配即再取，释放后不匹配则判断真正耗尽。来源/资源故障与输入耗尽分别呈现。
- 多个自动化共享同一项目表和状态目录，lease 排他跨自动化、跨批次生效。A 流程释放后 B 流程读取当前状态；B 不会读取 A 尚未提交的修改。没有任何跨批次或本批消费史阻止业务复用。
- DataLease 的排他键按来源解析：Excel 各次独立导入使用各自 RecordRef；Sheets 同 Workspace 内的同物理记录使用共享身份，即使跨项目、本地表/状态不同，也同时只能由一个 Task 占用。业务状态独立与共享活动排他可同时成立；它只防同时处理，不阻止释放后另一个项目按自己的状态/条件再取，也不承诺外部动作恰好一次。
- Sheets 绑定必须对齐同一已验证物理身份命名空间：可为同一个已验证系统 UUID 列，或同一个可靠业务身份列及精确编码规则。不同绑定若使用不同业务身份字段，必须在完整检查中证明它们到公共身份的一对一映射后才能参与共享排他；不能把两个不同字段中都叫 `001` 的值当成同一身份，也不能用当前行号长期关联。缺少该证明时仍可保存绑定、读取本地与修复身份，但受影响记录不能声称可安全并发领取；提供复用已验证公共列/显式初始化系统身份的解决路径，不禁止多绑定本身。
- Worker 失联先撤销写代次；数据只有在旧执行已确认终止/隔离、相关现场处置有权威结果后才重新分配。等待人工保留必要数据 lease；只读快照不增加 lease。具体任务/环境终结见执行文档。

**验收**：FX-01 每次显式把 W 从“待处理”改为“已完成”、A01 保持“可用”、节点只读查询 D01，上限 3 创建三个任务且 A01 不并发占用（`DATA-CLAIM-12`）；同一配置上限 2 恰好提交两 Task，节点重试不多占（`DATA-CLAIM-13`）；仅 A01 必要输入、筛选最终态且不改状态、不限数量，至少连续领取 5 次仍不被去重，用户停止后不再创建（`DATA-CLAIM-14`）；两个自动化争用 A01 只有一个取得 lease（`DATA-CLAIM-15`）；失联旧 Worker 恢复写入被拒，未确认停止前不把 A01 给新任务（`DATA-CLAIM-16`）；无必要输入且不限数量指向上限配置错误（`DATA-CLAIM-17`）。

## 7. 读取、写入与部分失败

### 7.1 三种值不要混淆

| 值 | 读取含义 | 更新方式 |
|---|---|---|
| 任务原始输入证据 | 领取时的完整字段值、statusId、关联、RecordRef、各版本、读取时间、字段映射与来源摘要 | 任务存在期间及历史查看均不改写；不只存版本号 |
| 当前项目记录 | 当前已提交数据与状态，可能已被用户更新 | 普通记录页及显式 `readProjectRecord` 读取；返回独立只读快照，不替换原始输入，不赋予写权 |
| 本任务已确认写入结果 | 某显式节点提交成功后返回的值与新版本 | 后续节点可显式引用该节点结果；内部按 RecordRef 更新已确认版本游标，供下一写命令检查 |

并发人工编辑不会被“刷新输入”悄悄吞入任务。写节点遇到冲突时可失败或进入人工处置路径；单纯重试同样的旧预期版本仍应冲突。用户如决定按当前值继续，必须通过明确的冲突处置重新核对业务前提，而不是后台读取新版后强制覆盖。

### 7.2 写命令与事务

| 命令 | 正向规则 | 竞争/失败 | 验收 |
|---|---|---|---|
| 人工新增 | 来源已完成本地数据集建立；验证身份及全部必填字段，默认状态 null；本地数据/版本/事件/必要同步意图同事务 | 并发同业务键只一个成功；重复操作身份返回同一记录；失败保留表单 | `DATA-WRITE-01` |
| `createProjectRecord` | 目标为节点明确选择的同项目表；返回完整 RecordRef 与版本、可写句柄，创建与本任务拥有的 lease 同事务，使后续节点可写/设状态 | 不要求目标预先成为批次必要输入，也不按任意字符串跨项目写表；创建后后续节点失败不回滚新记录；任务结束释放创建记录的 lease | `DATA-WRITE-02` |
| 人工编辑业务字段 | Patch 只提交改变字段；已有导入错误可保留在未改字段，改变字段需符合类型/必填/校验；检查 expectedContentRevision | 任务输入可靠固定后可以编辑；来源/占用未知或身份不可靠阻断。冲突不静默合并，未改字段不被全表单覆盖 | `DATA-WRITE-03` |
| `writeRecordFields` | 节点选择初始输入、本任务创建行或显式查询得到的精确记录；后者提交前按 §7.3 取得写 lease；Patch 字段有效，检查内容版本及有效 lease，返回新内容和版本 | 身份/公式/只读来源字段不可改；人工改过其他字段同样产生内容版本冲突，不自动取新版本重试 | `DATA-WRITE-04` |
| `setRecordStatus` | 检查 statusRevision、lease 和可选前态；任务根据输入作出的业务结论同时检查已确认内容版本，避免旧内容条件下标记新版记录 | 人工内容编辑使该任务状态结论也需重新核对；不因状态是独立列就忽略输入改变 | `DATA-WRITE-05` |
| `bindRecordEnvironment` / 记录关联修改 | 检查关联组 linkRevision 与有效 lease；只改关联元数据，不写浏览器内容；返回新关联版本；End 保留选项直接调用，不要求 Bind 节点 | 环境保存成功但关联冲突保留环境及 End 未完成事实；只读查询记录须先成功取得写 lease | `DATA-WRITE-06` |
| 删除记录 | 人工删除先检查占用/引用；任务删除仅针对拥有写权的记录，检查内容/状态/关联版本；先逻辑删除并保留历史证据，Sheets 追加远端删除意图 | 其他任务占用/当前关联引用阻断；同任务后续读取原始输入仍可用，但再次写已删除记录失败；删除不等于远端已删除 | `DATA-WRITE-07` |

本地记录修改、各修订、业务事件、幂等操作结果及必要出站意图在同一个本地事务提交；失败不得出现“值已变但无同步队列”。一次显式节点可原子提交其声明的一条记录 Patch；两个节点、两次写、浏览器动作与数据写入不自动组成大事务，也不在任务结束时重写整条输入。

查询节点可访问其明确选择的同项目表，使用受控筛选/排序/分页返回单条或记录清单；精确关联读取仍遵守 §5 的单条规则。清单由 Studio 既有循环节点逐行处理，不把一份清单隐式展开成多个 Task。每行返回 RecordRef、值及版本；这些读取结果可以成为后续增删改节点的显式目标，但读取本身不赋予写 lease。节点字段引用仍基于稳定 ID 与 UI 选择，不新增表达式语言，也不强制把查询涉及的每张表都配成必要输入。

固定部分失败：任务从 FX-04 领取内容 7/状态 3；节点 N1 成功写业务字段→内容 8；N2 明确设“已申请”→状态 4；N3 网页操作失败。最终任务失败，但记录仍是内容 8/“已申请”，已提交的同步意图继续按来源规则推进。下一批次只按当时业务条件决定是否领取，不能自动恢复“待处理”（`DATA-WRITE-08`）。若用户在 N1 前把备注改成新内容 8，N1 用版本 7 写入必须失败，用户新值保留，原始任务输入仍显示旧值（`DATA-WRITE-09`）。

不同记录间的批量业务原子结算不作为隐式功能。流程可以显式逐条提交、检查每步结果和执行补偿节点；已成功效果不能被后续失败抹去。数据服务不得承诺外部网站、Sheets 与本地数据库具有“恰好一次”的跨系统事务。

### 7.3 运行中查询后修改其他记录

用户确认工作流能够跨多张表增删查改，不能把所有写操作限制为启动时领取的输入。推荐采用以下最小规则，不增加通用事务脚本：

1. 写/删除/状态节点显式选择一个查询结果 RecordRef，携带其读取版本；若本 Task 已持有该记录 lease，复用同一记录句柄和最新确认游标。
2. 未持有时，节点提交在同一短事务检查同项目归属、节点声明的目标表范围、预期内容/状态版本、当前物理占用并尝试取得该记录写 lease。成功后写入，相关 lease 归当前 Task；读取后的人工变化不会因刚取得 lease 就被覆盖。
3. 另一 Task 已持有 lease 时，当前节点返回“记录被占用”，保留前序已提交效果。**不持有已有 lease 无限等待另一个 lease**：允许节点按已配置重试次数有限退避，耗尽进入既有失败/人工分支，避免 A 等 B、B 等 A 的死锁。重试期间不修改业务状态、也不抢占别人资源。
4. 单节点确需同改多条记录时，以节点明确给出的有限 RecordRef 组一次非阻塞原子取得新增 lease 并检查全部版本；失败全组不写，不在循环中逐条抢占再永久等待。长清单按既有循环逐条提交，界面能看见部分成功。
5. 新取得的 lease 与初始输入 lease 一样在 Task 权威终结/释放时回收，失联 fencing 同样适用，并遵守 Excel/Sheets 的物理身份规则；End 默认只关联已声明输入，高级目标可显式选择写节点返回且仍持有效 lease 的记录，普通只读查询记录不会被自动关联环境。任务历史保存读取与新增占用事实，不重写原始输入。

**验收**：查询资料表 D01 后显式修改字段，在无占用且版本未变时成功（`DATA-WRITE-10`）；查询后人工修改导致写节点冲突（`DATA-WRITE-11`）；T1 持 R01 想改 R02、T2 持 R02 想改 R01，两者得到可见占用冲突，不永久等待，不产生半组写（`DATA-WRITE-12`）；循环新增/修改第二张表，前两行成功第三行失败，前两行效果及队列保留（`DATA-WRITE-13`）。

## 8. 字段、校验、查询与影响确认

| 操作 | 正向规则 | 失败与竞争 | 验收 |
|---|---|---|---|
| 查询/筛选/排序/分页 | 服务端对完整有效本地集合筛选后分页；稳定次序加 RecordRef；区分业务状态、占用和同步状态 | 失败保留筛选和上次数据并标过期，不能显示伪 0；总数与本页来自同一查询视图 | `DATA-TABLE-01` |
| 记录校验 | 新增全字段检查，编辑改变字段检查；导入普通业务值不合规可保留原值及错误；自动化按自身必需字段契约校验 | 身份错误始终阻断发布/写入；业务格式错误不一概阻止人工设置状态 | `DATA-TABLE-02` |
| 新增字段 | 稳定 ID，可选字段在旧记录为空；必填新增须有完整有效赋值或先修复数据 | 不能把缺值默默补成空字符串/0；字段草稿与记录初始化提交边界明确 | `DATA-TABLE-03` |
| 重命名/顺序/显示 | 名称/显示不换 ID，不重排业务身份；视图状态与字段契约分开保存 | 并发配置修订冲突保留草稿；不可凭名称自动重绑自动化 | `DATA-TABLE-04` |
| 类型/必填/规则变化 | 先全量分析既有值、来源映射、自动化、关联和队列影响；兼容且无需改值可确认保存 | 不无声转换、截断或清空；不兼容先修复值或放弃更改；不预建通用迁移引擎 | `DATA-TABLE-05` |
| 删除字段/表 | 显示记录、本地修改、当前关联、自动化与未完成同步影响；服务端按新鲜影响版本复核 | 身份字段、活动依赖、未知影响/操作不能忽略；删除字段不删除 Sheets 物理列；表删除不触碰外部来源 | `DATA-TABLE-06` |

系统业务状态列属于每表固定元数据能力，不是普通 Field。普通字段/列节点不能删除它、改类型、占用其内部身份或把它映射为云端列；业务文件中名为 status 的字段可以作为另一个普通 Field 存在，界面须标出“业务字段”和“数据状态”的差别。字段校验或源结构变化不应抹掉本表状态目录和记录状态（`DATA-TABLE-08`）。

字段影响确认绑定 tableRevision、datasetGeneration、相关数据修订和出站状态，确认后才提交。发生并发记录变化时重新计算影响并保留草稿；“未知”不按 0 算。历史输入保存当时字段映射与值，不依赖当前字段还存在。已配置但未运行的自动化引用允许通过一次明确影响确认变成待修复，保留原引用和定位；活动运行仍依赖的结构不能被破坏，但**运行中兼容新增字段不应被一概阻断**（`DATA-TABLE-07`）。

### 8.1 工作流字段/列节点

`user-confirmed`：工作流除新增行外，还能新增字段/列；读写哪些业务字段和状态由节点配置决定。以下受控结构用例为 `recommended/proposed`，使用与人工字段管理相同的领域规则，不复制一套“流程专用表结构”。

| 结构操作 | 运行中正向规则 | 竞争/失败规则 | 验收 |
|---|---|---|---|
| 查询表/字段 | 节点选择同项目表，返回当前稳定字段身份、类型、来源能力和结构修订；结果可供后续节点明确选择 | 返回结果不是写授权；来源错误不以空结构冒充 | `DATA-SCHEMA-01` |
| 新增字段/列 | `addProjectField` 明确名称、键、类型、必填/校验和来源列策略；兼容的可选字段可在运行中添加，旧记录为空，本 Task 后续节点可引用返回的新 fieldId | 结构 CAS 冲突重新核对，不能静默覆盖同名字段；字段不足必填值时拒绝强设必填，用户可先可选新增→填值→设必填 | `DATA-SCHEMA-02` |
| 幂等确保字段存在 | 节点可明确选择“已有同键且定义完全一致则复用”；返回既有 fieldId，避免重复运行反复加同一列 | 同键不同类型/必填/来源策略返回结构冲突，不能悄悄改型；严格新增模式遇重名直接报错 | `DATA-SCHEMA-03` |
| 修改显示名称/列顺序 | 不换 fieldId，不改变已固定类型/值与节点引用，可在运行中提交 | 不能用显示重命名隐式更改字面键或远端映射；配置版本仍检查 | `DATA-SCHEMA-04` |
| 修改字段键/类型/必填/规则 | 先分析当前运行实际依赖的字段与校验契约；不破坏活动依赖、无需无损转换的兼容修改可提交 | 改型/删键破坏本 Task 或其他活动 Task 冻结契约时阻断该节点，说明引用位置；不把所有新增列视为破坏性变更 | `DATA-SCHEMA-05` |
| 删除字段 | 仅当前没有身份、关联、活动运行/节点或未决同步依赖的字段允许删除；与人工相同影响规则 | 引用保护不能因发起者是持有某条记录 lease 的 Task 而被绕过；记录 lease 不等于整表结构独占 | `DATA-SCHEMA-06` |

结构版本变动不应导致整个批次一律失效。`commitInputGroup` 和后续写命令按稳定 fieldId 重新校验**本次实际依赖的契约是否仍兼容**；别人新增无关可选字段时，旧任务仍能读写原字段。节点新增字段通过显式返回值扩展本 Task 后续可选择字段；原始输入映射和数据仍不改写。人工或其他流程新加的字段不会自动注入旧任务输入，节点可以显式查询取得它。

Excel 的新字段只改变本地表，原文件不增加列。Sheets 新字段分为明确的“仅本地业务字段”或“新增并绑定远端列”，**推荐节点默认展示并要求选择来源列策略**：选择远端时，结构操作登记稳定 fieldId/操作身份，再串行核验并新增或复用归属明确的目标列；本地字段与待建列状态可先提交，后续写该字段的本地值允许保存，但远端值推送必须排在建列核验之后。远端建列失败保留字段、本地数据及待处理结构操作，不伪称已映射；响应未知先核验，不再追加第二列（`DATA-SCHEMA-07`）。

兼容新增列保留原有列的稳定映射与数据身份，不因表宽增加而让旧出站 Patch 改写错误列。来源结构比对允许已登记的兼容扩展，发送前仍重新定位原字段；实际改动既有映射、身份或归属时才冻结受影响旧操作并进入换映射规则。删除本地字段不自动删除远端列，避免影响其他项目；用户确需删除远端物理列时必须由明确选择的源结构节点展示整列影响，并在无其他绑定/活动/未决依赖后执行，不能藏在普通字段删除中（`DATA-SCHEMA-08`）。

固定例：T1 已领取 W01，当前冻结字段 id/name；其节点确保“回执号”文本字段存在，第一次新增并返回 F-receipt，后续节点向 W01 写回执号；T2 仍按 id/name 运行不受影响。T1 再次执行该节点复用相同定义的 F-receipt；若另一任务已把同键建立为数值类型则明确冲突。删除被 T2 使用的 name 被拒，新增另一个无关可选字段仍允许（`DATA-SCHEMA-09`）。

## 9. Excel：导入、维护、再导入

`legacy-confirmed` 的来源边界来自旧 M4 契约 `:10,17–29,33–39`，身份模式以更晚的 Record Identity 契约为准；本地记录 CRUD 是最新数据设计与新系统的目标，不声称旧 Excel 已经具备。

1. 选择工作簿与一张工作表→检查完整布局/身份/值→映射已有字段或新建字段→展示阻断错误、可保留业务校验错误和行数→确认导入。一个工作表对应一张项目表，多张工作表分别操作；不按整个工作簿创建一个输入。
2. 输入是单层表：一行表头、一行一记录，不自动猜多级表头、合并单元格或夹杂汇总。保留完全重复业务行；完全空行可忽略并展示数量。普通样式/冻结首行不构成复杂表拒绝理由。
3. inspect 与 commit 校验文件指纹和选择的工作表；完整临时结果验证后发布新本地数据集，失败/取消保留旧绑定与旧数据。工作簿后续移动、修改、删除不影响已经发布的本地副本。
4. Excel 公式读取文件已保存的计算结果；缺结果说明需在原工具计算保存后重试，不在 AutoFlow 计算公式。导入为本地普通值后不再连接该公式，本地可以按字段规则编辑，明确不是编辑原 Excel 公式。
5. 导入后的记录支持新增、编辑、删除、状态、关联与自动化使用。新增系统身份在本地生成；业务身份由用户提供且全表唯一。没有“推送 Excel”或后台监测动作；输出文件的产品入口由完整范围文件单独裁定，不偷渡成来源写回。
6. 再导入提供“替换当前表”或“导入为另一张表”的明确目标。替换是完整新代次，展示本地新增/修改/删除、状态、关联和自动化引用影响；不追加、不自动合并、不按键名把旧状态迁移。
7. 有活动数据 lease、正在准备的有效输入组或依赖该代次的运行时不替换。先停止新领取并完成活动工作；已发布历史 Task 输入仍独立可读。旧 RecordRef/关联保留可识别的过期事实，不能悄悄指向新代次。
8. 表可以先保存空结构；完成空工作表（表头有效、0 条记录）导入后即有合法 Excel 本地数据集，可手工新增。未导入/未绑定的表只是待配置壳，不把它隐式变成第三种“独立手建来源”；是否另设空白本地表由总范围单独审查。

**验收**：`DATA-XLS-01` 文件检查后变化拒绝提交；`DATA-XLS-02` 发布中断不暴露半表，原 Excel 字节不改；`DATA-XLS-03` 同内容重复行独立状态，本地 CRUD 后原文件仍不改；`DATA-XLS-04` 活动占用阻止替换，结束后新代次全状态 null；`DATA-XLS-05` 旧任务和旧关联不按新行号接续；`DATA-XLS-06` 空工作表导入后新增成功，未配置壳不能冒充数据集；`DATA-XLS-07` 有缓存/无缓存公式分别给出真实读取结果和错误，不虚构重算值。

## 10. Sheets：多绑定、本地主库和公式

### 10.1 连接、绑定与多项目使用

- Google 连接属于项目，同项目多张表可共用；凭据使用现有凭据端口，不写入记录、任务快照或日志。连接有效、读取权限、写入权限和本地副本有效性分开显示。更换登录账号不自动切到另一个工作表。
- 一张项目表对应一个 SpreadsheetId＋SheetId 当前绑定；不同项目可绑定同一物理表。各项目本地业务值、字段目录、状态和关联独立，不自动互相读取另一项目的记录。
- 同一物理行的活动数据占用按 §6.3 的公共身份在整个 Workspace 统一；远端发送串行锁与任务数据 lease 是不同层次，不能只串行推送就宣称任务没有同时处理同一行。
- **推荐沿用同机按 Spreadsheet 串行远端定位、写入、核验的协调**。不同绑定映射不重叠字段可以分别推送；映射重叠时显示已有绑定和具体重叠列，用户明确确认后保存。每次写入只触碰实际改变的受管理非公式字段。
- 对同字段冲突沿用可解释的“后一次成功写入决定当时远端值”；每次请求核验各自实际发送版本，显示发现的外部变化。某次“已确认”仅表示该操作在核验时得到证据，不承诺远端以后不被另一项目改变。各项目普通值仍本地优先，不通过下一拉取自动互相覆盖。
- 新增相同业务唯一键、删除别人正在维护的云端行、身份列变化要显示具体冲突，不默认为安全。删除 Sheets 记录会影响整个物理行（包括未映射列及其他项目使用列），删除影响必须明确列出，不能套用“修改只碰映射列”的说明。
- 绑定草稿可保存；真正首次建立本地副本须完整身份验证、映射确认和源结构校验。用户选择系统身份时有独立明确初始化动作及操作证据；失败不发布半初始化本地表。

**验收**：FX-05 项目 P 改数量、Q 改复核备注，两次推送后都保留（`DATA-SH-01`）；两项目重叠改数量，历史确认及最终远端值可解释（`DATA-SH-02`）；同键并发新增不追加两条含糊记录（`DATA-SH-03`）；解绑一个项目不删共享身份列和另一项目数据（`DATA-SH-04`）；P/Q 两个 Task 竞争同一物理行只有一个取得有效 lease，释放后 Q 仍按自己状态再取（`DATA-SH-13`）；同表不同身份列尚未证明公共对应时阻止相关领取并显示具体修复原因，而不拒绝保存第二绑定（`DATA-SH-14`）。

### 10.2 入站与公式例外

| 来源事实 | 本地处理 | 失败/竞争与验收 |
|---|---|---|
| 新可靠身份行 | 引入为新记录，statusId=null，公式/源信息按映射保存 | 发布前重新检查本地修订并合入同期本地变化；`DATA-SH-05` |
| 既有普通业务值改变 | 保留本地值/内容版本/状态，记录已发现的远端变化供查看 | 不把“拉取新增”变成远端覆盖本地；`DATA-SH-06` |
| 既有公式结果或错误改变 | 刷新公式只读值、错误和来源信息；作为该记录新的可读内容版本，不改业务状态 | 任务原始输入不变；依赖旧公式内容的任务写入需通过版本检查；`DATA-SH-07` |
| 行排序或插入 | 按稳定身份更新当前远端定位 | 行号不成为永久身份；结构/身份含糊保留上次完整数据；`DATA-SH-08` |
| 云端缺行 | 保留本地记录，标明缺失；本地待新增/待删除不误报远端丢失 | 不自动删除本地，不自动把缺失行重新追加；`DATA-SH-09` |
| 本地已删除但云端仍有行 | 保留本地 tombstone，继续显示删除同步状态 | 拉取不复活该行；`DATA-SH-10` |

公式字段在 Sheets 来源中只读，人工与工作流写入统一拒绝替换公式。新增记录需要延续公式时，绑定设置明确选择并核验公式模板行/列范围，Provider 复制已确认公式，不由业务层计算；混合公式不能猜模式。公式复制是该新增操作的子步骤，未完成不得把整条新增操作标为云端确认。源模板被删除/改结构时保留本地新增和待处理意图，提示修复模板，不写错误公式（`DATA-SH-11`）。

FX-05 数量 1→2 推送成功后，云端合计为 20；下次公式刷新本地为 20，业务状态不变，原任务输入仍是 10。若公式返回错误，显示具体公式错误而非把合计填 0（`DATA-SH-12`）。这里的例外来自旧 M5.1 `:46,59,61` 与数据规则 v2 `:86–90`，不是新增任意双向同步。

## 11. 出站队列、核验与恢复

### 11.1 本地写入到远端确认

1. 本地 CRUD 先完成本地事务，返回本地已保存与独立同步状态。人工变化立即唤醒推送；工作流变化推荐沿用首次待推送时刻＋5 分钟截止，后续修改不顺延。人工变更可带同一记录尚未发送的工作流字段立即推送。用户可手动触发未到期变化。
2. 未发送同一记录变化可合并为最新目标 Patch/版本；删除替代其旧未发变化。已经发送或结果未知的版本不能被合并成“从未发出”，较新版本须排在它后面。
3. 每次发送固定操作 ID、账号引用、SpreadsheetId/SheetId、绑定发送代次、RecordRef、预期结构、操作类型、实际字段 Patch、目标版本和必要校验证据。网络调用不持有数据库事务；重启从操作记录恢复。
4. 发送前重新核验身份、归属列、映射与当次行位置；不凭旧行号写入。更新只改实际变化的映射字段；删除明确整行；新增先检查是否已有同身份记录，不能因超时重复追加。
5. 任何成功响应先进入待核验。核验比较实际发出的目标字段/新增身份与必要公式子步骤/删除事实；只有获得对应证据后该操作才确认。旧操作应答不能确认之后的新内容版本。

| 操作状态 | 可执行动作 | 竞争与恢复 | 验收 |
|---|---|---|---|
| 待推送 | 自动到期、人工立即发送、查看或显式放弃尚未发出意图 | 取消/合并与发送登记在本地事务竞争，只能一方获得发送权 | `DATA-SYNC-01` |
| 发送中 | 查看进度，等待同一操作结果 | 请求超时/进程中断转待核验；不能当明确失败重发 | `DATA-SYNC-02` |
| 待核验 | 读取原目标核验 | 已应用→确认；证据明确未应用且原发送上下文仍有效→可重试；仍不明→保留未知，不猜结果 | `DATA-SYNC-03` |
| 已确认 | 查看该操作的时间、目标版本和证据 | 后续写入另有操作与版本；不能把整个记录永远标为已同步 | `DATA-SYNC-04` |
| 明确失败 | 保留本地与队列，修复权限/映射/数据后重试或处置 | 有限网络退避，权限失效不无限重试；幂等重试不换目标 | `DATA-SYNC-05` |
| 已放弃未发意图 | 本地值及其覆盖层继续保留，后续新修改可产生新意图 | 不回滚本地，不冒充云端已确认；拉取不冲掉覆盖层 | `DATA-SYNC-06` |

同一物理 Spreadsheet 的发送协调避免本应用定位/写入互相穿插，但不能把 Google 外部协作者的竞态包装成跨请求比较交换。核验出现冲突时保留原操作证据，不覆盖未知归属系统列；本模块不承诺识别没有可区分证据的相同业务行之间的所有 ID 调换。

### 11.2 并发变化与部分成功

- 同一记录版本 8 已发送，版本 9 又在本地保存：版本 8 的响应只能确认 8，版本 9 保留待推送。不可用 9 的值核验 8，更不能把 9 直接标为已确认（`DATA-SYNC-07`）。
- 一次同步可含多个持久操作/子包，已确认包保留结果，失败包和未发送包分别显示；不回滚已发生的远端效果。重复手动同步请求合并为后续一次唤醒，不丢掉当前轮之后的新变化（`DATA-SYNC-08`）。
- 推送失败但仍有读权限，入站可以继续，遵守同一物理写协调与本地合并检查；一条待核验操作不永久禁用所有新增拉取，也不阻断其他不相关本地表运行（`DATA-SYNC-09`）。
- 本地值与日志/队列必须一起恢复；启动恢复先核验旧发送操作，再处理新队列，不因应用重启而重新执行网页任务或批次（`DATA-SYNC-10`）。

## 12. 改绑、断开、归档与删除

### 12.1 先分开数据身份代次与发送代次

`recommended/proposed`：datasetGeneration 表示记录是谁；bindingEpoch 表示某次出站操作按哪个账号、映射和结构发送。两者不能混用。真实换工作表、身份列/身份策略或 Excel 替换会换数据代次；同一账号重新授权、映射非身份列调整通常只换发送代次。旧发送操作始终固定原目标和 epoch，不向新目标重放。

| 用户动作 | 明确正向结果 | 竞争/失败规则 | 验收 |
|---|---|---|---|
| 同账号重新授权 | 恢复原连接权限后核验原操作，再按用户指令恢复队列；数据身份和状态不重置 | 凭据主体/目标不符不能冒充同账号；未知发送先核验 | `DATA-LIFE-01` |
| 更换账号、仍访问同物理表 | 重新验证同一物理 Sheet 与稳定身份，保留本地数据代次；启用新的 bindingEpoch | 旧请求需完成核验或转入隔离历史操作；不因账号变化自动向新表推送 | `DATA-LIFE-02` |
| 改非身份字段映射 | 影响确认后更新发送 epoch；保留 RecordRef 和本地状态 | 受影响旧队列先发送/核验/明确放弃；新映射不能解释旧 Patch；活动运行依赖结构变更阻断 | `DATA-LIFE-03` |
| 换工作表、身份方式或身份列 | 显式检查新来源、确认本地变化/状态/关联影响、建立新数据代次；新状态 null | 活动 lease/有效准备阻断；旧来源数据及历史证据隔离保留，不自动搬状态或重投旧队列 | `DATA-LIFE-04` |
| 暂停同步/断开连接 | 保留本地副本、状态、关联和队列；停新网络写入，本地合法 CRUD 继续产生待推送意图 | 正在发送的操作继续登记真实结果或转待核验，不能当未发取消 | `DATA-LIFE-05` |
| 解除来源绑定 | 停网络写入，保留旧本地数据/状态/证据供查看；表进入待配置，显式重新绑定前不创建新的业务记录或发新任务 | 不能把解除绑定变成偷偷启用第三种来源；允许保留导出入口与否由功能范围文档决定 | `DATA-LIFE-06` |

如果权限永久丢失，不能要求用户必须推送成功才能管理本地项目。推荐提供明确“停止向旧来源发送并保留未决记录”的处置：确认已停止本机发送进程后，把已知未发意图取消、未知已发操作保留为结果未知的隔离历史上下文；允许连接新来源或归档，但旧操作不再自动重试。若新绑定仍是同一物理目标，旧未知写的记录/字段继续处于核验冲突范围，不能通过换账号/重绑绕过。若旧发送进程是否停止仍不清楚，继续阻断该物理目标的新写，入口指向进程/操作核验（`DATA-LIFE-07`）。

### 12.2 归档、恢复和永久删除

1. 归档先阻止新批次、准备与领取，按执行协调停止活动任务并确认租约处置；Sheets 停止新自动发送。未发队列保留并显示数量，正在发送的操作取得结果或明确登记隔离未知；不会把“归档”理解为自动丢弃本地业务修改。
2. 归档后业务数据、状态、目录、关联、来源设置只读，不能手动同步或写远端。操作恢复核验是针对历史事实的只读协调，可由归档流程完成；不借核验重发写入。记录搜索、筛选、历史输入和失败信息仍可看。
3. 恢复只恢复项目可编辑性，不自动续跑旧 Task、重开旧批次、重发旧队列或恢复已失权 Worker。显示待处理队列与原目标，由用户明确恢复同步或处置。
4. 永久删除显示所属表、记录、旧代次、未同步本地变化、未知操作和当前引用影响；必须先确认无活动执行、未知所有权或仍可能写入的进程。删除不触碰原 Excel、远端 Sheet/身份列、其他项目和全局资源。必要的本地文件清理采用可恢复操作，失败显示残留，不谎报完全删除。
5. 归档与写入并发以服务端事务为准：先提交的业务写入保留，归档冻结以后未取得授权的写被拒；终态/归档不能被迟到 Worker 或同步应答解除。

**验收**：`DATA-LIFE-08` 归档与领取竞争只出现一种有效结果；`DATA-LIFE-09` 归档保留未推送本地数据且不新发网络写；`DATA-LIFE-10` 恢复不重跑/不重发，明确恢复才处理原目标；`DATA-LIFE-11` 永久删除不改外部文件/Sheet/其他项目，清理失败可见；`DATA-LIFE-12` 未知操作原始结果继续可解释，不被改标成功。

### 13.1 数据能力端口

| `setRecordStatus` | 可写句柄或有效人工上下文、目标/null、前态约束、版本和操作身份 | 新 statusRevision 与事件；不重写内容，不隐式结算 Task |
| `bindRecordEnvironment` | targets[] RecordRef、同项目 environmentId/null、expectedLinkRevisions[]、有效写 lease 与替换策略 | End 内部关联组全部提交或全部冲突；每行 currentEnvironmentId 与新关联修订，关联失败保留环境，不要求 Bind 节点 |
| `addProjectField` / 字段查询修改删除 | 节点目标表、稳定 fieldId/新字段定义、预期结构与影响版本、来源列策略、操作身份 | 兼容变更结果与稳定字段句柄；活动无关新增不使旧任务失效；破坏被依赖字段则明确阻断 |
| 删除/来源/字段操作 | 固定目标、最新影响版本、明确范围、操作身份 | 可查询的真实提交/后台清理事实；未知结果不当作明确失败重放 |

### 13.2 验收组合

除了各节独立 ID，完整模块必须通过以下跨场景闭环，不以第一个单输入成功替代。

| 验收 ID | 固定过程 | 成立条件 |
|---|---|---|
| `DATA-E2E-01` | FX-01 Excel 导入→显式状态初始化→W 每次从待处理改已完成、A 状态不变、节点查 D→连续 3 Task | 3 条待办因明确状态变化各被处理，A 释放后重取；把筛选改为最终态且不改状态后，同批仍可重复；无消费类型/历史过滤 |
| `DATA-E2E-02` | 注册流程 End 勾保留并关联 A01→资料流程按 A01 找到 E01→End 再次保留新内容代次 | 无额外 Bind 节点；稳定引用不变；保存/关联失败可分别恢复，数据文件不存浏览器目录或登录秘密 |
| `DATA-E2E-03` | FX-04 快照→人工编辑→旧任务写字段/设状态→冲突处置 | 新值不被覆盖，旧输入证据不改；节点失败不会回滚已经成功的其他节点 |
| `DATA-E2E-04` | FX-05 两项目不同字段推送→公式刷新→一次发送超时→重启核验 | 无重复新增/串版本，两个项目状态独立，本地修改与公式例外都正确 |
| `DATA-E2E-05` | 上述数据有待推送/未知操作时归档→恢复→显式处置→更换来源 | 不重跑旧任务、不自动重投旧来源变化；新代次不继承旧状态/关联；历史事实仍可解释 |
| `DATA-E2E-06` | 正在运行的 T1 确保回执列存在→新增第二张表的行→查询并修改既有记录→设置状态；T2 仍使用原字段 | 新行/新字段均真实持久；兼容扩展不阻断 T2；冲突及部分成功可解释；原 Excel 不改，Sheets 列和值分阶段核验 |

实现时运行范围匹配的后端规则/事务/契约、前端交互/类型/lint、构建与真实应用验收；Sheets 使用授权测试资源，Windows/macOS 分别验证文件选择、重启恢复及凭据适配。本文未运行这些测试，不能引用旧测试数抵扣。

## 14. 已确认边界与剩余设计取舍

- **已经确认，不重复向用户询问**：每表单值/null 业务状态由系统维护、名称由用户定义；反复使用完全由状态和筛选决定；释放后允许同批再取；节点可跨多表处理数据、新增行和新增列；End 保留同时兑现环境保存及相关行关联。此前消费类型/本批过滤推荐被明确替代。
- **推荐并已完整定义，供整体审查**：受控单条关联与同表别名；查询后写节点非阻塞取 lease 的竞争策略；兼容字段扩展与破坏性变更判定；End 关联组的 CAS 恢复；Sheets 多绑定、共享物理排他、公式刷新与发送代次隔离。不把这些逻辑留给编码时临时决定。
- **最少需要的决策**：用户对完整稿整体审查即可，无需再提供业务样例或选择已被否决的消费模式。若要改变本稿的精确关联、来源行为或关联失败处理，可以针对该规则反馈，设计再修订；这不是要求先填需求表才能推进。

空白本地表、独立导出入口等产品范围由[功能结构](functional-structure.md)统一裁定；来源与运行边界在本稿已闭合，不以这些相邻选项未确认作为数据设计的阻塞条件。
