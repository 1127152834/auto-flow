# 项目管理完整功能结构与文字交互规格

- 日期：2026-09-12。
- 状态：**proposed，完整设计阶段，未形成已批准实施基准**。
- 范围：项目入口及生命周期、概览、自动化四页签、运行记录、统计、数据表五页签、环境及人工处理；覆盖当前完整模块，不以首条执行链代替完整范围。
- 来源：[总规格](../../superpowers/specs/2026-09-12-project-management-design.md)、[完整设计先行 ADR](../../../.ai/decisions/2026-09-12-project-management-complete-design-first.md)、[历史决定](../research/legacy-decisions.md)、[汇总审查](../reviews/2026-09-12/README.md)。详细来源见文末。
- 配套规则：[数据与状态规则](data-and-state-rules.md)、[数据传递与共享契约](data-flow-and-contracts.md)、[执行与环境规则](execution-and-environment.md)。同批设计是精确取数、状态、环境选择与保存策略的统一来源；本文定义用户入口和行为要求，不另立一套策略。
- 验证方式：静态对照来源、功能编号覆盖、跨页场景走查、Markdown 链接与差异检查。未进行业务运行、UI 或跨平台验收。

## 1. 如何阅读与使用本规格

功能编号固定用于后续交互、共享契约、实施任务和验收追踪。编号不代表实现顺序，也不随页面排序更改。

- **confirmed 目标**：当前用户或已核实历史确认的能力边界；不代表现有 AutoFlow 已实现，也不代表本文所有细节都已被用户批准。
- **proposed 细化**：为形成完整设计提出的字段呈现、动作动线、错误处置等；确认前不能作为实施授权。
- **proposed 范围**：审查新增或修订能力，是否纳入完整范围仍需裁定。功能编号先保留，排除时记录结果而不把编号改用于其他功能。

除特别标记外，各模块沿用 confirmed 目标，本文交互细化统一为 proposed。不能以“所有文案都是设计建议”为由，把已确认功能改成可选，也不能以“该模块历史确认过”为由将新增限制自动升格。

**2026-09-12 用户新增确认**：记录是否再次处理由业务状态和工作流取数条件决定，不增加“一次性/可复用”记录类型，不做“同一批次只用一次”的隐藏限制；每张表都有系统维护的单值状态列，工作流显式修改字段/状态，支持表的增删改查，包括字段/列及记录操作；结束节点的“是否保留当前环境”选中时，须保存登录上下文并关联相关数据行，不要求用户额外添加关联节点。这三项见[本轮业务语义 ADR](../../../.ai/decisions/2026-09-12-project-data-workflow-semantics.md)，不能再列成等待业务案例才能决定的事项。具体组合表达、关联目标及已有环境处理仍由配套文档给出可审查推荐。

**项目**指同一业务的数据、自动化、运行结果和浏览器环境归属；不将项目称为“工作区”。**工作区**仍是应用设置中可切换的本地数据根。**自动化**是项目中可配置、反复启动的业务对象；**编辑工作流**是编辑它的动作步骤。**批次**表示一次启动，**任务**表示其中一次流程执行，不能统一解释为“一行数据”。

## 2. 整体页面组织与通用交互

### 2.1 导航与布局

在现有 AutoFlow 顶部导航加入同级“项目”入口，继续保留总览、浏览器配置、代理管理、模型管理、设置。不复制旧全局侧栏，不增加项目侧栏、全局任务中心、账号模块或项目资源中心。

项目列表打开项目后，显示项目上下文头和顶部六页签：**概览 / 自动化 / 运行记录 / 统计 / 数据 / 环境**。上下文头包括返回项目列表、项目名称、描述摘要、归档/处理中提示、编辑项目及更多菜单。项目基本设置不是第七个页签。

自动化详情使用**基本信息 / 输入数据 / 参数配置 / 运行设置**四页签，工作流编辑从详情头部进入 Studio。数据表使用**数据记录 / 字段与校验 / 数据状态 / 来源设置 / 数据表设置**五页签。内层页签是对象内部视图；返回上一级必须返回原目录状态，不能成为浏览器历史难以区分的多套容器。

应用统一暖灰画布、棕色强调和现有 shadcn/Radix 控件。使用已有 Button、Input、Select/Combobox、Dialog、Drawer、Tabs、Table、Pagination、ScrollArea、表单及反馈模式。长表和日志在内容区域滚动，页面不被长字段撑宽；无额外上下文需要时不加旁栏。

“已保存环境”是本文建议的用户文案，对应历史规格的“持久环境”；只是同一对象的措辞细化，不增加第二种环境库。

### 2.2 所有模块共同遵守的状态和返回规则

| 状态 | 用户看到什么 | 允许的动作及结果 |
|---|---|---|
| 首次加载 | 保持页面标题、导航与真实加载提示；数据区使用已有加载模式 | 不用零条、空闲或正常冒充未知；能返回上一级 |
| 空数据 | 明确对象尚未创建或从未运行 | 提供本页首要创建/配置动作；运行不存在时不伪造统计 |
| 无匹配 | 当前筛选和“没有符合条件的结果” | 清除筛选；不将无匹配误作整个项目无数据 |
| 后台刷新 | 已有内容和筛选保持，显示刷新进度/更新时间 | 不清掉表单、选中项、列设置和滚动位置；状态过期时限制依赖其真实性的动作 |
| 读取失败 | 有缓存则保留并标“暂时无法更新”；首次失败显示错误与重试 | 错误落到具体区块，不因一个同步失败禁用所有项目能力；读取不到影响数量不得显示为 0 |
| 保存或命令进行中 | 明确“正在保存 / 正在启动 / 停止中 / 正在核验”等实际阶段 | 同一动作防重复；非相关浏览和返回仍可使用。离开页面不等于取消后台工作 |
| 结果不明 | “结果尚未确认”及当前可核对的事实 | 查询该次操作，不能提供会无条件再发一遍的通用重试按钮 |
| 只读 | 说明归档、对象已结束或当前连接不可写的原因 | 查看、筛选、查历史及返回可用；普通业务写动作隐藏或禁用并说明原因。归档后的已知残留清理属于受控维护，按 ENV-09 保留允许动作；导出取决于 DT-13 的范围裁定 |
| 内容冲突 | 保留本地草稿，标出哪些内容在别处改过或对象现已不可写 | 查看最新内容并重新编辑/提交；取消仍保留原草稿。不能仅提示错误后强制清空表单 |
| 对象不存在或已删除 | 名称/历史引用能保留时保留，并解释现在不可打开 | 返回来源列表；历史记录不伪装成被删除对象仍可编辑 |

表单字段错误靠近字段显示，跨页签错误在对应页签标记并可定位；错误标记不代表四页签必须逐步完成。成功反馈说明真实完成边界，例如“本地已保存，等待同步”，不统一显示“全部成功”。

每个列表保存项目、页签、搜索、筛选、排序、页码和可恢复滚动位置；详情记录进入来源。对象删除导致页码越界时落到最近有效页并说明变化。从全局资源页修复后返回原表单，保留草稿并重新核对原引用，不自动换成另一资源。

关闭弹窗、Escape、遮罩、切换页签或离开对象时使用现有草稿保护：可保存的草稿提供保存后离开、放弃并离开、继续编辑；保存失败停留并保留内容。只关闭 Studio 窗口或任务详情，不等于停止执行。后端忙态、工作区切换和应用退出的精确协调按执行专项，不能由前端弹窗决定运行已经结束。

危险动作先显示具体对象、影响与后续处置，默认焦点在取消；复用已有焦点回到触发按钮、嵌套浮层、键盘、输入法和缩放规则。普通表单不暴露内部版本、租约、目录路径或操作代次供用户填写。

## 3. PM：项目入口与生命周期

**业务目的**：把同一业务持续使用的自动化、数据、运行和环境放在一起；在不同项目之间切换，不切换应用工作区或重启本地服务。

### PM-01 项目目录与最近访问

- **入口**：顶部“项目”；任一项目头部“返回项目列表”。
- **字段**：名称、描述摘要、归档状态、最近修改/最近打开；运行接入后展示活动批次、等待人工和需关注摘要，未接入时明确能力状态。搜索名称/描述，活动/归档筛选，稳定排序与分页。
- **动作与结果**：打开项目更新最近访问，不改业务修改时间；最近访问只来自实际打开记录。列表行进入项目，更多菜单提供编辑/归档/恢复/删除；不在列表添加跨项目启动、停止或批量运行。
- **验收例子**：打开 A 后返回搜索“报表”的第 2 页，再打开 B，列表筛选仍在；工作区不变，其他全局资源不会重新创建。

### PM-02 新建与编辑项目

- **入口**：项目目录“新建项目”；项目行及项目头部“编辑项目”。
- **字段**：项目名称、描述。沿用历史名称去首尾空白后 1–36 字符、描述 0–120 字符；同工作区大小写归一后唯一，归档仍占名。计数与服务端采用同一字符规则。
- **动作与结果**：新建成功进入该项目概览；编辑成功更新上下文头及目录，不改变数据、任务和环境关联。取消不创建空项目；重名或并发冲突保留已输入内容。
- **验收例子**：A 改名后原数据表和运行记录仍属于 A；试图创建与归档项目同名的新项目时，显示已有项目及修正入口。

### PM-03 项目上下文与六页签

- **入口**：项目目录打开项目、受校验的项目内深链接。
- **字段**：项目名、描述、归档/归档中状态、当前页签；需要关注摘要必须对应可访问对象。
- **动作与结果**：切页签只切当前项目视图；打开另一个项目更新项目上下文。参数型项目可以直接进入自动化，不先要求建数据表；无数据/无环境不会自动标项目异常。
- **验收例子**：空项目可直接新建零输入自动化；从项目 A 切到 B 后不得继续显示 A 的数据或可执行按钮。

### PM-04 归档与恢复

- **入口**：项目目录/头部更多菜单。
- **字段**：真实活动运行、人工现场、环境保存/清理、同步中的事项及待同步数量；归档进度、阻断原因、可去处理的对象。
- **动作与结果**：确认归档后先禁止新批次/领取，允许现有任务取消、收尾及完成明确环境保存，不能一开始锁死这些内部写回；只有权威状态符合归档条件才进入只读。已关闭且归属确定的清理失败按专项规则可保留警示归档，并提供 ENV-09 维护入口；未知运行/归属/保存/同步结果不能冒充已结束。恢复后项目可编辑，但旧批次和同步队列不因为恢复自动重发。
- **验收例子**：项目有等待人工任务时归档，能进入对应事项并看到当前处置；未确认结束前不显示“已归档”。恢复后的历史失败记录仍是历史失败。

### PM-05 永久删除与残留处置

- **入口**：归档项目更多菜单“永久删除”。
- **字段**：名称确认、将删除的项目自有对象及文件、独立流程关联与全局资源影响说明、阻断事项、未同步变化、清理进度和失败结果。
- **动作与结果**：先读取真实影响并确认；归属不明、仍活动或清理未确认时展示阻断及处理入口。删除成功返回归档目录；清理未完成保留该操作可查询入口。不得删除原 Excel、远端 Sheets、全局资源或其他项目对象。
- **验收例子**：删除 A 后 B 和两者引用的浏览器配置还在；本地文件清理失败时用户能看到待清理结果，而不是只收到一次消失的提示。

**PM 状态补充**：空目录主动作新建；无匹配可清筛选；目录加载失败不报“还没有项目”；项目更新忙态只限制对应命令；归档中显示实际阶段，归档后保留查看及恢复；同名/修订冲突保留草稿；返回保存目录筛选和页码，项目被删则回来源目录。生命周期状态与阻断细则引用配套规则。

## 4. OV：概览

**业务目的**：回答“这个业务现在有什么在做、哪里需要我处理、从哪里继续”，不再建一套运行控制系统。

### OV-01 项目摘要与继续工作

- **入口**：打开项目默认概览、六页签“概览”。
- **字段**：项目资料、自动化/数据表数量、实际最近修改对象、当前业务配置与运行能力状态。
- **动作与结果**：“继续编辑”进入实际自动化或数据表；“查看运行”进入该批次。新项目提供创建自动化、准备数据等并列入口，不要求按卡片顺序完成全部配置。
- **验收例子**：只有参数流程的项目能继续编辑并运行；没有数据表不影响其正常摘要。

### OV-02 当前活动与需要关注

- **入口**：概览当前活动/需要关注区域。
- **字段**：活动批次、等待人工、失败任务、失效资源、同步失败或未核验结果；对象名、发生时间、影响范围、可执行下一步。
- **动作与结果**：任务失败到 RUN-03；人工到 ENV-03；同步问题到 DT-08/DT-09；缺资源到 AU-05 或 ENV-08。健康仅依据实际受影响能力，支持受阻、需关注、正常、空闲以及未知/过期；业务“待处理”不等于运行健康异常。
- **验收例子**：某 Sheets 表推送失败，概览指向这张表，并不宣称同项目参数流程全部不能运行。

### OV-03 最近活动与业务变化摘要

- **入口**：概览最近活动区域。
- **字段**：实际已提交的创建/编辑/导入/运行/人工/同步/环境活动，时间、对象、动作结果；数据变化摘要与执行结果分开。
- **动作与结果**：活动跳到对象具体位置；对象删除后保留可解释历史，不把已不存在入口变成无反应按钮。查看更早运行进入运行记录并携带条件。
- **验收例子**：任务执行成功但同步未完成时可看到两项各自事实，不把同步失败重写成任务失败。

**OV 状态补充**：空项目显示开始工作的入口；无运行样本明确“暂无运行记录”；摘要各区独立加载/失败，不能整体降为 0；刷新保留已有信息并标过期；概览不持有业务编辑草稿，动作忙态来自对象命令；归档概览只读；跳转时对象变更则说明最新事实；返回恢复概览原位置。

## 5. AU：自动化与 Studio 入口

**业务目的**：维护可反复运行的业务配置；输入、参数、运行规模和流程编辑各有明确用途，用户无需创建额外“运行方案”。

### AU-01 自动化目录及基本生命周期

- **入口**：项目“自动化”；概览继续编辑入口。
- **字段**：名称、描述摘要、最近修改、配置问题摘要；搜索、排序、分页。没有输入、参数不是配置问题。
- **动作与结果**：新建、打开、编辑基本信息、编辑工作流、进入启动确认；删除显示流程、运行、环境等真实引用影响，活动对象按规则阻断。历史是否保留按配套归属规则，不能把删除自动化等同删除所有任务。
- **验收例子**：同项目“注册”和“资料更新”引用同一张数据表；改前者名称不会改后者，数据不会复制为第二份。

### AU-02 基本信息页签与管理保存

- **入口**：自动化详情“基本信息”。
- **字段**：名称、描述、当前工作流关联摘要、管理草稿保存状态；名称/标识约束随统一对象契约，不另照搬项目字段字数。
- **动作与结果**：四页签共享一次管理保存，保存成功才能确认本次管理配置已提交；不允许某页成功另一页失败。工作流文档单独保存。未完成配置可作为草稿保存，字段错误定位到对应页签。
- **验收例子**：同时改描述和输入筛选，保存失败时两处草稿都还在；后台刷新运行状态不覆盖草稿。

### AU-03 输入数据页签

- **入口**：自动化详情“输入数据”；工作流输入问题定位返回。
- **字段**：具名输入、用途、是否必需、所绑定项目表、字段要求与匹配结果、基于业务字段及该表单值状态列的条件树、排序、只读预览和检查时间。契约定义与表字段不复制成两套可独立编辑的结构。
- **动作与结果**：添加/移除输入绑定，选择表，编辑类型允许的 AND/OR 条件，调整排序，刷新预览；缺失/错误字段指向 DT-05 或 Studio 的实际契约来源。移除被流程使用的绑定先展示影响。没有默认主表，不按行号隐式配对。
- **组合边界**：是否再次取得某条记录只由当前字段/状态及工作流取数条件决定；不增加一次性/可复用类型，不添加每批只用一次的限制。同时处理的占用保护与下一次能否匹配是两件事。显式关联、一对多、同表多用途、可选输入及读取能力的表达，采用[数据传递与状态规则](data-and-state-rules.md)的推荐设计，本页显示其实际含义与样例，不另发明消费模型。
- **验收例子**：10 条待办逐条改为已处理，辅助账号状态一直符合条件，在并发 1、上限 10 时可继续使用该账号完成 10 项；若流程明确把账号改为不符合条件，后续不再取得它。账号 A 对应资料 A、B 对应资料 B 的显式关联样例与实际任务一致。

### AU-04 参数配置页签

- **入口**：自动化详情“参数配置”；启动缺参定位。
- **字段**：参数名称、类型、用途说明、默认值、必填、是否允许本次启动填写；字段规则与工作流参数契约一致。
- **动作与结果**：按契约维护参数定义/默认值，校验类型和缺失；移除或改类型展示流程引用影响。默认值随管理保存，本次覆盖仅属该次启动。零参数允许空列表，不能为了开始流程强制建无用参数。
- **验收例子**：默认网址为测试地址，本次启动填另一个地址，历史能解释实际值，回管理页仍保留原默认值。

### AU-05 运行设置页签

- **入口**：自动化详情“运行设置”；资源失效或启动受阻定位。
- **字段**：浏览器配置继承/指定、代理继承/不使用/固定/代理组、最大任务数、并发、超时与停止行为；允许的环境来源、选择方式和保存目标依执行专项呈现。每个资源显示最终采用值和来源。
- **动作与结果**：维护自动化唯一运行配置，查看项目默认及全局资源；缺资源时可去现有模块修复后回来。内核由浏览器配置解析，不增加内核管理；并发只表示同时执行数量，不生成逐槽资源表单。
- **边界**：启动数量、可耗尽条件、存活现场容量、环境优先级与选源策略引用[执行与环境规则](execution-and-environment.md)。来源有效与当前可运行分开显示，不静默用直连或另一配置替代。
- **验收例子**：项目默认代理失效时配置仍显示原引用及原因；用户修复后返回草稿，重新校验该资源，当前运行不会被本次设置编辑改变。

### AU-06 编辑工作流及返回

- **入口**：自动化详情“编辑工作流”、目录对应动作；从 Studio 返回该自动化。
- **字段**：当前自动化/流程身份、工作流保存状态、存在的编辑会话、不可用原因。
- **动作与结果**：打开对应 Studio 文档，已有会话按共享契约定位，不额外复制流程。管理草稿未保存时明确保存后打开、放弃管理修改后打开或继续编辑；不能让 Studio 悄悄读到未提交的另一版配置。回管理页显示各自保存状态，互不覆盖。
- **项目数据与结束配置**：Studio 使用项目提供的数据能力，工作流能够按字段/状态读取多表资料、明确写字段/状态及进行表/字段/记录增删改查，见 DT-14；人工字段编辑见 DT-05，两者采用同一影响规则。结束节点提供“是否保留当前环境”，选中时由 ENV-07 完整承担保存上下文和关联相关数据行；管理页只呈现配置概要，不复制另一套结束节点编辑器。
- **proposed 修订**：缺浏览器资源允许创作、真实运行前阻断；这是对旧画布准入策略的调整。独立流程的关联与删除规则见 AU-08，不在每次打开时询问内部所有权，不增加所有权转移或复制功能。
- **验收例子**：项目中改运行设置并保存，Studio 中改步骤并保存，关闭再打开，两份内容均保留；只关闭 Studio 不结束后台任务。

### AU-07 启动确认与启动结果

- **入口**：自动化目录/详情“运行”；后续范围入口获确认时由 RUN-06 预填进入。
- **字段**：自动化名称、实际使用的已保存流程与配置摘要、本次参数、输入绑定/筛选及预览、数量和并发、有效浏览器/代理/环境来源、启动检查结果。
- **动作与结果**：用户核对本次值后启动；缺失项定位原配置。本次覆盖与保存为默认明确区分，不因运行确认修改长期默认。成功进入 RUN-02；请求未返回时显示正在确认本次启动，查询同一请求，不重复创建。
- **验收例子**：零输入流程可运行一次；数据预览为估计，在并发占用变化后实际处理数和受阻原因可解释。最大任务数 N 只限制任务数量，不保证 N 个不同人员/账号；状态不变且排序仍靠前的记录可能再次取得。双击或断线重连只能看到同一次启动结果。

### AU-08 独立流程关联与删除影响（proposed 范围细化）

- **入口**：自动化选择既有独立流程的受支持动作；自动化/项目删除影响页。
- **字段**：流程名称、当前关联、编辑与运行占用、后续编辑是否联动、删除本自动化是否影响流程。
- **动作与结果（推荐）**：项目中创建的工作流由项目所有；关联已有独立工作流不转移所有权，默认直接关联同一份当前文档，界面说明“编辑会修改该 Studio 工作流”。一个工作流最多绑定一个项目自动化；已有绑定时展示该项目/自动化的去向，不能偷偷复制为另一份。以上为 proposed 机制，不增加所有权转移或复制功能。
- **删除结果**：删除自动化/项目只解除独立工作流关联，独立文档保留；项目所有的工作流列入删除影响，由核心确认运行/编辑占用已处理后删除，不能由项目页面绕过核心直接删文档。
- **验收例子**：关联独立工作流后在 Studio 编辑，再从项目打开仍是同一文档；第二自动化尝试绑定时看到已有去向。删除原项目后独立文档保留；项目自建流程若仍在编辑或运行，删除明确受阻并能定位占用。

**AU 状态补充**：空目录可创建，空输入/参数是合法配置；各选择器加载失败保留原引用；预览失败不显示 0；保存/启动忙态分开，超时查询原命令；归档仅查看配置与历史；管理冲突保留四页签草稿，Studio 冲突交其文档机制；关闭详情回目录原位置，跨资源修复和 Studio 返回定位原页签及出错字段。

## 6. RUN：运行记录、停止与后续处理

**业务目的**：解释一次启动究竟做了什么、当前处理到哪里、失败或等待人工后有哪些有效动作。

### RUN-01 批次、任务与等待人工列表

- **入口**：项目“运行记录”；概览、统计下钻。
- **字段**：三个视图“批次 / 任务 / 等待人工”；时间、自动化、状态筛选，分页；批次显示数量摘要，任务显示实际输入摘要/节点/时间，人工显示原因/期限/现场可用性。
- **动作与结果**：打开批次或任务，筛选定位问题；等待人工打开 ENV-03 同一详情。当前执行状态与数据业务状态分列，不用一个“完成”合并。
- **验收例子**：一次启动包含多输入任务，列表不会把任务数量当记录总数；从统计失败数量进入时筛选条件和数据范围一致。

### RUN-02 批次详情

- **入口**：RUN-01、AU-07 启动结果、概览活动批次。
- **字段**：本次启动参数、输入绑定/条件、规模、并发、有效资源、创建/运行/成功/失败/取消/中断数量，开始结束时间、停止状态、未继续创建原因。
- **动作与结果**：进入本批任务及人工项、查看自动化当前配置、发起停止。历史配置证据与当前可编辑配置明确分开；从历史返回当前编辑不能自动覆盖现配置。
- **验收例子**：必要输入暂被占用、真正耗尽、来源不可用分别显示；停止后仍活动的任务在列表持续可见，直到真实结果到达。

### RUN-03 任务详情与节点记录

- **入口**：任务列表、批次、失败下钻、环境所关联任务。
- **字段**：实际输入内容及当时值、参数、环境和代理摘要、当前/结束节点、起止时间、执行结果、业务结果（如有）、节点尝试及重试链、日志、输出、截图等产物；关联数据当前状态另行查询显示。
- **动作与结果**：查看节点记录、展开输入、打开可用现场/产物、查看对应数据当前值。数据已变化/删除或现场已清理时显示事实，不能把当前数据冒充历史输入，也不提供无效“打开浏览器”。
- **验收例子**：任务领取后用户修改字段，详情仍显示执行当时值，并可另看当前值；同一节点三次尝试仍只是一项任务。

### RUN-04 停止与强制停止

- **入口**：活动批次详情；生命周期协调引用同一操作。
- **字段**：将停止创建的任务、仍活动任务/人工现场、停止行为、受影响环境和数据、停止中/结果不明/已确认结果。
- **动作与结果**：停止后不再创建新任务，已开始任务如何结束按执行规则明确提示；停止中提供当前实际允许的强制停止。强制停止先确认影响，完成后分别显示任务结果和资源处置，不能以 UI 按钮切换代替真正停机。
- **验收例子**：停止响应丢失后查询同一操作；不再次启动或重复强停。失败任务的清理成功不改变其失败结果。

### RUN-05 失联、结果不明与核对

- **入口**：任务/批次异常提示、概览需要关注、环境异常。
- **字段**：最近确认的运行事实、待核对的网页动作/现场/记录、当前允许动作及限制原因。
- **动作与结果**：核对现有执行和现场，按专项命令确认或终结；未知期间不将同一未隔离现场/占用记录交给新任务。核对不是任意改状态表单，用户不手填内部代次。
- **验收例子**：服务重连后仍不能证明浏览器已停，任务显示待核对且保留历史；核对完成后才开放对应后续操作。

### RUN-06 失败后的业务继续处理（基础目标 confirmed，快捷入口 proposed）

- **入口**：失败任务详情/列表；数据记录与自动化配置。
- **字段**：失败任务的原始输入分组、各具名输入的稳定记录、当前值与业务状态、已发生的结果；显式候选记录范围、当前条件/关联检查及被排除原因。
- **动作与结果**：基础路径可从任务定位数据，用户明确修改需要修改的状态/配置，再启动新批次；历史任务不恢复成活动任务。推荐纳入“处理选中的记录”快捷路径，作为 proposed 范围：保留原始输入分组和来源任务供核对，明确各输入/分组的候选记录范围，预填 AU-07 后创建新批次；实际仍按当前字段/状态条件及组合规则取数，不偷偷拆开不同失败任务的资料凑组，不自动改业务状态，不对副作用不明项盲重发。
- **次数说明**：候选范围的行数不等于任务数，也不承诺“每条失败记录恰好处理一次”。仍符合条件的范围内记录可再次取得；任务数由有效组合、当前条件、并发占用、任务上限及停止决定。
- **验收例子**：93 项成功、7 项失败时，用户能核对这 7 项原始输入组、已发生结果和拟处理范围；若纳入快捷路径，新批次保留来源关联，但不会以“选中 7 项”保证恰好创建 7 个任务或处理 7 条不同记录。

**RUN 状态补充**：从未运行与无匹配分开；日志和产物局部失败不遮住任务事实；刷新失败保留最后确认状态并限制继续/停止等动作；命令忙态追踪原操作；历史结果只读，活动任务也不能任意编辑状态；迟到进度不得覆盖终态，冲突后展示最新可用动作；详情返回原视图/筛选/页码，跨环境和数据查看保留来源。

## 7. ST：统计

**业务目的**：用可解释的同一组运行事实判断处理量、失败情况和耗时，并能找到对应任务；不在本模块建设自定义 BI 或资源监控仓库。

### ST-01 统计范围与刷新

- **入口**：项目“统计”；概览查看运行统计。
- **字段**：时间范围、自动化筛选、统计时区、数据截止时间、最近成功刷新时间、样本与更新状态。
- **动作与结果**：应用筛选与刷新后整组指标/趋势一起更新；刷新失败保留上次范围和数据并标明过期。统计时区不取某份浏览器配置的时区；内部 UTC 和用户区间显示不得混淆。
- **验收例子**：跨午夜范围内同一任务只归入一个区间；刷新失败不会出现新时间标题配旧数值。

### ST-02 指标与趋势

- **入口**：统计主区。
- **字段**：成功/失败数量、成功率、吞吐、耗时、按日趋势；取消/中断/仍运行分别说明，有效样本数、无有效耗时数量。
- **动作与结果**：显示指标口径和区间；没有样本显示“无样本”，未采集不显示估算值。节点重试不增加任务数。成功率分母、包含人工等待的耗时和任务区间规则采用[总规格 §5.5「统计」](../../superpowers/specs/2026-09-12-project-management-design.md)的统一推荐口径，不能页面各自计算。
- **验收例子**：固定运行样例同时包含成功、失败、取消、人工等待和重试，每张卡与趋势均能按已确认口径复算；无样本时没有 100% 成功率。

### ST-03 从统计查看对应运行

- **入口**：失败任务入口及被设计为可下钻的指标/趋势。
- **字段**：本次统计的范围、自动化/结果条件、对应运行集合和查询有效性。
- **动作与结果**：进入 RUN-01，继承同一可解释统计范围与结果；不能在旧数字下悄悄打开另一组实时数据。对应结果已不可取时明确提示刷新，不把内部结果标识当用户设置。普通只读数字不伪装成链接。
- **验收例子**：点击“失败 7”看到相应的 7 项；返回统计仍保留进入前范围，刷新后所有相关数据同时更新。

**ST 状态补充**：零任务、分母为零、无有效耗时各自表达；加载不填零；刷新忙态防重复且旧内容可读；错误保留最后结果；归档仍可查看历史统计；数据变化导致对应集合不可查询时给出刷新动作；从任务返回保持统计范围与位置。精确查询一致性实现由共享契约确定，不先要求通用快照平台。

## 8. DT：数据表目录与五页签

**业务目的**：维护项目中可被多个自动化共同使用的业务资料，解释当前值、业务状态、来源变化与运行占用各自事实。

### DT-01 数据表目录与创建

- **入口**：项目“数据”；概览准备数据；AU-03 选择表后查看/创建。
- **字段**：名称、用途说明、来源、记录数、最近活动、连接/同步摘要；搜索、来源/状态筛选、排序、分页。
- **动作与结果**：新建表元信息与可保存的空结构，继续设置字段和来源；打开已存在表，进入数据记录。来源未就绪与空表分开。空白可运行本地表是 DT-12 候选，不把“先保存空结构”冒充已支持该能力。
- **验收例子**：项目两种自动化引用同一张表，目录只出现一张；未配置完成的表明确说明下一步，不伪造 0 条已导入结果。

### DT-02 数据记录查询与显示

- **入口**：表内“数据记录”、RUN-03 查看当前数据。
- **字段**：稳定记录显示身份、业务字段、每表系统维护的单值状态列、同步状态、正在处理提示；搜索/类型允许的筛选、排序、列显示、分页，长值详情。业务状态不是多标签，也不是任务运行状态。
- **动作与结果**：查询在服务端完成；打开详情保留表筛选。业务状态、同步与占用分别表达；来自历史任务的定位同时说明当前数据可能已变更。
- **验收例子**：带前导零的编号排序、筛选和详情仍保留原值；从任务打开记录时能分清任务当时值和现在的值。

### DT-03 新增、编辑与删除记录

- **入口**：数据记录新增、行详情编辑/删除。
- **字段**：可编辑业务字段及类型/必填/格式错误、不可编辑身份/公式说明、保存结果和删除影响。
- **动作与结果**：按来源能力保存本地记录；Sheets 的远端进展另行反馈。删除先展示正在处理、引用和同步影响，精确删除/推送行为由数据规则决定。占用期间哪些字段可改及冲突处理引用配套规则；不让旧任务写回覆盖人工新内容。
- **验收例子**：输入错误保存失败但草稿仍在；编辑一条 Sheets 记录后明确显示本地已保存、云端尚未确认；公式不能通过普通编辑被覆盖。

### DT-04 单条记录业务状态维护

- **入口**：记录列表/详情的业务状态动作。
- **字段**：该表状态目录、当前单一状态、未设置、相关占用与修改影响。状态列由系统维护，不需要用户手建普通字段来模拟。
- **动作与结果**：用户显式选择业务状态后提交；改普通字段不自动改状态，任务成功也不等于状态“已完成”。被占用/状态已变化时按统一规则阻断或核对，不允许前端无条件覆盖。
- **验收例子**：任务先明确写状态、后面节点失败，记录保留已经提交的状态，同时任务仍显示失败；用户不会看到系统暗中回滚。

### DT-05 字段与校验页签

- **入口**：表内“字段与校验”；输入契约缺字段定位。
- **字段**：稳定字段身份、显示名、键、字符串/数值/布尔/日期、必填、已有格式规则；身份字段/公式/来源映射约束、自动化引用、受影响记录数量。
- **动作与结果**：新增、重命名、调整允许属性和删除字段；字段编辑先形成草稿，整体保存前统一核对影响。无法确定影响时说明未知，不能填 0；禁止静默截断、清空或转换不兼容值。
- **验收例子**：字段改显示名不破坏自动化引用；删除流程必需字段时能看到受影响自动化并按规则阻断/保留待修复引用，不能保存后才发现所有流程失效。

### DT-06 数据状态页签

- **入口**：表内“数据状态”；自动化设置状态相关配置查看目录。
- **字段**：自定义状态名、稳定身份、使用记录数、自动化/节点引用；新表具有系统状态列，状态选项目录初始为空，记录可未设置。每条记录同时只有一个该表业务状态。
- **动作与结果**：新增、改名、删除状态；重命名保持引用。删除被使用状态展示记录和流程影响，具体替代/清除规则由数据专项明确；不凭页面自行将所有记录改成另一个状态。
- **验收例子**：将“待核对”改名为“待人工核对”，记录及流程引用保留；删除仍被节点使用的状态时能定位实际引用。

### DT-07 Excel 来源检查、导入与重新导入

- **入口**：表内“来源设置”选择 Excel、查看已导入来源、重新导入。
- **字段**：文件和工作表摘要、字段预览/映射、身份方式及校验结果、导入时间/结果；重新导入展示本地修改、引用、业务状态等影响。
- **动作与结果**：选择工作簿/工作表→检查映射和身份→核对→导入本地副本；检查后文件改变则重新检查，不导入另一份未经查看的内容。原文件不回写、不后台监测。替换策略及新旧身份/状态关系引用数据规则，不能只用“重新导入”四字隐藏全量替换后果。
- **验收例子**：检查后替换原文件，提交被拒且当前表仍可读；导入后编辑本地值，原 Excel 不变；重新导入影响能解释之前本地修改的去向。

### DT-08 Sheets 连接、绑定与来源调整

- **入口**：来源设置选择 Google Sheets；同项目已连接账号摘要；更换/断开连接或工作表。
- **字段**：项目连接状态、账号摘要、表格/工作表、字段映射、业务/系统身份检查、公式字段、已有绑定及映射重叠、同步队列影响。
- **动作与结果**：连接→选择工作表→检查字段/身份→核对绑定→首次建立本地副本；系统身份需远端初始化时明确该动作及核验。连接失效保留本地内容；换账号不悄悄换表。更换来源/映射前处理旧操作，不能将旧变化发送到新表。
- **策略边界**：采用[数据规则 §6.3、§10.1](data-and-state-rules.md)的多绑定推荐：各项目保留独立本地值和业务状态，同一物理 Sheets 行按已验证共享身份在本工作区统一活动排他；远端定位/写入/核验按同一 Spreadsheet 串行协调。映射不重叠的列可分别推送，重叠列展示影响并明确确认；同字段后一次成功写入决定当时远端值，各项目本地普通值不因此自动互相覆盖。界面显示已绑定项目、具体重叠列和身份修复动作，不新增单写绑定限制。
- **验收例子**：A/B 使用同一工作表不同列时，两边结果均保留；竞争同一物理行只有一个活动任务取得占用，释放后另一项目可按自己的状态再取。A 解绑不删除 B 使用的身份列；共享身份尚未证明时可保存绑定，但受影响领取被明确阻断并提供修复入口。

### DT-09 拉取、推送、核验与同步失败恢复

- **入口**：来源设置同步区域；表头摘要；概览同步异常。
- **字段**：最近拉取/推送/核验时间、待推送/发送中/待核验/失败数量、受影响记录、错误及当前允许动作；本地状态与云端结果分开。
- **动作与结果**：查看来源事实，按允许操作拉取/推送/核验；结果不明先核验原操作，不能盲重发。已有普通业务字段本地优先；按旧规则保留公式派生值/错误和来源定位更新例外，公式只读；不是任意双向合并。具体周期与合并规则以数据专项为准。
- **验收例子**：本地改数量→推送核验→刷新公式结果，合计更新而其他本地字段和业务状态保留；网络故障后队列仍在，重启继续查同一未明结果。

### DT-10 数据表设置与表删除

- **入口**：表内“数据表设置”、目录更多菜单。
- **字段**：名称、用途说明、视图设置、项目归属、真实记录/自动化/同步/运行影响。
- **动作与结果**：保存表资料不改变稳定身份；删除先核对在用记录和自动化引用、同步结果，按数据规则保护外部源和历史证据。成功回数据目录；失败留在影响页并提供处理入口。
- **验收例子**：改表名后自动化仍引用同一表；删除动作不会删除用户原工作簿；有未核验推送时能跳到对应操作处理。

### DT-11 数据与自动化/运行的互查

- **入口**：表/字段/状态引用影响、记录正在处理提示、任务详情。
- **字段**：引用自动化及用途、关联批次/任务、当时输入与当前记录摘要、删除/失效说明。
- **动作与结果**：直接定位实际自动化输入、任务或环境关联；只查看不能改正在运行任务的输入。用户无需抄内部 ID 在另一页搜索。
- **验收例子**：知道某字段不能删时，一次点击看到哪条自动化使用它；从任务查看当前记录后返回仍在原节点日志位置。

### DT-12 新建空白本地表（proposed 范围）

- **入口候选**：新建数据表的明确选项，与 Excel 导入/Sheets 连接区分。
- **字段**：表名、用途、字段规则、系统记录身份；无远端连接/同步设置。
- **动作与结果**：若确认纳入，创建后可直接新增或接收流程写出的业务记录，复用同一套本地记录能力；不要求先在应用外造空工作簿。未确认前不能把“完整模块”解释为已批准此选项。
- **验收例子**：参数型自动化产生新记录，后续自动化读取项目中该记录；不出现伪 Excel 来源。

### DT-13 结果数据导出（proposed 范围）

- **入口候选**：数据记录页导出，作用范围在确认页明确。
- **字段**：推荐单表 XLSX，范围选择整表或当前筛选，选择输出列及可选系统业务状态；预计行数、本地保存位置。格式已有明确推荐，不要求用户先提供格式需求才能设计。
- **动作与结果**：该功能仍为 proposed 范围；推荐生成新的 XLSX 文件，不覆盖原 Excel，不形成双向同步。文本身份和前导零保持文本值；公式输出已确认的显示值，不导出为需要重新计算的公式。归档项目仍可只读导出；不自动展开或导出凭据内容、内部运行证据。长操作进度/失败可查，取消不冒充完成。
- **验收例子**：导出当前筛选的记录及选定结果列、系统状态，编号“0012”仍是文本“0012”，公式列为已确认显示值；原文件未改变，归档状态未被解除，未选业务列及凭据/内部证据不被顺带加入。

### DT-14 工作流中的表、字段与记录操作（confirmed 目标）

- **入口**：Studio 项目数据操作节点的配置、执行日志；从任务的变更结果返回数据表/字段/记录。
- **字段**：目标项目表、明确操作、字段定义或记录条件/值、期望业务状态、所引用输入/节点输出、将影响的运行字段契约与其他自动化、实际变更结果及新建字段/记录的稳定引用。具体节点拆分和契约由 Studio 与项目数据专项共同规定，不在管理页另建流程编辑器。
- **动作与结果**：工作流支持表的增删改查以及新增/修改/删除字段和记录、显式修改状态；调用同一数据能力并反馈具体结果，不能把工作流限制为只改既有单元格，也不能绕过身份、公式、当前任务/其他运行依赖及来源保护。新增字段返回稳定引用，让后续节点可以继续操作，兼容增加不能因存在活动任务就全部禁止。新建记录结果可供后续节点使用，并可作为 End 保留环境的关联目标；字段结构改变对已固定输入与后续取数的效果按数据规则解释。
- **失败与影响**：规划时展示已知引用；执行时再次验证实际占用与字段前提，冲突定位当前节点并保留之前已提交事实。删除本任务后续仍依赖的字段等不合法操作必须明确拒绝，不以“工作流自己调用”获得绕过权限。此处保护细则为专项推荐，新增字段/列能力本身已经确认。
- **验收例子**：工作流新增一列无现有冲突依赖的可选“处理说明”，新增一条记录并明确写字段/状态，后续节点读到结果；End 保留环境后新行具有对应环境关联。试图删除活动任务仍使用的字段时返回明确冲突，既有数据不被无声破坏。

**DT 状态补充**：无表、空表、未配置来源、无匹配分开；检查/导入/同步分阶段加载，错误不破坏上次可读数据；表单忙态与后台同步分开，结果不明查原操作；归档只读且不能发送队列；身份/公式/在用字段说明只读原因；字段及记录冲突保留草稿并定位影响；表内五页签保留各自筛选和草稿，跨自动化或任务查看返回同一表和位置。

## 9. ENV：环境与人工处理

**业务目的**：找到正在运行的浏览器现场、处理需要人工的步骤，并保存可供后续业务继续使用的上下文。全局浏览器配置仍是启动模板，不是这里的登录环境。

### ENV-01 环境入口与分区

- **入口**：项目“环境”；概览人工/现场异常；任务相关环境。
- **字段**：运行环境、等待人工、已保存环境、项目默认资源四个区域，各自的真实数量/状态与搜索筛选。
- **动作与结果**：使用区域内页签/分段切换；不增加资源侧栏。默认资源与环境实例明确分区，来源配置卡不充当正在运行的实例卡。
- **验收例子**：一份全局配置产生两个任务环境，运行区显示两个真实现场，默认资源仍只有那份配置引用。

### ENV-02 运行环境列表与详情

- **入口**：运行环境区域、RUN-03 打开相关环境。
- **字段**：所属自动化/批次/任务、启动来源、实际内核/指纹/代理摘要、活动/保存/清理及未知状态、创建时间、现场可用性。
- **动作与结果**：查看浏览器、查看任务、查看诊断和当前允许的清理操作。已被占用的现场不以“打开”再创建第二个上下文；现场已关闭/清理则明确不可打开。
- **验收例子**：手工关浏览器后页面按权威状态更新；任务结果和清理结果独立，不残留一个能启动错误会话的按钮。

### ENV-03 等待人工列表与共用处理详情

- **入口**：环境“等待人工”、RUN-01 等待人工、概览关注项；三个入口指向同一个业务对象。
- **字段**：项目/自动化/批次/任务、等待原因、当前节点、最近截图、实际输入、浏览器/代理、剩余保留时间、现场与继续条件、允许动作。
- **动作与结果**：进入现有浏览器完成人工步骤；选择并校验可继续位置后继续同一任务；或明确按完成/失败结束。人工完成任务不自动把业务记录改成“已完成”，数据写入须由明确操作完成。继续失败显示缺少的前提并允许返回核对，不能任意跳节点绕过条件。
- **验收例子**：从运行记录和环境打开的是同一项等待；一处已继续后另一处刷新不得再次继续。期限到期或现场丢失时保留历史并移除无效动作，不伪造可恢复状态。

### ENV-04 已保存环境目录与详情

- **入口**：环境“已保存环境”；任务保存结果；自动化选择环境后查看。
- **字段**：名称、备注、保存时间、来源任务/人工操作、原始浏览器资源及实际环境身份摘要、可用性、业务记录关联（按专项定义）、被哪些自动化/运行引用。
- **动作与结果**：搜索、状态筛选、打开详情、改名备注、进入维护、使用此环境和删除影响；“使用此环境”将受校验选择带回调用的配置，不另建一套启动系统。
- **验收例子**：两份环境来源配置相同但保存内容不同，选择 B 明确绑定 B；改显示名不改变任务或业务记录的关联。

### ENV-05 环境来源选择与持续使用

- **入口**：AU-05/AU-07 环境字段、已保存环境“使用此环境”。
- **字段**：环境来源推荐支持“从浏览器配置新建 / 使用指定的已保存环境 / 使用所选输入记录关联的环境”；所选来源摘要、数据行的当前环境关联、实际资源来源及冲突/失效结果。每行只有一个当前环境引用，记录间具名关联槽不扩展成多环境标签。
- **动作与结果**：按[执行与环境规则](execution-and-environment.md)解析来源并预览实际采用的环境；记录关联采用配套数据规则的稳定引用，用户看到名称与关联用途，不手填环境 ID 或目录。失效时保留引用、定位修复，不自动打开空白环境顶替。具体来源选项为 proposed 细化，不将 Profile 当成登录上下文。
- **验收例子**：账号 A/B 只是通用样例：任务读取 B 的稳定环境关联后打开 B；全局模板重置指纹不会悄悄重置已保存环境身份。专项给出来源优先级与冲突时唯一预期，本文不重新问用户是否需要关联。

### ENV-06 人工打开与维护已保存环境

- **入口**：已保存环境详情“打开并维护”。
- **字段**：维护目标、现有占用、资源有效性、维护中的真实浏览器状态、退出/保存结果。
- **动作与结果**：按专项的独占与保存策略进入维护；已被占用说明由哪个任务/维护操作使用，并提供查看入口。登录或人工更新完成后执行明确保存/关闭操作，保存不明或失败保留可恢复事实；不以关闭详情当作保存成功。
- **验收例子**：两次点击不能同时打开同一受保护目录；维护保存成功后再使用得到更新状态，失败时用户知道现场和旧保存状态各自是否仍在。

### ENV-07 从任务保存环境与后续选择

- **入口**：Studio 结束节点“是否保留当前环境”配置及任务结束结果；受支持的人工保存动作、人工维护保存。
- **字段**：是否保留、本次环境、保存目标、需要关联的数据行/关联用途、已有环境关联影响；保存/关联进行中、失败或完成结果、下次使用对象。End 默认初值为持有效写占用的初始输入，可排除共享资料，并显式选择本任务新增记录或写节点返回且仍持有效占用的记录；纯查询结果不自动关联。配置或概要明确实际目标，不能让用户猜“相关”具体指谁。
- **动作与结果**：勾选保留后的完整承诺是保存登录上下文并关联相关数据行，不要求再加一个关联节点；未勾选不自动保留。已有保存来源更新、另存新环境、已有行关联冲突和零输入无行时的行为，采用[执行与环境规则](execution-and-environment.md)及[数据传递与状态规则](data-and-state-rules.md)中的明确推荐。用户确认整个设计前，推荐不冒充已批准的默认覆盖策略。
- **反馈与失败**：保存和关联都符合承诺后才显示保留完成，可打开 ENV-04 并从相应数据行再次找到环境；一部分未完成必须分别说明，不显示全部成功。保存/关联冲突保留可恢复现场与旧关联，不能自动丢现场或最后完成者覆盖；精确恢复命令引用专项。
- **验收例子**：取得账号输入、显式写节点返回的有效可写记录或本任务新建业务记录，在 End 勾选保留并指定相应目标；结束后数据行能打开已保存环境，下次任务取得保存的上下文。整个流程没有额外关联节点；已有行关联不能静默被换成另一环境。

### ENV-08 项目默认资源

- **入口**：环境“项目默认资源”；自动化继承来源查看。
- **字段**：浏览器配置、代理/代理组、模型等本模块确实使用的全局资源引用，继承/未设置/明确不使用的区别，受影响自动化摘要。
- **动作与结果**：选择现有资源并保存项目默认；去全局现有模块创建/修复后返回原草稿。不能在这里复制内核管理、代理凭据或模型供应商页面。改变默认影响哪些未来运行由继承规则说明，当前批次不被悄悄改配置。
- **验收例子**：两个自动化中一个继承、一个显式指定，更新项目默认只影响获规则允许的后续运行；全局资源删除检查能看到项目引用。

### ENV-09 环境清理、删除与异常恢复

- **入口**：运行环境异常、已保存环境更多菜单、项目归档/删除影响。
- **字段**：实际归属、活动/引用影响、任务结果、清理/删除操作状态、残留内容和可恢复结果。
- **动作与结果**：只有当前事实和规则允许时提供清理重试/删除；进行中不重复发起，结果未知先核验。删除保存环境展示关联影响；清理目录不删除历史日志。临时与已保存环境的规则分开，不能共用无条件“全部清空”。
- **验收例子**：任务失败而环境清理成功仍显示失败；删除被后续自动化引用的环境前能定位引用；未知清理结果不会马上允许同一现场被重新使用。

**ENV 状态补充**：没有现场、没有人工项、没有保存环境分别给出用途说明；加载失败保留最后状态，不显示空闲；打开/继续/保存/清理各自有忙态；运行历史和过期人工详情只读，归档维护动作受生命周期规则限制；占用或保存冲突说明真实对象并保留现场/草稿；人工详情从哪个列表进入就返回哪个列表，查看任务或数据后能回到该人工事项。

## 10. 跨页完整业务路径

以下是依据用户确认编写的设计验收样例，不代表用户提供了相同数据量。记录再次取得由字段/状态与工作流条件决定，End 保留连同相关行关联完成，这些已经确定；组合表达与异常恢复由专项提供明确推荐，整合后纳入完整设计审查。

| 路径 | 用户动作与功能编号 | 必须保持的业务事实与返回 |
|---|---|---|
| 首次参数型自动化 | PM-01/02 建项目 → PM-03 自动化 → AU-01/02 新建 → AU-04 填参数（可以为空）→ AU-05 选择资源 → AU-06 编辑并保存流程 → AU-07 启动 → RUN-02/03 看结果 | 不强制建表/登录 Sheets；四页签不是闯关；分别保存配置和流程；结果查询可回到该自动化 |
| Excel 批量处理 | DT-01 建表 → DT-07 检查导入 → DT-02/05/06 核对记录字段和状态 → AU-03 绑定 → AU-07 → RUN-02/03 → DT-11 查看结果记录 | 原文件不变、身份稳定、输入证据与当前值分开；结果导出只有 DT-13 纳入后才作为这条链的文件出口 |
| 多自动化共享业务数据 | 自动化 A 明确写业务字段/状态 → DT-02 可见 → 自动化 B 的 AU-03 按获确认规则读取 → RUN-03 解释实际输入 | 数据不为每个自动化复制；A 执行成功不自动假定记录符合 B；多人资料/多输入取数不按行号猜配 |
| 工作流产生并维护新业务数据 | AU-06 配置 DT-14 数据操作 → 运行中增列/增行/写值与状态 → 后续节点使用新字段/记录的稳定引用 → End 保留并关联新行 → DT-02/05/11 查看 | 兼容增加允许继续；结构变更采用与人工编辑一致的保护；新行不要求用户另加关联节点；流程已提交的变化不因后续失败偷偷回滚 |
| 多输入与共享资料 | DT-01/07 准备待办和资料 → AU-03 设置基于字段/单值状态的条件和显式组合 → 预览 → AU-07 → RUN-03 对照组合 | 记录未被改成不匹配状态且条件仍满足时可以再次取得；没有每批只用一次或一次性/可复用类型；同时占用保护不改变这个规则 |
| 同一业务身份连续使用环境 | AU-06 在 End 勾选保留并核对关联目标 → AU-05/ENV-05 选源 → RUN-03 → ENV-07 保存上下文并关联行 → DT-11 或 ENV-04 找到环境 → 下一次 AU-07 | End 承担完整保存和关联；无需额外节点，关联冲突不能静默覆盖；模板、环境身份、工作副本不混淆；不增加账号专用模块 |
| 等待人工后继续 | OV-02 或 RUN-01 或 ENV-01 → ENV-03 → 浏览器完成步骤 → 校验继续 → RUN-03 | 仍是原任务；三入口同步；不能超过当前有效期限/前置条件；返回保留原列表条件 |
| 失败后完成剩余业务 | ST-03/RUN-01 → RUN-03/06 看已发生结果 → DT-04 或 AU-02/06 明确修正 → AU-07 新批次 | 旧历史不变；新范围可核对；RUN-06 快捷入口是否存在单独裁定，不默认所有失败可直接再次发送 |
| Sheets 失败恢复 | DT-03 本地修改 → DT-09 推送核验 → OV-02 异常入口 → DT-08/09 修复/核验 → 返回原记录 | 本地保存和云端确认分开；公式值正确更新、普通本地值保留；旧变化不发到新来源 |
| 修复全局资源引用 | AU-05 或 ENV-08 发现资源失效 → 现有浏览器/代理/模型模块修复 → 返回原表单 → 核对 → 保存/启动 | 原草稿不丢、不重新造资源中心、不静默替换引用；当前已运行批次不受未来设置编辑影响 |
| 归档再恢复或删除 | PM-04 发起 → RUN-04/ENV-03/09/DT-09 处理实际阻断 → 回 PM-04 → 只读归档 → 恢复或 PM-05 删除 | 每项阻断有对象去向及回程；恢复不重发旧工作；删除不碰外部原表或全局资源 |

### 10.1 贯穿各页的综合设计样例

样例使用人员、邮箱、账号三张通用业务表；这些名称、状态和操作顺序用于解释设计，不声称是用户既有生产流程，也不成为应用内置模型。人员状态“已核验”、邮箱“待使用/已注册”由样例显式创建；新表仍没有系统预填状态。

| 阶段 | 页面或工作流操作 | 可验收结果 |
|---|---|---|
| 准备数据 | DT-02/06 核对人员表“已核验”、邮箱表“待使用”；账号表接收新记录。AU-03 绑定人员、邮箱，分别设字段与状态条件 | 两表各自有单值状态；没有给人员选择“可复用类型”，也没有给邮箱选择“一次性类型” |
| 注册处理 | AU-06 配置流程读取人员/邮箱；网页步骤后，明确节点把邮箱状态设为“已注册”，在账号表新增记录并写入对应人员/邮箱业务键 | 人员状态保持“已核验”，邮箱改变来自明确节点；账号是本次真实新增行，节点返回稳定记录引用 |
| 保留环境 | End 勾选“保留当前环境”，关联目标选邮箱输入及本任务新建账号记录；人员是共享资料，未选为关联目标 | ENV-07 保存登录上下文并关联这两条记录；人员行不会因为被用过就自动关联本次账号环境；无需额外关联节点 |
| 下一注册任务 | 最大任务数尚未达到时，重新按相同条件/排序取人员和邮箱 | 邮箱因“已注册”不再匹配；人员状态未改，排序最前的同一人可以再次取得。maxTasks=2 也不承诺得到两名不同人员 |
| 后续资料更新 | 另一自动化从账号行的环境关联选择来源，按账号中人员业务键显式取得对应人员资料 | ENV-05 打开正确账号环境，AU-03 取得正确人员；不会按两表行号配对，也不会选任意同模板环境 |
| 查看与故障恢复 | RUN-03 查看实际输入/新增记录/状态变更/环境保留结果，经 DT-11 到当前记录或 ENV-04 到保存环境 | 历史输入与当前值分开；保存或关联失败时看到未完成环节和有效处置，不误报全部成功；返回仍在原任务上下文 |

### 11.1 已确定的业务事实与专项推荐边界

多表取数以业务字段/每表单值状态为条件，记录可否再次使用按这些条件判断；不存在本批已用过就排除的隐藏规则。工作流支持表、字段/列及记录增删改查，明确读写字段和状态；任务成功不自动改变业务状态。结束节点选中保留环境时，同时保存上下文并完成相关行关联。这些采用本轮用户确认，不再等待用户提供例子才能设计。

显式相关记录表达、同表多用途、可选输入、任务上限、环境来源优先级、记录间关联槽与当前环境引用、End 关联哪些输入/新增行/明确写节点结果以及已有环境如何更新，配套专项已基于以上事实给出具体推荐。它们随完整设计统一审查，不能推迟到实现时选择，也不需要让用户逐项发明工程机制。

### 11.2 已有具体推荐，供整体审查

| 主题 | 影响功能 | 推荐与当前身份 |
|---|---|---|
| Sheets 多绑定与共享活动排他 | DT-08/09 | 保留历史多绑定目标，按数据规格使用共享物理身份排他、同机远端串行协调与显式重叠列影响；各项目业务状态独立。机制为 proposed，不回到单写绑定限制 |
| 失败记录创建后续新批次的快捷入口 | RUN-06 | 推荐纳入；保留原始输入组与显式候选范围，仍按当前条件取数，不保证每行一次。范围 proposed，原任务不可变继续保留 |
| 无外部来源的空白本地表 | DT-12 | 推荐纳入并复用本地表/字段/记录/状态能力；范围 proposed，不增另一套存储或同步 |
| 单表结果导出 | DT-13 | 推荐 XLSX 新文件、整表或当前筛选、选定列及可选系统状态、保留文本身份/显示值、归档可导出；范围 proposed，不自动带入凭据或内部证据 |
| 独立流程用于项目 | AU-08 | 推荐直接关联同一文档、不转移所有权；一个流程最多关联一个项目自动化，已绑定显示去向；删除项目或自动化时只解除独立流程关联，项目所有流程由核心检查占用后删除。不增加转移/复制功能；机制 proposed |

以上已经给出可审查的具体推荐，随完整设计统一评审，不能在每个页面开发时重新发明规则，也不要求用户逐项补写需求或提供格式/生产案例后才继续设计。控件选型、弹窗/抽屉、字段错误定位和列表返回按现有设计系统细化；proposed 身份用于区分推荐与批准，不代表这些方案仍没有答案。

### 11.3 配套专项必须统一但不应转嫁给用户的细则

任务与记录占用状态、写回冲突、操作结果不明、重连、停止/人工竞争、保存失败保留、公式派生值刷新、统计样本与区间、删除协调和 Studio 接入依赖，须在配套规则/共享契约中给出一致答案。本文不能成为要求用户理解租约、fencing、CAS 或后台文件代次的理由。

Sheets 公式只读及派生结果刷新属于已核实旧规则的恢复，不是让用户选择“是否接受正确数据”；实现粒度与验证方式由技术设计负责。实时现场容量、精确时间限制、输入类型约束也须从真实业务与当前核心能力得出，不照抄未经验证的数值。
