## 1. 用户应能完成的完整业务

用户在项目配置自动化及资源，在 Studio 保存工作流，然后发起一次批次。批次按已定义的数据规则取得每项任务的正确输入，执行真实 CloakBrowser 操作；显式数据节点将结果保存给后续自动化。任务详情能解释实际使用的记录、参数、浏览器身份、步骤、结果以及尚未完成的同步或清理。

需要继续登录状态时，任务从正确的已保存环境创建工作副本。结束节点勾选**保留当前环境**，便执行一次完整的“保存登录上下文并关联相关记录”动作；不要求用户另加关联节点。未勾选的普通成功、失败、取消不自动改写已保存来源。

需要人工介入时，暂停的是同一个 Run 的自动执行，保留页面、变量、数据占用与代理；用户可查看现场、从经过校验的位置继续、人工结束，或停止。退出 Studio 窗口不是取消；应用服务重启也不是恢复网页动作的授权。

本文覆盖手动批次、参数型及数据型任务、节点重试、取消、失联、人工、环境维护/保存/删除，以及归档和停机的执行配合。不建设另一套执行器、跨机器调度器、工作流发布库或环境历史版本产品。定时触发以后仍调用相同启动用例，不在本文增加调度产品。

## 2. 对象与唯一责任

| 对象 | 持有的事实 | 谁可以改变 |
|---|---|---|
| Batch | 一次启动身份、固定配置、领取是否开放、任务上限/并发、停止原因、任务聚合 | 项目执行协调用例；不解释工作流节点 |
| Task | Batch 的一组输入与一次 CoreRun 的关联、固定输入证据、实际资源、业务写入/环境保存关联 | 项目用例提交业务关联；执行状态从 CoreRun 投影，不由页面独立修改 |
| CoreRun | 一个确定请求的运行状态、当前节点、检查点、执行代次、终态与结果 | 自动化核心及其恢复协调器；项目只发命令 |
| NodeAttempt | 某个 Run 中一次节点访问的某次尝试，含循环访问身份、错误、输出及副作用证据 | 自动化核心；重试新建尝试，历史尝试不可覆盖 |
| DataLease | 稳定记录的排他持有者、写入代次、隔离/释放事实 | 项目数据用例；不能用业务状态充当锁 |
| ManualAction | Run 的当前人工等待项、检查点、允许动作、期限、处置人和结果 | 核心检查点决定可继续性，项目用例管理期限及入口；命令由核心裁定 |
| EnvironmentInstance | 本次运行或维护拥有的工作副本、浏览器进程、实际身份/资源、保存和清理事实 | 浏览器运行时与环境用例；窗口不拥有生命周期 |
| PersistentEnvironment | 同项目稳定环境身份、当前已提交的持久内容、身份参数、来源、关联及有效性 | 环境用例；只有显式保存或受控维护可更新内容 |
| Operation / Event / Artifact | 可查询命令身份、已提交变化、日志/截图/保存候选等结果 | 对应业务用例；运行事件由核心顺序化，日志不是第二套数据库 |

一个 Task 对应一个 CoreRun。节点重试、人工继续和断线后查询均保留这两个身份；新批次产生新 Task/Run。独立 Studio 的 CoreRun 可以没有 Batch、Task、Project，使用同一个核心。历史失败任务不变成新的活动任务。

所有项目写入均校验项目归属、当前生命周期、命令身份及所需版本；所有 Worker 回报均校验执行代次。数据、环境及命令的身份不得来自列表行号、名称、浏览器目录或 UI 数组位置。

## 3. 何时固定什么

| 固定时点 | 固定内容 | 后续变化的含义 |
|---|---|---|
| 保存自动化管理配置 | 输入绑定/选取方式、参数配置、环境选择策略、资源继承、数量/并发/超时 | 不运行；与 Studio 当前文档分别保存，互不覆盖 |
| 接受批次启动 | 管理修订、流程的实际执行内容、输入契约与选择规则、参数实值、资源策略及适用候选集合、任务规模 | 同批后续任务不读取刚保存的新流程或新运行设置 |
| 原子领取并创建 Task | 原始输入完整值、内容/状态/关联版本、RecordRef、有效占用、具体环境身份与当时已提交内容代次、实际可用资源预约 | 此后人工编辑和同步不能改 Task 的原始证据 |
| 核心接受 Run | 唯一运行请求、Task 提供的独立输入对象/参数、执行内容、资源描述与能力绑定 | 重复提交返回同一个 Run；启动不会再次从项目配置推导请求 |
| 节点显式写入成功 | 该节点提交的字段/业务状态/环境关联、返回值和已确认版本 | 后续节点可显式引用返回值；执行内 CAS 版本推进，原始领取证据仍不变 |
| 显式保存环境成功 | 稳定环境 ID 下的新内容代次及保存证据，或另存的新环境 ID | 下一项选择该环境的任务读取最新**已提交**内容；活动工作副本不改变 |

流程执行内容包括根流程、边、节点配置、变量初值，以及本次实际使用的子流程内容和非秘密资产。只保留 workflowId 或内容摘要不够；运行中再查“当前子流程”同样不满足固定要求。保存内容用于执行和解释，不提供版本列表、恢复编辑、历史重放或发布入口。凭据只保留引用，浏览器持久数据作为受控环境资产保存，不复制进日志或普通运行 JSON。

参数值采用启动覆盖 → 自动化保存值/默认值；缺少必填参数阻止启动。变量按 Run 从固定初值独立初始化，节点/循环变量不共享。项目表不是全局可变变量字典；通用变量赋值不自动写项目数据。

工作流不只可以写启动输入。显式查询节点可取得同项目授权表的记录快照；后续显式写节点在提交前按稳定目标、预期版本和权限**非阻塞**取得额外写 lease，已有其他 Task 占用时返回占用冲突并按节点策略有限重试，不能持有旧锁无限等待新锁。只读结果不自动获得写权；成功取得的动态 lease 和写返回记录登记到本 Task，与初始 lease 一起收尾/撤权。表、字段和记录 CRUD 及结构兼容影响规则由数据文档统一规定。

**对总规格“批次固定资源”的明确细化：**新建自 Profile 的参数内容、seed、内核固定在批次；“使用已保存环境”的**选择策略**在批次固定，而记录关联的 environmentId、当前内容代次及其身份包在该 Task 领取时固定。这样同一批次顺序复用环境也能读到前一任务显式保存的更新。必须在配置摘要展示“每项任务读取该环境最新已保存状态”，不能一面承诺持续保存、一面悄悄固定整批旧浏览器目录。

## 4. 从启动到真正执行：幂等与事务边界

### 4.1 启动前与批次接受

启动预检校验项目可运行、自动化/流程一致性、节点能力、参数、输入规则、资源引用和环境选择方式。无浏览器节点的有效纯流程不强制创建浏览器。环境引用缺失、内核不兼容或必要项目端口未接入时给出明确阻断，不静默换资源。

预览只显示当前匹配/可领取记录数，不预占整表，不把记录数当作最终任务数。活动租约只防同时占用；释放后仍满足业务状态与字段筛选的记录，在同一批次也可再次领取。没有“每批已消费”集合或一次性/可复用输入类型，失败历史也不加入排除条件。排序决定下次先取谁，有限 N 个任务不保证 N 条不同记录。

建议新配置默认有限 1 次；零输入/仅可选输入必须为有限数量。存在必要数据输入时可显式选择不限数量，含义是持续按当前条件领取，直至必要输入真无匹配或用户停止；即使表有有限行数，状态不变也不保证耗尽。页面明确显示这一语义，不建立无匹配后继续监听新增的常驻任务。

运行设置提供“任务失败后：停止新任务 / 继续执行”，推荐默认停止新任务。failed/timed_out/interrupted 触发默认关闭领取，已经开始的健康任务正常收尾；选择继续时，已释放且仍匹配的失败记录也可能成为下一 Task。取消批次始终停止新任务，不受此项覆盖。未知外部效果的占用仍须先核验并释放，不能为继续策略跳过隔离；不增加阈值熔断框架，也不通过暗改业务状态阻止重复。

客户端发起启动时生成并保留一个操作身份。相同身份、相同规范请求返回同一 Batch/结果；相同身份、不同内容返回冲突。发生超时后查询这个身份，不产生新身份重试。明确修改配置或明确“再启动一次”才创建新操作。被拒绝请求也有可查询原因，但不生成虚假运行任务。

### 4.2 领取与核心准备的一次本地提交

推荐复用同 sidecar、同 SQLite 的短事务，避免另建消息平台：

1. 在事务外完成必要预读/可用性检查，准备候选；这一步不启动浏览器、不消耗记录。
2. 在同一短事务重新检查 Batch 领取门闩、任务剩余额度、输入版本、数据占用和资源预约。`prepareInputGroup` 的预读结果不能替代 `commitInputGroup` 的重新检查。
3. 通过各自应用端口一起提交 Task、固定输入、租约、环境身份预约，以及核心 `prepareRun` 建立的 queued CoreRun。预分配稳定 runRequestId，将 core 返回的 runId 写入 Task。核心参与事务但不 import 项目表；不登记批内消费标记。
4. 事务提交后，运行器领取这个已准备 Run 的有效执行代次，重新确认未被停止/撤权，然后才创建浏览器工作副本与执行节点。网络、文件复制和浏览器运行不能占用数据库事务。

任何必要输入或预约失败，整次提交回滚，不创建半个 Task。已经提交 Task 后发生浏览器启动失败，则保留真实失败 Task，由核心给出失败原因；它与未能领取是两种不同事件。该 Task 结束并释放后，记录能否再领仍只由当前状态/筛选和运行停止策略决定。

| 崩溃/丢响应位置 | 权威事实与恢复动作 | 禁止行为 |
|---|---|---|
| Batch 接受前 | 查询启动身份，未提交则没有 Batch；可用同身份重试 | 因 UI 无返回先创建另一个启动身份 |
| Batch 已提交，响应未收到 | 返回既有 Batch；继续查询进度 | 创建第二批相同任务 |
| 领取/prepareRun 事务未提交 | 不存在 Task/租约/queued Run 的部分提交 | 只释放部分输入或只保留核心 Run |
| Task/Run 已提交，尚未派发 | 可查询 queued Run；同一存活服务内只派发此身份一次 | 再创建一个 Run 来“补启动” |
| Run 派发后、浏览器动作前后边界不明 | 撤销旧代次、核验进程和环境；未知则隔离 | 仅因尚无 node_succeeded 就重做网页动作 |
| 数据节点提交成功，节点返回丢失 | 用该逻辑写操作身份返回原提交结果和版本 | 以旧版本再写一次，或创建新动作掩盖超时 |
| Run 终态已提交，项目投影尚未更新 | 查询/事件补齐同 runId 的终态 | 以旧 Task 展示状态重新运行 |

Run 开始时间以核心首次实际进入执行为准，资源准备等待不伪装成已执行；失败发生在开始前则保留无开始时间及明确原因。结束时间只由核心接受的终态写入一次。Worker 时间不直接决定终态先后。

## 5. Batch、Run、节点尝试的状态转换

状态键是 proposed 契约名称，不声称与现有 Studio 已一致。展示用中文含义；API 枚举在共同 OpenAPI 中只定义一次。

### 5.1 Batch：管领取、停止与聚合

| 当前状态 | 触发与条件 | 下一状态/动作 |
|---|---|---|
| `accepted` 已接受 | 固定请求已提交，启动预检通过 | `running`；按空闲额度领取 |
| `running` 处理中 | 输入/环境暂占或现场容量满，但仍可能继续 | `blocked`；给出原因与持有者，不把暂占当耗尽 |
| `blocked` 等待资源 | 对应资源释放且门闩仍开放，重新校验通过 | `running`；不需要批次“恢复”按钮 |
| `running/blocked` | 达到总数或真实必要输入耗尽 | `draining`；永久关闭本批新领取，等待已创建任务结束 |
| 任一非终态 | 用户停止/归档/停机接受 | `stopping`；先关闭领取，再取消/结束活动 Run |
| 任一非终态 | 服务重启或运行归属不明 | `reconciling`；不新建任务，核验既有身份/进程/结果 |
| `running/blocked` | 输入结构失效、固定资源不可再满足、不可恢复协调失败 | 关闭领取并 `draining`，记录批次失败原因；已有健康 Run 可正常收尾 |
| `running/blocked` | Task 失败且本批选择“停止新任务” | `draining`，记录 `task_failure_policy`；已有任务收尾，不改任何数据状态 |
| `draining` | 所有已创建 Task 都有权威终态 | 正常数量/耗尽为 `completed`；准备/协调故障或任务失败策略收尾为 `failed` |
| `stopping` | 所有 Run 已终结，旧执行已终止/隔离 | `stopped`；保存停止前已完成的任务结果 |
| `reconciling` | 服务重启后的对账完成 | `interrupted`；本批不自动重新领取；确已提交的终态原样保留 |
| `reconciling` | 仅 Worker 失联，存活 sidecar 已完成核验 | 根据 Task 终态和失败策略转 draining 或恢复原领取阶段；不得重新派发原 Task |

`completed/stopped/failed/interrupted` 是不可逆批次终态。completed 只表示本批处理结束，不等于全部成功；结果摘要分别列成功、失败、超时、取消、中断。零任务的正常耗尽显示“没有匹配任务”，不是 100% 成功。按任务失败策略结束的批次标 failed 并解释原因；若明确选择继续，单 Task 失败不自动宣布整个 Batch 协调失败。

暂占等待由本地释放事件及有限频率补查驱动；来源无效/不可用不能伪装成持续监听任务。固定候选代理全部不可用时，本批停止新领取并显示资源原因；用户修复后显式发起新批次，不能悄悄带入新候选。

Batch 结束不要求所有磁盘清理成功；清理结果是独立事实。未知活跃进程不能因此被当作已结束，归档/删除还要检查第 11 节的资源门槛。

### 5.2 CoreRun 与 Task：执行终态只有一个来源

| 当前状态 | 触发与条件 | 下一状态与责任 |
|---|---|---|
| `queued` | 有效派发代次，资源准备完成并将进入首个节点 | `running`；核心记录 startedAt；此前浏览器准备仍属 queued，由统一 runtime 创建 |
| `queued` | 停止先到且尚未执行 | `cancelled`；核心取消准备请求，释放确定未使用预约 |
| `queued` | 已提交任务的资源启动失败 | `failed`；保留启动错误与准备证据 |
| `running` | 达到 End，未选保留 | 按显式业务结果 `succeeded` 或 `failed`；随后独立清理 |
| `running` | 达到 End，选中保留 | `finishing`；固定 End 请求及关联目标，完成持久化和关联后才能提交终态 |
| `finishing` | 保存与关联全部确认完成 | 按 End 原定业务结果 `succeeded` 或 `failed` |
| `finishing` | 保存/关联明确失败或冲突 | `failed`；保留原定业务结果、已保存上下文及可恢复 End 操作，不能声称保留完成 |
| `running` | 节点请求人工且检查点已建立 | `waiting_manual`；保存上下文，停止自动操作 |
| `waiting_manual` | 继续命令校验通过，等待执行额度 | `resume_queued`；同 Run/Task，记录被接受的检查点版本 |
| `resume_queued` | 获得执行额度，再次校验现场与期限 | `running`；从确认位置继续，不重新初始化 Run |
| `waiting_manual/resume_queued` | 人工结束、期限到达、真实现场关闭 | 人工确认完成为 `succeeded`（标人工裁定）；确认失败/期限/现场丢失为 `failed`，除非停止命令已先胜出 |
| `waiting_manual` | 人工选择“保存并结束”且配置通过 | `finishing`；复用 End 保留规则，不能提前记人工成功 |
| `running/waiting_manual/resume_queued/finishing` | 普通停止或强停请求被接受 | `stopping`；停止接纳后继节点/人工继续，核心协调终止；已提交保存/关联不回滚 |
| `stopping` | 旧执行和现场已确认停止/隔离 | `cancelled`；记录普通/强制/归档/退出原因及已发生效果 |
| `running` | 自动执行预算耗尽，终止得到确认 | `timed_out`；不是用户取消 |
| 任一非终态 | 进程失联、归属不明、终止未确认 | `reconciling`；撤权并隔离，不立即释放排他身份 |
| `reconciling` | 已证实旧执行终止，缺少可接受的正常终态 | `interrupted`；保留外部结果不明标记，不恢复网页动作 |
| `reconciling` | 找到撤权之前已经持久提交的有效终态 | 接受该既有终态；迟到 Worker 自述不算持久提交证据 |

Run 的 `succeeded/failed/cancelled/timed_out/interrupted` 均为不可逆终态。Task 只投影这些状态；项目服务不得独立发出“任务成功”来覆盖核心失败。End 勾选保留时，保存及关联属于节点成功条件，不得提前提交 Run succeeded。异步 Sheets 推送、终态后的文件清理仍分别展示，不改变 Run 已有结果。人工裁定的 succeeded 必须保留原因和裁定来源，不冒充全部节点自动成功。

超时按三种预算分别计：节点动作超时；Run 自动执行预算（含自动重试等待，不含人工等待和恢复排队）；每个人工等待项的保留期限。Run 总耗时指标仍可包含人工时间，不能拿指标口径替代超时预算。资源启动/文件准备另有有限操作超时；用户在运行设置能看见最终适用值。具体默认秒数由本地浏览器基线验证给出，不写未经验证的性能承诺。

### 5.3 NodeAttempt：重试与部分副作用

每次节点访问以 Run、节点、访问序号识别，循环第二次进入同一节点不是上次的“重试”。每次访问的 attempt 从 1 递增。尝试状态为 `running/succeeded/failed/timed_out/cancelled/interrupted/waiting_manual/resolved_manually`；终态不回退，waiting_manual 在人工裁定后留下处置记录。

| 情况 | 处理 |
|---|---|
| 节点已知失败，配置允许且可安全重试 | 旧 attempt 留存，新 attempt 执行；同 Run、输入、变量和资源；退避时间占执行额度 |
| 节点本地写入响应丢失 | 先查询同一逻辑写操作；新 attempt 不意味着再次提交同一写操作 |
| 网页请求可能已提交，无法确认结果 | 不自动重做；进入配置允许的人工检查点，无法建立检查点则按失败/中断并标“外部结果待核实” |
| 前面节点已写字段或业务状态，后面节点失败 | 保留前面已提交变化；结束节点不统一回滚/重写记录 |
| 从人工位置重新执行同一节点 | 清楚提示可能重复的外部动作；创建新的访问/尝试证据，保留此前尝试与人工选择 |
| 人工选择后继节点 | 前一尝试记 `resolved_manually` 及选择依据，不伪造自动执行输出；后继缺少必要输出则不能继续 |

错误边、节点重试和进入人工是核心的显式执行策略；项目协调器不在失败后擅自修改流程分支。外部网站动作没有本地数据库事务的“恰好一次”保证；已知、未知和用户核验结果分别记录。

## 6. 人工处理：同一个任务可继续

人工项在“运行记录 → 等待人工”和“环境 → 等待人工”共用。详情提供等待原因、Run/Task、当前节点、输入摘要、已提交业务变化、现场和截图、实际资源、剩余期限与允许动作。继续按钮是否可用来自后端校验，两个入口不能产生两份待办。

| 人工项状态 | 可接受动作/事件 | 结果 |
|---|---|---|
| `waiting` | 查看现场/截图 | 保持 waiting；查看 UI 不重置期限 |
| `waiting` | 校验继续位置 | 返回允许位置和缺失条件；不产生继续副作用 |
| `waiting` | 提交继续，预期检查点版本仍有效 | `resume_requested`；核心 Run 变 resume_queued，旧页面的重复命令返回同一结果 |
| `resume_requested` | 真正开始继续 | `resolved`，保留目标节点与检查点；本次等待期限停止计时 |
| `waiting/resume_requested` | 有效期限先到、现场先关闭、停止先胜出 | `expired/lost/cancelled`；撤销未开始的继续请求，由核心收尾 |
| `waiting` | 人工完成或失败 | `resolved`；核心提交人工裁定结果，不自动修改数据状态 |
| 终态 | 任意旧继续/终结命令 | 拒绝并返回当前事实；不创建新 Run |

继续必须同时满足：Run 仍等待或接受了本项继续；项目没有停止/归档关门；环境仍由该 Run 独占且页面可用；检查点、Run 执行代次、数据租约有效；目标节点属于本次固定流程且核心可从当前调用栈/循环上下文进入；变量、输入与前置产物满足契约。不能仅凭节点 ID 存在就允许跳入另一子流程或循环内部。

核心按固定控制图返回可继续位置，默认建议当前检查点的合法后继；可选择其他经过验证的位置。缺少上下文时保留等待及现场，显示具体缺项，允许另选或人工结束。人工更改网页不等于已生成某个节点的输出，需要的变量仅能通过核心允许的具名人工输入补入并校验。

等待期限在首次进入时固定，刷新/打开浏览器不延期。本设计不提供无限等待；受控延期若未列入已确认范围就不出现按钮。继续已提交但仍在排队时，期限照常有效；执行前再次检查。TTL、关窗、人工结束和继续争用同一预期检查点版本，只能一个转换成功。

人工等待可以按显式动作保存现场，但应先停止自动控制并由 runtime 验证保存能力。保存需要关闭浏览器时，该动作作为“保存并结束”执行，复用 End 保留的保存加关联契约；不能关闭唯一页面后仍显示可继续。普通“人工完成”只改变 Run 结果，不隐式保存环境或修改业务状态；选择保存并结束时，同样要等完整保留结果后才能报告成功。

## 7. 执行名额、现场数量与占用

每个 Batch 有执行并发 C 与存活现场上限 H，二者为正数；推荐默认 C=1、H=C，用户提高 C 是资源选择，不是系统容量已验证声明。H 的有效设置不得小于当前不能立即清理的存活现场数；下调时先停止新建，不强行关闭现场。

| 场景 | 执行名额 | 现场容量 | 数据/环境身份占用 |
|---|---|---|---|
| 已预约但尚未建立浏览器的 Task | 占一个调度/执行预约，防一次预取整批 | 所需现场预留一个 | 持有，阻止同记录/同环境同时派发 |
| 自动执行、节点重试/退避 | 占用 | 浏览器存在则占用 | 持有 |
| 等待人工 | 释放自动执行名额 | 保留 | 数据、环境身份、具体代理仍保留 |
| 继续排队 | 尚未获得执行名额 | 保留 | 保留；不另建浏览器 |
| 浏览器停止中/未知 | 不发新节点，相关名额/现场预约保持到确认 | 保留 | 撤销写权但保持隔离占用 |
| 浏览器已关闭，End 保留仍在收尾 | 继续占本 Task 执行预约，直到 End 完成/明确失败，避免无界累积保存任务 | 不占活浏览器额度 | 保留数据/环境发布权至收尾完成或明确失败处置 |
| Run 已终结，仅余已知文件清理/保留候选 | 释放执行名额 | 已关闭则不占活浏览器额度 | 文件/保存候选按独立操作持有，不复活 Run |
| 确认回收 | 不占 | 不占 | 释放 |

继续人工任务优先于创建新现场。H=C 时，全部现场等待人工会使新任务停止创建；界面应说明“等待处理现有现场”，不能显示假空闲。多个 Batch 分别有有限上限；runtime 汇总各批次、独立 Studio 及维护会话的真实现场与预约，但不把单批 C 宣称为整机总容量。本版不另加未经需求验证的全局智能调度政策。

记录排他与环境排他不同。两个不同记录可以指向同一个已保存环境，仍必须通过环境身份占用检查。数据占用按数据文档的有效物理身份判断：同 Workspace 的同一 Sheets 工作表及已验证稳定行身份跨项目共用活动排他，本地业务状态与配置仍各项目独立；独立 Excel 导入不因内容相同共用身份。代理可被多个任务配置使用，不因此虚构“独占 IP”；代理组实际分配固定到任务，人工期间不能重新选代理。

DataLease 推荐状态为 `held → released`，失联为 `held → revoked_quarantined → released`。撤权使旧 Worker 不能提交本地写入；quarantined 仍阻止别人领取。恢复协调器确认进程已停止、浏览器已隔离、结果核验标记已保存后，才释放。任务终态、环境清理、数据释放不可相互替代。

## 8. 正确的已保存环境：选择、身份与连续使用

### 8.1 三种方式及推荐

| 方式 | 用户持续使用方式 | 取舍 |
|---|---|---|
| **A：稳定身份，显式更新已保存内容（推荐，proposed）** | 业务记录关联稳定 environmentId；任务用工作副本；显式保存更新该身份下的当前内容 | 连续任务不必改每条记录引用；需要来源代次校验、身份占用和清晰保存冲突 |
| B：每次保留都另存新环境 | End 产生新 environmentId，并在同一用户动作内关联所选记录 | 来源永不覆盖，但会累积环境；新保存结果与旧引用替换仍需明确规则 |
| C：任务直接打开原保存目录 | 自动化直接维护同一目录 | 写入时机难与显式保存区分，取消也可能已改变来源；与默认不自动回写矛盾，不推荐 |

本文以下按 A 设计，并提供显式“另存为新环境”。这不是新增工作流版本系统；environmentId 是稳定业务资源身份，contentGeneration 是当前内容的内部并发标识，没有历史版本列表或回滚入口。

推荐同一 environmentId 在任一时刻只允许一个活动浏览器身份会话：任务工作副本或人工维护。即使复制了两个目录，也不能默认认为它们代表两个独立的网站账号。不同 environmentId 之间不推断相同/不同账号；应用无法靠文件内容证明外部网站身份关系。

### 8.2 自动化怎样选择环境

运行设置将“浏览器配置”与“环境来源”明确分开，来源只能选择以下一种：

| 来源方式 | 配置/读取 | 缺失或冲突时 |
|---|---|---|
| 从配置新建 | 自动化明确 Profile 或继承项目默认；每个任务创建独立临时上下文 | 必要 Profile/内核缺失阻止运行，不使用测试浏览器会话顶替 |
| 使用固定已保存环境 | 从本项目目录严格选择 environmentId；适合单一业务身份反复使用 | 不存在/归档/损坏/被独占时明确阻断或等待，不退回空白环境 |
| 使用输入关联环境 | 明确选择一个具名输入，Task 按固定 RecordRef 读取该行 currentEnvironmentId | 必要关联为空/失效返回该记录的配置问题；不按输入顺序或环境名称猜选源 |

推荐每条记录只有一个 currentEnvironmentId（可空），一个环境可以关联同项目多表、多行；历史关联从 Task/保存事件查，不增加多环境标签系统。它是受校验元数据，不把目录/显示名存进业务字符串。关联使用独立 linkRevision、同项目校验及有效写权，不改业务状态，详见数据规则。只读查询结果中的合法环境引用本身不赋予记录写权；启动选源仍以明确选定的具名输入为准。具名数据输入正常领取均取得排他 lease，不引入“只读输入”这种额外类型。

多个输入分别关联不同环境时，运行设置必须明确选哪个输入作为本次浏览器来源；不按输入顺序猜，不自动把多个已保存上下文混合到一个浏览器。若流程以后明确管理多个浏览器，那是需要单独声明的 runtime 能力，本模块当前一次 Task 一个浏览器环境。

输入关联环境不得让“可选输入为空”悄悄启动全新浏览器。需要该环境才能工作的流程将关联输入设为必需；允许无浏览器分支的流程必须由已校验配置明确声明，不在运行中临时猜兜底资源。

对每组候选输入，环境用例解析环境 ID、当前已提交内容代次/身份包并检查占用。数据与环境预约一起成功才提交 Task；环境暂占不是“数据耗尽”。独立配置来源与记录关联来源不自动串成三层备用选择，启动确认页显示唯一选择策略。

### 8.3 身份和运行资源优先级

| 资源类别 | 从配置新建 | 恢复已保存环境 |
|---|---|---|
| 环境身份 / 持久内容 | 新 instanceId，来源 Profile 的固定 seed | 稳定 environmentId + Task 固定的 contentGeneration，独立 instanceId |
| seed、UA、locale/timezone、视口及会影响身份的启动内容 | 批次固定的 Profile 内容 | 保存来源的身份包；当前 Profile 重置不覆盖它 |
| 内核 edition/version/channel | Profile 解析后固定 | 保存来源记录的内核与受验证兼容性；不可静默升级/降级 |
| 代理 | 启动明确覆盖 → 自动化 → 项目默认 → Profile | 同一显式代理链；没有覆盖时采用保存来源的代理策略引用及当次可用性验证 |
| headless、运行超时、已允许的操作行为参数 | 自动化/运行配置 | 可使用本批操作参数；人工等待必须有可查看现场，不能在等待中才发现 headless 无法接管 |
| License/代理等凭据 | 引用按需读取 | 引用按需读取，不从运行证据取秘密 |

身份包应包含 runtime 实际会使用的身份参数及必要扩展/资产引用；不能把不识别的参数静默丢掉。geoip 或未设置值会影响实际结果时，来源保存应记录实际有效值/明确的动态策略，详情能解释；不承诺外部网站无法观察代理变化。

恢复环境默认保持其身份和内核；“采用当前 Profile”只能是显式维护动作，先检查兼容性和影响，不进入普通任务隐式继承。若用户要新 seed，使用从配置新建或明确另建身份；不能偷偷改已有保存环境 seed 后仍称恢复原身份。

代理组的候选 ID、端点与策略按本批可接受集合固定；Task 分配时复验，实际结果固定到任务/人工现场。新成员及改动端点不进入旧批次；候选失效不降级直连。输入关联环境在 Task 时才知道的默认代理资源，其内容随环境代次一起固定并核验，记录这一来源，不能伪称已在批次选择了具体成员。

### 8.4 连续两次运行的完整路径

1. 用户从 Profile 创建一个受控维护现场，完成登录后点“保存为环境”，形成 `environmentId=env-B` 的首个已提交内容。
2. 首次 End 勾选保留后把相关记录 B 关联 env-B；也允许用户在记录详情显式选择已有环境。下次自动化选择“使用输入 B 的当前环境”。
3. 第一次 Task 取得记录 B，并预约 env-B；读取当前内容代次 g1、身份包和内核，创建独立工作副本 instance-B1。
4. 流程更新网页会话。End 勾选“保留当前环境”后，按推荐默认更新当前来源，并在同一个 End 操作内确认 B 的当前环境关联；失败/取消不会凭空补一个未到达的 End。
5. 核心停止自动控制，runtime 完成必要刷新并关闭该工作副本的浏览器，环境用例核验它确已静止；生成完整候选并检查来源仍为 g1、保存权有效。
6. 候选完整落盘并可识别后，短事务将 env-B 当前内容改为 g2；随后按本次固定关联目标校验并提交记录关联组。B 已指向 env-B 时保留相同稳定引用并确认有效，不无故推进其关联修订。只有两个阶段均确认，End 才成功。
7. 第二次 Task 在取得使用权后读取 env-B 的 g2，而不是旧工作副本或 Profile 测试现场；能观察第一次已保存的站点状态。

运行详情分别显示网页步骤、环境持久化、关联及 End 完整结果。更新来源与另存都由 End 内部完成关联，不要求额外 Bind 节点。关联失败不删除已保存环境，显示“保留环境未完成：上下文已保存，记录关联失败”，并提供恢复同一操作的入口。

### 8.5 End 的一个完整保留动作（用户规则 confirmed；具体默认 proposed）

| End 配置 | 推荐默认和规则 |
|---|---|
| 是否保留当前环境 | 默认不勾选；勾选即承诺保存可恢复登录上下文并关联已选相关记录，不另要求 Bind 节点 |
| 保存方式 | 来自已保存环境则更新来源；本次从 Profile 新建则保存为新环境。用户可显式选择另存新环境；不会更新未选中的其他来源 |
| 相关记录 | 可编辑初值为本任务具有写权的输入记录；同记录别名去重。配置可排除共享人员资料，并选择本 Task 新增记录或显式写节点返回且仍持有效 lease 的记录；不根据表名/创建时间猜认，不把纯查询结果自动升级 |
| 多行/多表 | 目标是实际 RecordRef 集合，可来自多表及本 Task 新增记录；每行只写 currentEnvironmentId，不改字段值/业务状态。关联组在一个短事务里全成或全冲突 |
| 已有引用 | 空值可设为本次环境；已是同环境为幂等确认；不同环境默认冲突。需在 End 配置明确允许替换相关记录既有环境，替换仍校验每条预期 linkRevision |
| 零输入/零目标 | 参数型且没有相关记录时，仅完成环境保存；配置页清楚显示“不关联记录”。有输入时不能把无写权限或运行时目标缺失默默当作零目标；预期存在的目标不存在即失败 |
| 名称 | 新环境提供可编辑命名模板，默认取自动化名与任务显示编号以便识别；名称不是身份，同名不被用作更新目标 |

End 的“默认全部输入”只是配置初值，不是不能修改的业务语义；纯查询所得参考结果不进入默认关联集，也不能在收尾时偷偷升级为写权限。共享人员若作为具名输入被领取，用户可以从 End 目标排除；若只需查阅，可用查询节点取得参考资料。配置对引用来源、实际输入、新增/已写记录输出及替换策略做预检。运行中把应关联的行删除后又到达 End，必须报告目标不存在；不能换成同名新行。原始 Task 输入中的关联证据保持不变，当前记录的 linkRevision 独立推进。

到达 End 时固定一项 `endOperationId`：Run/节点访问身份、是否保留、原定业务结果、保存目标及预期来源代次、去重后的关联 RecordRef 集合、各行预期 linkRevision、替换授权和任务写权。预期版本来自本 Task 已确认值；不能收尾时自动吸收人工的新关联以绕过冲突。此后编辑工作流不改已经接受的 End 请求。

内部执行顺序为：预检关联目标与写权 → 停止自动控制并关闭到一致状态 → 持久化并发布可恢复环境 → 校验并原子提交关联组 → 核验 End 完整结果 → 提交核心终态 → 释放占用/清理。第一步减少无谓保存，最后的再次校验仍不可省略；不把文件保存包进数据库长事务。来源身份占用保持到保存及关联完成或明确失败处置，防止下一 Task 在本次保留结果未明时提前复用。

保存已成功但关联失败时，Run 以 End 失败终结，记录原定业务结果及已保存环境 ID/代次。End 操作留下 `saved_unlinked` 及完整目标清单，用户可以打开“处理保留结果”：核对冲突的当前引用/缺失行，明确选择保留现有引用、重新授权替换或调整仍存在的目标，再以一个关联修复子操作完成。修复需要新的有效写权与用户确认的版本，不能拿失效租约继续写；它关联原 End，**只恢复关联，不重跑网页、不重复保存环境、不把历史失败 Run 改成功**。用户放弃关联则标为部分保留已接受，保留历史失败事实和已保存环境。

正常 API 超时或重连查询的是同一 endOperationId；已完成的保存/关联阶段不重做。若未知，应先核验是否已经提交，不能提前提示失败让用户另保存一次。未完整确认前展示“正在保留”；明确部分失败展示“上下文已保存，关联未完成”，不弹“保留成功”。关联组失败不清理唯一可恢复上下文，也不自动覆盖新引用。

## 9. 环境生命周期、保存竞争与安全回收

### 9.1 工作副本与持久来源的状态

| 对象/当前状态 | 事件 | 下一状态/限制 |
|---|---|---|
| Instance `reserved` | queued Run/维护预约获得执行许可 | `starting`；开始复制已提交来源或新建上下文 |
| Instance `starting` | 浏览器和目录所有权验证成功 | `active`；向核心交付受控会话句柄 |
| Instance `starting/active` | 启动失败、停止、关闭或已决定终结 | `closing`；确认后 `closed`；异常失联则 `unknown` |
| Instance `active` | 核心人工检查点成立 | `waiting_manual`；同一会话不被自动流程继续操作 |
| Instance `waiting_manual` | 有效继续开始 | `active`；保存同一页面/代理/输入上下文 |
| Instance `closed` | 无显式保存意图 | `cleaning → cleaned`；失败为 `cleanup_failed` |
| Instance `closed` | 有有效显式保存意图 | `saving`；失败/冲突保留 `retained_unsaved` 候选，成功后清理工作副本 |
| Instance `unknown` | 仅允许核验/受控终止 | 确认关闭后转 closed；未知时禁止复制、发布或删除猜测目录 |
| Persistent `ready` | 获得任务/维护身份占用 | 来源内容保持 ready，只增加独占使用事实；读者不能打开原目录 |
| Persistent `ready` | 显式保存成功 | 原子切换当前内容代次；rename 不改内容代次，保存不重置用户名称/备注 |
| Persistent `ready` | 当前平台不兼容、内容缺失/损坏 | `unavailable` 并说明原因；保留引用、记录与修复入口 |
| Persistent `ready/unavailable` | 删除影响通过、无活动/未决依赖 | `deleting → deleted`；清理失败保持删除操作可见，不能报告已经删除 |

保存内容以 provider 已声明且平台测试覆盖的持久浏览器上下文为范围。它不是“暂停整个进程后以后从原指令继续”：未持久的页面 JS、调用栈和正在进行的网络请求不属于保存环境。人工继续依赖仍活着的检查点；保存恢复依赖已提交持久内容，两者不能互相冒充。

浏览器必须通过 CloakBrowser 适配层关闭到一致状态后再发布保存；不能边复制活跃目录边宣称完整。文件路径由 workspace 路径服务生成，记录目录的归属与代次；业务层不拼 macOS/Windows 路径。实际支持的 cookies、站点存储和上下文范围须在 Windows/macOS 各自验证并展示限制；未验证的平台不宣布已支持。

### 9.2 保存操作及冲突

保存请求包含操作身份、来源 instanceId、模式、目标 environmentId（更新时）、预期 contentGeneration、来源使用代次及命名信息（另存时）。End 的调用还关联完整 endOperationId 和固定记录目标。所有目标都校验同项目和有效使用权。用户手工保存已关闭保留副本，也走同一保存用例；普通环境维护没有业务记录目标，不冒充 End 已完成。

保存分为：请求已接受 → 等待现场静止 → 准备完整候选 → 提交当前内容指针 → 核验提交结果 → 清理旧副本。候选文件准备和数据库提交不能构成长数据库事务。发布前的候选不是可恢复来源；提交响应丢失先查询同一操作，不能另存一个重复环境。

| 竞争/故障 | 唯一规则与用户可行动结果 |
|---|---|
| 两次相同保存请求 | 返回同一操作/环境/代次 |
| 预期 g1，来源已更新到 g2 | 拒绝覆盖；保留关闭候选，可另存新环境或明确放弃；不自动改预期版本重试 |
| 名称/备注被编辑 | 使用独立元数据修订保护；保存内容不得把旧名称/备注覆盖回来 |
| Task 工作副本使用中，人工要求维护来源 | 返回占用者；等待当前使用释放，不同时打开原来源 |
| 候选文件已完整，数据库提交前崩溃 | 由保存操作定位候选；核验原版本和归属后可继续同一提交，不重跑网页 |
| 数据库提交成功、返回/旧目录清理丢失 | 当前指针已明确为新内容；返回成功结果，旧文件清理另记，不把新内容判失败后再覆盖 |
| 磁盘不足/关闭失败/来源不兼容 | 不改变当前已保存内容；现场仍活则保留占用，已关闭则保留候选，显示恢复/另存/放弃入口 |
| End 原定业务结果成功、保存或关联失败 | CoreRun failed，原定业务结果与已发生网页事实另存；下一 Task 不得误称读到未提交状态或未完成关联 |

保留未保存工作副本是为了恢复明确失败的保存动作，不是无限历史备份。关闭且归属已知的 retained_unsaved 不占浏览器现场额度；它仍是可见待处理资产，阻止被依赖目标的破坏性删除。用户明确放弃后才清理，不能为了腾出执行名额自动丢弃。

推荐严格环境身份独占下仍需要 CAS：旧 Task 的保存曾失败并留下关闭候选，后续 Task 已保存新内容；用户稍后重试旧候选时必须冲突，不能覆盖更新。这个场景并不要求允许两个同身份浏览器同时运行。

End 保留在 finishing 阶段完成，是已经接受的结束节点操作；不能提前把 Run 记成功。强停不新增保存意图，也不保证未完成的保留动作会自动完成；停止后核验已提交阶段，保留已保存结果及未关联目标。源进程未确认静止时不能发布保存；已提交的保存/关联结果不能被后来强停撤回。

### 9.3 维护与删除

“打开维护”先预约稳定环境身份，创建独立维护副本。用户关闭时选择“保存修改/放弃修改/继续维护”；明确保存才更新来源。维护窗口意外退出不自动发布；可恢复的关闭副本作为待处理保存项出现。仅预览详情不获取浏览器身份占用。

持久环境删除先列当前自动化固定选择、记录关联、活动使用、维护、待决保存、未确认清理。活动/未知/待发布依赖阻止删除；静态引用需显式解除或按受控影响操作处理，不能让其他页面绕过检查。仅历史 Task 引用不永久阻止删除：历史保留环境身份与当次资源摘要，显示“来源已删除”，不需要保留可重新运行的浏览器目录。

临时实例清理只处理本次归属资源。确认失败允许重试同一清理操作；归属未知只允许核验，不能按目录名/旧 PID 杀进程。清理成功不会覆盖 Run 失败，清理失败也不把 Run 成功变成运行失败。

## 10. 取消、强停、失联与事件

普通停止先关闭 Batch 领取，再向每个非终态 Run 发送幂等取消。核心停止启动下一个节点，当前可取消动作尽快终止，不能取消的动作按其有限超时到安全点后结束；不能将“停止”解释为继续跑完整流程。等待人工和 resume_queued 也会取消，不等 TTL。仍在运行时保持 stopping，并显示能强停的对象与影响。

强停先撤销旧执行的本地写入代次，然后由 runtime 终止它拥有的浏览器/Worker；确认终止或隔离后，核心提交取消/中断结果并释放排他身份。撤权不能撤销网站已经收到的动作。无法确认时保持 reconciling 和“外部结果待核实”，不要把按钮点击成功显示成全部资源已清理。

运行事件最少携带 runId、单 Run sequence、事件身份、执行代次、节点访问/attempt 身份及提交时间。序号由核心持久提交分配；撤权后的 Worker 进度不生成新的有效事件，可保存为诊断。消费者按身份/序号去重，断线补查权威快照及其序号；事件流只通知变化，不能只靠内存日志重建状态。

事件早于项目页面订阅、重复投递、乱序和终态后迟到均不改变结果。终态只接受一次。用户核验网站结果可以追加核验说明和显式数据修正，不把历史 interrupted Run 改写成从未中断，也不自动创建“重试任务”。

## 11. 重连、重启、归档与应用停机

| 情况 | 处置 |
|---|---|
| 仅 Manager/Studio 窗口关闭或连接中断 | backend Run 继续；重开查询同一事实，恢复视图，不创建 Run、不延期人工项 |
| Worker 失联，sidecar 尚活 | 撤权并隔离该 Run 的记录/环境，包含动态取得的 lease；其他不共享资源的 Run 可继续。原 Task 不重派；核验终结并释放后，按失败后停/继续策略及当前条件领取，包括仍匹配的原记录 |
| sidecar/应用重启 | 先关闭历史批次领取，恢复操作账本，核验 Worker、环境目录与提交结果；未派发 queued Run 可确认取消，已派发无可靠终态则 interrupted；不自动继续旧批次/旧网页流程 |
| 显式保存/本地同步操作重启恢复 | 核对持久操作身份与外部/文件事实，可恢复同一保存/同步操作；不借恢复再次执行网页动作 |
| 项目归档请求 | 建立禁止新批次/领取的 closing 门闩；停止活动 Run、等待明确保存及已发/未知同步核验；内部收尾仍可写，不因提前只读而卡死结算 |
| 项目归档完成 | 无活动 Run/浏览器、无归属未知、无待决保存、无未知在途同步；未发送同步变化保留且不再自动发送。已关闭且归属明确的清理失败可保留警示及受控清理入口 |
| 项目恢复 | 恢复配置/数据操作资格；不自动重跑旧 Batch、不自动发送旧队列 |
| 永久删除 | 在归档基础上重新查归属/引用；未确认清理、占用、待决保存/写入阻断；按可恢复删除操作处理本项目数据和文件，不触碰全局资源或来源 Excel/Sheets |
| 切换 Workspace / 退出应用 | 复用现有停机协调：禁止新增、核对运行/维护/保存/同步、停止并确认，再切数据根/停服务；失败保持当前工作区和可核验事实 |

本地数据门闩要区分用户新写与受控收尾：closing 后拒绝新增批次、领取、新维护和无关编辑，允许持既有有效身份的取消确认、明确保存、必要数据结算、同步核验与清理。归档后的普通编辑禁用，必要生命周期处置由专门命令完成。

重启时 End 已部分提交也按操作账本核验：若 Run 已被权威终结为 interrupted/failed，后续只修复同一保留操作，不将 Run 重新置 finishing 或成功。独立管理保存和历史失败后的关联修复可以继续各自操作；它们不再消耗原 Task 的执行名额，也不得复用原 Task 已失效的写权。

Task 释放记录前，应完成其已提交本地写命令的对账；End 保留须在关联组完成或明确失败处置后释放相应写权及环境身份占用。即使既有记录已经指向同环境，也要确认 End 的保存与关联结果，不因无需更改 ID 就提前释放。失败保存留下的关闭候选可在明确处置后不再占用活跃身份；以后恢复操作必须重新取得合法占用和版本。客户端不能自行推断“浏览器关了，所以记录能删”。

当前设置 QuiesceGate 已有占用检查和暂停变更接口，但尚未包含这些新实体；必须注册真实运行、维护、保存、清理、同步 blocker。不能仅在新页面禁用切换按钮而让另一窗口绕过。

## 12. 双方所需完整契约

以下是要纳入统一 OpenAPI/应用契约的语义与身份，不是新增一套兼容协议或实现代码。HTTP 路由由完整契约文档统一映射；名称只保留一份，项目服务通过核心端口调用，不经自己的 HTTP 回调绕回项目。

| 编号 / 能力 | 请求必须表达 | 结果与不变量 | 责任 |
|---|---|---|---|
| XE-C01 工作流保存/读取/校验 | workflowId、编辑修订或条件保存身份、文档内容；校验所需输入/能力 | 当前文档、校验问题、输入/输出契约、需用能力；项目关联与独立 Studio 同一文档 | Studio/core |
| XE-C02 准备不可变执行内容 | 当前文档身份、子流程/资产依赖、入口、能力集 | 本次可执行内容与摘要；编辑不能改已准备内容；缺能力解释阻断 | Studio/core |
| XE-C03 startBatch / queryStart | 项目/自动化、预期管理修订、明确覆盖、操作身份 | 同身份同 Batch；校验失败无虚假 Task；提供权威状态与问题 | 项目 |
| XE-C04 prepareInputGroup / commitInputGroup | 固定输入计划、Batch/Task 身份、额度、预期版本；环境预约需求 | 完整固定输入、按数据文档物理身份合并的占用及独立权限，和 Task/queued Run 同事务；没有批内消费集合 | 项目数据 + 协调 |
| XE-C05 prepareRun / dispatchRun / queryRun | 稳定 runRequestId、确定内容、独立参数/输入、资源描述、能力绑定；有效派发代次 | 相同身份唯一 runId；queued 可查询；实际派发前检查取消/撤权 | core |
| XE-C06 cancelRun / forceStop / queryOperation | runId 或 Batch、操作身份、预期执行/操作版本、原因 | 命令接受不等于资源已停止；可查询至取消/核验结果，终态不可覆盖 | core + runtime；Batch 扇出由项目 |
| XE-C07 RunSnapshot / RunEvents / artifacts | runId、已见 sequence、分页/产物身份 | 权威状态、序号、attempt、输出、日志/截图；断线不重跑、不重复追加 | core |
| XE-C08 readProjectRecord / queryProjectRecords | 声明允许的具名输入/同项目表、稳定 RecordRef 或筛选分页、读取目的 | 当次完整只读快照、来源与版本；没有隐含写权、没有任意跨项目读取 | 项目数据能力端口 |
| XE-C09 项目表/字段/记录/状态操作 | 显式创建/查询/修改/删除动作、作用域、对象稳定身份/预期版本；包括 writeRecordFields / setRecordStatus 及新增字段 | 查询所得记录写入前非阻塞取得动态lease并CAS；通过结构/引用影响规则；同事务记录变化及同步意图；返回身份/新版本和本Task写权，供End显式选择 | 项目数据能力端口；初始/动态lease统一收尾 |

| XE-C11 resolveEnvironment / reserveEnvironment / openInstance | 来源策略、实际环境引用、内容代次/身份包、预期资源版本、Run/维护归属 | 唯一身份预约、实际资源与受控句柄；暂占与不存在/不兼容分开 | 环境 + runtime |
| XE-C12 checkpoint / validateResume / resumeRun | runId、检查点版本、目标节点、受校验人工输入、操作身份/代次 | 可继续位置/缺项；同 Run 原上下文；期限/停止竞争只能一方成功 | core；人工期限由项目协调 |
| XE-C13 finishManual / expireManual | 人工项/runId、预期检查点、成功/失败/到期/现场丢失、原因与操作身份；明确保留时携 End 保留选项 | core 权威终态，业务状态不自动改变；保存并结束复用 C18，不能提前成功 | 项目命令 → core |
| XE-C14 saveEnvironment / querySave / discardCandidate | 工作副本、更新/另存模式、预期来源代次/使用代次、操作身份 | 提交后的环境 ID/代次或可处置候选；响应不明先查询，不默认重写 | 环境 |
| XE-C15 maintenance / environment CRUD / impact | 稳定环境身份、元数据修订、动作和操作身份 | 独占维护、条件保存、真实引用/占用影响、可恢复删除 | 环境 |
| XE-C16 reconcileRun / reconcileInstance / releaseInputGroup | 原 Run/实例/租约身份、当前代次、进程/提交核验证据 | 旧执行终止/隔离后释放；归属不明保留占用；不重新执行网页 | core + runtime + 数据 |
| XE-C17 projectClosing / workspaceQuiesce | 范围、停止身份、当前阻断与操作账本 | 新工作禁入、已有受控收尾可完成；可查询 blocker 和失败恢复 | 项目生命周期 + 现有设置协调 |
| XE-C18 finalizeEnd / queryEnd / repairEndAssociation | End 保留选项、原定业务结果、固定保存/关联目标、预期版本、替换授权、endOperationId；修复操作的新授权 | 保存加关联才完整成功；阶段幂等；saved_unlinked 保留上下文/目标；修复不重跑/不改历史 Run | core 发起，项目环境/数据协调返回完整结果 |

项目数据节点接收已注入能力，不读项目数据库、不 import Manager。独立 Studio 可以使用通用变量、网页、输出与日志，无 Project 即可运行；只有声明需要项目数据/保存环境/项目人工协调的节点在未绑定能力时明确不可运行。项目文档可在缺资源时编辑，真实运行前必须完整校验。数据/环境节点与已有 WebRPA 同名节点有行为差异时须明确记录，不随意冒充已迁移能力。

## 14. 固定验收样例

以下均是将来实现的固定场景，不是本轮测试结果。站点用仓库受控本地 fixture，环境保存测试应覆盖 provider 声明支持的持久存储；不对真实账号发起副作用。每次记录应用/内核版本、OS/架构、样例文档、Task/Run/Operation、输入/环境代次及最终观察结果。

| ID | 给定与动作 | 唯一预期结果 |
|---|---|---|
| XE-A01 参数无数据 | 无数据输入；参数 message=first；数量 1；网页显示该值后读取 | 一个 Batch/Task/Run，无 DataLease；输入参数固定；资源回收；无表不算错误 |
