## 本轮修复的实际问题

1. **默认目录**：原配置初始化提交 `folder: ''` 表示默认目录；Mock 最初错误清空目录，导致无法保存。现按源语义解释，已增加测试。
2. **历史**：原 Store 只记录操作前状态，撤销可能跳过最近一次编辑；撤销前补当前快照供重做，导入重新建立历史基线。
3. **请求竞态**：保存快照比对不使用每次变化的导出时间；新修改不会被旧保存响应标为已保存。运行前更新失败中止启动，停止失败不假装结束。
4. **事件恢复**：去掉源断线重连直接标记完成逻辑；按 SSE 序号续读和去重，停止后不继续生成节点事件。模拟节点失败不先产生成功事件。
5. **协议兼容**：保留 `webrpa-encrypted-workflow` 和跨窗口节点剪贴板标识；不把品牌替换误用于文件协议。
6. **多预览存储**：旧 renderer 的内存副本可能覆盖另一页面刚保存的文件；每次请求进入文档处理前读取最新本地存储，新增跨实例回归。
7. **宿主退出**：先处理 Studio 的未保存确认，再停止 sidecar；用户取消时不会先关闭服务。

## Mock API 与状态边界

- 工作流、虚拟本地文件、自定义模块、浏览器/拾取/录制、Debug、资产、配置、助手会话/流式回复、整包与源事件反向命令均经过 `api/transport.ts`。无页面私设全局 fetch 替身。
- 同名文件按虚拟目录区分；测试包含保存失败、非法 JSON、未知路由、外部 URL 阻止、重复命令/冲突、SSE 断线间隔事件补读、录制尾部、快照与单运行占用。
- 反向事件采用稳定 commandId 的 HTTP 请求，重复相同命令返回原响应，改内容返回 409。HTTP 接受和节点终态分开；组件按事件确认投影。
- Mock 录制沿原前端轮询消费协议；它没有提供 M6 真实采集可靠性、持久确认或崩溃恢复保证。
- 未覆盖的原生文件/截图/坐标工具、远程数据库/机器人连接探测、实际媒体转换、安装器等请求明确返回 501/拒绝结果。前端表单源码保留，不伪造这些外部系统已工作。
- Mock 单资产上限 2 MiB，localStorage 容量错误明确失败；事件和运行只在页面内存中保存，刷新后不承诺恢复活动运行或全部日志。尚无跨窗口/跨工作区真实资源锁。
- 源文件的宽类型保留在清单限定范围，新增适配层严格检查；下一阶段逐接口用生成类型替换。真实工作区、Profile、凭据权限、持久事件、清理和平台对照仍是正式迁入门槛。

## 本地复测

1. `npm --workspace @autoflow/desktop run studio:preview`，打开 `http://127.0.0.1:5175/studio.html`。正式应用用 `npm run dev` 后从总览进入。
2. 从原动作库拖入节点、配置、连线，保存并用“打开”恢复。数据只在当前浏览器 Mock 命名空间。
3. 打开“自动化浏览器”，进入“录制 → 网页智能录制”；点击顶部“Mock 测试页”产生导航、输入和点击，再停止/生成。
4. 在节点上设置断点并运行，验证单步/继续/停止。顶部“接口场景”可注入断流、离线、恢复、保存失败、节点失败和拾取结果。
5. JSON/加密导出为源前端实际文件操作；后端脚本导出返回显式 Mock 文件，不应当作可运行自动化脚本。

**本轮交付的是可以编辑和联调的源码前端基线。它不是 R0–R8 全部完成，也不以 474 项检查替代原版全功能逐项验收。**
