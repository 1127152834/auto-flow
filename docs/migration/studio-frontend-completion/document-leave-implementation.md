# F5 文档替换保护切片

日期：2026-09-13；状态：本切片实现并验证（非 F5 全部完成）；依据已授权 F5。

本切片覆盖新建（按钮/快捷键/AI 入口）和打开本地流程：未保存文档统一选择保存后继续、放弃修改、取消。保存须确认成功且当前内容仍与保存快照一致；失败、覆盖取消或等待期间又有修改均保留草稿。重复操作不得令同一次确认放行多个文档替换。

打开列表：加载失败不触碰画布；加载过程中草稿变化、列表关闭、组件卸载使响应失效。选中文件实际加载成功后再处理离开选择。

新增确认组件复用现有 UI 样式，并登记 AI 弹窗动作。此切片不宣称导入资源事务、运行/录制/拾取清理、宿主退出和工作区切换已完成，这些继续按 F5 独立接入同一保护。

验收：新建的保存/放弃/取消；保存失败/覆盖取消/保存中编辑；打开的取消/成功/无效数据/迟到响应；全量前端和工程检查；实际 UI 验证。


## 2026-09-14 实测

真实界面先发现仅改名称不标记脏状态的遗漏，已修复 Store 名称更新路径。组件测试明确覆盖未失焦时的名称修改。

- 新建按钮/快捷键/AI UI 事件取消均保留变量；保存后新建先持久化，放弃不保存。
- 保存失败、覆盖取消、保存中修改、确认期间修改均不离开；重复请求不会共用一次确认放行两次。
- 打开成功/取消/404；关闭列表、卸载、加载期间编辑时，迟到响应不替换文档。
- 定向 23 项（含 i18n 3 项）通过；完整前端 99 文件 / 1,160 项通过；TypeScript、ESLint、renderer/main/preload 构建通过。
- 实际 UI：仅改名称为“F5 保存后新建验收”，新建出现三选项；取消后原名称及未保存标记保持；再次保存后继续，显示新空文档，打开列表出现新保存文件。另一个名为“F5 打开时保留的草稿”的未保存文档，打开目标后取消保留原名；再次打开并放弃后才显示已保存目标名。
- 以上用例使用独立 localhost 浏览器 Mock 数据；不是原生 Electron 离开/真实执行的证据。

证据：`evidence/f5-document-leave.txt`，对应 tests/toolbar-draft-protection.test.tsx 与 local-workflow-protection.test.tsx。
