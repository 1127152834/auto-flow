# F3 独立运行身份与日志历史

日期：2026-09-14。状态：本切片已实现并验证；F3 其余诊断能力及 F0–F6 整体仍按台账推进。

## 已实现合同

- 一次执行使用稳定 `runId`，与 `workflowId`、编辑文档 `documentId` 分离。同一个 `runId` 和相同请求幂等返回；同标识不同请求返回 409；同一流程重复运行生成两条独立记录。
- `GET /api/workflow-runs` 分页返回运行摘要。`GET /api/workflow-runs/{runId}/logs` 在服务端执行关键词、级别和节点筛选，按尾部游标读取，返回页内部保持时间顺序。
- `GET /api/workflow-runs/{runId}/logs/export` 导出当前筛选范围的完整 JSONL，不能把前端保留的 100–500 条日志冒充完整导出。
- 运行和日志响应经过生成 OpenAPI 类型及运行时身份、序号、级别、分页边界检查；连接修订变化或迟到的其他运行响应不会覆盖当前选择。
- Studio 日志栏提供最近运行选择、刷新后自动恢复最近一条、节点/级别/关键词筛选、向前分页和完整导出。实时 Store 继续保持有界渲染，持久历史由服务负责。
- `execution:log`、节点、暂停、恢复、数据和终态事件携带 `runId`；同一 `workflowId` 的旧轮次事件不会污染新轮次。

## 证据与边界

专项测试、后端合同、工程检查和全量回归输出保存在 `evidence/f3-execution-log-history/`。第一次全量发现 3 个旧断言未包含新增 `runId`，修正为同时校验运行标识后通过专项。第二次默认并发运行只有无关的 DataTableFormDialog 发生 5 个字符输入损坏/超时，单文件 17/17 通过；限制为 4 个 worker 后全量 284 文件、3,380 项通过。为使仓库标准测试稳定复现，Vitest 配置固定 `maxWorkers: 4`，没有延长用例超时或放宽失败断言。浏览器 UI 使用 localhost Studio 与持久 Mock 服务消费合同，未调用 Store 或页面内部函数。

内置浏览器能实际触发下载按钮，但其下载事件监听没有收到 Blob 下载事件；完整 10,000 行文件由内存/真实 HTTP 双传输测试和组件 Blob 测试确认。该限制如实保留，不能写成正式 Electron 下载通过。真实自动化后端、正式 Electron 宿主、打包应用及跨平台实机仍不由本切片证明。
