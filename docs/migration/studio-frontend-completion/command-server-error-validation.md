# F1 命令5xx与错误回执身份恢复

2026-09-14。服务/网关可能在命令已经应用后返回500/502/503。原客户端直接把所有非2xx当作明确拒绝，会误导调用方重试。现在服务错误先查询原commandId，不再次提交；查到记录按原结果返回，查不到或查询异常保持unconfirmed。

非2xx携带另一commandId，或同时声称success:true，也按矛盾回执处理并查询原ID。正常明确4xx拒绝的既有包络不变，不额外查询。共用已有命令查询与身份验证，没有新增调度器。

新增14项：memory/http分别验证500/502/503已应用和无记录，共12；错误身份409、矛盾成功409各1。初始13项全失败；修复后追加矛盾包络并通过。与既有命令、SSE和输入HTTP共6文件38项通过，类型/lint通过。

第一次相关回归发现我给明确拒绝结果多加了httpStatus，破坏原有精确断言；已撤掉不必要字段，保留原测试和回执结构，不放宽断言。

这些测试只证明前端命令合同恢复，不证明真实自动化动作或服务崩溃后的执行结果。尚未确认的请求不能自动重发；后台动作及更完整命令状态仍依各操作合同实现。
