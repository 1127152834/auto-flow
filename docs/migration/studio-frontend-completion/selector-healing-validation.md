# 选择器修复建议写回保护

启动前显式登记服务端workflowId到编辑器documentId的映射，ID不能直接等同。运行完成事件保留来源workflowId和已登记documentId；编辑器只接收当前文档、且每个字段仍等于oldSelector的建议。用户确认期间再次检查文档、字段、节点和组件有效性，后一个请求使前一个失效。任一字段变化则整批不写回，保留原草稿；有效批次通过updateNodesData一次写入、一次撤销。对话文案明确写入草稿后仍需手动保存。

新增11项规则/真实Store测试：整批写入撤销重做、换文档同节点ID、字段修改、删除、卸载、拒绝、外来文档、缺旧值、已修改字段、危险键、重复建议。另2项内存/真实本地HTTP-SSE验证来源身份未丢。定向39+2项通过；补充启动归属验证后与启动边界合计21项通过，类型/lint/构建/21脚本通过。测试首次失败为新模块未创建；实现后1项测试误用了不存在的isDirty，改用正式hasUnsavedChanges保持取消不改脏状态断言，未删除用例。

证据：evidence/f4-selector-healing。本批没有声称实际执行选择器自动修复或正式ElectronE2E。来源文档身份保护不等同runId：同一文档多次运行的独立身份仍须合同批次补齐。没有登记来源文档（包括完整刷新后）的建议不写回；缺少oldSelector的旧服务建议不再写入，避免无法验证来源值时覆盖草稿。

复核启动代码发现初版误将服务端ID等同编辑器ID，会拒绝有效结果；已改为启动前映射，并测试创建请求等待期间换文档仍绑定原文档。普通重新连接保留映射，整页刷新无法恢复此内存映射，属于待补运行历史合同。
