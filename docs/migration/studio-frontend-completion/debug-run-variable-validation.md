# F3 调试运行身份与暂停变量修改

日期：2026-09-14。状态：本切片已实现并完成专项验证；F3 其余诊断能力和 F0–F6 整体继续按总台账推进。

## 已实现合同

- 暂停上下文固定包含 `runId + pauseId + controlRevision`。相同工作流的旧轮次事件或命令不能控制当前运行。
- 继续、单步和暂停变量修改都使用稳定 `commandId`。同标识同内容返回原结果，同标识不同内容返回 409；响应丢失后只查询原命令，不重复提交。
- 一次变量提交包含 1–200 个变更，作为一个原子命令。变量名遵循工作流标识符规则；值只能是有限数字、字符串、布尔、列表、对象或 null；请求上限为 1 MiB。
- 成功 HTTP 回执不直接改写界面暂停快照。只有携带更高控制修订号的 `execution:paused` 事件确认新值后，界面才释放控制锁。
- 显式服务拒绝允许用户修正后重试；网络结果未知时禁止再次提交变量或单步，停止仍然可用。
- 暂停变量显示最近来源。循环局部变量由事件元数据标为只读，界面不会把它们纳入修改命令；旧服务不提供元数据时按可写流程变量兼容。
- 变量修改记录进入现有变量追踪合同，区分创建与更新。本切片 Mock 仅验证服务消费协议，没有执行真实浏览器或真实后端变量修改。

## 用例

| ID | 前置与操作 | 预期与断言 | 层级 |
|---|---|---|---|
| F3.DEBUG-ID.001 | 当前工作流收到旧 `runId` 的暂停或控制命令 | 事件忽略；命令 409；当前运行不变化 | Store、内存及实际 HTTP |
| F3.DEBUG-ID.002 | 相同暂停、相同命令并发提交两次 | 只推进一次并返回相同回执 | 内存及实际 HTTP |
| F3.DEBUG-ID.003 | 命令响应丢失或服务返回 500 | 使用原 `commandId` 查询，不再次 POST | API 与实际 HTTP |
| F3.DEBUG-VAR.001 | 在暂停中同时修改已有变量并新增变量 | 一个命令全部应用，控制修订号递增，事件返回完整新快照 | 内存及实际 HTTP |
| F3.DEBUG-VAR.002 | 重放已确认的变量命令 | 返回原回执；追踪记录不重复 | 内存及实际 HTTP |
| F3.DEBUG-VAR.003 | 重用命令 ID 但改变值 | 409；运行变量保留首次结果 | 内存及实际 HTTP |
| F3.DEBUG-VAR.004 | 空变更、重复名、非法名、非有限数字、非 JSON 值、超过 1 MiB | 422 或前端拒绝；不截断、不修改运行 | 契约 |
| F3.DEBUG-VAR.005 | 输入非法 JSON 后提交 | 本地显示错误，服务未收到请求，单步和停止可用 | 组件 |
| F3.DEBUG-VAR.006 | 服务明确拒绝后修正；未知结果后再次点击 | 明确拒绝解锁；未知结果保持锁定，停止可用 | 组件 |
| F3.DEBUG-VAR.007 | 暂停快照含循环局部变量 | 显示只读及来源；提交批次只含流程变量 | 组件 |
| F3.DEBUG-VAR.008 | 通过实际本地 HTTP 页面编辑变量，分别保留/丢弃首次响应 | POST 恰好一次；丢响应时查询一次；新暂停事件显示值和来源 | 组件 + 实际 HTTP/SSE |
| F3.DEBUG-VAR.UI.001 | 页面导入单节点流程，键盘设置断点，运行后编辑变量并单步 | 暂停命中；值从 1 变为 7；来源更新；调试完成；历史终态刷新 | 浏览器 UI + Mock |
