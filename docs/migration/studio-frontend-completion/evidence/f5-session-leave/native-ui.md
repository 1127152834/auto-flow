## 已实测

1. 主窗口“工作流工作台”打开独立 Studio。名称“正式窗口离开验收”→原生关闭→取消，窗口与草稿保留。再次关闭→保存后继续，回到主窗口。重开→打开列表→选择原文件，名称恢复。
2. 脏草稿“切换取消保留草稿”→Cmd+Q→取消，应用未退出且名称保留；再次 Cmd+Q→保存后继续，应用退出。重新启动正式入口，打开列表包含刚保存文件。
3. 工作区 A 创建并保存“工作区A往返验收”；修改名称“工作区A取消切换草稿”，从主设置选择 B。主进程自动聚焦 Studio 的保存确认。取消后主设置显示“工作台未确认离开，已保留当前工作区”，目录仍 A，无权限错误。
4. 再次 A→B，选择保存后继续；Studio 显示“正在切换工作区，编辑暂时锁定…”，日志先确认保存原文件，再重建目标窗口。B 的打开列表为 0 个文件。
5. B→A，打开列表恢复 2 个文件：工作区A往返验收.json、工作区A取消切换草稿.json；真实点击后恢复名称“工作区A取消切换草稿”。

## 实测发现并修复

- 原生切换/退出确认藏在后台窗口：prepareLeave 恢复、显示并聚焦 Studio；修复后切换无需手动切窗。
- 取消误报通用权限错误：沿用 SettingsError，区分 STUDIO_LEAVE_DECLINED，保留当前目录并显示正常未切换状态。
- macOS /var 与 /private/var 同目录被分成两个存储分区：分区标识使用 realpath。路径别名由宿主测试覆盖；新构建的 A/B/A 实机往返恢复通过。早期独立试验产生的未规范路径分区仅作失败证据，不计成功数据恢复。

## 验收边界

以上证明正式主/子窗口、正常保存关闭/退出及工作区切换的真实 UI；不证明真实自动化浏览器执行或进程清理。活跃录制/运行/拾取与原生退出/换区的全部交叉组合尚待实机覆盖；保存失败、身份竞态和清理失败目前由组件/HTTP/宿主测试覆盖。打包分发文件、macOS Intel、Windows 未实测。
