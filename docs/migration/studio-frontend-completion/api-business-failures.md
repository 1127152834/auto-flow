# 共享 API 业务失败语义

2026-09-14；F1 既有请求适配边界修复。

冻结源码的凭据及通知等服务使用 HTTP 200 + success=false 返回业务失败；现有 apiRequest 无条件将 HTTP 200 包装成 success=true，会使只检查 res.error 的表单误关或只检查 res.data 的 Store 接收失败包。

固定行为：仅顶层明确 success=false 判为业务失败，映射成与已有 HTTP 错误一致的 ApiResponse {success:false,error}；保留可读的 error/message/detail，不把业务失败广播为网络断线。普通对象、数组、null、零匹配以及嵌套业务数据保持原样，不展开或重写成功 payload。接口取消/非法 JSON/HTTP 错误继续现有语义。

通过同一套内存与本地真实 HTTP 测试验证，再用真实凭据编辑组件验证失败后保留输入，不调用真实凭据服务。这里只固定共享错误语义，不能据此声明 142 个接口全部冻结。

## 实际结果

内存/真实本地 HTTP 相同断言共 22 项；实际凭据编辑组件用例验证失败提示和输入保留。相关 43 项通过，全量 102 文件 / 1,219 项通过，类型、lint、构建通过。

失败前 8 项将业务失败判为成功，修复后全部通过。完整证据见 [验收日志](evidence/f1-api-business-errors/)。测试数据为虚构字段，不调用真实凭据服务，也不把本组件验收当作正式宿主端到端验收。
