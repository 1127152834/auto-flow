## 3. 证据记录格式

实际测试时在本目录下按 R 编号收纳报告/附件，并从上表链接。暂未生成的路径不写成已存在证据。每次记录至少包含：

```text
里程碑 / 用例 ID / 子场景：
源提交 / AutoFlow 提交：
平台、系统版本、CPU 架构、内核版本、Profile 非敏感参数：
入口：开发 URL / 构建 HTML / 冻结后端 / 目录包 / 安装器
临时工作区、fixture版本、复位方法：
原版结果：实测 / 仅源码核对 / 原版缺陷 / 宿主适配不适用
前置条件和准确命令 / 人工操作：
预期：
实际：
状态：通过 / 失败 / 阻塞 / 未测
截图、文档、页面状态、持久事件、产物哈希和进程清理证据：
有意差异（来源、理由及处理决定）：
```

失败不得覆盖成“通过（有问题）”。有意差异只有明确处理结论并测试符合该结论后才可通过；原版缺陷必须有复现，不以“前人代码如此”绕过数据丢失/错误执行。对原版未支持或用户明确排除的能力在来源清单中注明，不虚构对应原行为。

## 4. 固定快速回归与人工体验包

R1 建立后，每个里程碑交付至少保留：正式窗口打开、文档保存重开、F01真实执行、断点/单步/停止、显式关闭会话清理、日志恢复。保存/会话相关改动加保存失败和取消离开；构建/worker变化加冻结和实际包入口。未新增修改或疑点不反复跑无关全量测试。

交给用户体验时包含：**正式应用入口 + 一条参考流程 + 页面复位方法 + 一条短操作路线 + 可观察预期 + 自动检查结果 + 当前未接通清单**。深层命令竞态、迁移故障和资源锁由工程测试承担，不要求用户手工验证。
