# 浏览器管理实施裁决

本记录保留本轮实施中由协调者作出的边界判断。功能与交互以批准的实施计划为准；测试结果另见 [验收记录](browser-management-validation.md)。下表按裁决发生顺序记录，不把判断当成已验证的外部事实。

| # | 裁决与原因 | 如果判断有误，需要付出的代价 |
| --- | --- | --- |
| 1 | 在用户指定的现有 checkout 实施，按文件归属提交，保留并行任务的未提交内容；不整体 reset、stash 或覆盖。 | 出现共享文件冲突时需要逐项整合，不能用重置省略协调。 |
| 2 | 生成原型中的装饰性数值、额外表单侧栏与已核实行为冲突时，以批准的交互规则和旧项目真实能力为准。 | 若用户实际希望保留某个视觉细节，需要局部调整 UI。 |
| 3 | 配置服务可补充任务 2 未覆盖的领域端口和仓储生命周期方法，服务不直接依赖 ORM。 | 新端口若过多，后续需要缩减接口；不影响 HTTP 契约。 |
| 4 | License 复用代理模块提供的系统 CredentialStore，不新增一套凭据实现。 | 共享存储接口调整需要同时回归代理与 License。 |
| 5 | 配置删除占用检测覆盖 AutoFlow 的 OS 锁协议及已知 Chromium 占用标记；不声称能检测任意不合作的外部文件读取者。 | 外部程序绕过锁协议时，无法提供超出操作系统能力的占用保证。 |
| 6 | 系统凭据、依赖、SQLite 外键及 Alembic 打包资源由协调者串行整合；任务 4 的 provider 审查与这些共享改动分别划分范围。 | 边界遗漏会造成集成回归，因此仍需要共享集成测试和最终审查。 |
| 7 | 按用户在并行任务中的授权，在任务 5 审查后、任务 6 前整合代理模块；保留 App、bootstrap、生成契约和既有 Vite 内容。 | 合并接口不匹配时需在共享边界修复，不回退其他任务的功能。 |
| 8 | 将既有配置 OS 锁提取为最小 ExclusiveFileLock，供内核任务复用，并保留配置锁行为。 | 锁实现改变可能同时影响配置与内核，必须保留两侧回归覆盖。 |
| 9 | 任务 6 补充 catalog/License 的受监管 worker RPC 和最小异步 provider 接口；所有 wrapper 调用继续隔离在工作进程中。 | 进程生命周期与取消复杂度增加，需要超时、退出和资源清理测试。 |
| 10 | 下载与尚未结束的退出登录重叠时允许立即返回忙碌；退出登录完成后发起的下载必须看到凭据缺失。 | 用户并发操作可能需要手动重试；不隐式等待或重放写请求。 |
| 11 | 按用户授权，让配置弹窗与内核弹窗在接口固定后并行开发；共享整合由协调者控制，两项分别独立审查。 | 接口漂移会产生整合返工，因此页面组合必须等待组件审查通过。 |
| 12 | 任务 10 可最小修改内核 hooks，以修复 HTTP 与 SSE 到达顺序造成的状态倒退；保留现有公开接口。 | 合并策略需持续匹配后端任务历史保留规则；引入任务历史删除时需重新设计缓存清理。 |
| 13 | 后端稳定后，任务 12 可提前准备打包与 smoke，独立修复 tzdata 缺失；最终桌面验收和任务完成仍等待真实页面接入。 | 提前测试不能替代最终集成验收，需要在最终代码上补跑桌面与打包流程。 |
| 14 | 最终审查发现 SSE 阻塞退出，Windows 的进程终止也不具备 POSIX 协作信号语义。复用 host-token 私有协议增加隐藏的协作退出入口，设置有界连接排空和宿主等待预算，保留最终强制终止兜底。 | 需要维护一项内部生命周期接口及相应时间预算；必须验证实例 token 无法调用，并以真实进程证明 SSE 和活动 worker 能完成清理。 |

另外，用户另行授权的模型、设置和总览模块在本轮期间整合进同一应用壳。浏览器任务保留这些成果；它们并不意味着本模块扩大为工作流编排或浏览器启动控制。
