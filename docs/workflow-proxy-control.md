# 工作流代理控制

日期：2026-09-25。状态：implemented，实网与跨平台验收待执行。
来源：获批规格、当前源码、合成供应商/SQLite/真实 worker 管道测试。

在 Studio「代理控制」分类中添加以下节点。项目自动化运行同一套节点与执行器。

| 节点 | 用途 |
| --- | --- |
| 切换代理 IP | 切换后建立新连接探测出口，与节点进入时的固定 IP 比较 |
| 切换代理地点 | 使用供应商地点 ID，读回地点和切换代次，并探测新连接 |
| 查询代理状态／操作结果 | 只读查询；给出原操作 ID 时可核实未知操作，不重发切换 |

目标默认是当前任务实际使用的代理。代理池成员在启动时已选定，重试期间不会重新抽选。
「指定代理」使用本地代理目录 ID，不接受代理 URL 或 API Key，也不会重绑当前浏览器。
地点目录来自目标代理所属连接；变量代理的地点 ID 在运行时重新校验。

## 配置与结果

默认重试间隔 **10 秒**、最多 **5 次尝试**、单次确认 **30 秒**。次数包含首次，1 表示不重试。
次数为正整数，两个时间为正有限数；可填写 `{tries}`、`{delay}` 等既有工作流变量。
代理 ID 和地点 ID 同样支持变量；节点开始后冻结配置。非法配置不发送供应商请求。

每轮可能发起一次切换，也可能因冷却、占用或原操作未完成而只读；所以 `attemptsUsed` 与 `requestsSent` 不一定相同。
明确冷却时不发送写请求。供应商返回的剩余等待时间未知时为 `null`；不假定固定冷却时长。
管理 API 的 429 为 `PROXY_RATE_LIMITED`，与明确的 `PROXY_COOLDOWN` 区分。

结果默认写入 `<节点类型>_result`，也可指定变量。每次执行覆盖上次结果，包括失败。
例如结果变量为 `switch_result`，后续条件节点可以使用 `{switch_result['status']}`、`{switch_result['error']['lastCode']}`。

- `status`：切换最终为 `succeeded`、`failed`、`unknown`；查询还可为 `queued`、`running`。
- `proxyId`、`operationId`：实际本地代理和持久操作身份。
- `attemptsUsed`、`requestsSent`、`configuration`：处理轮数、实际发送次数、解析后的设置。
- `before`、`after`：观测 IP、时间、来源及可用的地点证据。
- `targetLocation`、`changed`：目标与是否发生变更；已经在目标地点时 `changed=false`，不发地点写请求。
- `error`：顶层稳定错误码、最后原因、可否重试、结果是否未知、已知等待时间。

耗尽尝试后，顶层错误为 `PROXY_IP_SWITCH_FAILED` 或 `PROXY_LOCATION_SWITCH_FAILED`；`lastCode` 保留冷却、占用、出口不变、地点不符、探测失败或未知等具体原因。
默认写结果后报错；选择「捕获结果，由流程判断」后，预期操作失败显示“操作失败，结果已捕获”，后续条件可分支。取消和协议/程序错误不转换为捕获成功。
Studio 日志显示轮数与重试等待倒计时；项目运行日志记录轮数和等待时间。倒计时表示用户配置的重试等待，不是供应商冷却推测。

## 未知结果、共享与浏览器

接口受理不等于切换完成，缓存的健康 IP 也不是新出口证据。请求丢失或仍在处理时，只核实同一持久操作，不创建第二个切换。
未证明原操作结束时，保留数据库互斥及 `unknown`；可用查询节点或代理管理页核实。
停止或超时不等于远端撤销成功。服务重启不恢复节点重试循环，也不会重放未知写入。

同一供应商代理按连接和远端身份归并。Studio、项目任务、测试浏览器的使用登记共同阻止误切其他使用者的代理；管理页写操作遵循同一限制。
切换期间不接纳新使用者。旧进程清理未经确认时，保守阻断代理操作；恢复流程移除旧目录证据后才解除。当前旧运行记录不包含可靠代理身份，因此此阻断作用于工作区全部代理。

当前代理验证使用该浏览器的本地转发入口。确认后关闭旧转发连接，再建立新连接探测；浏览器进程、页面、Cookie 保留，不刷新、不重启、不重放网页请求。
已有网络请求可能中断。同一浏览器并行节点与切换冲突时返回占用失败。外部程序及供应商后台变更不在本地登记范围内。

不包含：自动识别风控、代理池自动替换、指定任意出口 IP、定时轮换节点。
