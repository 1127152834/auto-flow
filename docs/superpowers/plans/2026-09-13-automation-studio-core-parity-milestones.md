## 范围

最终必须覆盖工作台核心：

- 编排编辑：动作库、节点配置、变量、连线、布局、快捷编辑、撤销重做、分组/注释、保存打开，以及图画布与模块条双视图。
- 执行：范围内的 Web 与通用流程节点、控制流、子流程、输入输出、错误处理、超时和取消。
- 日志与结果：实时日志、级别/关键词筛选、节点关联、执行耗时、变量变化追踪、采集结果与附件查看、日志和结果导出。
- 调试：断点、暂停/继续、单步、从节点开始执行、执行位置高亮和变量快照。
- 录制与拾取：元素拾取和选择器验证；录制支持的网页操作，生成可编辑、可保存、可重放的流程。

用户明确排除：企业管理功能、Windows 桌面/系统控件控制、工作流发布与版本管理等管理能力。企业角色、权限审批、组织管理及发布/版本相关入口不迁入。

边界说明：不做工作流版本管理仍需当前文档保存、编辑撤销和运行记录；不做 Windows 控制仍需在 Windows/macOS 上运行网页自动化。保留现有 CloakBrowser、目录架构和不集成旧运行时的约束，不新增 WebRPA 文件/协议兼容承诺。

M0 对全部候选做“纳入 / 排除及依据 / 边界待定”分类。旧文档中的“暂缓”不自动等于最终排除；属于核心范围的能力必须进入后续里程碑。办公、媒体、Android、AI 等专项节点逐项判断是否属于用户此次核心范围，不能因“等等”自动全量引入，也不能未经核实声称已经完整对齐。最终验收前不得剩余影响核心范围的未定项。

| M0：对齐范围与验收清单 | 核心能力总表、排除清单、来源对应、代表流程和最小数据契约 | 核心功能无遗漏；首批行为与输入输出明确；每项能追溯源码或运行证据，静态发现与运行验证分开标记。 |

| M5：元素拾取与完整网页录制 | 拾取、相似元素与选择器校验；把基线支持的点击、输入、选择、勾选、导航及其他录制动作转成正式节点 | 录制步骤可修订并生成流程，补齐必要配置后可保存重放；操作顺序与结果符合基线；跨页面/框架等场景逐项对照；上传等无法录得真实路径时明确提示补填。 |
| M6：全部核心差距收敛 | 完成对齐表剩余节点、配置选项、编辑交互与视图模式；补齐录制、调试和日志的边缘场景 | 每项核心能力都有实现和验收证据；不能因“非首批”继续无限延期；无假按钮、空执行器或静默跳过未知节点。 |
| M7：整体对照与稳定性验收 | 全流程回归、重复运行、服务恢复、窗口生命周期、Windows/macOS 运行与打包验证 | 纳入范围的能力逐项通过；差异均有明确依据；无影响验收的缺陷；脱离 reference 目录仍能独立构建运行。 |

顺序为 M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7。基础日志在 M2 交付，M4 补完整诊断体验。录制后置是为了生成已经可以可靠执行的节点，不代表降低最终录制范围。

M1 完成时能看到并使用正式编辑器；M2 完成时能跑真实流程；M5 完成时创作、执行、排错和录制链路均已具备；只有 M6、M7 通过后，才宣称核心能力完整对齐。

## 最终“完整对齐”的定义

1. 对齐表中所有纳入项均已验收；排除项有用户范围或明确架构约束依据，不用节点数量推测覆盖率。
2. 相同场景在新工作台得到约定的一致结果，包括正常输出、执行路径、失败位置和停止语义；UI 使用 AutoFlow 的组件和风格。
3. 同时覆盖手工编排与录制编排、执行与调试、日志与结果检查；没有只展示不可用能力的占位交付。
4. 修复旧缺陷、替换浏览器边界等有意差异有记录；旧项目的空实现不作为成熟能力的证据。
5. 数据格式版本字段、单次运行定义快照属于内部正确性需求，不提供版本发布、历史比较或恢复的产品管理功能。

参考核验中特别区分：`Toolbar.tsx:354` 的从节点执行会调用 `execute(startNodeId)`；`WorkflowEditor.tsx:1102` 的 `run_single_node` 入口只记日志。若以后增加严格的仅运行一个节点功能，应记录为增强，不误报为旧项目已完整支持的行为。
