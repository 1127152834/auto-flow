# Studio 前端完整交付实施计划

- 日期：2026-09-13
- 状态：实施中；按用例逐项实现与验收，F0–F6 均未宣布完整通过；具体结果见验收记录与逐项证据
- 规格：[正式规格](../specs/2026-09-13-studio-frontend-completion-design.md)
- 基线：业务代码 `690f13f`；整体方案 `a2f708a`
- 目标：完成保留能力的前端、工具和服务消费协议，后端阶段按契约实现，不再补缺失的前端功能

## 1. 执行约束

2026-09-14 范围更新：用户取消界面国际化，按中文单语言交付。删除 i18n 专属代码、英文教学内容和测试门槛；历史测试结果不改写，其他前端功能继续实施。

1. 不重新开发一套编辑器；以冻结源码及当前迁入模块为基础修复/补齐。
2. 保留节点清单以当前 284 个内置入口为基线。不得扩大删除范围；配套功能必须追踪消费者后才能清理。
3. 本计划只实施前端规则、契约、服务夹具和必要 Electron 宿主桥接。真实自动化执行、采集、数据库业务与外部服务调用不在本轮。
4. 原工作树的模型管理、UI、调研与文档改动不覆盖，不混入提交。
5. 一个有界任务一个可回退提交；每批关闭前更新台账、验收记录与 `.ai`。不以空提交或测试数量替代功能证据。
6. 下文未存在的文件是计划新增位置，不表示已经实现。优先扩展现有组件与测试；新增文件仅用于清晰独立的职责。

## 3. 任务图与状态管理

F0 范围冻结 → F1 契约冻结 → F2 编辑/工具 → F3 运行/结果 → F4 拾取/录制 → F5 宿主/全部依赖收口 → F6 总验收。

每个任务完成必须具备：代码或明确排除记录、测试 ID、实际结果、残留问题。状态依次为待核对/待实现/待验证/通过；失败保持待验证并附原因。

F1 必须冻结后续需要的语义；后续发现遗漏先补契约和样例，再改实现。不能在某个页面临时增加字段或事件绕开契约。

## 4. F0：范围、调用链和删除边界

### F0.1 生成逐项能力台账

- 从 ModuleSidebar 的有效目录、ConfigPanel 分发、默认值/必填规则和类型定义提取节点快照。
- 每个节点记录全部配置字段、条件显隐、辅助按钮/弹窗、变量/资源/凭据/连接需求及序列化路径。
- 对非节点入口逐个记录菜单、工具栏、上下文菜单、快捷键、事件订阅、AI 工具入口。
- 区分活跃调用与原版未使用文件；人工核对动态 import、事件名和字符串注册，不能仅靠静态 import 图。
- 交付 capabilities.json、excluded-capabilities.md；每条能力有源/目标路径和验收 ID。

验收：284 个入口无重漏；每项均有字段及依赖；每个现有可达操作可归属一个能力 ID。数量与基线不同必须列出解释。

### F0.2 清理排除能力的专属配套

- 检查 GlobalConfigDialog 的 QQ/飞书等标签、数据资源库 Excel 专属入口、媒体容器、帮助内容、AI tools/skills 和 Mock 路由。
- 为每个删除对象列出所有消费者；保留节点仍消费的部分保留或收窄。
- 清理仅排除功能使用的代码/依赖；不更改用户已保存数据。
- 旧文档含排除节点：保留结构与配置，显示不可执行原因；保存/导出不偷偷删除。

验收：分类、搜索、快捷添加、收藏/常用及 AI 添加均不能重新引入排除节点；保留节点工具无断链；旧文档无损往返。

## 5. F1：服务契约与测试基础

### F1.1 盘点所有服务操作

- 对 api.ts、api/*、events.ts、IPC 和原生资源 URL 按实际消费者列出完整方法清单。
- 覆盖文档、自定义模块、资源、连接配置、Profile、运行/Debug、日志/结果、拾取/录制、助手/工具、凭据、导出、宿主协调。
- 明确每个服务操作是读/写/命令；字段、错误、分页、限制、幂等、取消和状态查询逐项定义。
- 输出 contract-matrix.md；不在执行代码里用泛化 success 兜底。

### F1.2 确定唯一 schema 与生成路径

- 检查当前后端 OpenAPI 导出/前端生成脚本；选择可不启动真实业务的 schema-only 导出方式。
- 不另建第二套 contracts 包；沿用 generated.ts，保留源前端模型时用明确映射转换。
- 将 HTTP/SSE/IPC 样例变成可校验输入；定义事件 ID、关联 ID、修订、恢复游标、终态与错误路径。
- 验收生成结果可重复且无需人工编辑；错误样例会被 schema 拒绝；必需字段和状态无 TBD。

### F1.3 隔离 Mock 与页面

- 从 StudioApp 移出 Mock 专属场景控制，放入独立开发/测试装配；生产组件仅依赖服务接口。
- 现有 transport seam 接入协议一致的内存夹具和本地 HTTP/SSE 夹具。
- 测试支持延迟、失败、取消、重复、断线、服务重启和命令响应丢失；夹具数据独立于用户工作区。
- 对图片/下载等原生请求提供受控资源地址，不能直接返回虚拟域名给 src。

验收：同一调用测试可切换两种传输；实际 HTTP 状态码、SSE 分块解析及取消可测；无页面 import mock-server；测试场景明确标识模拟。

## 6. F2：编辑、配置与节点配套工具

### F2.1 修复应用装配

- 恢复 AI 面板宽度避让、原浮动入口、Tooltip 和必要焦点行为。
- 接通连接错误反馈、自定义快捷键事件与宿主注册请求；避免重复注册。
- 主题/布局/偏好保存及重连重建有明确归属。

验收：宽/窄窗面板、输入框快捷键、动态 Tooltip、离线反馈、重复挂载与重连均正常。

### F2.2 逐节点配置验收与补齐

- 按台账分批处理，不另建通用表单引擎；保留专用组件。
- 对每一节点测试默认值、显隐分支、校验、引用、特殊字符与序列化。
- 逐个追踪定位器、代码/JSON 编辑、选择变量、选择凭据、选择资源、连接测试等工具。
- 保留节点如依赖数据库/网络/模型配置，完整交付其前端编辑/测试/错误流程；外部动作由夹具模拟。

验收：所有节点至少有注册+字段映射用例；共享组件测试与节点实例测试相结合。任何保留配套按钮不得空实现。

### F2.3 文档、自定义模块与资源

- 完成保存冲突、保存途中继续编辑、失败重试、导入错误及兼容处理。
- 检查两视图、分组/子流程、自定义模块引用、复制/撤销一致性。
- 保留资源的 CRUD/引用/失效/缺失文件/导入导出完整接入契约。
- JSON/加密/bundle 使用实际前端逻辑；服务生成脚本导出测试合同与下载流程，不能将 Mock 内容标为真实脚本。

验收：完整文档重开一致；资源缺失可定位；删除/导入/冲突不丢未保存内容；所有工具配置参与真实请求快照。

## 7. F3：运行、Debug、日志和结果

### F3.1 状态与交互命令

- 从源控制规则建立明确状态转换及按钮许可表；映射 service 状态而非增加第二执行器。
- 运行捕获独立快照；标记、日志和定位依据运行内容；后续编辑不修改运行。
- 输入/JS 等交互请求以 requestId 关联；模拟等待、提交、取消、失败及迟到结果。
- 控制命令保留稳定 ID；查询接受/应用状态；停止失败仍保留占用。

### F3.2 复杂执行与诊断场景

- 准备条件真假、空分支、循环零/多轮、嵌套、重复节点、失败中止的确定轨迹。
- 测试断点/单步/继续/停止、变量变化及所有源版本保留的诊断操作。
- 所有调试操作必须绑定运行及当前上下文；过期请求不能作用于下一次暂停。

### F3.3 历史、结果与导出

- 接入契约分页、筛选、断流补读、去重、变量大值和按需资源读取。
- 区分刷新与服务重启；由 HTTP 夹具验证重开恢复，禁止伪造完成事件。
- 导出按冻结的事件截止位置输出；缺失资源与权限错误明确提示。

验收：1,000 次执行、10,000 条日志、超过 64 KiB 的变量/结果完整可读；未选分支不标成功；停止/失败不调度后续 UI；响应丢失不多走一步。

## 8. F4：浏览器、拾取、录制

### F4.1 浏览器与定位工具

- Profile 列表、无配置/配置失效、可用性、页面选择、导航、聚焦、关闭全部接服务契约。
- 定位夹具覆盖 CSS/XPath、主文档/框架路径、开放 Shadow DOM、零/一/多匹配、不可见和非法语法。
- 工具结果绑定文档/节点/字段修订/页面/请求；所有变更与取消使旧结果失效。

### F4.2 录制审查与生成

- 保留源录制 UI/转换逻辑，补会话控制、步骤分页、尾部确认、重连和错误显示。
- 输入/点击/导航/页面变化通过服务夹具产生明确步骤；敏感字段与不支持动作清晰标记。
- 步骤编辑、变量化、生成预览、加入画布按完整操作撤销；生成响应迟到不覆盖新草稿。
- 切换运行/Debug/拾取/录制先确认并等待清理完成；取消保留当前会话。

验收：用户在正式 UI 完成启动→步骤审查→生成→保存→重开→模拟运行/Debug 的闭环；同时覆盖页面失效、清理失败、请求丢失和取消。结果只能标为前端协议验收，不标真实录制通过。

## 9. F5：宿主、设置与全部依赖收口

### F5.1 真实宿主桥接

- 在现有 main/preload/shared 层加入受控运行上下文及必要服务能力，不允许 renderer 拼接端口/令牌。
- 原生窗口、目录/文件选择、资源打开与快捷键使用现有适配入口；验证取消与权限拒绝。
- WebRPA 旧安全令牌/端口配置映射为 AutoFlow 管理，不保留无效可操作控件。

### F5.2 离开与恢复

- 实现统一离开处理：提交输入→选择保存/放弃/取消→必要保存→停止/清理→离开。
- 接入新建、打开、关 Studio、退出、换工作区；处理多次关闭、保存冲突及清理重试。
- 普通断线只重连；服务重启不重放动作；换区期间锁编辑并在失败时回滚。

### F5.3 剩余工具逐项销账

- 对 AI 助手/本地画布工具/MCP、模型、凭据、数据库/网络连接及保留策略等台账依赖逐项完成。
- 测试批准/拒绝/取消/不可用/权限不足/空列表；工具变更有可追踪结果。
- 删除原排除能力残留说明和帮助入口，更新用户文案，避免将 Mock 成功描述为外部服务已运行。

验收：所有保留依赖都有可重复闭环；离开矩阵通过；仅关闭主窗口不误停 Studio；错误或取消不丢草稿、不切错工作区。

## 10. F6：全量验收与后端交接

### F6.1 完整性检查

- 核对每个能力有契约、实现、测试及证据；所有排除条目有依据。
- 扫描 TODO、空处理器、固定 success、501、mock imports、硬编码虚拟资源 URL；逐条归类，范围内必需功能不得残留。
- 比对全部节点配置入口及专属工具，无只测共享组件而漏注册的条目。

### F6.2 工程与宿主验收

按根 package.json 的实际脚本核对并执行；桌面当前命令：

```sh
npm run test --workspace @autoflow/desktop
npm run typecheck --workspace @autoflow/desktop
npm run lint --workspace @autoflow/desktop
npm run build --workspace @autoflow/desktop
npm run openapi:check --workspace @autoflow/desktop
```

同时执行目录/脚本检查、HTTP/SSE 集成和 Electron 交互测试；契约 schema-only 导出如修改后端 schema，需要对应后端契约检查，不运行未实现执行器来制造通过。

开发 URL、构建 HTML、正式 Electron 包分别验收。PyInstaller/真实后端分发入口在本轮只验证宿主兼容边界，真实执行及资源清理留后端阶段。macOS arm64/Intel、Windows 各自记录实际平台结果，缺平台不能标通过。

容量数据固定：500 节点、1,000 次执行、10,000 条日志、大于 64 KiB 的值。记录硬件/构建模式/响应与内存；检查有界渲染、交互未冻结、原数据无截断。

### F6.3 交接

交付 capabilities.json、contract-matrix.md、acceptance.md、backend-handoff.md、可运行 HTTP/SSE 夹具、schema 与同一套契约测试。

后端实现必须通过同一套测试；替换适配器不得修改组件、Store、表单或增加遗留缺失 UI。每项真实业务待实现内容明确对应操作 ID、输入输出、事件顺序、持久化、取消/清理和权限要求。

## 12. 停止条件与变更控制

- F0 发现共享依赖：保留并追踪，不先删后补。
- F1 存在不确定字段/行为：对照冻结源码形成决策；需要新产品选择时列出具体选项及影响。依赖任务不凭猜测继续。
- 任一验收失败：修复当前批次，不将已知前端缺口转移到后端阶段。
- 出现与用户范围冲突的新能力：单列变更，不以“完整复刻”为由自动添加。
- 不给未经测量的日程承诺。每批以可运行交付物和退出门槛衡量，不以完成多少文件衡量。
