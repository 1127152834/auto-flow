# M3 Task 5/6：长驻 worker 与浏览器会话复用（设计与实施计划）

- 日期：2026-10-04；状态：confirmed（实现与测试）；AC3-02 / AC3-05 正式数字待 Task 9 在安静环境复测
- 规格：[M3 规格](../specs/2026-09-30-remediation-m3-throughput.md) R3-06、R3-07；AC3-04、AC3-05
- 决策：用户 2026-10-04 选定"长驻 worker 带浏览器"（相对"宿主持有浏览器 + CDP"和"只做 worker 池"）。

## 测量依据

native-batch-v1（20 行、并发 2）每行约 5.9 s：起 worker 约 1.0 s，启动浏览器约 3.4 s，结束清理约 1.5 s，
其余是节点本身。只省 worker 启动到不了 5 倍；必须省掉浏览器启动与关闭。

## 设计

### 适用范围（R3-07）

- 自动化运行设置新增 `runPolicy.sessionMode`：`perTask`（默认）/ `pool`。不提供 perIdentity（M4）。
- `pool` 只允许"无登录采集"：环境来源必须是"按浏览器配置新建"，流程不得在结束时保存环境，不得使用节点级浏览器环境。
  保存自动化时校验，不满足直接拒绝并说明原因。
- 复用仅限浏览器进程：每个任务开一个新的非持久隔离上下文，不用环境工作副本目录。
  Cookie、Local/SessionStorage、IndexedDB、Service Worker、权限授予由 Chromium 上下文隔离保证，用真实内核测试证明；
  内核不满足时该内核不启用 pool（保持 perTask 并记录），不以清 Cookie 冒充隔离。

### 复用键

浏览器载荷去掉 `sessionId` 后与内核可执行文件路径一起做哈希。指纹种子、时区、语言、代理是进程级参数，键不同就不复用。
代理池每次分到不同代理时自然换键（不复用），不为 pool 制造临时身份。

### worker 生命周期（R3-06）

- worker 收到 `start` 且 `pooled: true` 时，运行结束发出 `finished` 后不退出：关闭本任务上下文与全部页面，
  确认浏览器里没有剩余上下文，回报 `released`，然后等待下一个 `start` 或 `shutdown`。
- 每次运行的产物目录、临时目录、凭据读取器、代理中继、回调全部按运行重建；上一运行的变量与凭据不跨运行保留。
- 父进程：
  - 归还条件：运行正常结束（succeeded / failed），worker 确认 `released`，执行代次未被撤销。
  - 停止、强制停止、超时、撤权、协议错误、清理未确认：直接结束整个 worker（含浏览器），不归还。
  - 回收：每个 worker 跑满 50 个任务、空闲超过 120 秒、或内存超过阈值（阈值按基准确定）就结束。
  - 空闲 worker 占存活浏览器名额；需要名额而没有同键空闲 worker 时，先结束一个空闲 worker。
- Windows Job 改为按 worker 创建；进程身份与原生归属校验不变。

### 首节点延迟（AC3-04）

- 池中有同键空闲 worker：从派发到首节点开始 < 300 ms。
- 新 worker + 新浏览器：< 3 s。

## 实施切片

1. 自动化 `sessionMode`：领域校验、HTTP 契约、运行设置界面、冻结进运行请求。
2. provider：池化浏览器会话（启动一次，按运行新建 / 关闭上下文，复刻 CloakBrowser `launch_context_async` 的上下文参数）。
3. worker 端：`pooled` 运行循环、按运行重建的状态；`finished` 带 `reusable`，父进程用 `shutdown` 结束空闲进程。
4. 父进程：worker 池（复用、归还、回收、名额腾挪、撤权即结束）；dispatcher 传复用键；pool 模式不使用环境工作副本目录。
5. 证据：真实内核隔离测试（Cookie、Local/SessionStorage、IndexedDB、Service Worker、权限）；撤权 / 回收 / 名额测试；
   首节点延迟基准；native-batch-v1 五次采样对比。

## 实施中的修正

- 节点级浏览器：native-batch-v1 在"打开网页"节点上声明浏览器（`browser: node`），第一版池化在这条路径上被静默跳过。
  修正为：复用键只是派发亲和提示，由冻结的资源请求计算；是否真复用由 worker 比较实际启动参数决定（不同就重启浏览器）。
  节点级声明为"按配置新建 / 当前"时可池化；节点使用已保存环境时自动化检查与启动都拒绝。
- 代理：代理中继每次运行端口不同，带代理的任务每次重启浏览器（正确但无收益）；中继跨运行保留留待后续。
- 无浏览器的纯数据运行暂不进池。

## 吞吐提升后暴露的事件循环阻塞（AC3-02）

池化后同口径 5 次采样吞吐中位数 121.74 行/分钟（M2B 基线 13.39 的 9.1 倍），但循环延迟 p99 181–209 ms。
用循环卡顿探针（心跳停顿 > 50 ms 时采样循环线程与其他线程的栈）逐项取证并修复：

| 发现 | 修复 |
|---|---|
| `list_tasks` 每个任务两次查询，并解码整行运行记录 JSON；调度每轮多次调用 | 一条 join 列查询，只取投影所需列 |
| 熔断检查每轮对整批历史逐条判定，且全程持写锁 | 从最新往回取到不影响结论为止（2000 例随机化等价测试）；先读判定，需暂停才拿写锁复查 |
| 调度每轮的状态读取、容量统计、终态租约释放在循环上 | `asyncio.to_thread`；每轮重复次数以核心容量为上限 |
| worker 目录创建、浏览器初始化的环境实例预留在循环上 | `asyncio.to_thread` |
| 循环上的提交偶尔承担 SQLite 自动检查点 | 后台每秒 PASSIVE 检查点（线程中），自动检查点保留为兜底 |

修复后单次探针样本：卡顿 353 → 18～42 次，p99 46–63 ms，吞吐 152–206 行/分钟。

测量环境说明：随后的 5 次采样（全部通过正确性断言，198 成功 / 2 隔离 / 204 次尝试）吞吐逐次下降 101 → 47 行/分钟、
p99 70–134 ms；同时段机器空载 CPU 87%，主要来自另一个 Codex 会话的备份进程（非本仓库），没有进程泄漏。
这些数字受外部负载干扰，不作为验收；Task 9 在安静环境下重测 AC3-02 与 AC3-05。
另有一次 3 样本运行中出现 1 次失败，输出未保留、单独与 5 次重跑均未复现，原因未定位，Task 9 继续观察。

## 证据

- `test_pooled_browser.py`（真实内核）：Cookie、Local/SessionStorage、IndexedDB、Service Worker、权限不跨运行；参数变化重启浏览器。
- `test_worker_pool.py`（真实 worker）：同键复用同一进程、换键腾名额、停止不归还、撤权结束进程、跑满上限回收。
- 规则与校验：`test_project_automation_rules.py`、`test_session_pool_validation.py`；前端运行设置开关测试。
- `bench_first_node_latency`：新浏览器 2,185 ms（< 3 s），复用 90 ms（< 300 ms）——AC3-04 达标。
