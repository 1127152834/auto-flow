# Studio WebRPA 源码迁入详细里程碑计划

> 2026-09-13 修订：用户在清除旧 Studio 后要求制定迁入方式，并明确架构、技术栈、开发习惯贴合 AutoFlow。产品方向及工程约束 confirmed，详细里程碑安排 proposed；用户要求“方便测试，稳步前行”。本次仅更新文档；迁入代码尚未开始。[设计规格](../specs/2026-09-13-studio-webrpa-source-migration-design.md)为行为和边界依据。

## 1. 当前基线与交付原则

- 计划起点：AutoFlow `52cc027`（架构对齐文档）；业务代码清除基线 `25273d5`；数据库 head `0008_workflow_debug`。旧 Studio 业务代码已清除，当前只保留总览入口、独立空窗口和共享宿主基础设施。
- 源码基线：`reference/WebRPA@5ccb900e8dcf1530aae66f676d87593c416c7ebb`。reference 只读；迁入文件进入正式领域目录，记录来源和修改。
- 原完整 Studio 归档：`codex/studio-before-removal-20260913@4eda207`；未完成 M6 试验归档：`codex/m6-unfinished-checkpoint-20260913@59ae8d4`。不恢复旧 Store、节点协议、执行器或兼容引擎。
- 清除已通过工程及 macOS arm64 三种 Electron 入口验证，详见[清除记录](../../migration/studio-removal.md)。这些结果只证明清除基线，不代表 WebRPA 迁入已通过。Intel/Windows 尚未实测。
- 保留用户已有模型/UI等工作树改动和旧工作区数据；不改写历史迁移，不删除历史数据库和产物。

迁入以原产品行为为基准，工程组织遵循 AutoFlow。先迁原实现、替换真实外部边界，再对有证据的问题局部修复。不先重新设计节点、表单、控制流或调试语义。

第一项可见交付是**原工作台在正式窗口中编辑并真实保存/打开**；同一批尽早做原执行器的真实浏览器探路。不会等全部 UI 迁完才验证后端，也不把探路样例做成另一套简化执行器。

## 2. AutoFlow 工程落点

| 事项 | 实施方式与边界 |
| --- | --- |
| 前端目录 | 原组件进入 `renderer/domains/workflows/{components,hooks,pages,tests}`；领域控件和表单放在 components 下。来源由迁移清单记录，不建平行 WebRPA 应用 |
| 前端状态 | 原图操作和撤销算法保留在领域 Zustand Store；Query 管服务端数据。显式打开文档才建立草稿，重连/refetch 不覆盖编辑；同一个事实不维护两份权威状态 |
| 样式及入口 | 建议同 renderer 构建增加 studio.html；加载原工作台样式并仅映射 AutoFlow 配色，保留同一 main/preload/sidecar 和固定窗口校验。原控件不等价于共享控件时留在领域内，主窗口主题不改 |
| 依赖 | 沿用当前 React/TypeScript/Vite/Tailwind/Python 及锁文件版本。按调用闭包添加 React Flow、Zustand、ELK 等；不复制 package.json/requirements，不新增第二套服务器或构建系统 |
| HTTP 与事件 | 使用共享 ApiClient、鉴权、错误包、OpenAPI 类型和 HTTP/SSE；保留原服务方法/事件含义。暂停、单步等控制通过 HTTP，输入提示等反向交互逐项建命令契约；不默认增加 Socket.IO |
| 后端分层 | 纯模型/解析/规则进入 domain；调度/会话用例进入 application；页面操作/录制/拾取进入 browser provider；SQL、文件和进程进入 infrastructure；路由及事件序列化进入 adapters |
| 浏览器及生命周期 | 使用 AutoFlow Profile、CloakBrowser、代理、使用锁和进程监管。提出工作区专属会话 worker，保留原共享浏览器协作；早期实测后固定。旧 Studio 离开握手已删除，必须重新接入 |
| 数据 | 显式持久化原文档字段和必要布局，排除选中/拖拽等瞬态。新格式与旧数据隔离，沿当前 head 增量迁移；保存原子性、revision 冲突和工作区隔离由仓储/用例承担 |

原版分组/子流程用节点位置、宽高判定成员，部分入口使用 y/x 排序；这些几何必须保存并冻结到执行快照。不得套用“坐标一律是执行无关状态”的旧假设。前端 moduleType/data 与后端执行模型的转换沿用原路径，不直接序列化整个 React Flow 节点，也不翻译回废弃的 M4 控制块模型。

原 Toolbar 运行前存在 create/update 调用。R0/R1 必须实际区分执行快照提交、用户保存和脏状态的行为；不能默认沿用旧 M2 的“运行不保存”限制。

## 3. 里程碑总览及推进规则

采用 **R0–R8**，替代上一版粗粒度 S0–S4；R 表示本次源码迁入，和已弃用的 M1–M6 区分。以下均为待实施/待验收，不能根据旧实现通过记录勾选。

| 里程碑 | 可交付成果 | 用户可直接验证 | 依赖 |
| --- | --- | --- | --- |
| R0：对照基准 | 冻结版能力清单、原文档样例、受控网页和复现说明 | 按固定步骤看到原版行为和页面预期 | 当前清除基线 |
| R1：最小真实闭环 | 原编辑器基础操作、真实保存、原引擎网页执行和最小调试控制 | 编辑→保存重开→输入/点击/提取→暂停/单步/停止 | R0 对应样例 |
| R2：完整编辑和文档 | 双视图、配置、历史、分组便签、布局、导入导出和行为设置 | 同一复杂文档往返编辑且状态一致 | R1 |
| R3：网页动作与会话 | 范围内网页动作、标签/框架、Profile 和原会话策略 | 真实表单、导航、提取、截图及浏览器复用 | R1；正式组合基于 R2 |
| R4：控制流及通用核心 | 条件/循环/并行、变量表达式、子流程、错误策略及核心通用节点 | 批处理输出正确；分支、重试和子流程可核对 | R2、R3 |
| R5：拾取和定位 | 原拾取工具、定位配置、预览/测试及应用 | 拾取→写回→保存→执行命中同一目标 | R3；沿用 R2 编辑链 |
| R6：录制与重放 | 原录制面板、采集、生成、编辑及录制相关交互 | 实际录制→保存→新浏览器独立重放 | R3–R5；R4 核心回归通过 |
| R7：完整 Debug 与诊断 | 原调试操作、运行变量展示、日志/结果检索及导出 | 复杂流程命中断点、单步、定位错误和恢复日志 | R4；与 R5/R6 集成 |
| R8：全量对照和平台验收 | 核心清单收口、容量/故障/宿主回归、各平台正式包证据 | 原版代表业务在正式应用中完整复现 | R1–R7 |

**每个里程碑都包含实现、匹配测试、正式应用演示和可回退提交。** 不将“开发完成、测试以后补”作为可进入下一阶段的状态。

推进规则：

1. 当前里程碑的必测项通过，已交付主路径无回归，再进入依赖它的下一阶段。未通过时只继续独立、不受影响的工作，不把该里程碑标绿。
2. 每个里程碑下再按本节的小批次提交。跨层功能由契约/用例/组件/页面/测试组成，先组件后组合；不分成长时间纯前端和纯后端两条交付线。
3. 范围内待接通入口在内部迁入构建明确标明阶段状态，不提供假成功；最终 R8 不保留核心占位入口。阶段完成与“全部原 UI 已对齐”分别记录。
4. 失败分成原版既有缺陷、宿主有意差异、迁入回归、环境未具备。回归必须修复；已知缺陷给复现及最小修复；有意差异逐项记录，不能用统一备注掩盖。
5. 记录“实现状态”和“各平台验收状态”。macOS arm64 通过允许后续本机开发推进，但不等于 Intel/Windows 已通过；最终跨平台完成要求所有目标平台实测，不满足就明确部分交付。
6. 每轮报告已通过用例、未通过项、原版差异、对应提交和下一批内容。门槛是客观测试与证据，不在每个小提交额外增加用户确认流程。

## 4. R0：建立可重复的原版对照

**目标：后续每一步都有共同输入和可核对结果。** 不以复查全仓的方式推迟首个交付。

### 实施与交付

- 从冻结源码梳理工作台菜单、编辑操作、配置字段、行为设置、节点目录和实际注册执行器，建立一张来源/能力清单。每项记录：源位置、纳入/排除/专项待定、目标里程碑、正向与失败用例、证据状态。
- R0 完成范围目录及 R1 的调用依赖和样例；其他节点逐项深读随所属里程碑进行。全部核心项必须有负责人/里程碑，不允许一直留在“待研究”。专项范围疑问不阻塞已明确核心，但最终报告不得隐藏未决项。
- 明确原保存/自动保存/覆盖/副本、运行前 create/update、浏览器复用与关闭、录制与运行/调试的状态转换。原按钮的可用性也属于对照对象。
- 在隔离环境运行冻结版，保留原提交。必要启动兼容修改单独记录，不能静默改原逻辑后称为原版基准。无法实际运行的特性标“仅源码核对”，缺少对照不标通过。
- 使用本地 HTTP 多 origin 网页，提供显式重置、计数器和可查询状态。按原版已验证语法生成代表工作流文件。原参考服务仅用于对照测试，不进入 AutoFlow 产品运行链路。

### 受控测试资产（本轮规划，R0 起随能力落地）

| 编号 | 页面/数据 | 预期结果如何核对 |
| --- | --- | --- |
| F01 基础表单 | 输入、提交、点击次数、回显区域；按钮每点一次计数加 1 | 填入 `AutoFlow测试A` 后提交，回显完全相同、计数为 1；重置后计数为 0 |
| F02 输入与页面状态 | textarea、contenteditable、选择/勾选、隐藏/延迟/移除、多匹配、长页面 | 页面显示各控件实际值；隐藏/移除由显式按钮或测试控制，避免依赖任意 sleep |
| F03 页面与框架 | 两个本地 origin、嵌套 iframe、开放 Shadow DOM、弹窗、目标页关闭 | 每个页面/框架有唯一标记和独立计数；可核对动作究竟落到哪一页 |
| F04 控制流 | A启用、B禁用、C启用的数据集，循环计数、两个并行分支、子流程输出 | 有序遍历选出 A/C；并行比较集合、次数及先后约束，不要求不确定分支按固定总顺序完成 |
| F05 错误与重试 | HTTP/页面操作按配置前 N 次失败、后成功；故障可复位 | 请求次数由服务端计数；验证仅允许策略发生重试，其他动作没有额外执行 |
| F06 文件与大值 | 临时上传/下载文件、大文本/JSON、截图、导出目录 | 比对内容/长度/哈希；截图检查真实文件与目标页面，不仅看链接存在 |

fixture 放进现有 tests/fixtures，使用现有 pytest/Vitest/Electron 测试方式；仅有真实消费时增加辅助脚本，不建立通用测试平台。新增资产和启动命令必须在对应交付中真实存在；本表不宣称已有这些 fixture。

### 验收

- **R0-A 原版重现：** 原版执行 F01 两次，每次先重置，都得到相同回显和单次点击；记录页面状态及执行文档。
- **R0-B 范围可追踪：** 每个工作台核心入口能追到配置/执行器或明确 UI 行为，并分配 R1–R7；已排除功能没有混入核心完成率。
- **R0-C 测试可复位：** 新临时工作区和页面重置不读用户 Cookie、账号或第三方网站；上次执行不会改变下次预期。
- **R0-D 原文档基准：** 保存/导出样例包含端口、变量、分组和必要几何；记录原自动保存、覆盖、副本和运行按钮行为。

退出条件：R1 所需的原 UI/保存/运行/停止路径有可重复证据，且核心能力已有明确去向。原环境缺失导致不能复现时保留阻塞项，不伪造截图或把 mock 当原版结果。

## 5. R1：最小可编辑、可保存、可运行的正式 Studio

**用户演示：** 总览打开工作台→按原方式添加基础网页流程→保存→关闭重开→运行 F01→看到真实回显与日志→命中原断点后单步/继续→停止并关闭浏览器。

### 小批次

- **R1.1 原编辑器基础与文档。** 迁原工具栏/动作库/画布/节点/必要配置控件和编辑动作。保留原视觉；当前只启用已接通操作。定义原格式转换、持久字段投影和 OpenAPI；新增工作区仓储及增量迁移；接真实保存/打开、未保存状态和错误提示。
- **R1.2 原引擎首次运行。** 直接接原 parser/executor、必要变量解释和打开/输入/点击/提取执行器；建立受管会话 worker、Profile 参数冻结与资源锁。接最小真实日志、原“设置断点（运行到此暂停）”及 DebugBar 的继续/单步/停止，尽早验证共享浏览器方案；不另写简化顺序引擎。
- **R1.3 生命周期与入口。** 新 Studio 入口和受控连接权限；保存/放弃/取消、窗口关闭/退出/换区协调；最小命令幂等、持久事件、重连补读、工作区隔离、worker/浏览器最终回收。验证开发与构建 HTML，首次引入 worker/入口时就跑冻结和本机目录包冒烟。

暂停通过冻结版已经核实的节点断点触发，不为探路新增“从头调试先暂停”产品入口。不等 R2 完整 UI 迁入后才做 R1.2；文档接口与原控件可独立推进，运行/停止探路失败时暂停扩展大量动作。

### 必测用例

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| R1-A | 添加 F01 基础节点、改参数、连线、移动，保存重开 | 名称、参数、端口和必要位置一致；没有假保存；文件/数据库确实有文档 |
| R1-B | 运行输入 `AutoFlow测试A`、点击、提取 | 页面回显和提取值相同、提交计数 1；由原引擎执行而非测试替身 |
| R1-C | 点击节点前设原断点，命中后单步；重复提交同一命令/模拟丢响应后查询 | 每个被允许的原调度步骤只执行一次；UI 根据确认事件更新，暂停等待可被停止解除 |
| R1-D | 长网页等待中停止，再关闭会话；启动中关闭 | 后续副作用不发生；停止与浏览器关闭分别遵从原策略；最终关闭后 worker/浏览器/锁均已回收 |
| R1-E | 保存中改字段、断网保存、制造 revision 冲突、取消离开 | 当前草稿不被旧响应覆盖，不误报最新修改已保存；保存失败/冲突/取消不先关闭现场 |
| R1-F | 保存/放弃/取消分别用于新建、打开、关窗、退出、换区 | 成功保存后才清理离开；放弃按选择处理；取消保持原文档及会话；仅关主窗 Studio 仍可用 |
| R1-G | 断开事件流再接回；请求重发；刷新连接 | 持久事件按序补齐不重复；同一工作区草稿保留；不因 SSE 断线重新执行 |
| R1-H | 空库和旧数据副本升级；写入失败；换工作区 | 新功能可用，旧文档/运行/文件原文与哈希不变；失败无半份文档；换区不读错数据。迁移失败须能事务回滚或恢复已验证备份 |
| R1-I | 杀 worker/sidecar；清理失败后重试 | 不重放动作、不报假成功、不提前释放仍被占用资源；重新打开能解释中断且可以恢复可用状态 |
| R1-J | 开发、构建 HTML、冻结后端、本机目录包各跑最小闭环 | 固定正式入口加载正确；所需模块/脚本打入包，生产无需 reference/开发服务器；退出无受管残留进程 |

退出条件：R1-A–J 在当前实测平台有证据；原编辑、保存、执行、控制、清理串通。最小闭环可供用户亲自测试；全部编辑功能尚未迁完这一事实必须明确。

## 6. R2：完整原编辑体验与文档行为

**用户演示：** 导入原版复杂文档→图/模块条切换→改配置→分组、便签、复制和撤销→保存重开→导出对比。

### 小批次

- R2.1 补齐原节点配置表单、变量/表达式输入、搜索/快速添加/收藏、菜单和快捷键；完整编辑能力先按原数据模型工作，节点执行由 R3/R4 逐项接通。
- R2.2 补齐双视图、拖放/插入/排序/连线、多选、复制剪切粘贴、撤销重做、禁用、布局、组/便签和子流程编辑入口。
- R2.3 完整保存/打开、原 JSON/Markdown 等文档导入导出、自动保存、覆盖确认、副本、自定义快捷键及工作台偏好；文件到 SQLite 的映射保持原可见行为。原共享控件不等价的部分保留领域控件。代码导出、含资源/自定义模块的工作流包不算本批文档往返通过，归 R4 实现与 R8 交付验证；导出不等于已排除的发布/版本管理。

### 必测用例

- **R2-A 编辑轨迹：** 原版和新 Studio 按同一轨迹编辑同一文档；比较每个动作后的图/配置和撤销结果。覆盖输入框内快捷键，不能误删画布。
- **R2-B 双视图：** 切换后再修改、排序和切回，节点标识/端口/配置不丢、不重复，执行转换前后语义一致。
- **R2-C 分组几何：** 移动组、节点及改变尺寸，保存重开；按原算法得到相同成员/入口。覆盖显式连线和无入口位置回退。
- **R2-D 持久往返：** 原样例导入、修改、保存、重开、导出；只排除规定的宿主元数据与瞬态，不能将位置/尺寸一概忽略。
