## 实施顺序

第一项可见交付是**原工作台 UI 在正式独立窗口中工作，并能真实保存/打开**。不会先再写一套六节点表单；不会用静态截图或假接口替代原组件。

| 切片 | 实施工作 | 退出门槛 |
| --- | --- | --- |
| S0：冻结源码范围与对照样例 | 遍历 WorkflowEditor/Toolbar/ConfigPanel/Store 的 imports、服务调用和动作配置，关联最终生效执行器；将核心/排除/专项待定逐项登记；准备原版代表流程、截图及交互脚本 | 核心入口、配置和执行器有源路径；所有依赖能够解释；固定截图和文档样例可重复。静态清单不得冒充原版运行通过 |
| S1：原编辑器与真实文档 | 完整迁入原组件、Store、控件、样式、双视图及编辑工具；先落原保存 DTO 与工作区仓储，再接正式 Studio 入口；适配离开保护及鉴权 | 动作库、配置、双视图、分组便签、快捷键、复制/撤销与原版对照；保存重开字段和布局不丢；原主应用主题不受影响。尚未接通的运行能力明确标记阶段状态，不能假成功 |
| S2：原执行链路 | 迁入原模型/转换、解析器、上下文、变量、范围内执行器、控制流、错误策略及子流程；在会话 worker 中接 CloakBrowser、资源锁和真实事件 | 同一原格式流程可真实执行；分支/循环/重试/子流程的顺序与原版核对；手动打开的浏览器按原规则复用；停止、关闭、崩溃清理可核验；未知模块明确失败 |
| S3：原拾取、录制、Debug 和诊断 | 迁入原注入/采集/生成、定位工具、Debug 协议及面板；统一接入同一会话；日志、变量、结果与导出连真实数据 | 用原录制交互生成流程，关闭原浏览器后独立重放；拾取结果可执行；断点/单步/局部执行和错误检查按原行为验收；重连无重复操作或日志 |
| S4：全量对照和正式切换 | 补齐核心清单所有缺口；逐项完成视觉/交互/行为对照和已证实缺陷修复；核验旧数据备份与旧代码归档；删除被替代实现；冻结后端和正式包验收 | 核心清单无未实现项；无无效按钮；旧数据未被改写且可核对原文；正式入口只加载新 Studio；工作区/退出/清理通过。平台结果逐项记录 |

每个切片迁入原实现，不重复做需求设计。组件及原测试先迁，页面随后组合；API DTO 先核实，再生成前端类型。S0 遇到不影响核心的专项范围项单列，不阻止原编辑器迁入；不能借“裁剪”删除核心交互。

## 修改控制

1. 每个源文件记录目标文件和变更原因：路径适配、宿主边界、用户排除、缺陷修复。无原因的业务改写退回。
2. 删除排除功能的真实调用入口和依赖，不创建返回成功的 stub；通用配置及菜单代码按原结构保留。
3. 原 Store、原文档转换、原执行语义共同迁入，禁止通过现有自定义编译器“翻译”后宣称完整对齐。
4. 新前端作用域独立，主窗口继续原主题。浏览器共享范围限制在所属工作区 worker；关闭和清理责任不可丢失。
5. M1–M5 历史数据不覆盖；新增存储沿 Alembic 当前 head 增量迁移，未执行的 M6 0009 文件不进入活跃迁移链。
6. 正式迁入前归档旧 Studio 代码。完成对应替代后删除旧实现，不继续打补丁、不维持两个产品入口。先核验原数据备份，再执行涉及旧持久化路径的改动；保留主应用和其他领域。

## 验收清单与证据格式

每条核心能力记录：原源位置、原运行证据或未验证状态、迁入文件、相同操作步骤、前后文档、真实页面/日志、允许差异、平台和测试日期。至少覆盖下列组：

| 组 | 核查内容 |
| --- | --- |
| 外观与布局 | 原工具栏、动作库、节点、属性、底栏、弹窗、面板拖动及窄窗口；相同窗口下逐图对照 |
| 编排 | 图/条视图切换、拖放/连接/插入/排序、多选、复制/剪切/粘贴、快捷键、撤销重做、自动布局、禁用、分组/便签 |
| 配置与变量 | 原字段、枚举、默认值、模板/表达式、变量面板和原格式导入导出；原 UI 出现的范围内选项不能被宿主适配悄悄忽略 |
| 执行 | 网页输入/点击/表单/导航/标签页/框架/拖拽/上传下载，条件循环、子流程、错误策略和重试，实际结果及取消 |
| 拾取与录制 | 当前/新文档、iframe、重复元素、中文输入、导航尾部、勾选/选择、标签页、原版支持的录制动作及独立重放 |
| Debug 与日志 | 原断点/暂停/继续/单步/起点执行、变量追踪、日志搜索/过滤/定位、结果预览与导出、断线恢复和大量结果 |
| 宿主 | 窗口复用、主窗关闭后 Studio 使用、保存失败/冲突/取消、退出、工作区切换、服务/worker 异常、资源锁及进程树清理 |
| 数据保全与构建 | 已有 M1–M5 数据原文与历史文件保留，新 WebRPA 格式往返，生产不依赖 reference，开发/HTML/冻结后端/正式包入口一致；不要求新引擎执行旧自定义格式 |

各切片运行相应原测试和新适配测试；核心检查包括后端 pytest/Ruff/mypy，前端 Vitest/TypeScript/ESLint，OpenAPI、目录和脚本检查，renderer/main/preload 构建，PyInstaller 和 Electron 包。真实动作使用临时工作区与受控多 origin 网页，不能用 mock 证明浏览器行为。

不提供未测的时间/代码复用百分比。先完成 S1 的正式原版 UI 交付，再依据真实依赖和对照结果评估剩余工作。
