# Studio WebRPA 源码迁入实施安排

> 2026-09-13 修订：用户在清除旧 Studio 后要求制定迁入方式，并明确架构、技术栈、开发习惯贴合 AutoFlow。产品方向及工程约束 confirmed，具体实施安排 proposed。本次仅更新文档；迁入代码尚未开始。[设计规格](../specs/2026-09-13-studio-webrpa-source-migration-design.md)为行为和边界依据。

## 1. 当前基线与交付原则

- 目标代码基线：AutoFlow `25273d5`；数据库 head `0008_workflow_debug`。旧 Studio 业务代码已清除，当前只保留总览入口、独立空窗口和共享宿主基础设施。
- 源码基线：`reference/WebRPA@5ccb900e8dcf1530aae66f676d87593c416c7ebb`。reference 只读；迁入文件进入正式领域目录，记录来源和修改。
- 原完整 Studio 归档：`codex/studio-before-removal-20260913@4eda207`；未完成 M6 试验归档：`codex/m6-unfinished-checkpoint-20260913@59ae8d4`。不恢复旧 Store、节点协议、执行器或兼容引擎。
- 清除已通过工程及 macOS arm64 三种 Electron 入口验证，详见[清除记录](../../migration/studio-removal.md)。这些结果只证明清除基线，不代表 WebRPA 迁入已通过。Intel/Windows 尚未实测。
- 保留用户已有模型/UI等工作树改动和旧工作区数据；不改写历史迁移，不删除历史数据库和产物。

迁入以原产品行为为基准，工程组织遵循 AutoFlow。先迁原实现、替换真实外部边界，再对有证据的问题局部修复。不先重新设计节点、表单、控制流或调试语义。

第一项可见交付是**原工作台在正式窗口中编辑并真实保存/打开**；同一批尽早做原执行器的真实浏览器探路。不会等全部 UI 迁完才验证后端，也不把探路样例做成另一套简化执行器。

## 2. AutoFlow 工程落点

| 事项 | 实施方式与边界 |
| --- | --- |
| 前端目录 | 原组件进入 `renderer/domains/workflows/{components,hooks,pages,tests}`；领域控件和表单放在 components 下。来源由迁移清单记录，不建平行 WebRPA 应用 |
| 前端状态 | 原图操作和撤销算法保留在领域 Zustand Store；Query 管服务端数据。显式打开文档才建立草稿，重连/refetch 不覆盖编辑；同一个事实不维护两份权威状态 |
| 样式及入口 | 建议同 renderer 构建增加 studio.html；只加载原工作台样式，保留同一 main/preload/sidecar 和固定窗口校验。原控件不等价于共享控件时留在领域内，主窗口主题不改 |
| 依赖 | 沿用当前 React/TypeScript/Vite/Tailwind/Python 及锁文件版本。按调用闭包添加 React Flow、Zustand、ELK 等；不复制 package.json/requirements，不新增第二套服务器或构建系统 |
| HTTP 与事件 | 使用共享 ApiClient、鉴权、错误包、OpenAPI 类型和 HTTP/SSE；保留原服务方法/事件含义。暂停、单步等控制通过 HTTP，输入提示等反向交互逐项建命令契约；不默认增加 Socket.IO |
| 后端分层 | 纯模型/解析/规则进入 domain；调度/会话用例进入 application；页面操作/录制/拾取进入 browser provider；SQL、文件和进程进入 infrastructure；路由及事件序列化进入 adapters |
| 浏览器及生命周期 | 使用 AutoFlow Profile、CloakBrowser、代理、使用锁和进程监管。提出工作区专属会话 worker，保留原共享浏览器协作；早期实测后固定。旧 Studio 离开握手已删除，必须重新接入 |
| 数据 | 显式持久化原文档字段和必要布局，排除选中/拖拽等瞬态。新格式与旧数据隔离，沿当前 head 增量迁移；保存原子性、revision 冲突和工作区隔离由仓储/用例承担 |

原版分组/子流程用节点位置、宽高判定成员，部分入口使用 y/x 排序；这些几何必须保存并冻结到执行快照。不得套用“坐标一律是执行无关状态”的旧假设。前端 moduleType/data 与后端执行模型的转换沿用原路径，不直接序列化整个 React Flow 节点，也不翻译回废弃的 M4 控制块模型。

原 Toolbar 运行前存在 create/update 调用。S0/S1 必须实际区分执行快照提交、用户保存和脏状态的行为；不能默认沿用旧 M2 的“运行不保存”限制。

## 3. 依次交付

| 切片 | 实施工作 | 可审查交付与退出条件 |
| --- | --- | --- |
| S0：最小来源清单与行为基准 | 沿编辑器、Toolbar、Store、配置和执行器调用链登记源路径、依赖、服务和事件；核心/用户排除/专项待定逐项标记；固定原版代表文档及操作轨迹 | 同一冻结版本的截图、保存原文和代表流程可复用；第一批依赖闭包明确。静态推断和真实运行分别标注；专项争议不阻塞确定的核心。清单随切片补齐，不先做全仓重构 |
| S1：原编辑器、真实保存与执行探路 | 先归位控件/配置组件及原编辑算法；定义文档 DTO、持久化投影、仓储和增量迁移，再接正式 Studio、鉴权、保存/打开/导入导出与离开保护。同时将原 parser/executor 的真实路径接 CloakBrowser，验证事件与调试边界 | 画布/条视图、动作配置、分组便签、快捷键、复制/撤销按原操作工作；保存重开不丢配置/端口/组几何，主应用无样式污染。原引擎完成打开/输入/点击/提取，并验证暂停、单步、停止及进程清理；保存失败/取消不丢草稿。尚未接通项不标为已迁入 |
| S2：原运行能力完整接入 | 迁入范围内执行器、变量/表达式、条件/循环/并行分支、子流程、错误策略和重试；补齐宿主会话、事件持久化、大值文件、分页、资源控制和工作区隔离 | 同一原格式流程执行与原版对照；工作区单活跃运行不削减图内部能力；浏览器复用/关闭符合核实后的原选项。未知模块明确失败；停止/关闭/崩溃后无失管资源；日志和结果真实可恢复 |
| S3：原拾取、录制、Debug 与诊断 | 迁入原脚本/采集/生成及面板，复用已验证的会话/事件边界；完成动态控制、变量、页面协作、日志筛选与导出 | 原交互录制生成流程，关闭原浏览器后独立重放；拾取结果可执行；断点/单步/起点执行和失败检查按原行为验收。重连/丢响应不重复动作，输入提示/脚本结果等双向交互没有遗漏 |
| S4：完整对照与正式验收 | 补齐核心清单；固定视口截图和操作轨迹对照；处理已复现缺陷；源测试及 AutoFlow 宿主回归；开发、构建、冻结和正式包验证 | 核心项无占位/无未实现入口；原格式导入、编辑、保存、重开、录制、独立运行、Debug 闭环通过。旧数据原文保全，生产不依赖 reference；平台真实证据分别登记 |

S1 的浏览器探路是后续大量迁入的前置门槛：先验证受管 worker 中原引擎、共享页面、事件回调和暂停/停止能成立，再扩展动作。不用自写顺序运行器代替原执行器，不恢复旧 M2–M5 的产品约束。

## 4. 第一批任务和验收细化

1. **整理直接依赖与行为样例。** 对 WorkflowEditor、Toolbar、ModuleNode、ConfigPanel、双视图和工作流 Store 建立源→目标清单；记录原保存、运行、导入和导出转换。保留原参数默认值、表达式和即时编辑行为。所有核心入口对应真实执行器；不复制 globalConfigStore 中的宿主资源或凭据，但保留范围内行为设置：自动保存、覆盖/副本保存、自定义快捷键和运行后关闭浏览器等，逐项映射目标配置。文件副本到 SQLite 文档副本的名称、标识和脏状态须有明确对照。
2. **归位控件及状态。** 原基础控件/配置输入先通过交互测试，再组合动作库、画布、属性和工具栏。组件只通过领域服务调用；把 Store 内直接 socket/fetch 副作用移到边界，保留原图变更和历史算法。先用独立组件验证外观，不搭第二个原型应用。
3. **实现真实文档链路。** API 先冻结必要 DTO 和错误，再生成类型、实现 SQLite 和页面调用。文档测试覆盖节点/端口/变量/便签/组几何、导入导出及 revision 冲突。旧历史表保留原文；新旧格式明确区分；用户文档迁移前验证备份。
4. **接入正式窗口。** 独立 HTML 仍由同一次构建产生；main 只加载固定入口，preload 只开放所需能力，Studio 在已登记主 frame 下获得受控连接信息。接通保存/放弃/取消和窗口关闭/工作区切换的协调；保存失败不能先关闭会话。
5. **验证原执行路径。** 用本地受控网页运行原格式样例：打开、输入、点击、提取；在节点边界暂停/单步/停止。保留原解析/调度，验证 Profile 参数、手动打开页面复用、会话归属和清理。事件按已确认序号持久化再通知；SSE 补读去重，稳定命令 ID 防止重复单步。
6. **提交可见成果与证据。** 正式窗口截图、同一原版操作轨迹、保存原文对照、真实网页结果、worker/浏览器清理记录及工程检查组成第一批交付。仅按钮可点或 mock 测试不算完成；有未验证边界如实登记。

上述步骤按依赖先后执行；控件整理和纯后端契约可独立并行。完整 UI 大量迁入以前必须完成执行探路，不能把浏览器兼容风险集中留到 S2/S3。

## 5. 修改控制与开发习惯

- 每个能力记录源 commit/文件/许可、目标文件、修改原因和对照证据；改动原因限于路径、宿主边界、明确排除项或已复现缺陷。保留算法不等于保留反向依赖、全局状态和源码相对路径。
- 组件先于页面，契约先于联调，按垂直切片联通真实数据；不长期依赖 mock，不创建返回成功的空执行器。
- 领域间复用使用现有服务/端口；平台差异集中适配器。只有真实 IO 需要接口，不给每个纯函数建包装，不新建通用插件/RPC 框架。
- 每个任务提交单独可回退；类型/lint 问题局部修正，不降低全局 strict，不全面格式化无关源码，不混入其他领域修改。
- 执行/日志事实由后端持有；前端编辑事实由草稿 Store 持有；服务重连不破坏本地编辑。实时订阅和查询缓存明确归属，避免同一事件被两条通路重复应用。
- 原 KernelEventBroker 是覆盖式快照，不可直接用于工作流日志。保留原事件语义，增加有序持久化、补读、文件引用和分页，不再建设 Socket.IO 并行通道。
- 旧代码已完成归档和清除，不再安排重复删除，也不重建旧测试/旧引擎兼容。历史迁移不改写，旧产物不清理；迁入有新表时从实际 head 增量添加。
- 各切片更新本计划状态、来源/差异清单、验收记录和 .ai；未测标未测，不写未验证复用比例、工期或“全部成熟”。

## 6. 验收与证据

每条记录：原源位置、原运行证据或未验证状态、目标文件、相同输入/操作、前后文档、真实页面和日志、允许差异、平台及日期。

| 验收组 | 必须核查 |
| --- | --- |
| 外观 | 工具栏、动作库、节点、属性、底栏、弹窗、面板拖动和窄窗口；固定视口/缩放/字体逐图比较，保留原控件尺寸/图标/即时反馈 |
| 编辑 | 图/条切换、拖放/连线/插入/排序、多选、复制剪切粘贴、快捷键、撤销重做、自动布局、禁用、分组/便签。变量修改的原历史行为先复现后决定修复 |
| 文档 | 原默认值/变量/表达式/端口、moduleType 转换、导入导出和保存；自动保存、覆盖/副本、自定义快捷键和会话策略；组/子流程几何成员与无入口顺序；保存/运行的脏状态；并发失败后草稿保留 |
| 执行 | 范围内网页动作、表单/标签页/框架、上传下载和拖拽，条件/循环/并行/子流程、错误策略、重试和取消；相同受控页面比较真实副作用，未知类型不能静默成功 |
| 拾取与录制 | 当前/新文档、iframe、重复元素、中文输入、导航尾部、表单与标签页；原版支持动作完整列出，采集确认和独立重放真实验证 |
| 调试和数据 | 原暂停/继续/单步/断点/起点、变量和双向交互、日志搜索/筛选/定位、结果与导出；重连、响应丢失、大值、长循环和分页界限 |
| 宿主生命周期 | 重复开窗/主窗关闭、保存失败/冲突/取消、退出、换区、服务/worker异常、Profile/内核锁、停止与关闭的不同职责及最终进程清理 |
| 数据与交付 | 旧数据原文和文件保留；生产无 reference 导入；开发 URL、构建 HTML、PyInstaller、正式 Electron 入口。macOS arm64/Intel/Windows 分别标实测状态 |

每切片运行所改范围的原特征测试和新边界测试；集成完成后运行 pytest/Ruff/mypy、Vitest/TypeScript/ESLint、OpenAPI、迁移、目录/脚本检查和 renderer/main/preload 构建，再验证冻结和正式包。真实动作使用临时工作区和本地多 origin 网页，不以 mock 代替。

## 7. 本次设计核验与未验证项

已静态核对 AutoFlow 目录、状态/请求/事件、窗口权限、Profile 启动和历史迁移，以及 WebRPA 组件/Store/服务、转换、解析、执行器、共享页面、录制及 Debug 调用路径。前后端独立复核用于识别架构冲突。

本次只修改设计/计划及 .ai 记录，未增加依赖、业务 API、表或执行器；只运行文档差异和链接检查。源码复用与工程分层置信度高；受管共享会话、真实行为及平台兼容仍须通过 S1 探路和后续验收，不把静态核对记为运行通过。
