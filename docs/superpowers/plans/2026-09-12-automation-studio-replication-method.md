## 1. 方法：以行为为基线，按场景逐步迁移

严格意义上的重构保持可观察行为不变；跨项目复刻同时涉及能力取舍、运行环境替换和架构适配，因此本工作包含“选择性迁移 + 必要适配 + 局部重构”。不能把改变功能、字段或默认值隐藏在“清理代码”之下。[重构定义](https://refactoring.com/)

采用渐进现代化的原则：先确定用户结果，再切成可以独立交付的小块，逐块替换并验证。这里借用渐进方法，WebRPA 只作为隔离参考，不接入 AutoFlow 的生产调用链。[渐进现代化方法](https://martinfowler.com/bliki/StranglerFigApplication.html)

每个迁移单元重复下面的闭环：

1. **选一个用户任务。** 例如“编辑并重新打开流程”或“填写表单并读回结果”，避免以搬完某个目录作为完成目标。
2. **记录旧行为。** 找到界面、状态、配置、执行器和测试的关联；记录默认值、输入输出、超时单位、错误、资源副作用。源码推断和实机观察分别标注。
3. **确定保留与差异。** 把每项归入直接提取、保留逻辑并适配、采用现有实现、暂缓。保留选中节点的 `moduleType` 和配置语义；字段变更必须有明确原因。
4. **固定最小契约。** 只定义本场景需要的数据、命令、事件和错误；先确定后端契约再生成客户端类型。为即将到来的控制流留出明确语义，不提前实现通用插件平台。
5. **提取或适配代码。** 纯逻辑优先连同有价值的测试一起迁入；UI 复用现有组件；外部依赖集中接入已有端口。一次只改变可审查的一类问题。
6. **对照验收。** 同一份输入、同一个受控测试页，比较结果、执行路径、失败节点和资源释放；编辑行为另做交互和保存恢复检查。
7. **局部整理并收尾。** 在测试保护下改善命名、拆分职责和删除临时代码；更新迁移表和验收证据，提交一个可回退的小变更。

行为对照不要求时间戳、随机 ID、浏览器坐标逐字相同；规范化这些非业务差异后比较确定结果。旧实现的缺陷单独记录，不能因“与旧版一致”就当作正确。旧功能无法运行时标为未验证，不用静态阅读代替验收。

### 每个能力只维护一条迁移记录

| 字段 | 内容 |
| --- | --- |
| 用户任务与边界 | 用户完成什么；本批具体支持哪些参数与场景 |
| 参考证据 | 固定提交、源码位置、相关测试、实机记录 |
| 行为契约 | 输入、默认值、输出、变量处理、失败、超时、取消、副作用 |
| 迁移决定 | 提取 / 适配 / 复用 AutoFlow / 暂缓及理由 |
| 目标位置 | 已有领域、应用用例、Provider、UI 组件和契约位置 |
| 有意差异 | 改动原因、旧结果、新结果、回归用例 |
| 验收状态 | 未分析 / 已定规格 / 编辑可用 / 执行可用 / 已验收；证据路径 |

“编辑可用”与“执行可用”分开标记，节点出现在面板中不等于节点已完成。

### 已发现且不能照搬的行为

- `WorkflowEditor.tsx:41` 起引入旧 Socket.IO、远程协作和 AI UI 事件；画布并不是独立编辑器包。
- `workflowStore.ts:2970` 的撤销快照只有 nodes、edges、name，变量未进入同一快照。变量编辑是否应可撤销必须明确验收。
- `frontend/src/lib/requiredFields.ts:29` 请求失败后缓存空校验集；新系统应显示配置加载失败，避免误认为无需校验。
- `backend/app/executors/base.py:674` 与 `services/variable_manager.py:97` 对空值的处理不同；新系统需要一套确定的变量规则。
- `backend/app/services/workflow_executor.py:976` 找不到执行器时返回成功并跳过；新系统应在运行前明确拒绝未知节点，定位到节点。

上述是静态源码证据。进入相应迁移任务时补充最小复现和回归测试，不扩大成无关模块的全仓修复。

## 3. 如何兼顾前端先出效果和隐藏的执行基础

采用“编辑器先可见，真实运行紧随其后”的顺序。先做真实可编辑的前端；保存恢复交付时补最小持久化用例。随后用少量节点贯通真实执行，再扩展动作目录。执行功能尚未实现时，界面明确显示能力状态，不提供模拟成功。

下面几项必须在对应首个切片内完成，不能等数百个节点的外观都完成后再补：

| 基础问题 | 最迟在哪一步解决 | 验收结果 |
| --- | --- | --- |
| 文档、画布状态、运行状态分开 | 编辑与保存 | 流程定义和布局可恢复；选中、拖拽等瞬态不污染执行定义。 |
| 文档格式与节点配置校验 | 第一次真实保存 | 有 `schemaVersion`；非法配置能定位字段；前后端类型一致。格式版本不意味着产品版本历史。 |
| 变量类型和引用 | 第一条使用变量的流程 | 缺失、null、字符串插值、完整表达式以及列表/对象访问有确定规则。 |
| 可控制的浏览器会话 | 第一条真实执行前 | 运行能取得受控 page，节点能操作并取消；资源归属和退出清理明确。 |
| 独立运行标识及定义快照 | 第一次运行 | 每次有独立 runId；编辑文档不会改变已启动运行；日志和输出不串到另一运行。 |
| 失败、超时、取消 | 第一条真实执行 | 明确终态；停止后不继续下一节点；失败能定位节点和原因。 |
| 控制流语义 | 分支/循环进入前 | 分支出口、循环体/退出、汇合和错误边有规格，不能用普通 DAG 排序替代全部语义。 |
| 恢复与冲突 | 基础版本发布前 | 服务中断不会被显示为成功；重连恢复权威状态；保存冲突不静默覆盖。 |

当前 AutoFlow `domain/profiles/ports.py:58` 只定义测试浏览器 start/stop/statuses。`providers/browser/worker.py:29` 读取启动命令，`:99` 启动 CloakBrowser，随后等待关闭；尚无工作流节点命令通道。

因此执行阶段入口需要一次有界验证：使用已保存的配置启动受控会话，操作 page 并取消清理；据结果决定复用/扩展 worker 控制通道还是建立工作流专用执行 worker。两种方式都复用现有配置、内核、代理和凭据解析，并明确使用互斥。此时不提前承诺新的进程框架。

Profile 是可复用配置，现有测试浏览器是临时会话，不能直接当成未来持久项目环境。首个流程采用运行拥有的会话，关闭规则明确；复用用户已打开浏览器留作后续独立能力。

## 4. 实施路线与退出条件

### R0：锁定首批行为和最小设计

交付：首批迁移表、受控测试页与预期结果规格、文档/节点/运行契约草案、前端组件对应关系。

验收：

1. 每个首批节点都找到配置 UI、执行器和输入输出来源；建议第一组为 `open_page`、`input_text`、`click_element`、`wait_element`、`get_element_info`、`screenshot`，具体字段逐项核实。
2. 明确正常流程、缺失元素、停止等待、保存恢复四类场景的预期，包括具体输入、预期值、事件和超时；在执行验证前确定停止响应的验收时限，不能只写“与旧版一致”或“停止有效”。
3. 当前架构与历史草案冲突在正式规格中归一：保留现有 apps 路径、domains 结构和 Provider 边界；统一 workflows/automation 的领域命名，避免双份实现。
4. 保留原节点名称和有效配置语义；格式包络、浏览器及事件边界的变化有映射说明。不增加旧文件兼容承诺。
5. 直接提取代码的来源与许可路径有记录；不据此阻断只读分析和行为规格整理。

R0 控制在首批场景需要的范围，不进行整个 WebRPA 的完美逆向。当前本文件仅完成方法和路线，尚不代表 R0 全部完成。

### R1：正式窗口内的编辑与保存闭环

内部顺序：先加载正式 Studio renderer 并展示领域组件，再接真实流程文档与保存。首个可见增量即在现有应用独立窗口中展示。

交付：动作库、画布、节点、连线、属性面板、变量声明、基本撤销重做和真实保存打开。动作库只展示本阶段已支持配置的节点，执行可用性单独标识。

验收：

1. 从总览打开、重复点击聚焦、关闭后重开均正常；正式 Studio 通过受控能力访问同一个 sidecar。
2. 新建流程，添加/移动/删除节点，连接/删除连线，修改参数，撤销/重做后数据符合规格。
3. 保存后关闭并重启应用，节点、参数、变量和布局恢复；保存失败可见，未保存内容不能静默丢失。
4. 画布转换成自有文档后保存，执行图不依赖 React Flow 内部对象；布局作为编辑信息单独序列化。
5. 实际数据库/仓储完成保存恢复，客户端类型由 OpenAPI 生成；没有硬编码“保存成功”或模拟运行。
6. 基础组件复用当前 shared UI，页面只组合领域组件；组件交互、契约、持久化和真实窗口验收通过。

这一阶段补充的后端仅服务文档和目录的真实闭环，不提前铺设全套执行引擎。

### R2：第一条真实浏览器执行链

入口：完成前述浏览器控制验证。交付流程：使用已保存的浏览器配置 → 打开本地测试页 → 输入 → 点击 → 等待结果 → 提取文本 → 截图。

验收：

1. 真正启动受控 CloakBrowser，页面收到输入并产生预期结果；日志与截图对应本次 runId。
2. 同一流程连续执行两次，变量、节点状态和产物归属隔离；运行取不可变定义快照。
3. 元素缺失触发超时，显示具体节点、错误和终态，不继续后续点击。
4. 等待中停止能中断执行，没有后续节点动作，也没有遗留运行任务或归属本次运行的浏览器进程；正常完成与失败同样验证清理。
5. 未知节点、不可用节点和非法配置在运行前拒绝；浏览器未安装或配置不可用有明确原因。
6. 节点目录、配置 schema 与执行器登记一一对应，重复类型直接失败。UI、执行事件和持久化运行摘要有契约测试。

R2 通过后再估算后续节点迁移成本；不能把第一个节点的工作量直接乘以静态节点总数。

### R3：确定的控制流与基础调试

内部顺序：变量/条件 → 有限循环与错误处理 → 断点、暂停、继续、单步。暂以串行执行为基础。

验收：

1. true/false 两条路径、0 次/多次循环、退出及汇合各有固定样例；非法环明确拒绝，合法控制流不死锁。
2. 变量类型、空值、引用以及循环作用域按规格验证；运行值不会写回为文档默认值。
3. 失败、显式错误边、超时和取消有确定优先关系；点击等有副作用的节点不增加未经定义的自动重试。
4. 断点能停在定义的位置，单步只推进预期节点；暂停或循环内部停止也会释放资源。
5. 节点状态与日志按 runId、nodeId 和顺序显示，不靠前端定时猜测运行进度。

### R4：面向实际网页的能力扩展

按真实场景逐批交付：元素拾取、iframe、标签页、上传下载，再评估子流程和录制。先有稳定的选择器、节点配置与执行语义，录制器才生成这些已有节点。

验收：

1. 拾取目标与执行目标一致，iframe/标签切换后上下文明确；关闭页面后有可解释错误。
2. 上传下载完成条件、产物归属和取消处理可验证，不用固定睡眠假设文件已就绪。
3. 子流程若入选，输入输出、局部变量、错误和停止传播有测试，父子运行可定位。
4. 录制若入选，录制产物保存后可重放，参数仍可编辑；不只验证录制日志有内容。
5. 每个新节点同时交付配置、校验、执行、输出、失败与取消用例，不能只扩充面板数量。

### R5：基础版本的恢复、平台和清理验收

交付：真实应用发布验证、恢复规则、源头对应记录、迁移临时代码清理。

验收：

1. 服务中断、窗口关闭重开、应用重启后的文档与运行状态明确；前端重连向后端核对权威状态。
2. 保存冲突或不支持的文档版本显式提示，不静默覆盖、清空或降级；不引入产品级版本历史。
3. 在 Windows/macOS 分别验证正式应用、sidecar、CloakBrowser 的打开、执行、停止和退出；记录实际验证平台，未测平台明确标为未验证。
4. 在干净工作副本中排除 reference 目录仍能构建运行；安装包不依赖旧 WebRPA 服务、旧路径或整套依赖清单。
5. 迁移表的“已验收”都有证据；删除无用适配、模拟行为和重复职责；运行匹配范围的测试、lint、类型检查及构建。

高级能力按需求继续使用同一迁移闭环。已有计划排除的市场、WebDAV、工作流版本历史等不会自动回到范围内；其他候选先记录价值与依赖，再决定是否实施。

## 5. 架构落位和 AI 工作约束

- 前端沿用 `apps/desktop/src/renderer/domains`，共享控件继续位于 `renderer/shared/components/ui`，API 客户端和生成类型位于 `renderer/shared/api`。当前 `packages/ui` 是骨架，不为本任务迁移整个组件体系。
- 后端沿用 `apps/backend/src/autoflow`：`adapters → application → domain`；`providers/infrastructure` 实现端口，`bootstrap` 装配。HTTP、ORM、浏览器 SDK 不进入纯领域规则。
- 浏览器动作在工作流执行所需的受控上下文中调用 Provider；节点不能各自启动浏览器、读取全局凭据或新建旧管理器。
- 文档状态、编辑器瞬态和运行状态职责分开；按已出现的职责拆文件，不用预设文件数量或行数证明架构质量。
- 单一节点定义提供配置和端口依据；特殊节点允许专用属性组件，不首版开发万能表单设计器或动态插件框架。
- 每次给 AI 的任务包含：一个场景、源文件与提交、目标路径、保留字段、允许差异、验收用例、相关检查。不得仅给“把这个项目重构得干净一点”。
- 先生成或补充行为证据再改实现；复刻、缺陷修复、局部重构在差异记录及提交中可区分，避免同时改语义、协议和界面后无法定位问题。
- 只并行互不抢占契约的任务；节点与运行契约由同一基线管理。完成后用独立审查检查行为遗漏、旧依赖残留、状态和资源归属。
- “成熟”以保存可靠、执行可解释、失败可定位、停止有效、状态隔离、可独立打包和改动可回归衡量；减少代码量本身不算验收。
