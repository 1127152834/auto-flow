# PM9 自动化删除清理实施计划

日期：2026-09-23。状态：proposed，未批准业务实现。
规格：`docs/superpowers/specs/2026-09-23-pm9-automation-delete-cleanup.md`。

1. **AD1 持久删除接受与阻断**：在现有ProjectOperation保存冻结Run目标；复用自动化仓库/项目生命周期提交门禁，补自动化启动与编辑竞争、终态批次但人工/环境未结束反例；更新影响与OpenAPI必要字段、删除对话框状态测试。保持同一执行核心和操作账本。
2. **AD2 文件清理与恢复**：扩展现有生命周期pending/advance处理原删除操作；平台适配器仅清理有归属的Run目录，失败留下可恢复事实。测试部分文件已删、剩余持锁、进程退出、重复原键/原操作、重启自动恢复；确认保留环境与独立文档不动。失败不擦除恢复目标，不扫旧孤儿。
3. **AD3 真实包与证据**：扩充现有桌面smoke，真实worker人工继续后浏览器失败生成PNG，确认HTTP摘要与真实目录；UI接受删除后故障/恢复，验证只删目标并保持同一operation。运行相关后端/前端/脚本/静态检查；候选稳定后完整回归和一次三平台流水线。更新AU-08/相关执行门禁的具体断言，不能整体升verified。

等待确认时：继续本轮已获授权的终态人工记录数据库清理、直接安全阻断、现有回归和PR记录；不先实现AD1的持久删除状态协议。
