## 2. 配色：模块识别与运行状态分开

以下数值是候选设计值，不是已批准 token。

| 角色 | 前景色 | 浅底色 | 使用位置 |
| --- | --- | --- | --- |
| 品牌 / 主操作 | `#8D4E2F` | `#F2E3D7` | 主按钮、全局活动标记、重点动作 |
| 浏览器模块 | `#476B91` | `#EAF0F7` | 浏览器图标底板、模块摘要 |
| 代理模块 | `#31756F` | `#E6F1EE` | 网络/代理图标底板、模块摘要 |
| 模型模块 | `#75618A` | `#F0EBF5` | 模型图标底板、模块摘要 |
| 正文 / 次级文字 | `#34322E` / `#625E57` | `#FBFAF7` | 保持可读的正文与说明 |

- 画布试验从 `#F1EEE7` 小幅调到 `#F3F1EC`，减轻黄感；surface 继续使用 `#FBFAF7`，先在样张对比。
- 绝大多数表面保持中性。辅助色集中在小面积图标、局部浅底和分类标记，避免整页彩色卡片或每个字段一种颜色。
- 全局主按钮保持品牌棕。模块色不接管按钮体系，导航选中也继续有统一的品牌标记。
- 首轮的 success/warning/danger 继续表达真实运行状态；模块颜色不用于表示健康、错误或权限。图标形状与文字同时承担识别。
- 供应商品牌保持原素材，不统一染成模块紫色。
- 普通卡片用低对比边界；输入、焦点等需要识别的边界保留足够强度，不因追求柔和全部淡化。

静态 sRGB 色对计算：白字/品牌棕 6.44:1，浏览器前景/浅底 4.84:1，代理前景/浅底 4.66:1，模型前景/浅底 4.67:1，正文/surface 12.26:1，次级文字/surface 6.18:1。实际叠色、hover、透明度和焦点背景仍需单独验证，以上不是整屏合规结论。

## 3. 图标：三种明确职责

### 日常操作图标

复用 Phosphor，不新增第二套图库。搜索、添加、编辑、复制、关闭、更多等使用 regular；常规大小16/18px，点击区域沿用32/40px。图标按钮保留可访问名称，纯装饰图标不重复朗读。

### 导航与模块图标

- 导航建议20px，模块图标24px；仅模块入口使用 duotone，搭配40px浅色底板。
- 区分浏览器窗口、浏览器内核、代理出口、代理组、供应商连接、模型资源的图形语义。
- 同一动作和资源在各页使用同一个图标；不靠增加细节让16px图标变得难读。
- Phosphor 原生支持 regular、fill、duotone 等 weight 与 size，无需自建图标引擎。[官方说明](https://github.com/phosphor-icons/react)

### 生图资产

建议只试验3–4张空态小插画：浏览器配置、代理连接、模型资源，必要时增加筛选无结果。使用低饱和、轻微体积感的哑光双色风格，与界面模块色对应，实际展示约72–96px。

资产流程：

1. 根据真实空态组件的插槽尺寸先生成1张风格样本，检查缩小后是否仍清楚。
2. 风格成立后生成透明背景2×2小批量图集，统一视角、光源、材质与视觉重量；不嵌文字、不生成品牌 Logo。
3. 四个格子明确分隔，物体及阴影不跨格。按格切分后检查 alpha 边界，统一画布与安全留白，按视觉大小校准，避免每张机械放大到顶边。
4. 检查真透明通道、棋盘格是否误画进像素、白边、裁切和浅/深测试背景下的边缘；若单个图形不合格，独立补图。
5. 输出独立透明 PNG 或 WebP；只在实际空态加载。生产不依赖整张图集裁切坐标。

可选资产预算目标：4张合计不超过约400KB，按质量实测调整；此为目标，尚无生成结果。功能图标始终使用现有SVG，不用小尺寸位图替换。

## 4. 圆角、留白与字体

| 项目 | 建议规则 | 对首轮的变化 |
| --- | --- | --- |
| 控件圆角 | 10px | 从8px小幅柔化 |
| 卡片圆角 | 16px | 从12px增加，但列表行不套卡片 |
| 弹窗圆角 | 20px | 从16px增加，内部仍按统一间距对齐 |
| 普通小标签 / 状态胶囊 | 6px / full | 以用途区分，不让所有按钮都变胶囊 |
| 默认控件 / 紧凑操作 | 40px / 32px | 复用首轮，无新增密度设置 |
| 页面主边距 | 常规32px，窄窗口24/16px | 统一响应规则，不压缩数据内容 |
| 卡片 / 弹窗内边距 | 卡片20px，弹窗24px，密集数据区16px | 依据组件职责分配 |
| 字段间距 / 分组间距 | 16px / 24px | 沿用并落实首轮token |
| 标签到控件 / 图标到文字 | 8px / 8px | 统一基线与视觉间隔 |
| 页面标题 | 24/32px，600 | 首先消除24与30px混用 |
| 区块标题 | 16/24px，600 | 标题靠大小与字重建立层级 |
| 正文与控件文字 | 14/20px，400–500 | 中文长说明允许22px行高 |
| 辅助文字 | 12/18px | 不用于关键字段或错误主信息 |
| 数字与标识 | 数量tabular-nums；ID/路径用现有等宽栈 | 普通中文不用等宽字体 |

系统字体优先补齐 macOS 的 `-apple-system` / `PingFang SC` 与 Windows 的 `Segoe UI Variable` / `Microsoft YaHei UI` 回退。不假定仅在 font-family 中写 Inter 就已经安装该字体；第一版不额外下载整套中文字体。

表格、长表单保持紧凑：不要把所有间距和行高同比放大。普通卡片减弱阴影，弹窗和浮层维持明确层级。避免卡片套卡片、边框与重阴影同时叠加。

## 5. 交互与工具取舍

首轮已实现CSS动效及减少动效偏好；本轮沿用协议，优先调整反馈质量。

| 场景 | 建议 |
| --- | --- |
| 按钮hover/active | 100–120ms颜色与边界反馈；保留位置和尺寸稳定 |
| Switch、选中标记 | 约120ms，立即反映真实状态 |
| 菜单、弹窗 | 150–180ms淡入与4–8px轻位移；保持焦点、Escape和锁定规则 |
| Drawer | 约180ms水平小位移；避免继承普通弹窗的纵向进入效果 |
| 可点击的入口卡片 | 轻背景变化，必要时至多1–2px位移；只读统计卡不伪装可点击 |
| 数据刷新 | 保留已显示内容及操作位置，不让表格整页淡出或数字无意义滚动 |

复杂度预算：第二轮首版不新增运行时动效依赖，不新增滚动劫持、持续装饰动画或常驻3D画布。

- **CSS / 现有组件：采用。** 足够覆盖本轮按钮、图标、浮层与选择反馈。
- **GSAP：暂不引入。** 它适合需要时间线或多元素编排的场景；当前候选效果没有这类需求。若未来确有复杂流程演示，再按需评估。[官方文档](https://gsap.com/docs/v3/)
- **Three.js：暂不引入。** 当前没有可操作的3D内容需求；体积感插画可以作为静态资产交付。[官方手册](https://threejs.org/manual/)
- **Remotion：留给产品演示视频。** 官方工作流面向程序化视频创作；目前没有视频产物需求。[官方文档](https://www.remotion.dev/docs/)

## 7. 验证方式与范围控制

实施后按该基线现有脚本执行 `npm test`、`npm run typecheck`、`npm run lint`、`npm run build`，并沿用现有控件/UI检查入口。执行前核对实际package脚本，不杜撰命令。

视觉核对覆盖：

- 1440×900、1280×800、1024×768窗口；100%、125%、200%缩放。
- 浏览器卡片、模型长ID表格、代理列表、供应商选择、长表单、确认弹窗与嵌套弹层。
- 正常、空态、搜索无结果、loading、错误、选中、focus、disabled、read-only。
- 图标光学大小、文字对齐、焦点可见、按钮文案不换行、图片透明边缘与减少动效。
- 新资产的真实体积、首屏加载影响；动画不在空闲时持续工作。

新增测试只验证新增或受影响的行为，不为每个颜色和圆角写className断言。静态视觉使用同尺寸、同状态的前后截图对照。Windows字体与系统缩放须在对应环境验收，不能由macOS截图替代。

本轮不改变：页面信息架构、供应商左栏、模型编辑双栏、既有向导/确认/保存/测试语义、后端与API、工作区数据。自动化Studio尚未作为本轮页面交付，只在后续接入时复用定稿组件。不新增暗色主题开关、密度设置或视频/3D功能。

## 8. 主要风险与下一步

- 最大工程风险是首轮分支与主目录尚未统一，应先锁定实施基线。
- 辅助色过量会削弱操作与状态层级，应限制使用面积和语义。
- 更大圆角/留白可能降低信息密度，需先用卡片与表格两个样板验证。
- 批量生图可能出现透明度、风格与视觉尺寸不一致，必须先样本后小批量，不以生成成功替代资产验收。

下一步：评审此方向；确认后先完成组件样张和一张空态资产样本，再实施共享层与代表页面。
