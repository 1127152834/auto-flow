# M2B Task 10：最小节点输出契约（R2-29 / AC2-17）

- 日期：2026-10-03；状态：confirmed（本机 Windows 验证）
- 规格：[M2 规格](../specs/2026-09-30-remediation-m2-business-model-reliability.md) R2-29

## 做了什么

- 输出声明 `domain/workflows/outputs.py`：节点类型的输出 = 执行器真实读取的"变量名"字段（取自 R2-11 推导的读取键），
  带显示名、敏感性（Cookie/页面存储为敏感）、可用性（循环变量只在循环体内）。随执行器 schema 导出给 Studio（`outputs`）。
- 稳定引用 `{node.<节点ID>.<输出键>}`：运行时按节点当前配置的变量名取值，改节点名或改变量名都不失效；
  敏感变量经该引用读取仍按敏感处理；引用已删除节点或未命名输出时预检拒绝 `NODE_OUTPUT_REFERENCE_INVALID`，
  项目运行把该原因原样返回（不再统一成"工作流包含不可执行的节点"，其他预检问题也带上原因）。
- 编辑器 `lib/nodeOutputs.ts`：成功路径支配分析——所有到达路径都经过产出节点成功点才算"必有"；
  分支汇合、循环零次、错误分支上的输出标为"可能为空"。变量选择器按稳定引用插入，显示名称而非内部标识，
  插入时若来源节点未命名变量则写入默认名。旧 `{变量}` 写法保留到 M6。

## 验证

- 后端 `tests/unit/workflows/test_node_outputs.py`：声明来源、引用检查、改名后仍取值、删除节点预检原因。
- 前端 `tests/node-outputs.test.ts`：分支汇合、零次循环、错误分支、改名稳定、选择器插入。

## 不做

- 表达式函数库、旧节点批量转换（M6）。
