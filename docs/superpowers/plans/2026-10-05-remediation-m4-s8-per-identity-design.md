# M4 S8：perIdentity 会话设计

- 日期：2026-10-05；状态：superseded（第 2–4 条被 [2026-10-06 决定](../../../.ai/decisions/2026-10-06-m4-s8-per-identity-v1-keep-instance.md) 取代：v1 保留实例、不保留浏览器；其余条目仍有效）
- 规格：[M4 规格](../specs/2026-09-30-remediation-m4-identity.md) R4-12、AC4-07

## 为什么单独设计

perIdentity 要求同一身份连续多个任务复用同一个浏览器并保留登录状态。现状是每个任务从环境版本恢复一份独立工作副本，
任务结束时保存或清理；浏览器开着时不能复制其目录（会得到撕裂的登录状态，`runtime_lock_present` 也会拒绝）。
因此复用必须改变"环境实例"的生命周期，牵涉实例状态机、占用、End 保存时机与崩溃恢复，属于架构级改动。

## 设计

1. **范围**：`runPolicy.sessionMode = "perIdentity"` 仅允许与环境来源 `inputIdentity` 组合；其他组合保存与启动时拒绝。
2. **身份工作副本**：同一身份第一次运行时照常预约实例并恢复版本；任务结束后实例不关闭，转为"身份保留"状态，
   持有者从任务改为身份（占用表 `holder_kind = "identity"`），同一身份的后续任务直接附着该实例，不再恢复。
3. **worker 复用**：复用 M3 worker 池，复用键为 `identity:<identityId>:<instanceId>`；worker 保留持久上下文。
   每个任务开始前：关闭多余页面、`clear_permissions()`、清空 sessionStorage；凭据、变量、回调按运行重建（与 M3 相同）。
   Cookie、localStorage、IndexedDB 属于登录状态，按设计保留。
4. **保存时机**：End 的"保存登录状态"在 perIdentity 下记为"待回收时保存"；worker 回收（空闲 120 秒、跑满 50 次、
   服务关闭、撤权以外的正常回收）时先关闭浏览器，再把实例保存为该身份环境的新版本，然后关闭实例。
5. **独占**：身份保留实例期间，其他批次的同身份行等待（领取门禁按身份占用判断），跨批次独占。
6. **失败与撤权**：撤权、结果未知、worker 崩溃 → 不归还、不保存；实例进入现有"待核实"流程，由原命令核实后解锁；
   未保存的登录变化丢弃（保留上一次保存的版本）。
7. **临时身份种子**：pool + 任务级新种子在 CloakBrowser 中是进程级参数，无法在隔离上下文切换 → 明确回退 perTask（M3 已如此）。

## 测试（AC4-07）

- 同身份连续 3 行复用同一 worker 与实例，登录 Cookie 保留；第 2 行看不到第 1 行注入的凭据、变量和授予的权限。
- 两个批次同身份：第二批次等待第一批次释放。
- 回收时保存：保存的新版本包含复用期间的登录变化；撤权/崩溃时不保存且实例进入待核实。
- 服务重启后身份保留实例按原规则核实，不被误当作空闲复用。
