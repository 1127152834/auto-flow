# M3 吞吐与性能 设计规格

- 日期：2026-09-30；状态：proposed，待用户审批
- 总纲：[整改里程碑总纲](2026-09-30-remediation-roadmap.md)；对应整改方案 B2、C3、C5（完整形态）、D2、E1、E2、E3、E4
- 前置：M2 已合并（台账表参与领取筛选）
- 实施计划：[M3 实施计划](../plans/2026-09-30-remediation-m3-throughput.md)（任务级）

## 1. 结论

M3 把规模从"几十行"推到"万级稳定"：领取变成索引查询，普通日志不再逐条同步提交，worker 进程和浏览器会话可以复用，登录环境只保存必要数据并定期清理。

## 2. 背景（M0 基线与评审实测）

- 1 万行表单次领取 2.0–2.6 秒；领取在线程中执行后主循环最大延迟仍约 130 毫秒（M1 原型实测，来自 GIL）。
- G4 每节点 5 个事件，每个事件一次同步提交（WAL 前 p50 4.1 毫秒，WAL 后约 1.4 毫秒），即每节点约 7–20 毫秒框架开销。
- 每个任务新起 Python 进程（启动超时 90 秒）和浏览器。
- 环境恢复与保存整目录复制、全量 SHA-256，没有清理旧代次。

## 3. 目标与非目标

**目标**：E4 性能预算全部达标（见第 6 节）。

**非目标**：身份与代理粘性（M4）；执行栈合并（M6）；分布式或多机执行。

## 4. 需求

| 编号 | 需求 |
| --- | --- |
| R3-01 | 领取 SQL 下推：业务状态、台账 state、next_eligible_at 为索引列；用户勾选"用于筛选 / 排序"的字段生成 SQLite 生成列（`json_extract`）并建索引。筛选表达式翻译为 WHERE；无法下推的条件在自动化预检中提示"此条件会导致全表扫描"。 |
| R3-02 | 候选预取：一次查询取 并发数 × 4 条候选，逐条用条件插入抢占租约；租约表对 `lease_key` 建部分唯一索引（仅活动租约），冲突即跳过下一条。租约判断改为索引查询，不再加载全库租约。 |
| R3-03 | 单一数据库写线程：`DatabaseWriter`（一个线程 + 队列）承载所有写事务；读用 `asyncio.to_thread`。运行事件提交、领取、台账、调度器状态写入都经过它。 |
| R3-04 | 事件分级：状态事件（数据写回、环境保存、End、人工检查点、运行终态、产物登记）保持同步提交与 ACK；过程事件（节点开始 / 结束、普通日志、变量变化、进度）由 worker 缓冲，每 200 毫秒或 100 条批量发送，主服务批量写入，不阻塞执行。过程事件带序号，崩溃最多丢最后一批。 |
| R3-05 | 大量日志存为按运行分文件的 JSONL，数据库只存索引与摘要；按保留天数清理（默认 14 天，可配置）。 |
| R3-06 | worker 进程池：大小 = 存活浏览器上限；任务结束后 worker 清理状态回池，执行 N（默认 50）个任务或 RSS 超过阈值后回收重建。执行代次与撤权机制不变。worker 输入改为事件驱动（去掉 10 毫秒轮询）。 |
| R3-07 | 会话模式（自动化运行设置 `sessionMode`）：`perTask`（默认，隔离最强）、`perIdentity`（同一身份连续多行复用浏览器，只关标签页）、`pool`（多个长期浏览器轮流接任务，任务间清 Cookie 与存储，只允许无登录采集）。 |
| R3-08 | 多批次公平调度：批次优先级（高 / 普通 / 低），同优先级按轮转分配名额；每个批次可设自己的并发上限。 |
| R3-09 | 环境存储瘦身：复制与保存跳过缓存目录（Cache、Code Cache、GPUCache、ShaderCache、GrShaderCache、Service Worker/CacheStorage、component_crx_cache 等，列表集中维护，可按环境覆盖）；摘要改为"路径 + 大小 + 修改时间"清单哈希，仅对 Cookies、Local Storage、IndexedDB、Preferences 做内容哈希；macOS 用 clonefile、Windows ReFS 用块克隆，否则增量同步。 |
| R3-10 | 每个环境保留最近 3 个代次，后台任务清理更旧代次与孤儿候选目录；设置页显示环境与产物占用的磁盘空间。 |

## 5. 设计要点

- 生成列通过 Alembic 迁移按字段动态创建时需要重建表：改为在独立的 `record_index` 表中维护"record_key → 已索引字段值"（写记录时同步更新），避免对大表做 ALTER；筛选下推查询 JOIN 这张表。取舍记录进 ADR。
- 事件分级需要修改 worker 协议（`protocolVersion: 2`）：新增 `eventBatch` 消息；主服务对 v1 worker 保持兼容一个版本。
- 会话复用下，浏览器生命周期与任务解耦：`WorkflowBrowserResources` 增加"租借 / 归还"语义；执行代次撤权时强制关闭该浏览器而不是归还。
- 性能验证全部通过 M0 基准扩展：`bench_claims` 加 100,000 行；新增 `bench_first_node_latency`（领取到首节点开始）。

## 6. 验收标准（E4 预算）

| 编号 | 验收 |
| --- | --- |
| AC3-01 | 领取一个任务（100,000 行表）< 20 毫秒（bench_claims，CI macOS）。 |
| AC3-02 | 领取期间及 G2 全程主循环延迟 p99 < 50 毫秒。 |
| AC3-03 | G4 框架开销 < 5 毫秒 / 节点（含事件持久化）。 |
| AC3-04 | 从领取到首节点开始：池中有空闲 worker、新浏览器 < 3 秒；复用会话 < 300 毫秒。 |
| AC3-05 | G2（8 核 16GB，pool 模式）吞吐 ≥ M0 基线 5 倍。 |
| AC3-06 | 一个典型已登录环境的恢复 + 保存 < 2 秒；100 次运行后环境总占用 ≤ 单个环境大小 × 4。 |
| AC3-07 | 并发 1,000 次领取（随机筛选、随机并发）的随机化测试：不重复、不遗漏、不死循环。 |
| AC3-08 | 崩溃注入：worker 在批量发送前被杀，丢失的只有最后一批过程事件，所有状态事件完整。 |

## 7. 风险

| 风险 | 应对 |
| --- | --- |
| 排除缓存导致个别网站登录失效 | 排除列表可按环境覆盖；M4 的 G1 验证登录保持 |
| 会话复用串数据 | pool 模式只允许无登录采集；每任务结束执行清理并校验 Cookie 为空 |
| 写线程成为瓶颈 | 批量写入；监控队列长度，超过阈值记警告 |
| 协议升级 | v1/v2 共存一个版本；契约测试覆盖两种 |
