# PM9 W1–W3：项目 Studio 会话与展示切换

日期：2026-09-23。状态：proposed，未批准实现。来源：项目设计 XE-G01/XE-G07、原 Studio R9、2026-09-13 WebRPA 迁入规格和当前632caf6d源码。只补项目实际消费的宿主能力，不接入全部 Studio 节点。

## 已确认现状与范围冲突

- `StudioWindowController` 只拥有一个独立 BrowserWindow，支持复用、最小化恢复和离开保护。主进程/预载 `openAutomationStudio()` 无参数；项目自动化详情没有打开指定工作流入口。没有 automation/session 关联或 presentationMode 协议。
- 旧 `docs/automation-studio/PLAN.md` 第3.2节要求 window/docked、同一automation唯一会话；2026-09-13迁入规格要求独立正式窗口和未保存保护，旧自定义Studio行为不自动算必须回归。项目XE-G07仍引用旧R7/R9，不能用此冲突把停靠标成“只有实机证据缺失”。
- 本机打包新断言已证明现有单窗口复用、越权打开拒绝、关闭取消/保存、显式重新打开文档和Run不重复。它们不证明项目关联、自动会话恢复、运行中两个页面一致或停靠。

本附录提出把项目消费的会话关联、项目Run展示和停靠/弹出作为W1→W2→W3三个明确切片；需用户确认该范围与新迁入架构的衔接。其他Studio能力继续由Studio计划负责。

## W1：打开项目自动化的现有文档

沿用单Studio约束：同一目标重复打开只聚焦；切换到另一个自动化先执行既有离开确认。不同自动化不同时开启多个编辑器。默认无目标调用继续打开独立Studio。

扩展既有IPC请求为可选目标 `{projectId, automationId, workflowId}`，主进程将请求绑定当前workspace partition及sidecar instance。服务端项目自动化读取结果为关联关系权威；UUID格式校验与查询失败必须显式拒绝。渲染器提交的workflowId不构成项目权限，不允许越权打开、归档项目启动、删除后沿旧关联继续写入。

控制器保存一个短期会话记录 `{sessionId, workspaceIdentity, serviceInstanceId, target, navigationRevision, presentationMode}`，复用当前单窗口所有权与离开请求机制，不引入执行器或第二套运行事实。打开请求/确认携sessionId和navigationRevision，迟到确认不能覆盖新目标。renderer读取现有文档服务、校验目标仍有效，再按既有import流程载入；失败保留原草稿并向Manager返回原因，只有载入确认后才展示为该目标。

Manager管理草稿未保存时，复用现有保存/放弃/取消保护；未获得明确结果不能打开另一版自动化配置。管理资料与工作流分别保存，不能互相覆盖。

项目自动化详情增加“编辑工作流”；会话抬头显示所属项目和自动化，保留返回Manager入口。现有revision条件保存保持不变，保存不改已冻结批次。project-owned workflow的创建/删除所有权另见AU-08，不凭“从项目打开”把独立文档变成项目所有。

## W2：双窗口消费同一个项目运行

项目绑定会话不能把带项目节点的文档交给独立 `/api/workflows/*/execute`。复用现有自动化运行配置、批次接受/查询和Task接口，从自动化管理修订创建冻结批次；权限继续由服务端根据Task和项目事实注入。未保存编辑先保存成功、再读取最新自动化/工作流修订，失败或竞争不发起运行。

一次显式启动保留原操作键和operationId，未知响应沿原键查询，不能换键重试。两个窗口都读取同一batchId/taskId/runId和持久事件游标；复用现有项目任务证据/人工处理组件和客户端，不把项目Run转写成独立运行记录。不把历史Run日志归到后来编辑的图上，节点定位核对冻结文档身份。

项目Task属于后台项目协调器，关闭Studio只解除展示订阅，不套用独立运行的停止资源释放；独立Studio仍保留其原有离开策略。已有批次、人工等待、取消及End继续由现有project runtime负责；关Studio或切换展示不得启动新Run、重放节点或改变人工恢复协议。停止/人工继续使用原命令、检查点和操作恢复语义；主机重启后只显示服务端恢复事实，不恢复浏览器执行栈。

## W3：停靠/弹出与状态交接

复用同一Studio组件、preload能力和后端；不新增iframe、BrowserView执行器或第二窗口状态服务。主进程仍控制唯一会话及展示所有权，presentationMode仅属于桌面壳，不写入工作流领域。

切换顺序：锁定目标与代次→既有离开/资源协调→未保存文档明确保存成功或取消切换→冻结必要编辑展示快照→装载目标展示→目标确认正确session/文档/服务身份→释放原展示。目标失败/超时保留或恢复原展示；没有确认就不得销毁唯一可用编辑器。双重切换合并原请求，旧确认/旧窗口消息被拒。

展示快照只包含文档修订、viewport、选中节点、展开面板及经过验证的编辑历史等必需字段，不复制完整React store、后端令牌、浏览器句柄或运行栈。Manager/Studio运行事实仍通过HTTP/事件读取。全局样式必须保持隔离，先验证迁入CSS与Manager同文档共存；无法保证时该片保持未开放，不能用两个同时可编辑窗口冒充停靠。

关闭/重开恢复的是明确已保存文档与会话目标；程序崩溃后不承诺恢复未提交草稿。工作区切换/归档/删除要先完成会话关闭或返回具体阻断；不能把短期会话记录当成持久后端锁。正在运行的Task继续由现有生命周期门禁处理。

## 验收与退出

每片均包含契约、组件/主进程检查和真实Electron/HTTP/worker证据。至少核验重复打开、切换目标中取消、保存冲突、过期目标/确认、恶意renderer/subframe、跨工作区响应、保存响应丢失、同一Run两窗口日志与人工状态、失败目标装载回退、连续停靠/弹出不丢选择/历史且不重放任务。

Windows x64、macOS Intel、Apple Silicon各自运行CI；物理窗口、原生面板/凭据、安装与签名另列待验，不由本机ARM抵扣。现有主目录并行Studio工作保持只读；该附录批准后仍只在PM9分支实施并更新草稿PR。未闭合W1–W3与其余退出条件前，XE-G07最多partial、releaseAccepted=false。
