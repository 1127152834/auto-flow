## 1. 目标与范围

浏览器配置是模板。工作流基于模板创建独立环境实例，执行和后续修改作用于实例；更改模板不能改变已有实例。打开网页节点负责声明实例来源及新实例的模板、代理、内核，删除 Studio 顶部“运行浏览器配置”下拉框。

环境页去除右侧全部概览卡片；项目默认设置提供真实编辑入口，作为新建实例的默认值。保留现有项目权限、运行占用、资源准入、显式保存和停止清理规则。

本轮实例属性编辑只扩展代理和内核，不扩展所有指纹属性编辑。内核继续使用已安装且符合现有授权的 CloakBrowser edition/version，不接入其他浏览器。实例不是常驻进程：关闭浏览器不等于删除保存的实例。

## 2. 当前事实与方案选择

- `ProjectDefaultsPanel.tsx` 只展示默认值，提示去项目资料编辑；`ProjectFormDialog.tsx` 和 `projects/form-schema.ts` 实际仅支持名称、描述。
- `Toolbar.tsx` 在执行前调用 `browserApi.resolveProfile()`，将顶部选择的 `profileId` 作为执行请求字段。删除控件而保留此依赖会导致不能运行或继续隐式使用旧选择。
- `OpenPageConfig` 只有网址、打开方式、等待条件；`OpenPageExecutor` 要求已经存在的浏览器。
- dispatcher 先取得浏览器资源，worker 的 `launch_workflow_session` 在 Runtime 执行节点前启动浏览器。节点设置必须进入真实资源/启动链。
- 已保存环境恢复仍有读取当前 Profile 的路径。既有 I1–I3 身份规格记录了身份漂移反例，本方案沿用其身份包方向，不把该缺陷当作已经修复。

选择：复用现有环境服务、资源快照、worker 命令通道和 Runtime，把新工作流的浏览器启动延迟到需要初始化环境的打开网页节点。

不采用“只移动控件、继续全局提前启动”：条件分支中未执行的节点会错误决定实际启动配置。不新增第二执行器或独立浏览器管理系统：已有服务负责占用、工作副本、保存与清理。

## 3. 节点行为

在原有导航配置前增加“环境来源”。导航的 `openMode` 仍仅表示新标签页/当前标签页，与是否创建实例互相独立。

| 来源 | 展示与执行 |
| --- | --- |
| 使用当前实例 | 不显示模板、代理、内核覆盖项，只导航。没有当前实例时明确报错并定位节点，不偷偷选择模板。 |
| 基于模板新建实例 | 展示模板、代理、内核三项；创建独立工作实例后启动浏览器并导航。后续节点使用该实例。 |
| 使用已有环境 | 选择当前项目中的固定环境，或现有声明输入所关联的环境；使用环境自身身份与配置，不重新套模板。 |

新插入节点：已有明确初始化节点时默认“使用当前实例”；没有时默认“基于模板新建实例”。此 UI 默认只是编辑便利，不代替分支路径的运行校验。

新建实例三项：

- 模板：明确选择或使用项目默认模板；无可用值时显示必填错误。
- 代理：使用项目默认值、使用模板代理、不使用代理、指定代理或现有代理池。复用现有代理引用与凭据边界，不在节点存密码。
- 内核：使用模板内核，或指定已安装的 CloakBrowser 内核。没有可用内核时阻止启动并给出安装入口，不自动替换版本。

本切片每个 Task 保持一个活动浏览器实例，不引入多个命名浏览器或隐式切换。已有活动实例时，再执行新建/加载另一环境的节点明确报配置错误，保留当前实例；不得自动关闭、丢弃或覆盖当前登录状态。循环反复打开网页应使用当前实例。后续若要同一 Task 先后创建多个环境，需要独立的显式结束/切换设计，不在本次暗中加入。

## 4. 默认值、实例编辑与保存

环境页去掉右侧 aside，两张卡片对应测试更新为不存在；主内容使用原有布局组件扩展。

“项目默认资源”改为可编辑的“新建环境默认设置”，提供默认模板、代理及保存按钮。模板显示实际名称；无效、删除、未安装的引用明确展示错误。默认内核来自所选模板，本轮不增加第四处内核选择器。模型提供方既有数据原样保留，不因本次表单保存丢失。

新建时，节点明确指定值优先；节点选择使用项目默认值时解析项目配置；最终使用模板值或明确的无代理策略。解析结果在准备执行时冻结，运行中编辑项目默认值或模板不改变已经准备的 Run。

已有环境始终使用自身配置。项目默认代理不能覆盖它；“使用模板代理”在创建时复制模板的代理策略，恢复时不再次读模板。代理池继续使用既有分配策略，保存池引用不代表固定某个 IP。

环境管理的实例编辑仅提供代理、内核。本轮仅允许实例无活动占用时提交；运行中展示当前值及“关闭浏览器后修改”，不做热切换。编辑需带期望修订，并在提交时重新检查占用、项目归属、内核和资源引用。新设置在下一次启动生效，不反写模板。

工作流创建的是临时工作实例，默认不自动成为永久保存环境。继续沿用 End 的明确保存/另存及环境与记录关联流程；失败、取消不自动覆盖原环境。环境管理中对已保存实例的显式配置保存与工作流 End 保存互不混淆，参与相同的版本冲突保护。

## 5. 持久身份与旧环境

复用 `2026-09-24-pm9-persistent-environment-identity.md` 的版本化身份包：模板快照、seed、实际内核与实例内容同代次保存。worker 和人工维护使用相同权威身份组装规则。代理保存策略引用，凭据按现有受控服务读取；不将秘密写入节点、快照、日志或列表 API。

显式修改内核允许改变该实例的启动内核；必须保留 Cookie/目录，不自动降级或抹除数据。若既有兼容校验不能证明该内核可打开原目录，则拒绝原地修改并说明原因，不把“可选内核”解释为所有版本都能无损切换。

旧环境缺少可靠身份包时，不能拿当前模板猜历史身份。沿用 I1–I3 的“身份资料缺失，无法恢复”，保留目录和数据；只有可证明完整同代次来源的记录才可回填。这是需要审阅的兼容行为，不宣称旧环境已全部支持独立属性。

## 6. 执行契约与兼容

建议节点新增版本化 `browserEnvironment` 配置，来源枚举为 `current`、`newFromProfile`、`fixedEnvironment`、`inputEnvironment`。配置采用已有 Profile、代理、KernelRef、声明输入引用类型，服务端拒绝不适用来源的额外覆盖字段。精确 DTO 在实施计划中沿现有类型确定，不创建另一套通用资源协议。

准备执行冻结节点引用的模板、代理策略、内核及项目默认值；服务端验证归属、授权和引用。动态输入环境仍按现有 Task 领取规则固定具体环境/内容代次，不能由 renderer 任意传目录或其他项目的环境身份。

执行初始化节点时，宿主通过现有受控 worker 命令通道取得/预约资源并记录 Run、执行代次、节点执行身份与实例；worker 按宿主授权启动。节点负责声明，不能自行读取宿主凭据、任意启动进程或绕过容量/占用锁。新协议字段和幂等键必须覆盖命令响应丢失、停止竞争和清理确认；导航重试复用本次已经创建的实例，不重复创建。

初始化命令成功、但导航失败时，实例仍属于同一 Run 的受控资源，按原失败/人工处理/清理规则保留或释放。未进入的分支不启动浏览器。并行分支争用同一个当前实例时不得悄悄串用页面或创建两个实例；沿已有准入检查拒绝不能证明隔离的组合，不扩大并行浏览器能力。

Studio 删除顶部选择器，但保留运行、停止、录制、拾取和调试操作。独立录制/拾取选择明确的节点配置或已打开实例；无上下文时要求先选择初始化节点，不能悄悄回退到全局旧选择。从中间节点开始调试若无实例，显示缺少浏览器上下文；“从入口运行到此处”正常执行上游初始化。

旧文档缺少 `browserEnvironment` 时保留旧执行契约，不能仅因打开/保存文档就改写图。项目自动化原有的显式资源策略继续支持旧文档；新的节点配置文档由节点控制，自动化资源页说明其来源并停止提供冲突的覆盖控件。新旧模式由持久化文档版本区分，不能依赖 renderer 是否传旧 `profileId` 猜测。

旧独立 Studio 文档只保存在本机偏好中的顶部选择不是可靠持久配置。迁移提供明确的“把原浏览器选择写入初始化节点”操作，并先展示影响；多个入口/分支不自动猜测。未完成迁移时可保存、导出，执行提示到节点补齐配置，不恢复顶部下拉框。旧 PreparedContent/已接收 Run 继续使用其冻结资源，不重新解释为新协议。

## 7. 验收条件与实施切片边界

1. 独立身份：模板 A 创建 E，E 修改代理/内核不改变 A；A 后续编辑/重置 seed 不改变 E 的恢复参数；任务和人工维护均覆盖。身份缺失旧环境不破坏目录。
2. 项目设置：真实 API 保存、刷新仍在；默认值只影响以后准备的新实例；已有环境不受影响；修订冲突、只读项目、失效引用正确反馈。
3. 节点闭环：Studio 保存三个属性并往返读取；真实 worker 在初始化节点才启动；后续打开网页保留登录状态；未进入分支不启动；第二次初始化不覆盖当前实例。
4. 生命周期：启动响应丢失不重复建实例，导航失败后停止无泄漏，停止与启动竞争不产生脱管进程；End 保存/关联修复沿用原操作，不重复保存。
5. 一致入口：Studio 运行、从中间调试、录制/拾取、项目自动化使用相同资源规则；无浏览器的流程不强制选择模板。
6. 兼容：旧文档不自动改写；显式迁移有明确目标；旧 Run 资源不变；新文档不能被旧自动化默认资源覆盖。

建议依赖顺序：A 独立身份及实例代理/内核编辑；B 项目默认设置和环境布局；C 节点契约、受控延迟启动和真实 worker；D Studio/自动化/调试入口切换及旧文档迁移。每片包含后端、组件、针对性验证和记录，C 的运行能力就绪后再删除顶部选择器。
