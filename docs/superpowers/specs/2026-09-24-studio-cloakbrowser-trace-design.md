## 1. 已核实事实与边界

本机 Python CloakBrowser 为 0.5.9。现有 workflow_session 使用 launch_context_async / launch_persistent_context_async，已有 CDP 读取进程身份；未在该会话入口发现正式 Trace 采集。小助手已有 application/workflows/assistant.py 与 providers/assistant/langgraph.py，底部 LogPanel 已有日志、数据、变量、图片页签。现有产物和运行事件基础设施继续复用。

CloakBrowser 官方提供兼容 Playwright 的浏览器接口；Trace 的基础来自 Playwright BrowserContext，不是确认存在的 CloakBrowser 专属“全量 JS 记录器”。本机 Playwright tracing 接口已有 screenshots、snapshots、sources、start_chunk/stop_chunk。

- Trace 能记录浏览器操作和网络活动、DOM 快照与截图；`sources=True` 是操作对应的源文件，不能解释为“所有网页 JS 源码”。
- 网页脚本源码需要单独采集：记录加载资源，评估 CDP scriptParsed/getScriptSource 补充内联及动态脚本；按实际协议版本验证。
- 控制台、JS 异常/堆栈、页面与框架生命周期需要结构化事件，不能仅交付一个 ZIP。
- 不承诺每一条 JS 指令、所有函数调用、全部堆内存、服务器内部状态。CPU 采样也不是完整执行记录。
- 缓存、Service Worker、跨进程 iframe、Worker、页面过早关闭、资源驱逐等可能造成缺口；必须显式记录覆盖状态。不得事后重新请求网页资源并伪称运行现场。
- 浏览器操作时间相邻不等于因果关系。后台网络/脚本事件没有可靠归属时标为“页面后台事件”，不能强行挂在当前节点上。

## 2. 产品入口与采集模式

在运行菜单中提供“追踪设置”，和工作流保存；启动时冻结到本次运行，之后编辑不影响当前运行。

| 模式 | 用途与采集 |
| --- | --- |
| 标准追踪（普通运行建议默认） | 节点执行与浏览器动作、页面/框架、快照、网络、控制台、JS 异常；不承诺所有脚本源码 |
| 增强追踪（Debug 建议默认） | 标准内容＋实际可取得的网页 JS 源码及资源正文、可用的堆栈与来源关联；显示对性能和采集覆盖的实际影响 |
| 关闭 | 保留现有运行日志；Trace 面板明确显示本次未开启，不允许“补录此前现场” |

模式是待批准的产品默认值，不是本轮变更生产配置。运行前展示采集范围和本地产物预算。容量阈值需通过真实典型页面测量后确定，不能凭设计图宣布无开销/无限容量。

采集在受管浏览器 context 建立后、首次工作流导航前开始；关闭时在 context 关闭前尽力完成归档，所有成功/失败/停止路径都经过统一收尾。纯数据工作流显示“本次未启动浏览器”。对浏览器启动之前的动作只提供运行日志。

运行状态和证据状态分别展示：例如“运行失败 / 追踪已保存”，绝不能用绿色“已完成”掩盖执行失败；归档失败也不能被视为成功保存。默认不因可选 Trace 写盘失败而重试或重放网页动作；显式诊断节点的失败走现有节点错误策略。

## 3. 新增节点提案

先在“浏览器诊断”中增加以下三个入口，不把所有启动配置变成动作节点。

| 节点 | 参数 | 行为与输出 |
| --- | --- | --- |
| trace_mark：Trace 标记 | 名称、可选说明、可选业务关联值 | 给本次执行写标记；继承已有变量插值规则，敏感变量脱敏；标记可搜索和定位，返回标记引用 |
| capture_diagnostics：采集诊断快照 | 名称、页面/框架目标、截图/DOM/控制台片段等勾选项 | 捕获当前时点证据，复用页面和 framePath；不执行目标页面操作；返回诊断包引用及各项成功/缺失状态 |
| save_trace_segment：保存追踪片段 | 片段名称、可选起始标记、输出变量 | 保存已采集的指定区间并返回产物引用；不关闭采集，不清空全程证据，不直接把大量内容写入变量 |

没有开始/结束节点也有全程 Trace。追踪关闭时 trace_mark 可作为运行标记保存；capture_diagnostics 只生成当前快照；save_trace_segment 明确失败 TRACE_NOT_ENABLED，不能伪造此前记录。起始标记不存在时报具体字段错误。

循环内每次标记/快照独立，使用执行标识区分；标记重复名称时必须按当前运行中显式选定的标记实例解析，配置“最近一次同名标记”时清楚显示该规则。切片可重叠，底层共享内容对象，不能互相截断。分块边界不是用户可见的丢失区间。

其他 CloakBrowser 能力归类：指纹、语言、时区、代理、GeoIP、人类行为模拟等启动策略继续归主应用 Profile；节点可读取本次冻结的非敏感环境摘要，不直接修改全局 Profile。页面/网络/存储类操作先对照已有节点，缺口逐项确认后再扩展，不能凭 SDK 函数名批量注册重复节点。环境摘要节点仅候选，不列入本次三节点交付范围。

## 4. 底部 Trace 面板

在“图像资源”后加入“Trace 追踪”，复用底部面板收起、拖动调高及展开能力。默认展开约占窗口 45%–55%，具体依视觉稿选择；窄窗口改为列表→详情切换，不挤出三列微型界面。

### 4.1 公共工具栏

运行选择器和执行日志共享所选 runId；切换标签保留同一运行和筛选上下文。展示采集模式、运行状态、采集/归档状态和覆盖缺口。主要操作“交给小助手分析”，次要操作“导出”，容量/保留设置放更多菜单。

状态包括：未开启、等待浏览器、采集中、归档中、已保存、部分证据、采集失败、文件已不存在。SSE 断线显示连接状态未知，不将其当作采集失败；恢复按序号补读。停止调度和完成 ZIP 归档分别呈现进度。

### 4.2 同一套数据的三个布局候选

1. 时间线排查：顶部时间轴/缩略图；左侧事件，右侧快照与细节；适合排查跳转、异步请求和页面变化。
2. 节点执行复盘：左侧按调用/循环轮次展开的执行树；右侧执行前后对照及证据标签；适合复杂流程与重复节点。
3. 问题证据聚合：左侧按失败位置聚合的事实列表，右侧小助手解释及证据引用；保留“查看全部事件”入口；适合快速诊断，不让 AI 摘要替代原始证据。

三图只是同一功能范围的视觉候选，不代表三套独立系统，也不增加同时开发三种视图的要求。最终选择一种主布局，保留必要的筛选与证据钻取。

### 4.3 证据详情

| 标签 | 展示与交互 |
| --- | --- |
| 页面 | 执行前/动作时/执行后可用快照、页面URL与frame路径、截图；历史页面只读；不重新执行JS或发送请求 |
| 网络 | 方法、脱敏URL、状态、耗时、发起来源；点开头部/正文；大正文按需读；未采集正文显式标明 |
| 控制台 | 等级、消息、页面/框架、时间、来源行号；展开安全序列化内容；JS异常独立可筛选 |
| JS源码 | 实际采集的资源列表、URL/内容哈希、来源类型、关联堆栈；只读行号视图；无源码时解释原因，不伪造source map |
| 执行详情 | 节点配置快照、实际选择器、framePath、动作耗时、调用与循环轮次、脱敏变量变化引用 |

日志“查看 Trace”跳到对应 executionId；Trace“定位节点”只有当前文档语义与运行快照一致时才定位草稿，否则打开/展示只读运行快照，不错指已编辑节点。多次执行的同一 nodeId 不能合并成一条结果。

对实时事件与已归档快照区分：运行中先展示结构化事件和已完成分块；未形成可读快照的区间显示“等待归档”，不声称 ZIP 原生具备本项目实时查看能力。

## 5. 小助手怎样使用 Trace

复用主应用模型管理与实际 LangGraph 编排，新增受控、只读证据工具，而不是把整个 ZIP、DOM 或JS直接塞入提示词。

建议的工具合同（正式命名在实现前与现有工具注册统一）：
- get_trace_summary(runId)：状态、覆盖范围、失败执行、页/框架摘要和证据统计。
- query_trace_events(runId, executionId/timeRange/type, cursor, limit)：有界分页，返回稳定证据ID和摘要。
- read_trace_evidence(runId, evidenceId, offset/limit)：读取指定来源的源码行、正文片段或安全快照资源；严格验证所属运行/项目。

诊断顺序固定为：确认本次 runId/文档快照 → 找失败执行与前置事件 → 读取必要页面/网络/JS → 区分已证实事实、推测和缺失证据 → 提出修复。输出示例：“请求返回401【网络#48】；随后等待#dashboard超时【执行#12】。可能为会话失效；尚无证据判断凭据本身是否错误。”不能从401直接断言密码错误。

每条引用可点回 Trace 的具体事件或源码行。分析面板显示正在读取的证据类型和当前范围，支持取消。新的运行或工作区到来后，旧结果只归属于原运行，不覆盖新选择。

分析不会自动重跑网页动作、改 Profile 或保存工作流。应用修复沿用现有批准、差异预览及一次撤销；对历史/快照不一致的草稿先比对。网页内容/脚本注释均作为非可信证据，不成为小助手新指令。

本地原始证据与发送给模型的诊断包分开：沿用现有秘密过滤，额外处理Authorization/Cookie/敏感请求参数与输入值。截图/DOM不能保证自动彻底脱敏，发送前展示证据范围、模型去向及可排除内容。不能暗中上传整份原始Trace；License/代理凭据不进入证据包。

## 6. 最小工程接入

- domain/application/workflows：诊断配置、节点参数、事件关联、运行生命周期，原执行器不重写。
- providers/browser：同一个受管context上的 tracing、事件监听及经实测的CDP补充采集；页面/框架/Worker要登记能力与缺口，不新增其他浏览器。
- infrastructure/filesystem + database：原始Trace、内容寻址资源、版本化manifest和证据索引；复用现有产物身份/权限，诊断不混入用户提取结果计数。迁移仅增量，不改用户旧数据。
- process：大文件走产物引用，命令与SSE只传摘要/ID；每个运行独立目录与采集器，支持PM9并发，禁止全局单例占用别的运行。
- HTTP：沿用当前运行资源和鉴权，拟增 Trace 摘要、事件分页、单证据读取与导出入口；来源为Standalone或Project时沿用现有归属解析，不能靠可猜runId访问其他项目。
- 前端：TracePanel 消费同一运行选择和事件边界，分页/虚拟列表；列表滚动、面板高度不进入工作流撤销历史；模式配置和三个节点配置进入文档保存。

索引至少包含 runId、traceId、seq、context/page/frame身份、documentGeneration、nodeId、executionId、调用/循环路径、wallTime和monotonicTime、证据种类、内容引用及覆盖状态。browser actionId 与 executionId 显式关联；后台事件只标时间窗口关系。归档格式记录CloakBrowser/Playwright/内核版本，读取适配器按版本处理，不把未稳定的 trace.zip 内部格式当永久公共合同。

本地Viewer复用Playwright已有能力优先评估；嵌入时使用隔离renderer/禁用Node、严格本地资源路由，不让页面快照脚本和外部链接主动访问网络。没有离线安全快照适配前，先展示安全静态截图与文本，不能用未经隔离的HTML注入替代。

## 7. 收尾、恢复、容量

- 普通停止：取消动作→有限时间归档→关闭浏览器/worker→释放锁；归档超时显示partial，不能无限阻止退出。原失败原因不被归档异常覆盖。
- Debug暂停仍可能发生网页活动，继续采集；人工浏览行为需标为人工/未归属，不伪造成节点操作。failed_paused保留现场时持续状态明确。
- 崩溃：已完成分块可读；未完成尾块标partial，不自动恢复执行/重放。清理仅当前运行拥有的进程。
- 磁盘不足/超过预算：明确采集降级或停止、记录最后seq与缺失区间；禁止静默截断后仍标“完整”。预算默认值由首批性能实测确定。
- 内容按哈希去重，大值按需读取；导出固定截止seq，归档中的任务不能导出成看似完整的ZIP。缺失文件报可理解的错误。
- 不在本轮设计中擅自开启用户历史数据自动删除。保留/清理由既有产物管理扩展，显式显示被清理后不可再诊断的范围。
