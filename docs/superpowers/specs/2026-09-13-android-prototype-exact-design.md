## 7. R4：工作流占用与暂停接管

TAKE-01：设备头有“已就绪 / 工作流占用 / 临时实例”，右侧更多和“打开设备”；四标签不变。标签下整行浅棕锁提示：“工作流正在操作设备，当前为只读预览。”

TAKE-02：左面板“只读预览”、查看画面下拉、全屏、手机画面；返回/主页/最近任务工具为明显禁用，截图可用；底注“取得控制权后才能点击、输入或安装应用。”。页脚为“画面连接正常·输入已锁定”。触控、键盘、安装都必须由后端租约拒绝，不能只禁按钮。

TAKE-03：右面板“当前工作流”：工作流名称、运行标识、运行状态、当前步骤与进度条、相邻步骤时间线。使用runId/executionId/loopPath关联本次执行；循环中不把nodeId早前成功当成本轮完成。直线示例显示3/6；动态循环总量未知时真实显示已执行次数/当前轮，不能编造百分比。

TAKE-04：“手动接管”保持原图说明“暂停成功后，设备才交给你操作。”、“当前步骤结束后暂停。”、满宽棕按钮“暂停并接管”和“保持只读”。点击后先进入请求中，当前动作完成、设备命令无在途、worker确认暂停后才给人工输入；请求期间不许立刻点画面。

TAKE-05：若暂停发生在最后一步，必须停在完成后处理之前。当前动作超时/结果不明不能授予输入，保留失败/待核实；停止优先于接管与继续。人工期间保持原运行和设备绑定、暂停自动清理；恢复时显示“结束接管并继续”，收回人工输入、确认连接交接、再从边界继续，不重复前一步。

TAKE-06：右下“完成后处理”、灰标签“临时实例·自动清理”、说明“手动接管时暂缓回收。”。回收失败显示待处理，不能先隐藏卡片；持久实例只释放占用，保留应用与数据。保持只读不产生控制权变更。

本项是对显式android_manual节点的补充，复用已有M4调度与M5边界闸门能力，不把浏览器debug page对象强塞到安卓provider，也不另做第二个执行引擎。普通安卓运行也需可请求安全边界暂停，不能要求用户重写流程插入人工节点才实现原型按钮。

## 8. R3：创建实例规格

CREATE-01：面包屑“返回资源看板 / 创建实例”；标题和副标题逐图；左三组编号表单、右创建预览，底部固定动作栏。分组标题精确为“基本信息 / 环境配置 / 数据与启动”。

CREATE-02：实例名称与数量同一行；数量有减号、数字输入、加号，默认3（R3验收状态）；输入下方“将创建：测试设备01、02、03”。生产创建页初始数量同样设为3；用户可减为1，资源不足时明确排队/容量提示，不自动改数量。名称后缀与数量变化即时更新；服务端分配唯一ID，禁止同批名称歧义。初始批次上限建议20，服务端声明真实上限，超过时原位报错；这不代表同时能启动20台。

CREATE-03：选择“环境配置”，不是裸Docker镜像列表；右侧“管理配置”。说明条含软件渲染、尺寸、shell root结果、应用root需单独验证。分辨率在下行。“更多设置·语言与时区”展开对应两字段；CPU/内存归环境模板，不改成占用原位置的CPU/内存折叠标题。

CREATE-04：并列“持久实例 / 临时实例”单选卡，选中描边、棕色单选点、解释文本按图。临时实例受任务清理策略约束，不能只换一个标签。绿色“创建后启动”开关，旁注“启动完成且Android就绪后才可操作。”。

CREATE-05：右侧创建预览包含与图一致的手机缩略图、数量、系统、分辨率、数据策略；分隔后运行环境：Mac本机、已连接、当前配置兼容、资源限制说明。兼容、容量不足、未连接必须由真实能力判断，不能恒定绿勾。

CREATE-06：底栏左取消，右进度去向提示、将创建3台持久实例、创建并启动。关掉启动则按钮“创建实例”。提交后回看板逐台显示进度；每台独立卷，部分失败不抹掉已成功设备；可只重试失败项/取消尚未开始项。相同批次编号重试不生成第二批。

临时实例生命周期：手动批量创建的临时实例未分配前不得因为页面离开而删除；绑定运行后按显式策略回收。建议默认运行成功后自动清理，失败/中断保留待检查，用户可在环境/分配策略中选择终态后清理。进入人工接管一律冻结回收。原型“完成后自动清理”显示策略概述，详情明确触发条件。

## 9. 四图以外的必要内容

以下是让可见入口可用的支撑设计，不声称有对应原图。实施前先做与四图组件一致的局部样例，不能随意新增产品导航。

- 应用标签：真实安装应用列表、图标/名称/包名/版本，上传APK和启动；沿用右侧应用区组件。安装前校验大小/文件类型、后端固定命令，不做任意shell入口。MVP不含原图未要求的卸载或应用商店。
- 环境配置：模板列表和编辑表单，镜像固定摘要、系统/架构、显示、CPU/内存、渲染、语言/时区、清理策略；已有设备保留配置快照，修改模板只影响新实例。root分shell/application两项，值unknown/checking/available/unavailable/error及探测时间；模板级结果不能冒充某实例级结果。
- 运行记录：按deviceId后端分页，定位本次运行，复用既有日志与产物索引；不能先分页全局历史再在前端过滤而漏记录。
- 分配/删除/失败详情弹窗：复用项目Dialog和表单组件，宽度、标题、按钮密度与原图一致。若涉及不可逆删除，明确资源和数据范围。
- 列表、空态、加载、断线、空间不足、无兼容镜像、无已保存工作流、应用无启动入口、等待容量、清理失败均有组件样例和真实失败路径。

## 10. 数据模型与接口契约草案

这是待实施的契约，不表示现有API已支持。沿用正式鉴权、本地服务与OpenAPI生成客户端。路由名称可在契约评审中调整，但交互语义不能减少。

| 对象 | 核心数据/不变量 |
| --- | --- |
| EnvironmentProfile | id、revision、name、imageDigest、Android/arch、display、resources、locale/timezone、cleanupPolicy、capabilityEvidence |
| AndroidDevice | 既有身份/归属 + profile快照、persistent/temporary、readiness、owner、lastFrameAt、cleanup状态 |
| CreationBatch | batchId、不可变请求摘要、预分配deviceIds、每项状态/错误/回执；已成功项不重建 |
| AllocationRequest | requestId、workflow快照、环境要求、选择策略/指定设备、queue状态、runId、完成后策略 |
| DeviceLease | deviceId、ownerKind/ownerId、generation、sessionId、inputEndpoint、state；同设备单写入者 |
| ControlSession | sessionId、viewerId、generation、只读/可输入、frame尺寸/方向/代次、连接状态；旧消息无权影响新会话 |

| 接口组 | 操作/语义 |
| --- | --- |
| 现有 /android/environment、/devices | 保留，扩展能力与列表投影，兼容已有单台创建与操作回执 |
| /android/environment-profiles | 查询/新增/修改模板，revision冲突，受控探测 |
| /android/creation-batches | POST返回202批次状态；GET进度；取消未开始项/重试明确失败项 |
| /android/allocations | POST接受任务，GET等待列表/详情，取消；指定或自动选设备 |
| /android/devices/{id}/control-sessions | 请求手动控制、连接只读、结束/切换输入端；命令要带会话与代次 |
| /android/control-sessions/{id}/commands | 固定键/手势/文本等控制命令；输入超时只返回未知，不自动重发 |
| 画面通道 | 受控的本地实时帧通道，绑定会话、鉴权、尺寸/方向时间戳；具体传输由技术验证定稿 |
| /android/devices/{id}/apps | 应用列表/前台应用、multipart安装、受控启动；与设备操作冲突时409 |
| 工作流run控制 | 请求边界接管/查询/结束接管并继续；沿用runId与逐次执行标识，和M5命令规范统一 |
| /android/devices/{id}/runs | 设备级历史分页，复用运行/产物查询 |

错误契约：无兼容环境、资源不足、设备忙、过期租约、画面尺寸变化、未知命令结果、安装失败、启动超时、传输中断、回收失败分别可识别。重复管理命令回读原回执；点击/文本等未知副作用不自动重放。API验权与origin检查涵盖实时通道；凭据不写URL查询参数或日志。

## 11. 执行、并行、画面与安全交接

### 11.1 最小必要架构变化

现有全局active_slot和单个AndroidRuntime会话不支持原图两台同时工作。实施必须改为按设备运行/会话上下文，并以数据库约束和安装级设备锁保持跨工作区独占；只给单例套一层字典但保留全局互斥不算完成。VM创建/预算检查用短时串行锁，不能整个运行期间锁住所有设备。

安卓至少验收两台设备同时工作，一台接管不影响另一台。保留浏览器原有运行预算和M5语义，不顺手扩成浏览器无限并行。待运行队列复用现有SQLite与应用生命周期，不新增Redis/Celery或跨主机调度服务。资源预算区分已运行、已预留、等待；不因一次批量请求同时启动超预算容器。

### 11.2 实时画面技术门槛

当前10秒截图只适合静态预览，不能支撑R2触控和“实时画面”。实施先验证从现有Android运行时获取连续编码画面、在Electron受控区域显示、与真实尺寸和输入通道同步的路径。优先复用已固定版本的本机运行组件，若需新解码/桥接依赖，先记录版本、许可证、Mac打包结果再定稿，不在规格中虚构某个scrcpy内嵌API已经存在。

建议验收目标（proposed，需实测）：720×1280单设备连续画面至少15fps，点击到可见反馈p95≤250ms，两路只读预览+一路人工控制稳定10分钟。记录软件渲染下实测值。若达不到，属于未通过项，不能退回每10秒截图仍标“实时”。后台小缩略图可降频，当前控制台不能降成静态截图。中文输入须包含中文、ASCII、换行、特殊字符；不能把ADB基础text命令当作Unicode支持证明。

### 11.3 状态与恢复

设备状态与控制权分开：offline/starting/ready/stopped/error；none/workflow/manual/transition/recovery；持久/临时另存类型。每次控制权交接递增generation，服务器校验设备、运行、会话和代次。暂停成功不是仅UI变色，而是worker边界确认且旧输入排空。

崩溃/失联后不盲目释放设备或清理临时数据，先核实旧进程/命令/卷归属；无法确认进入待恢复。UI刷新重连读取原会话，不创建新运行或重播手势。只有明确结束控制/恢复工作流/清理完成才改变所有权。动作结果未知时停止进一步输入并保留证据。

## 12. 双重验收门槛

### 12.1 原型还原门槛 V

必须建立四个专用确定性测试场景：R1六台原图状态+两条等待任务；R2手动控制、笔记画面和文本；R3数量3/持久/已连接；R4订单回归第3/6步和只读接管。固定时间、字体、屏幕素材和动画采样；这些样本只用于独立测试入口，不进入正常资源API。

1. 同尺寸同状态截图，先提交原图/实现并排，再提交50%透明叠图与差异图；不得以不同设备数量/不同页面状态对照。
2. 每个编号控件和静态文案100%覆盖，不增删主要区块、不换列名、不用说明卡替代操作区。
3. 拟定几何容差：主区块边界≤4原图像素，重复控件高度/间距≤2，字体基线/行数匹配，素材无拉伸和缺失。容差是栅格对齐标准，不是允许自由重设计。
4. 动态文字只在真实设备回归中允许变化；视觉fixture中不屏蔽主要文字、卡片、工具条或整块手机。原生OS标题栏可单独排除，产品导航不可排除。
5. `design-qa.md` 对R1–R4分别记录reference、实际截图、视口、状态、差异、修复；遗漏原型区块属于P1，位置/样式偏差属于P2，全部解决后才可passed。图像算法分数只辅助，人工叠图检查必须完成。
6. 缺数据、缺素材或捕获失败写blocked；绝不根据pytest/构建成功判视觉通过。当前状态是not started，历史passed不继承。

### 12.2 真实功能门槛 F

- 批量创建3台并逐台查询；容器/卷独立；重复批次不重复资源；部分失败和取消可核验。
- 指定停止设备时进入等待启动，Android真就绪后才跑；两台兼容空闲设备分别承接任务并发执行，同设备争抢仅一个成功。
- 手动点击/滑动/长按/键盘/中文发送/导航键/音量/旋转/截图/APK安装与启动，在Mac正式包逐项实测。
- R4自动运行时输入拒绝；动作结束后才接管；接管期间另一个设备继续运行；手动结束后不重播步骤；最后一步接管不能触发提前回收。
- 临时实例成功终态按策略清理且核实卷已删除；持久实例保留；失败/中断/人工接管均按明确策略处理；清理失败留可恢复卡。
- 页面与原生输入端互斥、断线旧请求拒绝、停止与继续竞争、应用退出和工作区切换安全；迁移保留旧M4/M5运行与安卓设备数据。
- Python/React/OpenAPI/lint/typecheck/构建及M4/M5回归通过。Windows、root应用授权、摄像头等未实测能力如实标记，不借用其他镜像测试结论。

完整交付要求V与F同时通过。只完成静态还原是中间检查点，不能宣布整个模块完成。
