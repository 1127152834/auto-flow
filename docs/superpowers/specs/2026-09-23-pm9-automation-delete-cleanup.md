# PM9 自动化删除的持久清理

日期：2026-09-23。状态：proposed，待确认新增删除恢复契约。
依据：AU-08、PM8-A2 删除影响；当前5346ceca ARM真实打包反例见 `docs/project-management/implementation/pm9/automation-deletion-follow-through.json`。已确认删除成功后任务所属人工事项和实际失败截图残留。人工事项数据库清理及未结束事项阻断是本轮有界修复；本方案只扩展文件清理与删除命令恢复，不引入执行器或工作流所有权转移。

## 当前缺陷和目标

自动化删除目前同步删除自己的批次/Task/Run/事件/产物登记，但仓库没有运行目录入口。截图在 `AppPaths.workspace/runs/<runId>/generation-<n>/`，删除数据库后无法再按批次证明目录归属。不能靠扫描全部孤儿目录、删除共享环境或重新运行工作流来补救。

目标：用户确认的同一个删除命令持久记录本自动化实际拥有的Run；在删除这些Run目录、数据库事实和自动化后才成功。独立Studio文档、其他自动化/项目内容、项目数据和已保存环境保留。历史无归属孤儿不自动清扫。

## 契约

- HTTP DELETE输入保持impactRevision、expectedManagementRevision和unlink。仍拒绝无法证明所有权的deleteOwned。
- 同一SQLite写事务重新校验项目状态、自动化版本与完整影响，登记现有ProjectOperation的deleteAutomation命令及冻结Run标识，返回202和原operationId。内部清理数据只含稳定ID，不公开文件系统路径或凭据。
- 清理中的自动化只读。自动化编辑、批次启动、再次关联及项目生命周期操作在各自提交边界检查同一持久删除事实；返回明确占用信息，不只依赖页面禁用。
- 复用现有生命周期轮询/恢复入口推进deleteAutomation，不增加第二个后台执行系统。进程重启后继续推进未结束原命令；重复DELETE原键只查询/推动同一命令，不重新删除另一份内容。
- 阻断范围必须包括目标批次、目标Run真实状态、目标人工事项，以及关联临时环境的活动/保存/清理事实。saved_unlinked或retained_unsaved仍有可执行补救时不能先抹去所需运行事实；用户先按既有环境动作完成或放弃。不得因批次已终态就推断所有资源已释放。
- 删除影响应明确包含运行目录/产物和已结束人工记录，同时列出保留资源。未结束事项给出可定位ID与原因。
- 清理仅处理冻结且权威归属于此自动化的规范UUID Run子目录，复用平台文件边界；拒绝根目录/父目录/目标重定向和外部符号链接、junction。不删除用户指定的外部输出文件。
- 文件清理可部分完成。失败必须保留原操作、未清理ID和可重试失败事实；不能报告succeeded或删除用于恢复的归属事实。已删除产物显示不可用，不能承诺文件系统事务回滚。人工重试或重启恢复均处理原目标，不再产生业务副作用。
- 文件清理完成后，同事务删除本自动化数据库运行事实、冻结快照、终态人工事项和关联配置，最后将原命令标为succeeded。保留必要的操作账本以恢复丢失响应；已保存环境及其内容不能随之删除。
- 前端复用现有操作查询模式显示受理/进行中/清理失败/完成；只有完成才离开详情。原命令身份贯穿超时查询和重试。

## 不在范围

项目自建工作流所有权持久化、Studio全节点开放、跨进程人工恢复、历史孤儿扫描、任意外部文件删除、FR字段授权、L1/M1/S4附录均不在此方案。

## 验证退出条件

实际失败截图在删除前可通过HTTP读取并校验PNG摘要；删除后目标运行目录、目标人工事项、Task/Run/批次和快照消失，独立文档、其他任务目录与数据、保留环境完整。覆盖删除中途停止服务、文件锁/权限失败、部分清理后重启、响应丢失原键恢复，以及启动/修改与删除接受竞争。Windows原生边界需验证真实持锁文件和junction，不能用Mac代替。完整回归/真实worker/三平台打包链均按最终源码确认，releaseAccepted仍需PM9其他门禁。
