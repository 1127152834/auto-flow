# 工作流代理控制节点

- 日期：2026-09-25；状态：confirmed（设计）；来源：用户批准的实施计划与当前源码。
- 实施状态与证据见同日 implementation 计划；设计批准不代表实网验收。

## 契约

新增 proxy_change_ip、proxy_change_location、proxy_query，Studio 与项目运行共用应用服务。
目标默认为当前任务实际绑定的代理，也可显式选择代理；不得重新解析代理池或修改浏览器绑定。
重试间隔默认10秒、最大尝试次数默认5（含首次）、每轮请求与确认预算默认30秒。
三个数值、代理ID、地点ID支持现有变量语法，进入节点解析冻结。正有限间隔/预算、正整数次数；非法配置在写入前失败。
结果变量每次覆盖，默认最终失败报错，可选择捕获结构化结果。中间轮次失败不污染工作流终态。

## 确认与重试

IP基准是节点开始时通过实际连接探测的公网IP，不能使用缓存健康值；后续新连接IP不同才成功。
地点按供应商目录与已验证的国家/城市覆盖/运营商/位置代次判断，已经在目标则无需写入；仍需实际连接探测。
每轮先检查冷却、占用、原操作；允许时只发一次。未成功则等待配置间隔，最后一轮不再等待。
轮数不等于POST数：冷却只检查，unknown/running只核实原操作；只有明确结束或明确允许再次操作才新建写入。
认证/参数/资源错误直接结束；取消/失联/代次失效不捕获为成功。已发送的操作不能假称撤销。
未知冷却时间为null，不将429一律视为操作冷却，不假设两个操作共用冷却窗口。
每操作使用独立预算，管理页保持旧默认；轮询遵守Retry-After。

## 输出与错误

输出status、action、proxyId、operationId、attemptsUsed、requestsSent、configuration、before、after、targetLocation、
观测时间/来源、error(code/message/retryAfterSeconds/retryAllowed/outcomeUnknown/lastCode)。
切换终态succeeded/failed/unknown；查询可queued/running。最终错误PROXY_IP_SWITCH_FAILED或PROXY_LOCATION_SWITCH_FAILED。
捕获模式显示“操作失败，结果已捕获”；程序和协议错误不转换为业务成功。

## 运行边界

API Key只在宿主代理服务。worker通过归属校验的请求/结果管道访问服务，不使用公共HTTP绕过归属。
复用proxy_operations，UUID幂等键绑定run/generation/node visit/attempt，重放找原操作。
重启不自动继续循环或重发unknown。未知操作继续占据数据库互斥。
使用登记覆盖Studio、项目、测试浏览器；按连接和供应商代理身份聚合。唯一使用者可以控制自己的代理，
其他使用者存在时拒绝；新使用者与切换互斥，管理页也遵守。清理未确认时保持阻断。
保留页面/浏览器/Cookie，不自动刷新或重启。切换确认后断开旧转发连接，新连接经同一relay探测。
同一浏览器并行节点与切换不能交叉。外部工具的操作不由本地登记控制。
旧工作流不迁移；复用目录、操作表、日志和协议，不新建调度服务或表，不添加依赖。

## 验收

覆盖首次成功、三轮成功、五轮耗尽、配置变量、冷却/429、未知结果、地点别名/无容量/已满足、
实际探测失败、捕获/报错、跨任务/管理页占用、取消/重启/旧代次及页面保留。
模拟Provider不冒称实网。真实写入只针对明确指定且允许中断的代理；Windows/打包分开记录。
