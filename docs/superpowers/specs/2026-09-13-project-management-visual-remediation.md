# 项目管理视觉整改规格说明书

日期：2026-09-13。状态：按用户已批准原型与逐页审查结论固化；本轮用户授权先写规格/计划，随后开始实施。当前源码 `09b56f6`，审查源码 `b288633`。执行工作区 `autoflow-project-management-implementation`；主项目、旧项目只读。本文澄清视觉与测试标准，不重开业务设计。

## 1. 目标与交付边界

目标不是“换配色”，而是让真实页面的布局、信息层级、卡片构成、操作位置及状态表达符合已确认原型，同时保持已交付 PM2 行为。端到端流程通过与截图对照通过是两个独立退出条件，任何一个失败都不得标记里程碑完成。

先修复 **R1** 的 V01–V07 和通知；通过用户验收后才进入 **R2** 的 V08–V10，继而 **R3** 的 V11–V15、V17–V18、V23 的对应完整状态。V19 完整概览和自动化/运行/统计/环境仍按原业务里程碑，不造假数据补图。V16/V20为PM2保留，V21/V22为PM1保留，V24–V27为未来里程碑。项目新建/编辑、空白表弹窗继续复用现有统一组件并作回归。全部27项审查记录都有归属，未匹配图稿的项目不编造相似度。

输入：[逐页审查](../../project-management/design-alignment/acceptance/visual-audit-2026-09-13/README.md)、[B0 图稿](../../project-management/design-alignment/prototypes/manifest.json)、[原批准业务设计](2026-09-13-project-management-prototype-alignment-design.md)。优先级为：用户明确修订 > 已确认业务规则和阶段边界 > B0对应画板 > 最新旧原型。冲突必须登记原因，不由实现者自行改设计。

取舍：只改颜色无法修复结构；重写项目模块会破坏现有业务与恢复机制。因此采用现有组件定向重组，保留 API、状态机、记录身份、查询和占用合同。R1 不新增后端/IPC/迁移/路由依赖。

## 2. 全局视觉与布局合同

- G01：全局顶部导航不变，不新增模块侧边栏。六个项目页签、五个表页签保持顺序和功能。表详情保留项目页签作为已批准的导航能力，但压缩上方项目上下文，不叠加第二个大标题。
- G02：沿用 `renderer/styles/tokens.css`：canvas #f1eee7、surface #fbfaf7、clay #8d4e2f；正文14/20、次信息12/18、区块16/24、主标题24/32；圆角8/12/16；控件32/40px；边框1px；间距8/12/16/24。新增装饰色仅用已存在 sage/clay 语义色，不用随机颜色假装项目类型。
- G03：桌面基准内容视口1440×1024、100%缩放。主内容最大1280px、左右至少24px；200%可重排，不强制保持一行。全页 scrollWidth ≤ innerWidth+1px；横向溢出只允许记录表格/导航的明确滚动容器。展开浮层前后主内容宽度变化≤1 CSS px。
- G04：一个页面一个 h1。搜索不得包在没有信息价值的全宽白色空壳中。主操作黏土棕，每个当前操作区域一个主操作；危险色只用于危险动作。描述最多两行，长名称换行或省略并可获取全文。
- G05：沿用现有 Radix/OverlayHost/Modal、语义 input、焦点环及减弱动效。模态150ms、Toast2600ms停留+150ms退出；恢复/错误仍在页面保留，不依赖短暂通知。所有可点图标须有可访问名称。

## 3. R1 页面目标（必须逐项验收）

### A：最近与全部项目（V01/V02，对应 R1-A 和旧项目目录图）

- A01：标题和说明在上；新建项目位于标题下方左侧操作行，刷新为次操作；搜索靠该行右侧，全部模式在同区保留状态/排序，空间不足自然换行，无搜索背景空壳。
- A02：最近/全部仍是切换视图，不同时复制两份目录。最近区标题/真实数量/查看全部形成相邻操作组。最近最多6个已访问活动项目，100%下2列、间距16px；未访问项只在全部目录可见。
- A03：最近卡片按横向构成：48px柔和色图标块、名称/描述/访问时间纵向信息组、右上更多菜单。内边距20px，内容撑高，不强行制造空白。使用通用项目图标，不凭业务名称猜项目类型；不增加图标配置API。默认中性边框，hover/focus强调，不能用第一张常亮边框暗示未存在的选中状态。
- A04：全部目录用紧凑条目：40px图标、名称/描述/时间信息，更多在右；不改变服务端六种排序、50/200分页合同。点击标题/卡片打开、更多编辑不触发open；可键盘操作，无嵌套button。
- A05：空、无匹配、加载、刷新失败保留旧数据各有明确表达；不把尚无最近访问称为项目库为空。保留工作区偏好、双视图滚动和重连恢复。

### B：数据表目录（V03，对应 R1-B）

- B01：紧凑项目上下文、项目页签后，唯一“数据表”标题与说明；搜索/导入/新建在同一标题工具区，来源筛选和排序保持可用，在空间不足时换行。避免全宽巨大搜索行。
- B02：2列卡片。图标块40px，本地用sage、Excel用clay现有令牌；左名称/描述，右来源Badge，底部真实记录数/更新时间、右下打开/编辑。只有接口提供的真实字段数才展示，不能逐卡拉schema或填假值。
- B03：标题/元信息/动作对齐；只有明确打开动作导航，编辑不误开。保留分页、来源筛选、返回位置、Excel入口和归档只读。

### C：表详情与记录查询（V04–V07，对应 R1-C）

- C01：项目上下文合并为紧凑一行（返回、项目名、必要状态、编辑），描述不再单占一行；表名称为唯一h1，来源Badge紧邻标题，返回表目录/重新导入仍可访问。保留现有项目和表页签，减少无内容间距；1440×1024、100%时有数据的记录表表头顶部≤380 CSS px（不计系统标题栏）。该值为整改验收预算，不声称由合成原图像素测得。
- C02：记录工具顺序：指定字段+搜索 → 筛选/排序/显示列 → 批状态 → 导出 → 新增记录。最后新增为primary，其余secondary/ghost配现有Phosphor图标。未选记录禁用批状态，选择数量与清除明确可见。
- C03：记录身份列宽112px；UUID仅视觉省略，完整带类型身份通过title和可访问名称保留，绝不能把行序号当记录键。业务列正常宽度、状态Badge，异常值/null/空字符串仍区分。实际当前页行号如新增只能是显示值，不能替代身份；本次不要求新增行号。
- C04：三浮层互斥，有标题、明确关闭按钮、内容滚动和取消/应用底栏。筛选宽度≤512px，排序≤400px，显示列≤288px；均受视口宽减32px和可用高度约束。Select Escape先关Select，再关浮层；关闭后焦点返回触发按钮。
- C05：复杂筛选能力保留，用“添加条件/条件组”等业务标签和清晰区块呈现，不能删反向、状态、复杂组。应用标记由已应用查询派生，不使用草稿条数。无变化应用不发请求，选列不发记录读取；其他应用回第一页；取消、外点、Escape、切面板丢弃草稿。
- C06：输入不查询；Enter/搜索才应用；快捷搜索与高级条件AND组合，清空仅清快捷条件，导出同一最终表达式。代次/结构变化撤销旧查询草稿，后台刷新不覆盖业务草稿。

### D：通知（15-statuses.png中附带观察到的Toast，不改变V13页面归属）

- D01：应用内容右上（全局导航下方）统一Toast，图标区分success/error/info，文案指明“项目已保存/记录已保存”等真实动作；恢复成功也必须依据原Operation事实。
- D02：只改展示与可证明语义，保留现有operationId去重/最多3条/计时清理/旧作用域隔离。不得为截图固定生产时间或屏蔽错误。

## 4. 后续阶段目标与端到端覆盖

R2沿用既定整页记录规格：独立详情/新增/编辑路由，业务字段为主，完整身份按需查看，状态/时间分区、受控外链、保存与离开保护。E2E必须 UI 新增→详情→编辑→保存→返回，另测设置/清空状态、删除取消/确认、外链拒绝、冲突保留输入、重连与双工作区。每一页面正常/脏/错误/只读状态必须有截图。

R3沿用字段整体草稿/有界原子提交规格：右抽屉应用到草稿，统一预检保存；引用查询真实，来源/设置可操作；Excel完整向导和批状态结果不能只拍入口。E2E必须多字段修改/抽屉取消/预检冲突无部分保存/回填边界、受引用状态删除拒绝、UI导入/重新导入/导出及源文件不变、部分结果和重启恢复。业务数据库和文件故障全部在隔离资料中注入。完整概览等不得因为视觉整改抢先模拟实现。

## 6. 截图比对和通过门槛

两级比对不可混淆：

1. **原型符合性**：保存B0原图hash；比较相同页面/状态，有标注的原图/实图并排。多画板原图只允许记录坐标后裁出对应区域，不拉伸/重绘原图来适配实现；不能对整张合成图声称95%像素相似。G/A/B/C/D逐条判定pass/fail，四维人工评分布局30/层级25/样式25/操作20，每画面≥85且布局≥25、层级≥20，同时全部强制条款通过；平均分不能掩盖单页失败。分数仅人工审阅，不能自称机器测量。
2. **应用视觉回归**：经上述原型审查通过的应用截图才可成为候选金图；用户R1验收通过后冻结。未来同OS/DPR/viewport/fixture对比差分，记录diff图及变更区域；像素差>0.5%触发复审而非自动认定业务失败，≤0.5%也不能替代结构/功能检查。不同平台单独基线。时间/随机UUID仅限预登记的局部区域掩码，不能掩盖标题、主要卡片、工具栏或整表。

至少保存 R1最近/全部/空/无匹配/刷新错误，数据目录，记录列表，三个浮层，选中状态，成功Toast，1440和200%浮层。截图与用例一一关联，附边界box测量；不能只有截图文件没有审查结果。静态文档检查不填业务证据。
