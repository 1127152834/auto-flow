## 1. 为什么下一步做录制

现有工作台已经具备编辑、真实执行、定位、控制流和调试，下一步可以让真实手动操作成为这些能力的输入。录制器生成现有工作流文档，由原运行器和调试器执行，不建立另一种脚本或回放引擎。

完成标志：在正式 Studio 打开录制浏览器，录制包含输入、选择、勾选、按键、导航及框架操作的流程，审查并加入画布，保存重开；关闭原浏览器后，以新的临时浏览器运行，页面状态和结果符合预期，失败时能够使用 M5 调试。

“成功收到了 DOM 事件”和“生成了节点”均不等于可重放。录制可能遗漏先前的登录、页面准备及不支持的操作；这些缺口必须可见。

## 2. 建议范围与明确边界

### 2.1 本轮交付

| 范围 | 建议行为 |
| --- | --- |
| 会话 | 专用可见临时浏览器；准备、开始、暂停、继续、停止、审查、关闭 |
| 自动捕获 | 页面导航、单击/双击/网页右键、文本输入、原生下拉选择、原生勾选、限定按键、页面/容器滚动 |
| 定位 | 主文档、嵌套/跨域 iframe、开放 Shadow DOM；沿用 selector + framePath |
| 标签页 | 记录受管页面身份；明确绑定弹窗来源；生成页面别名与切换/关闭步骤 |
| 审查 | 步骤名称、参数、删除、顺序调整、变量化、定位问题及导航原因确认 |
| 生成 | 生成普通节点链；加入空流程，或追加到结构完整流程唯一的顶层尾部；一次撤销 |
| 数据 | 工作区内保存录制草稿和已确认步骤；同服务重连可继续，服务重启仅恢复审查 |
| 验收 | 原浏览器关闭后独立运行；新节点同时支持 M3 定位与 M5 Debug |

### 2.2 本轮不纳入、但不能从总目标删除

拖拽、文件上传/下载、复杂按键组合、鼠标坐标轨迹、浏览器原生菜单操作、相似元素批量提取、选择器自动修复、自动推断循环/条件、不经审查的自动修复回放，留到后续专项。

其中 **WebRPA 录制源码已经包含 drag 和 upload**，它们是明确的未对齐项，不是最终排除项。本轮遇到可检测的拖拽或文件选择，记录“不支持的操作”问题项；不能忽略后继续把整段标为可重放。封闭 Shadow DOM、浏览器内部页面等不可观测区域显示覆盖限制，不承诺能够检测其中每个动作。

子流程、错误处理/重试、双视图/分组及其余核心动作仍未完成。M6 通过后仍不能宣称完整对齐 WebRPA。Windows 桌面控件不纳入；Windows 上的网页自动化仍在目标平台范围内。

## 3. 用户流程

### 3.1 打开与准备

工具栏增加“录制”，进入组件化录制侧面板，显示 Profile、状态、页面列表、地址栏、开始/暂停/继续/停止和步骤数量。

- 每个工作区只能占用一个自动化浏览器任务：普通运行、Debug、拾取或录制相互排斥。
- 录制新建临时会话，强制 headless=false，但不修改 Profile；内核、代理、语言、时区、扩展、指纹沿用现有启动能力。
- 启动为空白页，先处于 ready。用户手动准备后点击开始；准备期间操作不录入。
- 首次开始时选择目标页，将当前地址作为“起始导航”候选。about:blank 可以保留为准备状态，不能生成可执行的空 URL。
- 面板明确说明：录制前的登录、Cookie 和未录入操作不随流程保存，也不会传入运行浏览器。用户可在 ready 阶段直接开始，以捕获后续登录步骤。
- 当前目标页关闭后必须明确重新选择；不自动使用列表中的第一张页面。

录制为被动监听：不调用 preventDefault/stopPropagation，不改变焦点，不自动滚动。M3 拾取时的事件拦截器不能与录制同时启用。

### 3.2 暂停、停止与审查

录制控制与浏览器生命期分开：

| 对象 | 状态 |
| --- | --- |
| 浏览器 | starting / ready / closing / closed / failed |
| 捕获 | idle / recording / pausing / paused / stopping / stopped / interrupted |
| 文档生成 | 未生成 / 已生成预览 / 已加入当前编辑会话；不是运行状态 |

- 暂停先刷新当前输入及滚动缓冲，经 worker 确认截止序号后成为 paused；等待确认时显示 pausing。
- 暂停只停止记录，网页仍能操作。暂停后继续增加新的段标识，并保留“此段前有未录入操作”提示，不能无痕拼接。
- 停止是终止本次捕获，刷新所有可响应框架并固定截止序号。之后只审查，不在同一录制里再次开始；继续采集需新建录制。
- 停止捕获默认保留浏览器，便于测试定位和核对页面。关闭浏览器不删除录制草稿。
- 停止确认时若有框架失联或未确认缓冲，记录完整性问题；不得把已接收前缀标成完整记录。
- 浏览器最后一页被关闭时结束捕获并清理；保留已持久化步骤，无法确认末尾时显示 interrupted/不完整原因。

录制中列表只显示已确认步骤及单独的“正在输入”提示；审查编辑在 stopped 或 interrupted 后开放。审查支持删除、改名、改参数和调整顺序；每次改动增加录制 revision，保留原 sourceEventIds，删除不会重新出现。展示动作来源、页面别名、框架路径、定位状态和问题。

定位状态分为“采集时已核验”“当前页面重新核验”“待核验/已失效”。历史页面离开后，不能把采集时的匹配当作当前页面匹配。录制期间禁止主动测试产生高亮干扰；停止后可以使用同一会话进行只读定位测试。

### 3.3 加入画布与手动保存

- 不在采集期间向工作流逐个插入节点。用户可继续编辑当前草稿。
- 生成前提交聚焦字段，捕获工作区、文档 ID、编辑语义摘要、目标尾部和录制 revision。
- 空流程：生成一条顺序链。非空流程：仅追加到**结构完整且唯一的顶层尾部**；条件/循环整体结束后的尾部合法，块内插入、任意选区替换和智能接线留后续。
- 参数未完成不阻止预览和加入草稿；结构损坏、没有唯一尾部或选择过期时阻止应用。提供加入当前空流程或经原离开保护新建流程的明确路径。
- 生成结果包含节点、边、必要变量、问题及稳定 generationId。它不保存工作流，也不执行网页动作。
- 一次应用完成节点、边、变量和布局修改，形成一次可撤销操作；复制来源不进入运行语义。
- 请求期间移动节点不使语义预览失效，最终布局以应用时现有位置计算；节点/参数/变量/连线变化必须重新预览。不能用旧快照覆盖新编辑。
- 同一 generationId 重复回调或连点，在同一编辑会话只应用一次；撤销后可明确“重新加入”。不维护跨崩溃的全局导入台账，重启后不自动导入。
- 插入前处理变量名、页面别名冲突：预览提出确定的新名称并一次更新片段内引用，用户审查后应用，不覆盖已有绑定。
- 应用后保持手动保存和 revision 冲突保护；保存失败不删除录制草稿。

## 4. 录制动作与执行契约

所有新增字段由后端目录提供默认值，通过 OpenAPI 生成前端类型。新节点先达到可手工配置、可独立运行、可 Debug，才允许由录制器生成。

### 4.1 动作规范

| 录制动作 | 正式节点/字段 | 实际执行语义 |
| --- | --- | --- |
| 单击/双击/右键 | 现有 click_element.clickType | 同一手势仅保留对应动作；右键只代表网页 contextmenu，不操作原生菜单 |
| 文本输入 | 现有 input_text，增加 inputMode=fill/sequential，默认 fill | fill 保持旧行为；sequential 是明确的逐字输入选项，clearBefore 继续有效；不承诺复原按键节奏或全部输入法事件 |
| 原生 select | 新增 select_option：selector、framePath、values:string[] | 按 option value 精确选择；允许多选空集合；单选必须恰好一个值；找不到值或多个同 value 候选明确失败 |
| 原生 checkbox/radio | 新增 set_checked：selector、framePath、checked:boolean=true | 设置目标状态，不是盲目翻转；radio 仅支持 true，false 需要用户改流程；不把自定义 ARIA 控件自动转为原生操作 |
| 有业务意义的按键 | 新增 press_key：selector、framePath、key | 首个明确元素上的 Enter、Tab、Escape、ArrowUp/Down/Left/Right；不向未知焦点发送全局按键，不捕获字符键来重复输入文本 |
| 页面或容器滚动 | 新增 scroll_page：target=page/element、selector、framePath、x、y | x/y 为有限非负 CSS 像素的绝对目标；当前 frame 的文档或首个指定容器；禁用平滑动画，返回实际位置及被边界限制的提示 |
| 导航观察 | 新增 wait_page：url、waitUntil=domcontentloaded | 只检查/等待当前标签页匹配期望 URL 及指定加载状态，不发起第二次导航；支持同文档 URL 变化；共用节点超时 |
| 用户发起导航 | 现有 open_page，录制生成 current_tab，首次可 new_tab | 明确访问用户确认的 URL；不把重定向结果当作另一次访问 |
| 页面选择 | 新增 switch_page：pageAlias | 选择本次运行中已绑定的页面；别名不存在或页面已关闭则失败，不能选“最新页”兜底 |
| 关闭页面 | 新增 close_page：pageAlias | 关闭明确页面；关闭当前页后 currentPage 为空，后续需要显式切换；不自动切到其他页 |

共新增七种节点；input_text、open_page、click_element 为兼容扩展。新增网页动作使用 timeoutSeconds 默认 60 秒、正小数、同一节点总预算；选择器和 framePath 共用 M3 定位入口。scroll_page 的整页目标忽略保留的元素 selector，但保留 framePath 以定位框架文档。

inputMode 默认 fill，录制也默认生成 fill；逐字输入由用户选择。对于依赖逐字符事件的网页，验收明确测试 sequential，不能宣称 fill 和手动键入总是等价。富文本仅承诺纯文本 contenteditable，不采集格式。

### 4.2 页面身份与导航因果

会话 pageId 只用于录制通信，不写入可重放节点。运行使用独立的页面别名表，和流程变量表分开；别名采用现有标识符规则。

- open_page 增加可选 pageAlias，成功后绑定实际页面。click_element 和 press_key 增加可选 newPageAlias；配置时必须明确跟随新页。press_key 的 followNewTab 默认 false。
- 旧 click_element 的未配置行为不变。配置 newPageAlias 后必须在共享超时内获得唯一、与本次动作来源匹配的新页；没有或多于一个时失败，不能猜测。
- 别名已指向其他活页时拒绝覆盖；绑定同一页可幂等确认，原页关闭后允许重新绑定。循环重复打开同一别名前必须先关闭旧页。
- 预检按控制路径检查页面别名是否已产生，循环体可能 0 次，分支合流使用交集；运行时仍检查页面存活。M5 顶层起跑缺少别名时，在正常暂停的页面准备里明确绑定页面，诊断记录该操作，不自动使用旧会话 ID。
- 新页出现先加入面板列表；不是仅凭“最新页”就切换录制目标。用户选择或可验证的目标页交互可以确认切换。跨页并发且顺序不明确时提示审查，不能按各页 Date.now 推导业务因果。
- 点击/Enter 后出现导航，保留原动作，将导航作为 wait_page 候选；直接地址栏访问、后退/前进等无法可靠判断来源的导航显示“需确认：主动访问 / 前一步结果”。Studio 地址栏导航因命令来源明确，可以自动分类。
- 不沿用旧实现“10 秒内的导航全部认为由上次点击导致”的规则。用户确认导航分类后，执行计划中不得同时重做点击及其结果 URL 的 goto。
- 重定向只记录最终候选及导航关系，不展开为多个 open_page；同 URL 的显式重载不能简单去重。无法表达的历史状态恢复标为缺口。
- 子框架导航使对应定位采集 epoch 更新；不生成全局 switch_iframe，后续元素节点各自携带完整 framePath。

### 4.3 合并、刷新与不支持动作

- 合并键包含 sessionId、pageId、frame/document epoch、元素身份及录制段；不同页的相同 selector 不得合并。
- 连续 input 合并为最终文本；compositionstart/compositionend 确保中文输入不留下中间拼音。在 blur、change、业务按键、后续动作、暂停、停止及导航前刷新。
- 输入后 Enter 必须先提交输入再提交按键。普通字符、删除键引起的文本变更由 input 表达，不能重复生成 press_key。
- 双击的两次 click 仅在尚未定稿的同一手势范围内折叠；采集器不能在步骤已消费后偷偷删除旧序号。不同目标或穿插其他动作不折叠。
- 原生选择/勾选以 change 后状态为准，抑制同一手势中的冗余 click；label 转发点击和单选组取消事件需要去重，不抑制网页真实事件。
- 滚动仅在同页面/框架/滚动容器连续区间合并；点击等其他动作作为刷新边界。脚本造成的滚动无法可靠区分来源时显示“滚动观察”，不声称都是用户手势。
- 不从用户思考时间生成 sleep。需要等待时用户使用 wait_page、wait_element 或已有条件，并可在 Debug 中核对。
- 选择器无法验证、可检测的拖拽/上传、未知按键等生成带 sourceEventIds 的问题项。用户可以补成支持动作，或明确排除并接受覆盖缺口；不能仅删除警告文字。

## 5. 定位、字面量与数据边界

### 5.1 定位

复用 M3 的候选生成、CSS 转义和实际定位校验；提取纯候选能力，不让录制模式调用拾取高亮/拦截。候选必须唯一命中真实目标，framePath 每层唯一定位 iframe；不回退到框架名称或序号。

事件同步采集元素身份和候选；provider 尽快通过共享 locator 核验，并绑定当时 document epoch。元素或框架已移除、跨域跳转导致无法核验时保留待修订项，不猜主框架、不改为标签名。只检查当前 DOM 唯一性，位置路径标为依赖页面结构。

开放 Shadow DOM 用 composedPath 及共享定位器；封闭内部不生成不可执行路径。录制不能为了校验而阻止原点击导航，所以快跳转可能产生待核验项，这必须进入真实验收。

### 5.2 原文不应被当作变量模板

用户实际输入的 `{name}`、`${name}`、URL 或属性中的大括号必须保持原文。现有节点文本默认解析模板，M6 增加可选的节点级 `literalPaths: string[]` 元数据（字段路径数组，缺省 []），只允许指向目录登记的可模板化字符串叶子。

- 录制生成的原文叶子标为字面量；手工旧节点缺省继续模板解析。数组逐项使用路径，例如 config.values.0、config.framePath.1。
- 前端明确显示“原文/变量引用”，切换为引用才调用现有插入与校验；重命名不修改 literalPaths 指向的原文。
- 变量化绑定已有声明或用户显式创建的声明，不自动把录制原文搬进会解析模板的变量初值。声明初值继续沿用原规则，不能借变量化绕过原文/引用区别。
- 保存、运行预检、参数解析、M3 定位测试、M4 条件引用分析、M5 起跑预检/快照一致性必须统一处理，不能仅在录制转换处替换字符。
- 元数据路径失效、非字符串、指向不允许字段均为结构问题；录制重排不影响节点内路径，数组编辑须原子维护对应路径。
- 此项改变解释语义，工作流写入格式升级 **schemaVersion=3**；v1/v2 读取保持旧语义且不自动写库，旧运行快照不改写。不能以版本 2 悄悄保存旧客户端会误解释的数据。

### 5.3 输入与持久化

普通录制值会成为工作区文件/数据库中的草稿，面板应明确这一点。已识别 password 字段只采集“需要补值”，在页面侧就不读取其 value，也不把值放进 selector/名称/文本提示；不先保存明文再在列表画圆点。用户名、其他普通文本不会被推测成密码。

用户可停止后把步骤值替换为变量引用。密码补值使用现有运行/Debug 本次输入能力，不自动创建含密码初值的声明；M6 不新增凭据管理产品。保存未完成节点仍允许，未补齐值的输入步骤必须有明确的必填补值标记且运行前阻止，不能用合法空文本冒充已补齐。

`input_text` 增加 `requiresValue` 布尔字段，默认 false；录制密码步骤设 true、text 留空，用户明确补值或绑定变量后才解除。合法空文本的普通输入维持 M1 行为。

页面 HTML、Cookie、请求响应体、剪贴板和完整键盘流不进入录制数据。系统代理密码和 License 继续仅经已有受控启动通道使用。大输入使用文件引用和有界传输，禁止静默截断文本后生成节点。

## 6. 分层与持久化

### 6.1 职责

| 层级 | 实现方向 |
| --- | --- |
| domain/workflows | 动作规范、确定性归并规则、问题、录制片段转换、literalPaths 与页面别名规则 |
| application/workflows | 录制状态、互斥、命令确认、录制草稿修订、持久化事务；复用 acquire_browser 和原离开协调 |
| providers/browser | 被动注入、现有/新文档 frame 覆盖、目标定位验证、页面导航观察；原执行器承接新增节点 |
| infrastructure/process | 一次录制一个 worker；复用现有启动、单读取方、命令关联、心跳与进程树清理 |
| infrastructure/database | 录制摘要、定稿步骤、幂等命令与 source 去重信息；不写普通运行表 |
| infrastructure/filesystem | 大值的受控文件、原子写入、删除清理；不让 domain 拼路径 |
| adapters/http | 鉴权、DTO、分页、错误、停写守卫；静态录制路由先于工作流动态 ID |
| renderer/domains/workflows | RecordingPanel、步骤审查、生成预览、useWorkflowRecording；组件完成后接 StudioPage |
| Electron | 延伸原离开/退出/工作区切换、显式重启保护；不捕获操作、不运行浏览器命令 |

保持拾取和录制为独立 application 会话；共享页面簿、定位和启动能力。不要把 InspectionService 加满录制状态，也不要建立通用浏览器 RPC。原 run/debug 数据通路与成本不变。

### 6.2 数据模型

在实施时的 Alembic head 后新增迁移；当前 head 为 0008_workflow_debug，实施前再次核对，禁止改写历史迁移。

最小数据：

- 录制：recordingId、名称、来源文档 ID（允许未保存）、Profile ID/非凭据信息、浏览器/捕获状态、revision、最后持久化序号、固定截止序号、完整性问题、时间。
- 步骤：stepId、递增 seq、sourceEventIds、录制段/page/epoch、动作参数或大值引用、定位证据级别、问题、审查状态。步骤序号不因审查排序或删除复用；展示顺序单独存储。
- 命令：commandId、请求摘要、预期 revision、接受/应用/拒绝/无法确认状态、确认截止序号。约束同 ID 同内容幂等、异内容 409。

revision 用于已确认的控制状态及停止后的审查变更；持续采集的定稿追加使用 seq，不因每个 input 更新控制 revision，避免暂停请求不断过期。状态变更和修订号由同一事务推进；worker 实际应用前再次校验命令所属状态。generationId 的摘要和固定录制 revision 的转换结果使用同一幂等记录机制，同 ID 异内容拒绝，不新增调度框架。

已确认步骤与接收游标在同一事务内提交，提交后才确认 UI/worker；大值先原子写文件再登记引用，失败不提交该步骤。录制草稿与工作流文档分别持久化，生成不自动保存工作流。删录制需先关闭浏览器并确认，删除所登记的大值文件；不得删除已保存节点依赖的数据，生成时应复制原文进入流程契约或独立受管引用。

### 6.3 传输、顺序与恢复

建议使用 context 受控 binding 接收页面事件，先注册未来文档脚本，再显式初始化所有已存在页面和框架；不能仅依赖 add_init_script，也不使用网页 sessionStorage 做唯一缓冲。具体 binding 在当前 CloakBrowser 上是否可靠，是批次 A 必须实测的技术门槛。

- 页面来源由 browser binding 的 source 确定；session/page/frame/epoch 不能只相信网页提交的 JSON。只接收有限事件 schema，不提供任意 evaluate/文件/网络命令。
- 页面给事件分配本地递增 sourceSeq；worker 串行归并，父进程为定稿步骤分配 seq。按来源保持顺序；跨页不从不可靠的墙钟推断动作因果。
- 有界未确认缓冲及稳定 sourceEventId 支持重传、去重。暂停/停止使用 flush barrier；只有全部可确认来源到达屏障后才能报告完整截止。
- 页面卸载前的异步发送不保证送达；未确认尾部、失联文档或不明确导航交接标为 coverage gap。严格验收覆盖范围内的正常导航必须无缺口；遇到无法确认的异常要准确报告，不能声称绝对无丢失。
- 建议保护阈值：单值 1 MiB、单录制 10,000 个定稿步骤/64 MiB 原文，桥接大值分块不超过 32 KiB。到限进入受控暂停并标明尚未保存部分，不截断、不静默丢弃；这些是本方案默认值，批次 A 用实测验证。
- 工作区查询使用非破坏性分页。录制面板可见时每 500ms 补读步骤/命令，闲置会话每秒读状态；终止后停止高频轮询。不增加第二套 SSE。
- UI 断线先重连：回查原 recordingId、commandId、afterSeq，保留当前草稿，不重启浏览器。
- worker/sidecar 真正退出后，历史活跃捕获标为 interrupted，已确认步骤仍可审查；不恢复浏览器或重放手动操作。未持久化命令显示无法确认，不能盲目重放。

## 7. 最小 API（建议契约）

前缀 `/api/v1/workflows/recordings`，沿用鉴权、停写和错误包。以下名称为建议新增接口，不代表已经存在。

| 接口 | 职责 |
| --- | --- |
| POST /recordings | recordingId、profileId、可选 sourceDocumentId；创建草稿并打开可见浏览器，不自动开始 |
| GET /recordings | 当前/最近录制，工作区隔离、分页；不替代工作流管理首页 |
| GET /recordings/{id} | 双状态、revision、页面、当前命令、步骤数量、lastSeq/cutoffSeq、完整性问题 |
| POST /recordings/{id}/commands | start/pause/resume/stop/page/close；commandId、expectedRevision；需要页面上下文时附 pageId/epoch |
| GET /recordings/{id}/commands/{commandId} | 非消费式查询是否已应用；响应丢失使用原标识恢复 |
| GET /recordings/{id}/steps | afterSeq、limit、固定截止；审查快照使用 revision 绑定游标，版本不一致返回 409 |
| GET /recordings/{id}/steps/{stepId}/value | 读取登记大值，工作区/录制归属校验，有界流式输出 |
| PATCH /recordings/{id}/steps | 停止后批量改参、删除/排序/补值标记；expectedRevision 原子更新，失败无部分写入 |
| POST /recordings/{id}/test-selector | 停止且浏览器仍在时，共享 M3 的 10 秒只读测试；绑定页面 epoch 和审查 revision |
| POST /recordings/{id}/generate | generationId、expectedRevision、选定步骤、目标流程语义摘要/尾部及冲突命名方案；返回片段、映射和问题；无工作流写入 |
| DELETE /recordings/{id} | 已关闭录制的显式删除及文件清理，revision 校验 |

启动与变更命令均使用稳定 ID；HTTP 接受不等于 worker 已完成。关闭始终可以打断启动/刷新等待，并保留缺口；资源清理失败仍处于 closing，可重复关闭，不能因过期普通 revision 阻止紧急清理。

录制问题至少包含 `recordingId + stepId/sourceEventId + path + code + message + severity`；生成问题同时给出 `nodeId`，继续接入现有定位问题 UI。对未知动作/页面/定位不返回空成功。

## 8. 离开、互斥与故障顺序

录制与原 run/debug/inspection 的占用检查必须原子完成；从接受启动到进程树清理完成始终持有活跃名额和 Profile/内核目标锁。删除占用资源继续被拒绝，其他内核版本管理不受整轮全局锁阻塞。

- 开始录制前如有活跃 run/debug/inspection，明确要求通过原确认/清理流程结束；取消不关闭现有浏览器。不能悄悄接管拾取登录态。
- 在录制会话中点击运行/Debug，先提交字段、捕获快照并进行不占浏览器的预检；再确认停止并关闭录制浏览器；清理完成才提交已捕获快照。生成步骤不是点击运行的隐式行为。
- 新建、打开、关闭 Studio、退出、换工作区：处理工作流草稿 → 刷新审查编辑 → 停止捕获并确认已接收步骤 → 关闭浏览器/worker → 离开/停写/关闭 sidecar。
- 有工作流草稿时使用“保存流程并结束录制后离开 / 放弃流程修改并结束录制后离开 / 取消”；提示录制草稿会保留，不把“放弃流程”误当“删除录制”。没有流程改动也要确认正在录制的会话将结束。
- 保存冲突/失败不停止录制；审查写入失败保留未提交内容；取消不停止或丢弃会话。刷新无法确认可显示已保存前缀与缺口，允许用户明确结束不完整录制；不能静默当成功。
- 清理失败阻止离开并保留资源占用和重试责任。工作区切换失败保留原文档和录制草稿，已关闭的浏览器不自动重启。
- 仅关闭主窗口、Studio 仍在时继续录制；普通重连不重启服务；活跃录制禁止显式重启 sidecar。
