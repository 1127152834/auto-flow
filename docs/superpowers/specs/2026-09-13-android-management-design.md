# 安卓设备管理第一版与 M4 接入

日期：2026-09-13。状态：confirmed（范围与原型已获本轮用户授权）；实现与验证状态另见验收记录。
来源：用户确认“先做合入 M4 + 设备管理第一版”，并要求按此前选定原型开发；已有原生交接规格、M4 实现、原型 README 的后续修订。

## 范围与架构

沿用现有 Electron / React / FastAPI / SQLite / Mac Lima Android provider，不增加服务或工作流引擎。正式实现位于 android-handoff 隔离工作树，接入已提交的 M4 主线；不修改主工作树无关草稿。先做持久设备、串行管理和已有五类安卓节点。只验收 Mac Apple Silicon。

M4 的 WorkflowExecution 负责条件、循环、变量与每次 executionId；安卓 worker 注入固定设备动作，输入仍由父进程持有。安卓图允许通用控制节点，拒绝浏览器动作及网页条件；混合运行仍不支持。人工节点每次进入产生独立 handoffId，关窗不继续；截图绑定逐次执行并进入 M4 产物索引。旧 schemaVersion1 图、profileId 请求与手动入口保持兼容。

数据库用 0008_merge_android_m4 汇合已经使用的两个 0007，旧迁移不改写。设备管理的配置、操作及恢复状态保存在既有设备 payload；持久化操作意图早于 Docker 写入。按现有 VM 独占锁串行执行管理与设备控制，同一设备占用时拒绝生命周期修改。安卓管理进度加入应用 busy / shutdown 边界。

## 页面与原型映射

视觉基准：reference/redroid-demo/prototypes/2026-09-13/00-resource-board.png 与 02-create-instances.png。使用已有暖灰/黏土棕 token、Phosphor 图标、shadcn 基础组件，不创建另一套视觉系统。界面不绘制假设备截图；未获取真实帧时用设备图标与明确状态，停止时不冒充在线。

资源页：宽内容区，顶部标题、运行环境入口和创建实例按钮；实例列表/资源看板切换、名称搜索与状态筛选。看板按“可分配 / 使用中 / 启停与待处理”分列；使用中细分手动与工作流，错误不计入可分配。卡片显示名字、Android/架构/尺寸、持久数据说明、实际状态、操作进度。主入口打开原生操作窗口；详情可查看实际配置与最近运行，菜单提供复制配置、重命名、启停、重启、删除。

创建页：左侧三组表单“基本信息 / 运行配置 / 数据与启动”，右侧实时配置摘要；底部取消与创建按钮。本轮一次一台，可连续创建多台；批量队列以后单独实现。默认 Android13 ARM64、720×1280、dpi320、1CPU、1536MiB、软件渲染；镜像只能选实际缓存且受支持的镜像 ID，不自动下载或执行用户参数。创建后可立即启动或保持停止。

复制配置：进入预填表单，使用新 deviceId/独立卷。明确不复制应用及登录态。配置快照不可就地修改；通过新建改变规格。可独立修改名称。

详情：概览、环境配置、运行记录；当前原生人工会话复用已有面板。显示逐项真实状态、配置信息、错误和操作时间；运行记录按设备筛选并可查看该次运行的日志与截图。不放未实现的应用/摄像头/环境伪装按钮。运行工作流入口复用 Studio 的设备选择，手动操作沿用一次单节点运行。

## 生命周期与接口

GET environment 增加实际可用镜像、VM CPU/内存；GET devices 返回已登记设备与生命周期操作投影。POST devices 使用客户端生成 deviceId 作为创建去重键，请求含名称、镜像ID、尺寸、dpi、CPU、内存和 start。相同编号不同配置冲突，重复请求返回已接受状态，不重复创建资源。

POST devices/{id}/operations 接收 requestId 与固定动作 start/stop/restart/delete/recover；deleteData 显式声明删除范围。相同 requestId 只查询原操作，相同编号不同输入返回冲突。操作接受后返回202，页面轮询现有设备接口；本轮不增加独立任务平台。PATCH name 为有界重命名。

进度保存在 device.operation（id/action/state/stage/error/timestamps）。先记录意图和生成的资源名称，再执行、核实真实状态，最后完成。恢复不重放未知副作用；中断任务标 interrupted，需显式核实或清理。删除失败继续保留设备记录与错误，允许显式重试。

停止保留容器与数据；删除支持“仅移除实例运行环境并保留数据”和“连同独立数据删除”。保留数据仍留登记项，显示“数据已保留”，允许按原配置恢复容器；完全删除仅在容器和卷都确认不存在后移除登记项。所有写操作和清理逐个校验 workspace/device labels 及 /data 卷关系；对不属于本工作区的对象拒绝操作。

创建和启动须区分容器启动与 Android boot_completed；限时等待180秒，失败返回实际阶段，不假报就绪。超时 Docker 写命令不盲目重发，先读取实际容器/卷结果。新设备资源预算不超过实际 VM 可用容量，避免直接复制图中数量作为并发承诺。

## 验收

测试迁移从 M3、Android0007、M4 0007 和已合并起点保留数据升级；安卓循环/条件/变量、逐轮截图、重复人工节点及取消；浏览器现有控制流回归。管理关键分支测试创建去重、所有权拒绝、占用冲突、部分创建/删除失败、重启恢复、shutdown。React 测试筛选/导航/创建校验/复制/删除范围/手动入口/错误反馈；类型、lint、OpenAPI一致性、构建检查。

真实 Mac 在独立工作区创建两台测试设备：一台运行循环截图与人工交接，另一台数据保持；检查启停重启、保留数据删除与恢复、完全删除、失败反馈。原有测试设备及 reference 三台设备不删除。原型与渲染页面同视口比较，记录明确的范围差异。打包应用验收后交付启动入口，未测平台如实标记。
