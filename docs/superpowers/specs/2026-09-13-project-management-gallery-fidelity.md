## 1. 权威依据与旧结论处理

唯一页面视觉依据是主项目 `docs/references/project-management-prototypes-2026-09-13/gallery.html` 指向的 `latest/` 原始图片。用户当前明确点名的新增记录是 `latest/05-data/004-record-create-72de4a.png`。目录、具体文件、尺寸和 SHA-256 见 [原图清单](../../project-management/design-alignment/gallery-baseline/source-manifest.json)。本轮重新看图17张；其余登记的是文件事实，不宣称本轮逐图看过。清单逐图保留gallery原归档说明；latest中仍含“修订候选、未找到批准记录”（如100-field-impact）。这些文件是本轮计划拟采用的原始依据，随本计划审阅，不伪称历史已批准；same-day-variants/history不自动纳入。

- 允许的全局布局调整只有：原左侧应用级菜单移为现有顶部导航。工作区和服务状态使用已有应用级入口，不另造侧栏。
- 页面内容区的层级、卡片边界、行列、标题与页签关系、操作位置、表单、弹窗、抽屉、返回与保存流程跟随各自原图。适配顶部占高与可用宽度不等于授权重排内容。
- 具体页面原图优先于通用控件示意图：公共图中的“二级页不重复大项目头”不能覆盖用户点名004/005实际保留项目头的版式。
- B0生成图是历史设计偏差记录，不能再当开发输入或验收基准。旧规格中“B0 > 最新旧原型”顺序、压缩项目上下文、表头 y≤380等派生要求废止。现有控件是技术复用基础，不能反向决定页面布局。
- R1历史功能测试及其版本证据保留；R1“视觉通过/整阶段可交付”的当前结论撤回，重新验收。R2部分实现保留，视觉未通过；R3尚未完成，不能跳过R1重验。
- 用户已批准的数据/事务/恢复规则继续有效。图中旧业务、样例数据与未交付能力不冒充现成实现。所有必要差异必须逐项登记；不能把业务差异当布局自由度，也不能将有差异页面称为完全一致。

100%按原图桌面布局；200%仅做避免裁切的换行/内部滚动，保留顺序和归属，不切成另一设计。原图中的数据、日期、状态条是条件性内容：没有同步失败事实的本地表不显示“云端推送失败”。

## 4. 业务差异、缺图与边界登记

以下为已经存在的能力差异；本修订不自动批准新增业务或新画板。

| 差异 | 当前真实规则与处理边界 | 验收标记 |
|---|---|---|
| 图中Sheets、外部SQLite、云端告警 | Sheets仍在PM6；外部SQLite不是当前来源；仅显示当前真实本地/Excel来源事实，原信息位置保留。不可伪造同步和错误 | 对应业务条件未实现，不算全图库功能通过 |
| 字段删除、整表删除 | 当前R3合同不包含删除；保留原操作位置为明确禁用且有“暂未开放”说明，不能提供假预检/删除；危险区不得装成已可用 | 能力差异明确列入阶段交付，不算删除验收通过 |
| 状态引用原图含历史数 | 当前计划只实现当前记录数与活动批操作；保留表格位置，在引用单元格分项标明真实口径；无读结果不能填0 | 已有业务合同差异，未来历史引用另行交付 |
| 系统生成身份、动态业务字段 | 不能把样例R019硬编码成系统记录键；生成身份用同一身份行只读说明；业务身份可编辑仅限创建。字段按真实定义顺序 | 合成测试分别建立业务身份/系统身份，展示事实对应 |
| 缺失/null/空串和异常值 | 常规值仍按原图输入行；必要值状态/原始证据入口放在该字段的辅助区，不加常驻侧栏；不能删除已有值语义 | 增补状态须在映射里逐项说明与截图，不冒充原图已有 |
| 指定文本字段搜索、多排序、导出、批状态 | 保留已授权业务能力；与原图已有工具区结合，不能新增永久第二工具栏。新增入口的具体位置先在原图映射中登记审阅 | 原图缺少完整状态，不能凭B0自行认定一致 |
| 冲突比较、未知结果恢复、文件向导、批状态进度 | 保留已有正确机制。原图未展示的状态标为“原图缺图”；继承最近原图布局与公共控件，不默认采用B0两列冲突页 | 开工前完成状态位置/触发/退出的文字映射，缺图页面不填相似度 |
| 全部项目完整视图、项目表单 | 目录图只有“全部项目”入口，不能声称紧凑全部条目来自原图；复用原目录卡片语汇及现有真实表单，登记衍生状态 | 直接原图覆盖与衍生状态分开验收 |

必要的新差异若会改变用户操作方式或页面结构，必须在对应包开始前给出具体差异供确认；不能靠内部评分批准。已确认的顶部导航改动不重复请求确认。

## 5. 验收规则

1. 新证据必须包含原图相对路径及SHA、真实路由、当前数据/状态、截图、源码与构建哈希、视口/原生窗口尺寸/缩放/DPR/字体。来源清单不是通过报告。
2. 全图并排检查导航之外全部内容；可补内容区对齐图，只有已登记的左菜单→顶部导航区域从差分中排除。不得遮掉项目头、表页签、工具条和底栏；不得缩放扭曲原图来制造相似。
3. GF-01–10逐项硬性通过；缺一项即失败。保留原约定人工评分≥85，逐页分别评估，但分数不能抵消结构/流程错误。原图缺图、未实现功能、未执行状态用明确标记，不补造分数。
4. 使用真实Electron+FastAPI+隔离SQLite，从UI创建核心数据并走全部路径；API规模数据/竞争修改/事实查询、直接hash和合成故障分别标注。截图不能替代写入、恢复、原子性验证。
5. R1重新通过后才关闭其阶段；R2/R3不得拿历史B0审查结论通行。持续实施授权不等于降低退出条件，也不等于用户已手测。
6. 主项目/旧仓只读；未提交QA文件保留。Windows、其他架构与打包未运行明确记录未执行。
