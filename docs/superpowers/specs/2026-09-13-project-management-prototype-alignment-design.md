## 2. 固定外壳与信息层级

1. 全局导航继续位于顶部，保留当前系统模块与工作区切换入口。
2. 项目一级页为“返回项目目录 → 项目名称/用途/必要操作 → 概览、自动化、运行记录、统计、数据、环境六页签”。页签为水平导航。
3. 对象二级页使用紧凑上下文头，保留项目定位、明确的返回对象和当前对象标题；不重复堆叠巨型项目标题。数据表仍有记录、字段、状态、来源、设置五页签。
4. 工具栏优先展示搜索、筛选摘要和主操作。筛选、排序、选列按需展开，不常驻完整编辑表单。筛选是查询草稿，不能改变业务数据。
5. 右侧状态/属性区域是详情内容；字段Drawer是临时编辑器。两者不成为资源树或第二套模块导航。
6. 窄宽度或200%缩放时，详情两栏转为上下内容，表格在自身区域横向滚动，页签可横向滚动且保留键盘可达；全局导航不自动改侧边栏。

### 视觉基础

复用 `apps/desktop/src/renderer/styles/tokens.css` 与 `shared/components/ui`，不另建主题、组件包或第二套控件API。当前令牌：暖灰canvas `#f1eee7`、surface `#fbfaf7`、正文 `#34322e`、次要文字 `#625e57`、强调 `#8d4e2f`、边框 `#d8d3c9`；危险/成功/警告沿用既有语义色。颜色不单独承担状态意义。

## 4. 路由、返回和作用域

继续现有hash导航和 `app/navigation.ts` 的guard，不引入路由库。既有 `#/projects/{projectId}/{tab}`、`#/projects/{projectId}/data/{tableId}/{tableTab}` 保持。

新增记录路由建议（拟新增，尚未实现）：

- 新增：`#/projects/{projectId}/data/{tableId}/records/new`。
- 详情：`#/projects/{projectId}/data/{tableId}/records/{datasetGeneration}/{keyType}/{encodedKey}`。
- 编辑：详情地址追加 `/edit`。

`keyType` 仅为 `text/integer/uuid`；`encodedKey`复用当前API的规范UTF-8 base64url无填充编码。真实身份始终包含项目、表、代次及带类型的键；不能把文本“001”、文本“1”和整数1折叠。键值DTO是字符串，整数使用规范十进制。源码支持最长8000 Unicode码点的文本键，必须测试长地址、非法编码和Unicode往返，不截短后用于查询。UI不以原始UUID/路由代替业务标题。

其他对象路由在原六页签下使用类型与稳定ID：自动化 `automations/{id}/{managementTab}`，批次 `runs/batches/{id}`，任务 `runs/tasks/{id}/{logs|inputs|exception}`，人工 `runs/manual/{id}`，环境 `environments/{id}`。这些是拟新增语法；实现前以路由解析单元测试消除页签、详情和新增保留字歧义。环境入口查看人工事项复用同一事项身份和页面，不复制第二份处理状态。

返回上下文保存搜索、筛选、排序、页码、列显示、滚动及触发行。读取键含工作区、服务实例、项目及查询；浏览状态按稳定工作区和对象保存。导航必须校验当前工作区归属，不能采用任意returnUrl。外部直接打开详情没有返回快照时回当前表第一页；行已删除时焦点回列表标题并说明变化。代次或结构变化后移除失效字段引用并提示，不默默把旧RecordRef改成新代次。

## 5. 草稿、查询与命令的共同规则

| 状态/触发 | UI表现 | 保存、离开和恢复 |
|---|---|---|
| 初次加载 | 保持页头与尺寸稳定的Skeleton | 无完整基线前禁用写入；读取失败给重试 |
| 已加载、无数据 | 空态含真实创建/返回动作 | 与“无匹配”“未开放”严格区分 |
| 清洁 → 有修改 | 当前表单显示未保存；按钮随校验状态变化 | 草稿绑定稳定工作区、对象和编辑会话，不绑定服务实例 |
| 后台刷新 | 不覆盖脏字段；展示远端已更新提示 | 保留原比较基线，新事实供用户主动核对 |
| 校验失败 | 顶部摘要+字段错误；聚焦首错 | 保留输入，不提交；数字/布尔/空值/未提供按typed规则区别 |
| 正在提交 | 主按钮忙碌、阻止重复 | 响应必须通过scope/会话/请求epoch校验才能更新当前界面 |
| 409冲突 | 我的修改和最新事实摘要，继续编辑/采用最新基线 | 不自动合并有冲突字段；采用新基线后重验影响，保存用新命令身份 |
| 响应不明 | “正在核验上次操作”，保留草稿及原操作身份 | 查询原键；确认未接受才原键重发；不得因超时换键再写 |
| 命令已完成但响应迟到 | 原结果仍可查询 | 不关闭另一对象弹窗，不覆盖新工作区缓存，不弹误导成功 |
| 项目只读或正在切工作区 | 资料仍可读，业务写动作禁用并说明；归档仍可只读导出到新文件 | 后端准入不省略；持久未完成操作继续由现有切换保护处理 |

离开脏表单默认“继续编辑”，覆盖关闭、Escape、遮罩、页签外跳、全局导航和前进/后退；取消离开时URL与页面一致。管理四页签内部共享同一草稿，切页不触发离开确认。弹窗提交期间禁止关闭；已接受的持久长操作允许离开进度视图，离开不等于取消或删除命令。批状态另用“停止后续处理”。

同工作区重连保留草稿，只刷新远端事实；真实工作区切换完成才清理对象上下文。失效版本的草稿可看可复制，不能直接提交给新代次。所有写操作继续沿用Operation幂等、版本与查询合同，不因更换页面布局改写业务状态机。

## 6. 数据模块纠偏的明确交互

### 6.1 列表、详情与编辑

记录页用紧凑查询栏。筛选Popover持有未应用草稿，应用才查询并回第一页；取消不改变当前列表。排序与选列同样使用共享控件，保留已有高级表达式能力。批量状态提交仍冻结明确RecordRef和statusRevision，不通过重新执行筛选扩大目标。

详情改为独立页，左侧字段、右侧业务状态及更新时间；长文本换行/展开，不挤宽整个应用。链接显示复制/打开动作；打开外链是缺失能力，需受控desktop桥只允许HTTP/HTTPS并验证调用窗口和主frame，拒绝任意协议，不能拿现有打开本地目录接口替代。

新增和编辑复用现有record-draft、ScalarValueEditor、编辑协调Hook和真实命令，把表单从Modal拆成可组合内容。编辑页底部保持取消/保存栏，滚动不遮字段错误。系统身份只读；业务字段身份在创建时填写并校验，普通编辑不能修改。只提交改动字段，未触碰异常Excel值不要求先修整行。普通文本/数值字段直接输入；只有需要表达空值/缺失/原始异常的场景才展开值语义，不能让每个字段先选内部值状态。

占用画板采用同日紧凑候选 `PMUI-d7724054d211` 的布局建议，**不是声称它晚于另一稿或已批准**。按已确认业务规则，人工普通内容可做CAS修改，当前记录与任务原始输入分开；占用期间状态与删除受保护。PM2不造假占用。

### 6.2 字段整体草稿与一次保存（合同增强提案）

依据DT-05和原图字段表/影响Drawer，建议字段页维护完整schema draft，新增/编辑Drawer只“应用到草稿”。统一“保存字段”先预检全部变化，再确认一次提交；“重置修改”恢复已保存结构。字段删除保留阶段限制：本阶段完整候选必须包含每个当前fieldId恰好一次，缺失、重复或未知fieldId均拒绝，不把遗漏解释为删除。身份字段、公式及其他受保护属性沿用现有规则锁定；新增项使用候选身份，确认成功再映射为持久fieldId。

现有PM2单字段preview/PATCH不能用前端循环调用伪装全体原子保存。建议在当前project_data领域补充一组聚合schema预检/提交用例，复用现有字段类型、异常证据、约束检查和Operation基础设施，不另建schema服务。准确HTTP名与DTO在批准后的实施计划中定稿。既有 `POST /tables/{tableId}/fields`、`PATCH /tables/{tableId}/fields/{fieldId}`、`DataFieldCreate/DataFieldPatch` 和 `mutateField/FieldMutationResult` 保持原语义与可查询历史结果；聚合命令使用独立Operation种类及结果，不替换旧端点或挪用旧结果结构。两类写入共用同一tableRevision和相关impactRevision证据，交错修改会使旧聚合预检失效，不能绕过并发检查。

预检需绑定：项目/表/数据代次、tableRevision、覆盖相关记录变化的impactRevision、完整候选摘要、既有稳定fieldId与新字段候选身份、实际已实现引用证据。返回每项变更、受影响记录数、阻断/警告及有效候选凭证；未接通自动化/Sheets引用明确“暂未接通”，不能报零引用。

确认提交先按幂等键/规范请求查历史结果，再校验候选摘要、代次与相关版本。约束全量检查可在提交前执行，但短写事务必须重验其证据仍有效；事务内发布全体字段变更及操作结果。任何冲突全部不写，保留草稿、使旧预检作废。新增必填默认值须覆盖旧记录。本轮推荐**有界原子回填**，不创建新数据代次，也不分段改动当前可见记录：预检在一致读快照中计算全部需改写记录和写后values_json，最多1000条且其UTF-8序列化总量不超过4 MiB，任一超限则阻止整个候选提交。展示实际影响和上限，用户可返回草稿调整字段要求；不得自动拆成多次写入或先发布字段再慢慢回填。规模上限是此新增聚合能力的保守设计预算，不是性能实测结论；实施时须对边界规模测量写锁与响应，不能因未达预算就宣称足够快。无需回填的约束全量检查不受1000条上限限制，但必须完整检查并绑定变更证据。最终短事务重新核验代次/结构/impact并一次写入有界记录集、结构和Operation，全部提交或全部回滚；超限大表原子回填的影子存储方案不在本次纠偏中偷偷扩建。既有单字段接口的能力和历史行为保留，本限制专属于新增聚合路径；UI不得用循环旧接口绕过聚合上限。响应丢失查询原Operation，成功结果冻结新fieldId映射。该增强必须有后端失败注入测试，不能作为纯CSS修正交付。

### 6.3 状态、来源和设置

状态页恢复表格与引用说明。列表当前只有状态定义，不能凭空显示引用数；建议由后端投影当前记录数，并区分已实现配置引用与历史身份。删除继续真实影响预检和墓碑身份保留。清空状态推进修订、同一非空状态不推进修订等规则不变。

归档项目禁止业务编辑、同步和重导入，但允许从可读取的表执行查询型XLSX导出到受控新文件；工作区正在切换、不可访问或授权无效仍阻止该导出。Excel来源显示文件名、工作表、导入事实和“本地副本”；导入/重导入/导出沿用当前受控文件令牌、候选代次和恢复路径。旧图未涵盖的已批准PM2能力必须保留并补图，不以对齐为由删功能。Sheets正常页推荐方向拆分稿 `PMUI-d6ac8c03659a`；旧011用于绑定信息和失败结构参考。拉取/推送/本地状态各有事实，结果未知先核验。外部SQLite来源不出现在新入口。

设置改为页内表资料草稿；危险区按能力开启。整表删除尚未实现，不放能点却无效果的按钮。来源不明或云端待核验时，影响与删除必须遵循后续PM6/PM8合同。

## 7. 自动化四页签：旧能力复用与待定边界

详见[补充设计](../../project-management/design-alignment/automation-management-supplement.md)。目录原型不能代替缺失的管理画板。四页为基本信息、输入数据、参数配置、运行设置，共享草稿，完整resolve后单事务保存项目配置。预览不领取、不写状态；PM3配置/预览可交付，数据执行到PM4。

参数与文档变量分开。**推荐参数定义由Studio/core工作流文档唯一维护，项目自动化保存绑定、默认覆盖和启动填写策略。此归属仍待确认。** 当前Studio变量只有名称/类型/值，不能假称稳定parameterId已经实现，更不能每次启动改写document.variables默认值。参数定义放自动化的旧方案可作为备选，但必须补齐独立workflow使用时的唯一参数合同，不能两边各存一份权威定义。

推荐输入预览沿用旧行为：新输入/换表先保存完整配置，再预览已保存事实；不隐式保存。未保存时按钮解释依赖，并提供明确“保存后预览”，失败留在当前草稿。支持未保存候选预览属于另一个合同增强，不作为本轮默认。

PM3参数型批次默认有限1次，零输入/只有可选输入禁止不限；PM4必要数据输入才开放完整有限/不限语义。运行设置中的资源选项复用当前Profile/代理等稳定身份；内核选择遵循已经统一的浏览器配置管理入口，不恢复独立内核导航。默认资源修改只影响随后解析的配置，不更改历史Run或已冻结任务资源。

## 8. 执行、数据、环境与恢复不能混同

- Batch结束不等于全部Task成功；CoreRun终态不等于项目外部清理完成；业务状态只有人工或显式节点修改。
- 记录可复用由当前状态与工作流条件决定，没有“使用过就排除”的隐形规则。
- 任务输入是不可变快照，当前记录可继续变化；节点输出不自动写回表。
- 每个Task使用独立工作实例，持久环境是来源；是否保留由End配置统一保存上下文并关联指定记录。保存成功关联失败必须显示部分完成，保留可修复副本，不重新执行网页、不改历史Run结果。
- 停止/强停、worker撤权、重启先核验从PM3首次执行开始交付。人工现场倒计时不重置也不决定服务端状态。
- PM3提供基础节点日志、错误/截图与序号恢复；完整节点访问/重试链、变量快照、输入/当前数据/输出互查和统计下钻按PM7交付。日志按核心事件序号补读、去重与缺口恢复；旧日志可见时显示非最新状态，不把内核下载SSE冒充完整Run协议。
- 清理请求未知先查原身份；确认未接受才原键重发。已接受且失败的操作保留终态，新“重试清理”是只处理残留的新操作；不能重跑原任务。
- 截图缺失不隐藏仍存在的错误文本和运行事实；附件打开走受控产物能力。前端不能猜测磁盘路径。
