**A-06：先落实合同再替换 Mock。** 逐项核对现有请求、响应、事件、状态机、错误和恢复规则，沿唯一服务传输边界接入真实后端。需要从原版接口投影到 AutoFlow 类型时，在适配边界集中完成，不逐页面添加 fetch 或另一套状态管理。

**A-07：合同冻结不等于禁止修复。** 真实行为暴露合同缺项时，记录来源、影响入口、兼容方式和测试。最小联调修复必须同步类型和证据；新增产品行为需批准。不能通过删除已批准功能、返回假成功，或强迫用户重做整个前端来解决冲突。

**A-08：继续使用本机鉴权 HTTP 与编号 SSE。** 复用现有工作区/实例身份、错误包和 OpenAPI 生成链。所有边界数据运行时验证。错误须保留节点、字段、请求或会话身份，业务冲突与网络离线必须区分。不得只修改生成的 TypeScript 文件，或另建 Socket.IO/WebSocket 体系绕开当前合同。

**A-09：命令和事件提供可确认事实。** 相同命令 ID 与相同有效载荷返回原结果；同 ID 不同载荷返回冲突。HTTP 接受不等于动作完成。状态与需恢复的事件先提交持久化，再通知前端；补读可重复投递但必须可去重。不能承诺数据库事务可令网页和外部系统动作天然“恰好执行一次”。

## 3. 小助手：LangGraph 专项约束

### 3.1 职责和模型接入

**L-01：LangGraph 管理小助手的真实控制流。** 必须覆盖上下文准备、模型调用、结构化工具请求校验、权限等待、工具结果回传、后续对话、结束/失败/取消。允许按现有需求保持简单图，不要求预先建设复杂多 Agent 系统。

**L-02：LangGraph 与模型 API 分工不同。** 用户要求替换的是简单 API 调用承担整个助手编排的实现；底层仍可通过 AutoFlow 的模型 provider 使用 OpenAI 或兼容 API。模型、地址、能力与密钥来自主应用模型管理，不增加 Studio 专属供应商目录或隐藏备用 API Key。不得固定为 OpenAI 单一供应商。

**L-03：小助手图与工作流执行器分离。** 普通工作流继续使用迁入的确定性执行规则；小助手通过受控工具调用已有能力。不会因为采用 LangGraph 就把全部 227 节点转换为模型决定下一步的图。普通 AI 节点是否需要多步编排，由它的已批准语义决定，不机械套用助手图。

**L-04：按实际模型能力选择适配。** 流式、工具调用、结构化输出和视觉能力使用现有模型配置验证；不支持时按合同返回可理解错误，不伪造工具结果。依赖版本、Python 兼容、取消、流式解析和 PyInstaller 收集方式必须有实测。

### 3.2 工具与权限

**L-05：只暴露现有批准工具。** LangGraph 的工具集合映射前端服务/AI 动作台账。MCP 工具也经过配置、能力和权限检查，不因来自 MCP 就获得额外权力；已排除节点、浏览器类型和管理功能不得通过助手恢复。

**L-06：保留前端编辑的所有权。** 添加、连接、配置、撤销等画布操作沿现有 UI 工具协议执行，并等待实际应用确认；后端不能直接改浏览器内的 Store，也不能把“已发出事件”当作“草稿已修改”。保存、运行等命令分别确认，不隐式合并为自动保存或自动启动。

**L-07：权限由确定性代码执行。** 现有工具开关和批准/拒绝策略在服务端复验，模型文本不构成授权。批准绑定工作区、会话、工具、实际参数和有效上下文；参数变化或过期不得借用旧批准。网页文本、检索内容、工具结果及导入内容是数据，不能覆盖系统规则或扩大工具范围。

**L-08：取消贯穿整条助手链。** 取消、拒绝、停止或工作区退出后，不再启动后续模型请求和工具操作；释放当前任务拥有的资源。已完成外部动作按事实保留，取消不伪称撤销外部副作用。不允许以再次请求模型的方式绕过拒绝。

### 3.3 状态、检查点与恢复

**L-09：会话隔离和持久化方案必须显式设计。** 业务会话身份与 LangGraph thread/checkpoint 建立受控映射，并绑定工作区。正式运行不能把只在内存中的检查点当成重启可恢复证据。状态、检查点版本和存储清理统一归入工作区策略，采用与当前 SQLite 和装配边界相容的实现。

**L-10：恢复对话不等于重放工具。** 持久化工具调用身份、批准结果和应用结果；恢复时先查询原命令。LangGraph 中断恢复可能重新进入所在节点，不能把未经幂等保护的副作用放在可能重跑的路径。数据库已提交、外部动作已发生而确认丢失时，记录未知/待核查，不能自动重复点击、发消息、运行或保存。

LangGraph 提供图状态持久化与中断机制，具体机制见官方[持久化说明](https://docs.langchain.com/oss/python/langgraph/persistence)和[中断说明](https://docs.langchain.com/oss/python/langgraph/interrupts)。上面的工具恢复边界是 AutoFlow 的工程要求，不是框架自动保证。

**L-11：事件向前端合同投影。** 模型文本增量、工具请求、权限等待、结果、错误和结束事件复用现有消费合同及游标；不要直接把框架内部原始事件推给 UI。切换文档、修改草稿后，编辑工具依当前合同校验目标和修订，迟到结果不能覆盖新草稿。

**L-12：有界执行和可诊断性（补充建议）。** 明确模型请求超时、单轮工具/图步数上限、最大上下文和结果容量；具体数值经模型适配与受控测试写入规格，不在本约束中猜测。记录模型标识、工具名称、状态、耗时和安全摘要，不能把模型隐藏推理当作审计数据或强制输出。

### 3.4 运行与部署边界

**L-13：LangGraph 在本地后端运行。** 不因引入框架而强制增加 LangGraph 云部署、LangSmith 账号、云数据库或向量数据库。确有已批准功能需要时再设计对应依赖。模型和 MCP 的外部访问仍受用户配置控制，未配置追踪服务时不默认外发对话和工具输入。

**L-14：不以示例证明重构完成。** 必须在正式 Studio 验证多轮工具调用、批准与拒绝、取消、错误、模型能力不支持、重连和编辑应用确认。还需通过有持久副作用的幂等回归；仅返回一段聊天文本或运行 LangGraph demo 不构成验收。

## 4. 浏览器、执行、数据和恢复

### 4.1 CloakBrowser 与 Profile

**R-01：Profile 和内核仍由主应用管理。** Studio 传资源标识，后端读取并验证，按会话规则冻结必要参数。不得相信 renderer 任意提供的可执行文件路径、代理秘密或启动参数。语言、时区、指纹、代理、扩展和无头设置按有效 Profile 与已批准会话差异执行；中文界面不限制浏览器语言和时区。

**R-02：不增加浏览器回退。** CloakBrowser、内核、Profile、License 或代理不可用时准确报错。Playwright/CDP 等如果是 CloakBrowser 现有控制实现的必要依赖，可以在 browser provider 内复用；这不授权下载或启动其他浏览器。

**R-03：启动前完成资源准入。** 按现有合同原子协调运行、Debug、拾取和录制的互斥及 Profile/内核使用锁，启动失败也要释放已获取资源。保留会话内正常页面协作及已批准的关闭策略；不把“只用 CloakBrowser”扩大成一套新会话产品规则。

**R-04：清理完成前保持占用。** 取消必须能中断当前等待，worker 受父进程监管，必要时清理受管进程树。清理失败须保留重试责任与可见错误，不能过早报告关闭或靠启动第二个会话绕开锁。普通成功结束是否保留浏览器，以当前合同和有效配置为准，不能恢复历史“一律立即关闭”的假设。

**R-05：页面身份与定位一致。** 当前页面、标签页选择、框架路径、Shadow DOM、定位候选和动作语义以现有字段及源码映射核验。页面关闭或导航后的旧请求不得转移到另一页执行；定位测试与真实执行必须使用一致定位入口。不得无声忽略不支持的 iframe、输入模式或其他配置。

### 4.2 执行与 Debug

**R-06：执行已接受的独立快照。** 冻结节点、连线、变量、模块依赖、相关配置及参与业务的几何；后续草稿编辑或依赖修改不改变本次运行。日志中的节点名称和配置来源于快照，不能反查当前草稿。秘密只按需受控读取，不进入快照。

**R-07：保持原版及批准适配的执行语义。** 顺序、分支、循环、子流程、变量作用域、表达式、超时和错误策略逐项验证。不能用 Mock 的节点数组遍历当执行器，不能把原版有效表达式能力缩减为旧自研版本的简单变量替换。显式错误值不得被默认值掩盖。

**R-08：预检严格、编辑进度可保留。** 区分可保存的未完成配置、不能保存的结构损坏和不能执行的缺失能力。运行前解析子流程/自定义模块依赖并检测无效引用；未知执行器必须明确失败。分支中尚未触发的动态错误按既定语义处理，不能假造静态可推断结论。

**R-09：Debug 使用同一个执行器。** 暂停、单步、继续、断点和变量交互沿当前合同，校验命令身份和有效调试上下文。不得让调试器与普通运行采用两套节点实现。响应丢失查询原命令，不生成新标识再走一步；停止优先于待执行控制命令。

**R-10：自动重试必须区分操作语义。** 已批准节点错误策略按原行为迁入；传输重连和通用网络重试不能擅自重跑点击、输入、发送、文件写入等副作用。sidecar 崩溃后的执行按中断记录，不自动恢复网页动作。无法确认完成时保留不确定事实。

### 4.3 数据与秘密

**D-01：使用当前工作区持久化基础设施。** 业务数据按现有 SQLite/SQLAlchemy/Alembic 管理，产物及大值通过文件适配器登记。LangGraph 检查点属于同一工作区受管存储；具体表或受管文件布局需在设计中说明，不能擅自另建不受管理的数据目录。

**D-02：只做增量迁移，保留既有数据。** 实施前核验实际 Alembic head、多分支及已存在旧表；不凭历史计划猜编号，不重写已发布迁移、不自动 drop/stamp。未知 revision 明确阻止不安全启动并报告，不靠清空数据库修复。临时工作区验收不等于用户数据迁移已验收。

**D-03：保存与导出确认真实提交。** 更新使用当前修订合同，冲突保留草稿；依赖写入和文档更新保持所需原子性。导出先确认所需更新成功，失败不能导出旧服务内容。旧文档、Mock 文档和正式数据分别处理；Mock 记录不能未经明确流程自动升级为生产事实。

**D-04：秘密复用系统凭据存储。** API Key、代理密码、License 和凭据秘密不得进入普通 SQLite 业务字段、文档、事件、检查点、异常栈输出或导出。检查点和日志使用引用/安全摘要；必要模型输入按工具权限按需构建，不能把整个 Profile 或全部配置交给模型。失败时不回退为明文保存。

**D-05：文件操作验证归属与冲突。** 产物读取基于已登记身份，导入检查格式、依赖、大小及路径穿越，临时文件失败后可清理。已批准的自定义输出路径和覆盖规则必须保留；不能为了实现简单禁止全部外部路径，也不能无条件允许任意路径或覆盖现有文件。

### 4.4 事件、容量与离开

**D-06：日志覆盖多次执行。** 循环中同一节点各次执行和各次产物分别可识别；日志、诊断、结果和录制步骤保留各自顺序与身份。分页、筛选、补读和导出覆盖实际持久数据，不能只处理前端已加载部分。大值使用登记引用按需读取，不截断后仍声明完整。

**D-07：采用真实恢复语义。** SSE 断线只影响连接状态，恢复时补读并查询原会话/命令。持久记录可以恢复，不等于进程或外部动作继续。录制确认以持久提交为准，尾部丢失要明确，不能伪造步骤或重放用户动作。

**D-08：离开次序沿统一协调。** 新建/打开/关闭 Studio/退出/换区处理草稿后，再停止或关闭应清理的会话，清理完成才进入停写、sidecar 退出或换区。保存失败与用户取消保留会话；仅关闭主窗口且 Studio 仍存续时按既有合同继续。后台助手任务也必须纳入对应所有权和退出协调。

**D-09：容量限制须有数据依据。** 复用当前合同和配置的步骤、日志、文件及大值边界；未定义部分先测量再定值，不从已弃用里程碑机械搬数值。磁盘不足、凭据不可用、模型限流和文件缺失必须给出可追踪错误。达到限制不能丢数据后继续报成功。

## 5. 执行方式、验收和交接

### 5.1 开发纪律

**V-01：一个功能块完整交付。** 源码映射、契约、实现、错误/取消/恢复、必要测试和证据一起关闭。先打通真实保存、Profile、执行、日志和清理的最小闭环，再按依赖扩展；第一阶段小不等于后续范围缩水。小助手可有独立验收阶段，但不得落成临时直接 API 实现后宣布完成。

**V-02：保护工作树和主应用。** 每次开工核实目录、分支、状态；不覆盖无关改动，不为文档任务重启服务、清空测试外的数据或改写主任务现场。共享 Store、合同和生命周期修改必须有唯一负责人。源码改动按功能边界提交，文档任务不混入业务变更。

**V-03：不制造重复台账。** 复用当前能力 ID、服务合同和证据索引。新发现问题记录来源、影响和阻塞性；非阻塞问题按优先级排队。新增产品功能、浏览器类型、节点或基础设施需另行批准，不能在迁入过程中自然扩张。

### 5.2 必须落实的测试组

以下是后端用例矩阵的强制覆盖方向，不声称这些测试当前已经通过；具体前置数据、操作和预期由各阶段展开。

| 测试组 | 必须覆盖的行为 | 核心证据 |
|---|---|---|
| T-01 范围与兼容 | 227 类型映射；未声明及排除节点拒绝执行；嵌套模块绕过防护；旧文档无损保存 | 类型集合检查、接口测试、保存/导出往返 |
| T-02 浏览器与执行 | 只有 CloakBrowser；Profile 参数生效；网页/控制流/变量/子流程；iframe 与真实定位；启动/取消/清理失败 | 本地受控网页、真实浏览器行为、受管进程与锁记录 |
| T-03 数据与恢复 | 修订冲突、幂等、响应丢失、SSE 补读、磁盘失败、崩溃、迁移及工作区隔离 | 临时 SQLite、真实 HTTP/SSE、故障注入和持久数据核对 |
| T-04 LangGraph 助手 | 多轮工具；批准/拒绝；取消与迟到结果；重启查询；中断恢复不重复副作用；模型差异；权限与秘密隔离 | 图状态/安全事件、工具计数、正式 UI 应用确认；至少一条已配置真实模型链路 |
| T-05 正式应用 | 保存重开、运行/Debug、拾取应用、录制审查后独立重放、助手编辑、离开保护及打包入口 | Electron 真实点击/输入/快捷键，冻结 sidecar 和各平台独立记录 |

**V-04：分清证据层次。** 单元/组件测试、HTTP/SSE 合同测试、真实浏览器、真实模型和正式 Electron 分别记账。Mock 可验证错误分支和稳定协议；不能证明真实节点执行、采集或模型工具调用完成。核心 UI 链不能通过直接修改 Store 或调用页面私有函数替代。

**V-05：有针对性地扩大回归。** 局部变化运行受影响测试和必要检查；共享基础设施变化、功能块关闭及最终交付扩大回归。不能删除失败用例、放宽文档断言或把未测标通过。后端运行 pytest/Ruff/mypy；涉及前端则检查 Vitest/TypeScript/ESLint；合同、迁移、目录和打包按影响验证。

### 5.3 平台与最终完成标准

**V-06：平台结果独立记录。** macOS arm64、macOS Intel、Windows x64 分别核对 CloakBrowser、秘密存储、进程取消、路径/Unicode、LangGraph 依赖、PyInstaller 及 Electron 包。模拟平台分支、开发 URL 成功或未签名本机包启动，不能自动转记为其他平台或发行验收通过。

**V-07：每次交付提供五项结果。**

1. 用户现在能完成的真实业务链路，以及对应能力 ID。
2. 本次采用的源码、必要适配和与原版的行为差异。
3. 执行的测试、证据位置、平台及服务版本。
4. 当前剩余功能块、阻塞项和未实测部分。
5. 下一交付物；时间分开发、验证、外部等待，缺乏依据就标未知。

**V-08：完成必须同时满足以下条件。**

1. 全部有效节点及配套服务有实际实现，不存在被当成完成的 Mock 或假成功入口。
2. 前端合同接通，必要异常、取消、恢复、秘密和工作区隔离验证通过。
3. 小助手实际使用 LangGraph 完成工具及权限闭环，恢复不导致副作用重复执行。
4. 正式窗口核心链路及目标平台验收有真实证据，用户数据兼容和未验收平台如实列出。
5. 源码映射、规格、合同、测试台账、差异记录和后端交接保持一致。
